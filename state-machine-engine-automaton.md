# Движок стейт-машины: код исполнителя

Движок любой стейт-машины, записанный кодом на языке Нов: конверт запроса и ответа (`Запрос`, `Исход`, `КодСбоя`), снимок и хранилище, исполнитель (цикл, приём при приходе, фиксации, отправка запросов, повтор, журнал и трасса, передача сигналов вложенным, необратимые действия), общие события «стоп человека», «стоп от родителя», «отмена_запроса», пауза цепочки и протокол `Вызываемое`. Машина подставляется протоколом `Автомат`: движок не знает ни её состояний, ни событий, ни ролей; поэтому он обобщён по `Состояние`, `Событие`, `Вход`, `Выход`, `ВходРоли`, `РезультатРоли`, `Действие`, и это труднее читать, чем код одной машины. Машина может быть событием в другой машине (правило 35): исполнитель с машиной реализует `Вызываемое`.

**Нормы — [state-machine-spec.md](state-machine-spec.md)** (правила 12–25, 31, 35). Этот файл — запись движка, а не вторая спецификация: при любом расхождении верна спецификация, а этот файл правится вслед за ней. Пример реализации машины, подставляемой в движок, — [task-runner-meeting-automaton.md](task-runner-meeting-automaton.md) (машина совещания; её первоисточник — [task-runner-meeting-states.md](task-runner-meeting-states.md)); имена блока «Типы на Нове» и таблица соответствия — там же. Язык записи — Нов, https://github.com/nv-lang/nova (синтаксис — по `spec/syntax.ru.md`, `spec/effects.md` и `nova.ungrammar` того репозитория). Внешний мир — пять эффектов Нова: `Хранилище`, `Журнал`, `Связь`, `Объекты` и стандартный `Time`; обработчик каждого может быть любым (база, диск, очередь сообщений, чат) и в этом файле не записан. Ворота человека не эффект: машина фиксирует состояние, отправляет вопрос через `Связь.отправить` и завершает шаг; слово приходит позже сообщением, а после перезапуска состояние берётся из `Хранилище.загрузить` (ожидание часами, переживающее перезапуск, в Нове не определено). **Код не компилировался и не проверялся компилятором Нова:** это псевдокод в синтаксисе Нова; места, где Нов не выражает записанное или где синтаксис не подтверждён спецификацией, помечены строкой `// псевдокод:` (перечень — в соглашениях, пункт 5). Имя файла — по `AGENTS.md`, «Вынесенные алгоритмы» (документ `state-machine`, часть `engine`, форма `automaton`).

## Соглашения записи

1. **Типы и параметры.** Имена — русские: слово или слитное сочетание с заглавной буквы без подчёркиваний (`КодСбоя`, `СостояниеДвижка`). Параметры типов — осмысленные русские имена: `Состояние`, `Событие` (перечисления машины), `Вход`, `Выход` (вход и итог машины как вызываемой), `ВходРоли`, `РезультатРоли` (вход запроса к стороне и её результат), `Действие` (необратимое действие машины), `Маш` (тип машины с протоколом `Автомат`).
2. **Идентификаторы** все русские: типы и варианты — с заглавной буквы без подчёркиваний, поля, параметры, локальные переменные и функции — змеиный регистр (правило 25 спецификации: имя одной сущности одно). Латиница — только стандартные имена Нова (`fn`, `type`, `match`, `Option`, `Some`, `None`, `Result`, `Ok`, `Err`, `HashMap`, `str`, `int`, `bool`, `never`, `effect`, `with`, `protocol`, `loop` и др.). Нов кириллические идентификаторы не поддерживает (владелец, 2026-10-17); русские имена в псевдокоде — решение этого файла.
3. **Запись Нова.** `ro` — неизменяемая привязка, `mut` — изменяемая переменная; отсутствующее значение — `None`, значение — `Some(x)`; строки — `"… ${выражение} …"`; комментарий — `//`, документирующий — `///` (перед объявлением, пустая строка перед ним). Метод — `fn Тип @имя(…)` читает, `fn Тип mut @имя(…)` меняет; обращение к полю и вызов метода — через `@`. Данные движка у исполнителя — `@д.<поле>`, метод машины — `@машина.<метод>`, служебные операции машине — через значение `Среда`. «То же состояние» — `Остаться`, «запуск заново» — `Заново(S)`, «Куда» — `Куда(S)`, «сразу» — событие `событие_сразу()`.
4. **Механика исполнителя.** Раздел «Механика исполнителя» — перечень механики контракта, фиксации и приёма (правила 13–22, 31, 35 спецификации): свободные функции и методы `Исполнитель`; большинство объявлено только сигнатурой, телом записаны те, что выражаются данными.
5. **Строки `// псевдокод:`** стоят там, где записанное — не Нов или не подтверждено его спецификацией: функции без тела (сигнатуры механики); `недостижимо`; кодирование среза исполнителя в строку снимка (`кодировать`, `раскодировать`); ресивер как значение протокола (`среда`). **Подтверждено спецификацией Нова** (проверено оркестратором проекта по чтению репозитория языка, 2026-10-18; компилятором не проверено): `///` — внешний документирующий комментарий (`spec/decisions/03-syntax.md`, D104; привязан к следующему полю записи и варианту суммы); `never` строчная — тип выражения, которое не возвращает значения (`spec/decisions/04-effects.md`, D25), его и берёт `недостижимо`; `Never` заглавная — пустой тип, нужен только как аргумент `E` в `Effect[E, Never]`, здесь не используется; `fn Тип.new()` — статическое объявление (`spec/syntax.ru.md`, `fn Account.new(…)`); `.contains()` на `[]T` (std, `collections/vec/access.nv`); `.len()` на списке (`vec/core.nv`); срез `v[a..]`, `v[a..b]` (`vec/slice.nv`, Plan 284; за границами паника, безопасно `v.get(a..b)`); присваивание как ветка `match` допустимо (`nova.ungrammar`, `MatchArm`), здесь оно записано блоком `=> { x = v }`; длина текста (`.len()` на `str`) нигде не берётся. **Протоколы** (прочитано в `spec/syntax.ru.md`, раздел «Структурные "интерфейсы" — protocol», 2026-10-18; компилятором не проверено): `type Имя protocol { @метод() -> T }`, изменяющий метод — `mut @метод(…)`, обобщённый протокол — `type Next[T] protocol { … }`, соответствие структурное, `impl` не нужен — поэтому `Исполнитель` реализует `Вызываемое` совпадением метода `вызвать`, а машина — `Автомат` совпадением методов. **Эффекты** (прочитано в `spec/effects.md`, 2026-10-18, D61/D142/D434/D456; компилятором не проверено): `type Хранилище effect { fn … -> T }` — операции без `@` и без `mut`, тип возврата обязателен; эффект в сигнатуре между `)` и `->` (`fn … Хранилище -> …`); вызов по имени `Хранилище.сохранить(…)`; обработчик подставляет `with Хранилище = обработчик { … }` один раз у вызывающего кода; прямой эффект объявляется в сигнатуре, транзитивный — предупреждение, при `--strict-effects` ошибка; требование проекта Нова — объявляют все функции цепочки, так в этом файле и записано; единый `with` — на точке запуска. **Записано по выводу, спецификацией не подтверждено:** ошибка операции эффекта через `Result` (форма `Fail[E]` для операции эффекта в спецификации не найдена); форма метода с эффектом `fn Тип @метод(…) Эффект -> Т` (в спецификации — только свободные функции; метод — вывод, не цитата), в том числе у методов протокола; эффекты без параметров типа: обобщённые эффекты в Нове не поддерживаются (`E_EFFECT_GENERIC_UNSUPPORTED`), поэтому через `Связь` ходят конкретные типы `ВходСтороны`, `РезультатСтороны`, `СобытиеСтороны`, а кодирование и раскодирование — методы машины; `Timestamp` и `Time.now()`, `Time.now_monotonic()` (тип результата принят как целое число миллисекунд); подстановка `Time` обработчиком по умолчанию без `with`. **Не подтверждено спецификацией, без пометки в коде:** русские имена параметров типа `[Вход, Выход]`; `return` из `loop` значением функции (`цикл`); протокол с несколькими параметрами типа и параметр типа с границей-протоколом (`Маш Автомат[…]`); `.clone()` и `.reverse()` на списке (по образцу std, не проверено); многопривязочный `with Хранилище = …, Журнал = …, …` (в спецификации — одна привязка); оператор `?` для `Option` в теле метода (`общие_события`); обобщённые свободные функции `fn имя[Тип](…)` (в спецификации есть `fn get[K, V, C Index[K, V]]`). **Записано по слову владельца, спецификацией не подтверждено (2026-10-18):** оператор `??` для `Option` — значение либо запасное, правая часть вычисляется только при `None` (`обработать_очередь`). **Тело функции:** блок без стрелки `fn … { … }` (последнее выражение — значение) или `fn … => выражение`; `=> { поле: значение, … }` — литерал записи, так записаны только конструкторы `.new` (спецификация Нова: `FnDecl … (Block | FnExprBody)`, `FnExprBody = "=>" Expr`; проверено оркестратором проекта, 2026-10-18).
6. **Исполнитель, хранилище, вызываемое.** `Исполнитель` владеет машиной `Маш` и данными движка `СостояниеДвижка`: очередь входящих `очередь`, запрос вызова `вызов`, `готовый_ответ`, `необратимые`, `в_работе`; данные раздела «Данные» первоисточника машины, которые пишет исполнитель (`трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `запрос_вызова`, `открытые_запросы`, `принятые_запросы`, `к_отправке`, `ожидание` и др.), лежат в `СостояниеДвижка`, остальное — у машины. `Хранилище` — эффект (`type Хранилище effect`) с операциями `загрузить` и `сохранить`, возвращающими `Result[…, ОшибкаХранилища]`; вызов по имени `Хранилище.сохранить(…)`, обработчик подставляет вызывающий код (`with Хранилище = …`) — любой, вне файла; так же `Журнал` (`записать`), `Связь` (`отправить`, `принять` без ожидания) и `Объекты` (необратимые действия над объектами и чтение для отпечатка); эффекты `Хранилище`, `Журнал`, `Связь`, `Объекты`, `Time` объявляют все функции цепочки в своей сигнатуре (от `начать`, `возобновить`, `вызвать`, `цикл` до обёрток), единый `with` — на точке запуска; «нет ответа в срок» рождается из сравнения сроков запросов со `Time` (срок — данные запроса, `Ожидание`); после перезапуска `Ожидание` сбрасывается, потому что моменты монотонного времени несравнимы: запросы к ролям без принятого ответа отменяются, повторённые запросы к вложенным получают срок заново при отправке; внешний мир закрыт эффектами — `Хранилище`, `Журнал`, `Связь` (отправка, приём, отмена, сигналы вложенным, ответ вызвавшему), `Объекты`, `Time`; ответ покидает машину только через `Связь.ответить` (повторяемое необратимое действие последнего этапа фиксации; `вызвать` отдаёт вызвавшему тот же `готовый_ответ` как значение и второй раз не шлёт: `ответ_отправлен` в снимке ставится отдельной фиксацией, `возобновить` повторяет отправку, если ответ не ушёл); если `сохранить` не удалось — исполнитель аварийно прерывается (`недостижимо`), шаг не считается зафиксированным, запросы не отправляются. `Снимок` — две строки: данные движка (`СрезИсполнителя`) и данные машины (`снять` машины); `зафиксировать` вызывает `сохранить` в конце шага, ДО отправки запросов (правило 13). Входов два: `начать(запрос)` — состояние движка, фиксация, цикл; `возобновить(идентификатор_запроса)` — загрузка снимка и продолжение с сохранённого `состояние` (запросы без принятого ответа уходят повторно, пауза остаётся до «продолжить»; правила 12, 14, 22); остановка исполнителя — завершение процесса: состояние уже сохранено. Запрос вызова всегда есть (`запрос_вызова` = `запрос.идентификатор_запроса`): через `Вызываемое` машину вызывают только запросом; решение, оставлять ли `""` у верхнего уровня, открыто (владелец не решил). Событие `ПросроченЗапрос` исполнитель порождает как `Входящее` с `запрос: Some(ид)` и стороной по `сторона_запроса(ид)`. `Вызываемое[Вход, Выход]` с методом `вызвать(запрос) -> Исход[Выход]` реализует `Исполнитель`; повтор запроса с тем же идентификатором возвращает готовый ответ или, если прогон идёт, ждёт его (правило 35, п. 4); при перезапуске запросы к вложенным машинам не отменяются, а повторяются тем же идентификатором.
7. **Граница с машиной.** Движок требует от машины протокол `Автомат` (методы `начальное`, `перейти`, `вид`, `общее`, `обращение`, `вход_запроса`, `следующая_попытка`, `при_приёме`, `записать_результат`, `выполнить_операцию`, `при_входе_в_конец`, `ответ_по_концу` и вспомогательные) и даёт ей `Среду` (журнал, слова человека, сигналы вложенным, необратимые действия, данные движка `к_отправке`, `открытые_запросы`, `предыдущее`, `запрос_вызова`, `запись_перехода`). Машина сводит свои события к `ОбщееСобытие` методом `общее`; движок разбирает «стоп человека», «стоп от родителя», «отмена_запроса» и «продолжить вне ПАУЗЫ» до строк состояний. Предел одновременных запросов отдаёт машина (`предел_запросов`); срок бездействия роли — данные запроса, задаёт машина (`обращение`).
8. **`недостижимо(текст)`** — тип `never`: ничего не отдаёт и аварийно прерывает исполнителя. Ветка невозможна при соблюдении инвариантов — это ошибка программы. Дефект самой машины (развилка, у которой ни одно условие не подошло) идёт иначе: строка «иначе → ОШИБКА», состояние ошибки, ответ-отказ `НетРезультата`. В движке `недостижимо` стоит: в `получатель` (запрос вызова не принят), в `вызвать` (снимок только что загружен), в `сохранить_снимок` и `загрузить_снимок` (хранилище не ответило); в реализации машины — по её описанию.

## Типы

```nova
module движок_автомата

/// Запись автомата: сигнал вложенной машине (правило 35): что передать и по какому запросу
type СигналВложенному { сигнал str, запрос str }

/// Запрос
type Запрос[Вход] { идентификатор_запроса str, номер_попытки int, сторона str, вход Вход, срок_бездействия int, трасса str, номер_шага int }

/// Ответ
type Исход[Результат] enum
  | СРезультатом(ОтветСРезультатом[Результат])
  | Отказ(ОтветОтказ)

/// Ответ (с результатом)
type ОтветСРезультатом[Результат] { запрос str, сторона str, результат Результат, трасса str, номер_шага int }

/// Ответ (отказ)
type ОтветОтказ { запрос str, сторона str, причина КодСбоя, текст str, трасса str, номер_шага int }

/// КодСбоя
type КодСбоя enum
  | НетРезультата
  | ОтказМодели
  | СоединениеОборвалось
  | ФормаНеИсправлена
  | НетОтветаВСрок
  | ОстановленоЧеловеком  // остановлено человеком
  | ПотолокЗаходов  // потолок заходов с открытыми находками
  | ОтмененоРодителем  // отменено родителем

/// Запись движка: событие с конвертом (правила 13 и 31 спецификации); `Событие` — тип событий машины
type Входящее[Событие] {
  идентификатор str,        // «<вид>-<номер по счётчику событий>»
  сторона str,              // «событие.сторона»; у событий ворот и общих событий не читается
  запрос Option[str],       // идентификатор запроса, чьим исходом событие пришло (механика закрытия запроса)
  тело Событие              // вариант события машины и его данные
}

/// Запись движка: вид состояния (четыре вида первоисточника, раздел «Состояния»)
type Вид enum
  | Обращение
  | Операция
  | Развилка
  | Конец

/// Запись движка: то, что исполнитель обрабатывает при приходе — типизированно, типами машины: ответ или отказ роли, слово человека, сигнал, срок (правила 14, 16, 23)
type Получено[Событие, РезультатРоли] enum
  | ПолученОтвет(Исход[РезультатРоли])  // результат или отказ открытого запроса
  | ПолученоСлово(Событие)              // слово ворот человека или общий сигнал
  | ПросроченЗапрос(str)                // «нет ответа в срок»: идентификатор запроса; порождает исполнитель сравнением со сроком

/// Запись движка: куда ведёт строка
type Переход[Состояние] enum
  | Куда(Состояние)         // «Куда»: состояние
  | Заново(Состояние)       // «Куда»: состояние, запуск заново (правило 18)
  | Остаться                // «Куда»: то же состояние
  | НеЖдёт                  // событие этого состояния не ждёт: остаётся в очереди (правило 13)

/// Запись движка: общее событие — то, что разбирается до строк состояний любой машины (правила 17, 23, 35);
/// машина сводит к нему свои события методом `общее`
type ОбщееСобытие enum
  | ЧеловекСтоп { слово_человека str, автор str, источник str }   // «стоп человека»
  | РодительСтоп { идентификатор_запроса str }                    // «стоп от родителя»
  | ЗапросОтменён { идентификатор_запроса str }                   // «отмена_запроса»
  | ПродолжитьВнеПаузы                                            // «продолжить» вне ПАУЗЫ: отбрасывается

/// Запись движка: вход запроса к стороне, закодированный машиной (`кодировать_вход`): через эффект `Связь` ходят конкретные типы,
/// обобщённые эффекты в Нове не поддерживаются (`E_EFFECT_GENERIC_UNSUPPORTED`)
type ВходСтороны { данные str }

/// Запись движка: результат стороны, закодированный стороной; машина раскодирует его в `РезультатРоли`
type РезультатСтороны { данные str }

/// Запись движка: событие стороны (слово человека, сигнал), закодированное; машина раскодирует его в `Событие`
type СобытиеСтороны { данные str }

/// Запись движка: выход машины (её итог как вызываемой), закодированный машиной (`кодировать_выход`)
type ВыходСтороны { данные str }

/// Запись движка: запрос к стороне, как он уходит через `Связь`
type ЗапросРоли alias Запрос[ВходСтороны]

/// Запись движка: то, что приходит через `Связь`: ответ или отказ стороны, слово человека или сигнал «стоп»/«продолжить»/«остановить»/«отмена» (человека и родителя)
type Сообщение enum
  | ОтветРоли(Исход[РезультатСтороны])
  | Слово(СобытиеСтороны)

/// Запись движка: сколько запрос ждёт ответа — для «нет ответа в срок» (срок бездействия — данные запроса, правило 19)
type Ожидание { отправлено int, срок int }

/// Запись журнала: конверт трассировки и текст строки (правило 31); `счёт_по_моделям` — буфер строк счёта по моделям, пишется при фиксации
type ЗаписьЖурнала { трасса str, номер_шага int, причина_шага str, состояние str, идентификатор_запроса str, время Timestamp, текст str, счёт_по_моделям str }

/// Запись движка: как состояние-обращение обращается к сторонам (правила 15, 21)
type ОписаниеОбращения enum
  | Набор { срок_бездействия int, порядок []str }                                // набор сторон из `к_отправке`, запросов одновременно не больше `предел_запросов` машины
  | Одна { сторона str, срок_бездействия int }                    // одна сторона
```

```nova
/// Данные движка любой машины: конверт трассировки, очередь запросов, журнал и хранилища слов; поля названы как переменные раздела «Данные» первоисточника.
/// Сохраняются целиком вместе с состоянием машины, после перезапуска исполнитель входит заново в «состояние» (правило 22).
type СостояниеДвижка[Состояние] {
  трасса str,                                  // назначается при старте, не меняется; конверт трассировки, в Вход не входит
  номер_шага int,                              // число фиксаций шагов; растёт на 1 внутри фиксации, откат возвращает; перезапуск и пауза не сбрасывают
  счётчик_событий int,                         // +1 при приходе любого события; перезапуск и пауза не сбрасывают
  причина_шага str,                            // идентификатор события, с которого начался шаг
  запрос_вызова str,                           // идентификатор запроса вызова; пишет исполнитель при начале (запрос.идентификатор_запроса)
  состояние Состояние,                         // где машина ждёт (обращение или конец); пишет исполнитель при фиксации шага (правило 13)
  предыдущее str,                              // имя состояния, прерванного «стоп человека» или «стоп от родителя»; пишут только они
  открытые_запросы []str,                      // идентификаторы запросов, не закрытых переходом (правила 16, 21)
  принятые_запросы []str,                      // идентификаторы запросов с принятым ответом, ждущим перехода (правило 14)
  к_отправке []str,                            // стороны набора, которым запрос ещё не отправлен
  сигналы_вложенным []СигналВложенному,        // сигналы вложенным машинам («стоп», «продолжить», «остановить», «отмена») с идентификаторами их запросов, поставленные шагом; после фиксации их передаёт и очищает исполнитель (правило 35)
  ожидание HashMap[str, Ожидание],             // открытые запросы и их сроки: «нет ответа в срок» рождается из сравнения с `Time`; в снимок не входит осмысленно: после перезапуска сбрасывается
  счёт_по_моделям str,                         // буфер строк счёта по моделям: пишется в журнал при фиксации
  запись_перехода str,                         // текст журнала перехода в ОШИБКУ; пишет ошибка_машины
  слова_человека str,                          // слово человека с автором и источником, ключ — идентификатор события; никакой шаг не читает
  тексты_сбоев str,                            // свободный текст отказа, ключ — идентификатор события сбоя; никакой шаг не читает, в журнал не идёт
}

/// Начальные значения данных движка; состояние — начальное состояние машины.
fn СостояниеДвижка.new(начальное Состояние) -> СостояниеДвижка[Состояние] => {
  трасса: "",
  номер_шага: 0,

  причина_шага: "",
  запрос_вызова: "",
  состояние: начальное,
  предыдущее: "",
  открытые_запросы: []str.new(),
  принятые_запросы: []str.new(),
  к_отправке: []str.new(),

  тексты_сбоев: "",
```

## Протоколы и хранилище

```nova
/// Среда: что движок даёт машине внутри перехода — служебные операции и данные движка (правила 8, 13, 14, 17, 18, 19, 21, 35).
/// Машина меняет данные движка только через неё.
type Среда[Состояние, Событие, Действие] protocol {
  mut @писать_журнал(текст str) Журнал Time -> ()                                   // строка журнала с конвертом: трасса, номер_шага, причина_шага, состояние, идентификатор запроса, время (правило 31)
  mut @ошибка_машины(текст str) Журнал Time -> Переход[Состояние]             // писать_журнал(текст); запись_перехода = текст; Куда(состояние ошибки)
  mut @записать_слово_человека(событие Входящее[Событие], слово str, автор str, источник str) Журнал Time -> ()
  mut @отбросить(событие Входящее[Событие]) Журнал Time -> ()                       // чужой или поздний сигнал: строка журнала, состояние то же (правило 17)
  mut @передать_вложенным(сигнал str)
  mut @добавить_необратимое(действие Действие)                    // выполняется после сохранения (правило 13)
  @к_отправке() -> []str
  mut @установить_к_отправке(стороны []str)
  mut @вернуть_первой_в_отправку(сторона str)
  @открытые_запросы() -> []str
  @предыдущее() -> str
  @запрос_вызова() -> str
  @запись_перехода() -> str
}

/// Автомат: что движок требует от машины. Любая машина, у которой есть эти методы, подходит (соответствие структурное, `impl` не нужен).
/// Параметры: `Состояние` и `Событие` — перечисления машины, `Вход` и `Выход` — вход и итог машины как вызываемой, `ВходРоли` и `РезультатРоли` — вход запроса к стороне и результат стороны, `Действие` — необратимое действие машины.
type Автомат[Состояние, Событие, Вход, Выход, ВходРоли, РезультатРоли, Действие] protocol {
  @начальное() -> Состояние
  mut @перейти(текущее Состояние, тело_события Событие, событие Входящее[Событие], среда Среда[Состояние, Событие, Действие]) Журнал Объекты Time -> Переход[Состояние]
  @вид(состояние Состояние) -> Вид
  @общее(текущее Состояние, тело_события Событие) -> Option[ОбщееСобытие]
  @состояние_паузы() -> Состояние
  @состояние_остановлено() -> Состояние
  @состояние_ошибки() -> Состояние
  @имя_состояния(состояние Состояние) -> str
  @обращение(текущее Состояние) -> Option[ОписаниеОбращения]
  @вход_запроса(текущее Состояние, сторона str, среда Среда[Состояние, Событие, Действие]) Объекты -> ВходРоли
  @предел_запросов() -> int
  @кодировать_вход(вход ВходРоли) -> ВходСтороны
  @раскодировать_результат(результат РезультатСтороны) -> РезультатРоли
  @раскодировать_событие(событие СобытиеСтороны) -> Событие
  @кодировать_выход(выход Выход) -> ВыходСтороны
  mut @следующая_попытка(сторона str) -> int
  mut @при_приёме(текущее Состояние, ответ Исход[РезультатРоли])
  mut @записать_результат(текущее Состояние, ответ Исход[РезультатРоли])
  mut @выполнить_операцию(операция Состояние, среда Среда[Состояние, Событие, Действие]) Журнал Объекты Time -> Option[[]str]
  @результат_как_событие(операция Состояние, результат Option[[]str]) -> Событие
  @событие_сразу() -> Событие
  @событие_сбоя(причина КодСбоя) -> Событие
  mut @при_входе_в_конец(конец Состояние, среда Среда[Состояние, Событие, Действие]) Журнал Time -> ()
  @ответ_по_концу(вызов Запрос[Вход], конец Состояние, среда Среда[Состояние, Событие, Действие]) -> Исход[Выход]
  mut @записать_остановку(причина str)
  @метка_инварианта() -> int
  @объект_менялся_с_начала_попытки(текущее Состояние) Объекты -> bool
  mut @выполнить(действие Действие) Объекты -> ()
  mut @принять_файл_попытки(идентификатор str) Объекты -> ()
  @снять() -> str
  mut @восстановить(данные str)
}

/// Событие: машина как вызываемое событие другой машины (правило 35). Вход и выход — типы запроса и итога.
type Вызываемое[Вход, Выход] protocol {
  mut @вызвать(запрос Запрос[Вход]) Хранилище Журнал Связь Объекты Time -> Исход[Выход]
}

/// Снимок: всё состояние движка и машины на конец шага — две строки: данные движка (`СрезИсполнителя`) и данные машины (`снять` машины); кодирует их сторона-владелец.
type Снимок { данные_движка str, данные_машины str }

/// Ошибка операции хранилища (запись движка): минимальный текст причины.
type ОшибкаХранилища { текст str }

/// Объект хранилища машины (рабочий документ, находки и т. п.): имя, по которому обработчик находит файл (запись движка, конкретный тип)
type Объект { имя str }

/// Ошибка операции над объектом (запись движка): минимальный текст причины
type ОшибкаОбъекта { текст str }

/// Журнал — эффект: куда писать строки журнала с конвертом; обработчик — любой (файл `log.md`, база).
type Журнал effect {
  fn записать(запись ЗаписьЖурнала) -> ()
}

/// Связь — эффект: как запрос уходит стороне и как приходят ответы и сигналы; обработчик — любой (файлы и процесс, очередь сообщений, чат).
/// `принять` не ждёт (по образцу `try_recv`): нет сообщения — `None`. Ворота человека — не эффект: машина фиксирует состояние, отправляет вопрос
/// через `отправить`, завершает шаг; слово приходит позже сообщением, после перезапуска состояние берётся из `Хранилище.загрузить`.
type Связь effect {
  fn отправить(запрос ЗапросРоли) -> ()                        // запрос стороне (и повтор того же запроса с тем же идентификатором)
  fn принять() -> Option[Сообщение]                            // пришедшее сообщение без ожидания
  fn отменить(идентификатор_запроса str) -> ()                 // отмена открытого запроса (правило 18)
  fn сигнал(идентификатор_запроса str, сигнал str) -> ()       // «стоп», «продолжить», «остановить», «отмена» вложенной машине (правило 35)
  fn ответить(ответ Исход[ВыходСтороны]) -> ()                 // ответ вызвавшей стороне (правило 35): повторяемо и идемпотентно по запрос_вызова
}

/// Объекты — эффект: доступ к объектам машины, необратимые действия над ними (правило 13) и чтение для отпечатка; обработчик — любой (поверх `Fs`).
type Объекты effect {
  fn закрыть_для_записи(объект Объект) -> Result[(), ОшибкаОбъекта]
  fn открыть_для_записи(объект Объект) -> Result[(), ОшибкаОбъекта]
  fn перенести_в_архив(объект Объект, суффикс int) -> Result[(), ОшибкаОбъекта]
  fn прочитать(объект Объект) -> Result[[]u8, ОшибкаОбъекта]
  fn принять_файл_попытки(объект Объект, идентификатор_запроса str) -> Result[(), ОшибкаОбъекта]
}

/// Хранилище снимков по идентификатору запроса — эффект: как сохранять и загружать, выбирает вызывающий код (`with Хранилище = обработчик`).
/// Обработчик — любой (база, файл поверх `Fs`/`Db`, очередь сообщений), вне этого файла. Ошибка операции — через `Result`.
type Хранилище effect {
  fn сохранить(идентификатор_запроса str, снимок Снимок) -> Result[(), ОшибкаХранилища]
  fn загрузить(идентификатор_запроса str) -> Result[Option[Снимок], ОшибкаХранилища]
}

/// Срез исполнителя: то, что кроме данных машины входит в снимок (поля `Исполнитель` без машины и флага `в_работе`).
type СрезИсполнителя[Состояние, Событие, Вход, Выход, Действие] {
  д СостояниеДвижка[Состояние],
  очередь []Входящее[Событие],
  вызов Option[Запрос[Вход]],
  готовый_ответ Option[Исход[Выход]],
  ответ_отправлен bool,
  необратимые []Действие,
}
```

## Механика исполнителя

```nova
// Раздел записывает механику контракта, фиксации и приёма (правила 13–22, 31, 35 спецификации). Функции делятся по владельцу:
//   свободные — без данных; методы `Исполнитель` — очередь, хранилище, транспорт, журнал и данные движка.
// псевдокод: функции без тела — сигнатуры; тело пишет исполнитель, в Нове внешняя реализация здесь не показана

// Свободные функции
// идентификатор запроса = сторона, «-», номер попытки (правило 15)
fn сторона_запроса(идентификатор str) -> str
fn запрос_ответа[РезультатРоли](ответ Исход[РезультатРоли]) -> str
fn форма_верна[РезультатРоли](ответ Исход[РезультатРоли]) -> bool
fn проверить_инвариант(выполнен bool)
// псевдокод: недостижимая ветка; в Нове — по выбору исполнителя (прерывание)
fn недостижимо(текст str) -> never
// псевдокод: кодирование и раскодирование среза исполнителя в строку снимка; формат — за реализацией хранилища
fn кодировать[Срез](срез Срез) -> str
fn раскодировать[Срез](данные str) -> Срез

// Методы Исполнителя: данные движка и механика
// конец ли состояние (вид «конец»)
fn Исполнитель @в_конце(состояние Состояние) -> bool => match @машина.вид(состояние) {
  Конец => true
  _ => false
}
// конец или состояние паузы: «стоп человека» и «стоп от родителя» здесь отбрасываются
fn Исполнитель @в_конце_или_паузе(состояние Состояние) -> bool => @в_конце(состояние) || состояние == @машина.состояние_паузы()
// сам исполнитель как значение `Среда`: его методы машина вызывает из перехода
// псевдокод: ресивер передаётся как значение протокола
fn Исполнитель @среда() -> Среда[Состояние, Событие, Действие]
// строка журнала с конвертом: трасса, номер_шага, причина_шага, состояние, идентификатор запроса, время (правило 31)
fn Исполнитель mut @писать_журнал(текст str) Журнал Time -> () {
  Журнал.записать(ЗаписьЖурнала {
    трасса: @д.трасса, номер_шага: @д.номер_шага, причина_шага: @д.причина_шага, состояние: @машина.имя_состояния(@д.состояние),
    идентификатор_запроса: @д.запрос_вызова, время: Time.now(), текст: текст, счёт_по_моделям: @д.счёт_по_моделям })
}
// писать_журнал(текст); запись_перехода = текст; Куда(состояние ошибки)
fn Исполнитель mut @ошибка_машины(текст str) Журнал Time -> Переход[Состояние] {
  @писать_журнал(текст)
  @д.запись_перехода = текст
  Куда(@машина.состояние_ошибки())
}
// «слова_человека», ключ — событие.идентификатор; ссылка в журнале (правила 19, 31)
fn Исполнитель mut @записать_слово_человека(событие Входящее[Событие], слово str, автор str, источник str) Журнал Time -> ()
// чужой или поздний сигнал: строка журнала, состояние то же (правило 17)
fn Исполнитель mut @отбросить(событие Входящее[Событие]) Журнал Time -> ()
// правило 18; стороны запросов набора возвращаются в к_отправке перед неотправленными, в прежнем порядке
fn Исполнитель mut @отменить_открытые_без_принятого(кроме_вложенных bool) Связь -> () {
  mut возвращённые = []str.new()
  for ид in @д.открытые_запросы.clone() {          // копия: `убрать_из_открытых` меняет список
    if !@д.принятые_запросы.contains(ид) && !(кроме_вложенных && @вложенные_запросы().contains(ид)) {
```

```nova
      @писать_журнал("пауза: причина — стоп от родителя, ${идентификатор_запроса}, запись ${событие.идентификатор}")
      // слова человека не записываются (""): слов_человека не пишется

      @отменить_открытые_без_принятого(true)

    }

        return Some(Остаться)
      }
      // ОБЩ отмена_запроса #2: = запрос_вызова, и ответ уже отдан (состояние — ОСТАНОВЛЕНО, ОШИБКА или КОНЕЦ)
      if идентификатор_запроса == @д.запрос_вызова && @в_конце(@д.состояние) {
        @писать_журнал("отмена отброшена: ответ уже отдан, ${идентификатор_запроса}, запись ${событие.идентификатор}")
        return Some(Остаться)
      }
      // ОБЩ отмена_запроса #3: = запрос_вызова, и ответ не отдан
      if идентификатор_запроса == @д.запрос_вызова && !@в_конце(@д.состояние) {
        @писать_журнал("отмена запроса: ${идентификатор_запроса}, запись ${событие.идентификатор}")
        @машина.записать_остановку("отмена_запроса")
        // сигнал ставится ДО отмены: вложенные ещё лежат в открытые_запросы (правило 35, п. 10)
        @передать_вложенным("отмена")
        @отменить_открытые_без_принятого(false)    // правило 18
        return Some(Куда(@машина.состояние_остановлено()))
      }
      // ОБЩ отмена_запроса #4: иначе
      Some(@ошибка_машины("ошибка машины: разбор отмены_запроса, ни одно условие не подошло"))
    }

    ПродолжитьВнеПаузы => {
      // «продолжить» вне ПАУЗЫ отбрасывается с записью в журнал (правила 17, 23); в ПАУЗЕ — строки состояния паузы машины
      @отбросить(событие)
      Some(Остаться)
    }
  }
}
```

## Цикл исполнителя

```nova
/// Исполнитель: ведёт машину `Маш` по правилам 13–24 и 35 спецификации; единственный пишет в хранилище и отправляет запросы.
/// Данные поступают только через события; запросы отправляются только после фиксации шага; снимок сохраняется до открытия ворот.
/// Исполнитель с машиной реализует `Вызываемое[Вход, Выход]` структурно (метод `вызвать`) и подаёт себя машине как `Среда`.
// псевдокод: параметры типа `Исполнитель` перечислены в объявлении и в методах не повторяются
type Исполнитель[Состояние, Событие, Вход, Выход, ВходРоли, РезультатРоли, Действие, Маш Автомат[Состояние, Событие, Вход, Выход, ВходРоли, РезультатРоли, Действие]] {
  машина Маш,                                  // данные и логика автомата
  д СостояниеДвижка[Состояние],                // данные движка
  вызов Option[Запрос[Вход]],                  // запрос, которым машину вызвали (конверт исполнителя)
  очередь []Входящее[Событие],                 // входящие события в порядке прихода (правило 13)
  готовый_ответ Option[Исход[Выход]],          // ответ, отданный вызвавшей стороне; машина отвечает ровно один раз (правило 35)
  ответ_отправлен bool,                        // ответ ушёл через `Связь.ответить`: ставится после успешной отправки отдельной фиксацией
  необратимые []Действие,                      // действия шага, которые выполняются после сохранения; в снимке, чтобы повториться после перезапуска
  в_работе bool,                               // цикл идёт: повтор запроса не запускает вторую машину (исполнитель на запрос один; исключение процессов — вне файла)
}

/// Исполнитель над готовой машиной; хранилище — эффект `Хранилище`, обработчик подставляет вызывающий код.
fn Исполнитель.new(машина Маш) -> Исполнитель => {
  машина: машина,
  д: СостояниеДвижка.new(машина.начальное()),
  вызов: None,
  очередь: []Входящее.new(),
  готовый_ответ: None,
  ответ_отправлен: false,
  необратимые: []Действие.new(),
  в_работе: false,
}

/// Событие `Вызываемое[Вход, Выход]`: повтор запроса с тем же идентификатором возвращает готовый ответ или продолжает прерванную работу (правило 35, п. 4).
fn Исполнитель mut @вызвать(запрос Запрос[Вход]) Хранилище Журнал Связь Объекты Time -> Исход[Выход] {
  // прогон идёт: повтор не поднимает вторую машину поверх живой, а ждёт готовый ответ идущего прогона
  if @в_работе { return @ждать_готовый_ответ() }
  match @загрузить_снимок(запрос.идентификатор_запроса) {
    None => @начать(запрос)
    Some(снимок) => match раскодировать(снимок.данные_движка).готовый_ответ {   // псевдокод: раскодирование среза исполнителя
      Some(готовый) if раскодировать(снимок.данные_движка).ответ_отправлен => готовый   // уже ушёл по `Связь.ответить`: второй раз не шлётся
      _ => match @возобновить(запрос.идентификатор_запроса) {
        Some(ответ) => ответ
        None => недостижимо("снимок только что загружен: возобновить его находит")
      }
    }
  }
}

/// Новый запрос: входит в начальное состояние машины, фиксирует шаг и входит в цикл. Машину по входу запроса создаёт вызывающий код.
fn Исполнитель mut @начать(запрос Запрос[Вход]) Хранилище Журнал Связь Объекты Time -> Исход[Выход] {
  @в_работе = true
  @вызов = Some(запрос)
  @д = СостояниеДвижка.new(@машина.начальное())
  @очередь = []Входящее.new()
  @готовый_ответ = None
  @ответ_отправлен = false
  @необратимые = []Действие.new()
  @д.запрос_вызова = запрос.идентификатор_запроса
  @д.трасса = @новая_трасса()                  // дочерняя от внешней (запрос.трасса)
  @выполнить_шаг(@новое_событие("старт"), Куда(@машина.начальное()))
  @цикл()
}

/// Продолжение после остановки исполнителя: загружает снимок и продолжает с сохранённого `состояние`; None — снимка нет.
/// Ждавшая обращения машина повторно получает только запросы без принятого ответа; на ПАУЗЕ остаётся, пока человек не скажет «продолжить» (правила 12, 14, 22).
fn Исполнитель mut @возобновить(идентификатор_запроса str) Хранилище Журнал Связь Объекты Time -> Option[Исход[Выход]] {
  match @загрузить_снимок(идентификатор_запроса) {
    None => None
    Some(снимок) => {
      ro срез = раскодировать(снимок.данные_движка)      // псевдокод: раскодирование среза исполнителя
      @д = срез.д
      @очередь = срез.очередь
      @вызов = срез.вызов
      @готовый_ответ = срез.готовый_ответ
      @ответ_отправлен = срез.ответ_отправлен
      @необратимые = срез.необратимые
      @д.ожидание = HashMap[str, Ожидание].new()      // моменты `Time.now_monotonic()` после перезапуска несравнимы: сроки открытых запросов отсчитываются заново при повторной отправке
      @машина.восстановить(снимок.данные_машины)
      match @готовый_ответ {
        Some(готовый) => {                           // ответ уже отдан
          if !@ответ_отправлен { @отправить_ответ() }   // не успел уйти: повторяется, идемпотентно по запрос_вызова; ушёл — ничего не шлётся
          Some(готовый)
        }
        None => {
          @в_работе = true
          @после_перезапуска()
          Some(@цикл())
        }
      }
    }
  }
}

/// Цикл: берёт события по одному, пока ответ не отдан. Остановка исполнителя — завершение процесса в любой точке цикла:
/// состояние уже сохранено фиксацией шага, дописывать ничего не нужно.
fn Исполнитель mut @цикл() Хранилище Журнал Связь Объекты Time -> Исход[Выход] {
  loop {
    match @готовый_ответ {
      Some(ответ) => {
        if !@ответ_отправлен { @отправить_ответ() }   // повторяемо: идемпотентно по запрос_вызова
        @в_работе = false
        return ответ
      }
      None => {
        @принять_сообщения()                   // `Связь.принять` без ожидания
        @проверить_сроки()                     // «нет ответа в срок» — из сравнения со `Time`
        @обработать_очередь()
      }
    }
  }
}

/// Приём при приходе: в порядке прихода и в любом состоянии (правило 14).
fn Исполнитель mut @при_приходе(сообщение Получено[Событие, РезультатРоли]) Хранилище Журнал Связь Объекты Time -> () {
  @д.счётчик_событий += 1                               // +1 при приходе любого события
  match сообщение {
    // ответ роли или отказ (Исход от открытой стороны)
    ПолученОтвет(ответ) => {
      ro ид = запрос_ответа(ответ)
      // чужой или поздний ответ: неизвестный идентификатор, закрытый или отменённый запрос, повторная доставка (правило 17)
      if !@д.открытые_запросы.contains(ид) || @д.принятые_запросы.contains(ид) {
        // отбрасывание — отдельная фиксация со своей строкой журнала и номером шага (правило 31)
        ro лишнее = @событие_из_сообщения(сообщение)
        @начать_фиксацию_приёма(лишнее)
        @отбросить(лишнее)
        @зафиксировать()
        return
      }
      // форма: ответ не по форме исполнитель возвращает стороне в том же запросе; число возвратов задаёт состояние
      if !форма_верна(ответ) { @вернуть_стороне(ответ); return }
      // объект, куда пишется результат (у машины — рабочий документ), изменился с начала попытки — результат не принимается,
      // запрос отменяется и отправляется заново (новая попытка, вход прочитан заново)
      if @машина.объект_менялся_с_начала_попытки(@д.состояние) { @повторить_запрос(ид); return }
      // приём — одна фиксация: идентификатор в принятые_запросы, «При приёме», запись результата в хранилище, событие в очередь (правила 14, 31)
      ro событие = @событие_из_ответа(ответ)
      @начать_фиксацию_приёма(событие)
      @д.принятые_запросы.push(ид)
      @машина.при_приёме(@д.состояние, ответ)
      @машина.записать_результат(@д.состояние, ответ)
      @положить_в_очередь(событие)
      @зафиксировать()
      // последним, повторяемым без вреда этапом — принятие файла попытки (при старте завершается по принятые_запросы)
      @машина.принять_файл_попытки(ид)
    }
    // слово человека или сигнал
    ПолученоСлово(_) => {
      ro событие = @событие_из_сообщения(сообщение)
      @начать_фиксацию_приёма(событие)                // слово человека — своя фиксация: не теряется при сбое (правила 19, 31)
      @записать_слово_ворот(сообщение)                // на воротах (правило 19)
      @положить_в_очередь(событие)
      @зафиксировать()
    }
    // «нет ответа в срок»: порождает исполнитель по таймеру, код НетОтветаВСрок; у обращения человека срока нет (правило 19)
    ПросроченЗапрос(ид) => {
      // запрос уже закрыт или принят: срок поздний (правило 17) — отдельная фиксация со строкой журнала
      if !@д.открытые_запросы.contains(ид) || @д.принятые_запросы.contains(ид) {
        ro лишнее = @событие_из_сообщения(сообщение)
        @начать_фиксацию_приёма(лишнее)
        @отбросить(лишнее)
        @зафиксировать()
        return
      }
      ro событие = Входящее {
        идентификатор: "сбой-${@д.счётчик_событий}", сторона: сторона_запроса(ид), запрос: Some(ид), тело: @машина.событие_сбоя(НетОтветаВСрок) }
      @начать_фиксацию_приёма(событие)
      @положить_в_очередь(событие)
      @зафиксировать()
    }
  }
}

/// Обработка очереди: первое событие, которое ждёт текущее состояние; остальные остаются в очереди (правило 13).
fn Исполнитель mut @обработать_очередь() Хранилище Журнал Связь Объекты Time -> () {
  match @взять_первое_ожидаемое() {                   // сигналы ждёт любое состояние, кроме концов
    None => @ждать_прихода()
    Some(событие) => {
      ro переход = @общие_события(событие) ?? @машина.перейти(@д.состояние, событие.тело, событие, @среда())
      @выполнить_шаг(событие, переход)
    }
  }
}

/// Шаг — одна фиксация (правило 13): переходы, записи в хранилище, строки журнала, новые значения «состояние», «открытые_запросы»,
/// «принятые_запросы», «к_отправке» и счётчиков попыток пишутся вместе; незавершённый шаг откатывается.
fn Исполнитель mut @выполнить_шаг(событие Входящее[Событие], переход Переход[Состояние]) Хранилище Журнал Связь Объекты Time -> () {
  @начать_фиксацию()
  ro метка_до = @машина.метка_инварианта()
  @д.номер_шага += 1                                    // растёт внутри фиксации; откат возвращает
  @д.причина_шага = событие.идентификатор
  mut ход = переход
  match ход {
    НеЖдёт => {                                  // событие остаётся в очереди
      @откатить()
      return
    }
    _ => ()
  }
  // принятый запрос закрывается переходом по своему событию: убирается из открытые_запросы и из принятые_запросы
  match событие.запрос {
    Some(ид) => @закрыть_запрос(ид)
    None => ()
  }

  // цепочка операций и развилок и их переходов «сразу» до первого обращения или конца
  loop {
    match ход {
      Остаться => break                                  // то же состояние
      НеЖдёт => break                            // первое событие проверено выше; в цепочке не встречается
      Куда(цель) => match @войти_в(цель, событие) {
        Some(следующий) => { ход = следующий }
        None => break                                // ждёт события или конец
      }
      Заново(цель) => {
        @отменить_открытый_запрос_обращения(цель)        // «запуск заново» (правило 18): прежний запрос сначала отменяется
        match @войти_в(цель, событие) {
          Some(следующий) => { ход = следующий }
          None => break
        }
      }
    }
    // инвариант машины: её метка не уменьшается
    проверить_инвариант(@машина.метка_инварианта() >= метка_до)
  }
  @зафиксировать()                                    // запись шага: снимок сохранён, необратимые действия лежат в нём
  @выполнить_необратимые()                            // последний, повторяемый без вреда этап: переименование в архив, смена права записи
  @после_фиксации()
}

/// Вход в состояние: запись «состояние» подразумевается у каждого перехода; None — обращение или конец, цепочка заканчивается.
fn Исполнитель mut @войти_в(куда Состояние, событие Входящее[Событие]) Журнал Объекты Time -> Option[Переход[Состояние]] {
  @д.состояние = куда
  match @машина.вид(куда) {
    Обращение | Конец => None                        // ждёт события или конец
    Операция => {
      ro результат = @машина.выполнить_операцию(куда, @среда())
      Some(@машина.перейти(куда, @машина.результат_как_событие(куда, результат), событие, @среда()))
    }
    Развилка => Some(@машина.перейти(куда, @машина.событие_сразу(), событие, @среда()))
  }
}

/// После фиксации шага: сначала очередь, потом запросы (правило 13).
fn Исполнитель mut @после_фиксации() Хранилище Журнал Связь Объекты Time -> () {
  @передать_вложенным_накопленные_сигналы()           // «стоп», «продолжить», «остановить», «отмена»; журнал «… передан(о) <идентификатор_запроса>»
  // конец: ответ вызвавшей стороне отдаётся всегда, даже если в очереди сигнал, и ровно один раз (правило 35, «один запрос — один ответ»);
  // сигналы в концах отбрасываются по правилам 17 и 23 уже после ответа
  match @машина.вид(@д.состояние) {
    Конец => match @готовый_ответ {
      None => {
        @отменить_все_открытые_запросы()              // вход в любой конец (правило 22)
        @машина.при_входе_в_конец(@д.состояние, @среда())
        @выполнить_необратимые()
        @отдать_ответ(@машина.ответ_по_концу(@получатель(), @д.состояние, @среда()))
      }
      Some(_) => ()                                    // ответ уже отдан
    }
    _ => ()
  }
  // перед отправкой смотрит во входящую очередь: «стоп человека», «стоп от родителя» или «отмена_запроса» — запросы не отправляются,
  // а сигнал разбирается (правила 23, 35)
  if @в_очереди_есть_сигнал() { return }
  match @машина.вид(@д.состояние) {
    Обращение => @отправить_запросы(@д.состояние)
    _ => ()                                          // операции и развилки до сюда не доходят: цепочка идёт до обращения или конца
  }
}

/// Отправка запросов по состоянию. Состояние сохранено до открытия ворот; повторный вход ничего не отправляет стороне,
/// чей запрос открыт или лежит в принятых (правила 12, 14, 21). Как обращается состояние, говорит машина (`обращение`).
fn Исполнитель mut @отправить_запросы(обращение Состояние) Хранилище Связь Объекты Time -> () => match @машина.обращение(обращение) {
  None => ()
  Some(Набор { срок_бездействия, порядок: _ }) => {
    // стороны из к_отправке по порядку, пока открытых запросов меньше предела движка (`предел_запросов` машины, правило 21)
    while @д.к_отправке.len() > 0 && @д.открытые_запросы.len() < @машина.предел_запросов() {
      ro сторона = @д.к_отправке[0]
      // механика контракта — отдельная фиксация со своим номером шага и сохранением ДО отправки (правила 13, 22):
      // перенос из к_отправке в открытые_запросы и рост счётчика попыток; после падения снимок уже содержит новую попытку и открытый запрос,
      // возобновить отменит его (правило 18), а поздний ответ отбросит (правило 17)
      @начать_фиксацию_запроса()
      @д.к_отправке = @д.к_отправке[1..]
      ro попытка = @машина.следующая_попытка(сторона)
      @д.открытые_запросы.push("${сторона}-${попытка}")
      @зафиксировать()
      @отправить(Запрос { идентификатор_запроса: "${сторона}-${попытка}", номер_попытки: попытка, сторона: сторона,
        вход: @машина.вход_запроса(обращение, сторона, @среда()), срок_бездействия: срок_бездействия, трасса: @д.трасса, номер_шага: @д.номер_шага })
    }
  }
  Some(Одна { сторона, срок_бездействия }) => {
    if @есть_открытый_или_принятый(сторона) { return }
    // отдельная фиксация со своим номером шага и сохранением ДО отправки, как у набора (правила 13, 22)
    @начать_фиксацию_запроса()
    ro попытка = @машина.следующая_попытка(сторона)        // фиксируется до отправки вместе с открытые_запросы
    @д.открытые_запросы.push("${сторона}-${попытка}")
    @зафиксировать()
    @отправить(Запрос { идентификатор_запроса: "${сторона}-${попытка}", номер_попытки: попытка, сторона: сторона,
      вход: @машина.вход_запроса(обращение, сторона, @среда()), срок_бездействия: срок_бездействия, трасса: @д.трасса, номер_шага: @д.номер_шага })
  }
}

/// Перезапуск исполнителя: не переход и «состояние» не пишет; шаг со своим номером (правила 22, 31).
fn Исполнитель mut @после_перезапуска() Хранилище Журнал Связь Объекты Time -> () {

  // открытые запросы умершего исполнителя к ролям без принятого ответа отменяются; их поздние ответы отбрасываются (правило 18);
  // запросы к вложенным машинам не отменяются (кроме_вложенных = true): они повторяются тем же идентификатором — вложенная вернёт готовый ответ
  // или продолжит, заново не запускается (правило 35, п. 4)

  @после_фиксации()
```
