# Движок стейт-машины: код исполнителя

Движок любой стейт-машины, записанный кодом на языке Нова: конверт запроса и ответа (`Запрос`, `Исход`, `КодСбоя`), снимок и хранилище, исполнитель (цикл, приём при приходе, фиксации, отправка запросов, повтор, журнал и трасса, передача сигналов вложенным, необратимые действия), общие события «стоп человека», «стоп от родителя», «отмена_запроса», пауза цепочки и протокол `Вызываемое`. Машина подставляется протоколом `Автомат`: движок не знает ни её состояний, ни событий, ни ролей; поэтому он обобщён по `Состояние`, `Событие`, `Вход`, `Выход`, `ВходРоли`, `РезультатРоли`, `Действие`, и это труднее читать, чем код одной машины. Машина может быть событием в другой машине (правило 35): исполнитель с машиной реализует `Вызываемое`.

**Нормы — [state-machine-spec.md](state-machine-spec.md)** (правила 12–25, 31, 35). Этот файл — запись движка, а не вторая спецификация: при любом расхождении верна спецификация, а этот файл правится вслед за ней. Пример реализации машины, подставляемой в движок, — [task-runner-meeting-automaton.md](task-runner-meeting-automaton.md) (машина совещания; её первоисточник — [task-runner-meeting-states.md](task-runner-meeting-states.md)); имена блока «Типы на Нове» и таблица соответствия — там же. Язык записи — Нова, https://github.com/nv-lang/nova (синтаксис — по `spec/syntax.ru.md`, `spec/effects.md` и `nova.ungrammar` того репозитория). Внешний мир — пять эффектов Нова: `Хранилище`, `Журнал`, `Связь`, `Объекты` и стандартный `Time`; обработчик каждого может быть любым (база, диск, очередь сообщений, чат) и в этом файле не записан. Ворота человека не эффект: машина фиксирует состояние, отправляет вопрос через `Связь.отправить` и завершает шаг; слово приходит позже сообщением, а после перезапуска состояние берётся из `Хранилище.загрузить` (ожидание часами, переживающее перезапуск, в Нове не определено). **Код не компилировался и не проверялся компилятором Нова:** это псевдокод в синтаксисе Нова; места, где Нова не выражает записанное или где синтаксис не подтверждён спецификацией, помечены строкой `// псевдокод:` (перечень — в соглашениях, пункт 5). Над движком — слой общих типов и операций для машин методики задач: [state-machine-methodology-automaton.md](state-machine-methodology-automaton.md); движок о нём не знает. Имя файла — по `AGENTS.md`, «Вынесенные алгоритмы» (документ `state-machine`, часть `engine`, форма `automaton`).

## Соглашения записи

1. **Типы и параметры.** Имена — русские: слово или слитное сочетание с заглавной буквы без подчёркиваний (`КодСбоя`, `СостояниеДвижка`). Параметры типов — осмысленные русские имена: `Состояние`, `Событие` (перечисления машины), `Вход`, `Выход` (вход и итог машины как вызываемой), `ВходРоли`, `РезультатРоли` (вход запроса к стороне и её результат), `Действие` (необратимое действие машины), `ТипМашины` (тип машины с протоколом `Автомат`).
2. **Идентификаторы** все русские: типы и варианты — с заглавной буквы без подчёркиваний, поля, параметры, локальные переменные и функции — змеиный регистр (правило 25 спецификации: имя одной сущности одно). Латиница — только стандартные имена Нова (`fn`, `type`, `match`, `Option`, `Some`, `None`, `Result`, `Ok`, `Err`, `HashMap`, `str`, `int`, `bool`, `never`, `effect`, `with`, `protocol`, `loop` и др.). Нова кириллические идентификаторы не поддерживает (владелец, 2026-10-17); русские имена в псевдокоде — решение этого файла.
3. **Запись Нова.** `ro` — неизменяемая привязка, `mut` — изменяемая переменная; отсутствующее значение — `None`, значение — `Some(x)`; строки — `"… ${выражение} …"`; комментарий — `//`, документирующий — `///` (перед объявлением, пустая строка перед ним). Метод — `fn Тип @имя(…)` читает, `fn Тип mut @имя(…)` меняет; обращение к полю и вызов метода — через `@`. Данные движка у исполнителя — `@состояние_движка.<поле>`, метод машины — `@машина.<метод>`, служебные операции машине — через значение `Среда`. «То же состояние» — `Остаться`, «запуск заново» — `Заново(S)`, «Куда» — `Куда(S)`, «сразу» — событие `событие_сразу()`.
4. **Механика исполнителя.** Раздел «Механика исполнителя» — перечень механики контракта, фиксации и приёма (правила 13–22, 31, 35 спецификации): свободные функции и методы `Исполнитель`; большинство объявлено только сигнатурой, телом записаны те, что выражаются данными. Раздел «Помощники машин» — функции, одинаковые у всех машин (`обязательное`, `объект_ок`, `слово_кода`, `код_сбоя_общей_остановки`, `отказ_по`): машина зовёт их по имени и своих копий не держит.
5. **Строки `// псевдокод:`** стоят там, где записанное — не Нова или не подтверждено его спецификацией: функции без тела (сигнатуры механики); `недостижимо`; кодирование среза исполнителя в строку снимка (`кодировать`, `раскодировать`); ресивер как значение протокола (`среда`). **Подтверждено спецификацией Нова** (проверено оркестратором проекта по чтению репозитория языка, 2026-10-18; компилятором не проверено): `///` — внешний документирующий комментарий (`spec/decisions/03-syntax.md`, D104; привязан к следующему полю записи и варианту суммы); `never` строчная — тип выражения, которое не возвращает значения (`spec/decisions/04-effects.md`, D25), его и берёт `недостижимо`; `Never` заглавная — пустой тип, нужен только как аргумент `E` в `Effect[E, Never]`, здесь не используется; `fn Тип.new()` — статическое объявление (`spec/syntax.ru.md`, `fn Account.new(…)`); `.contains()` на `[]T` (std, `collections/vec/access.nv`); `.len()` на списке (`vec/core.nv`); срез `v[a..]`, `v[a..b]` (`vec/slice.nv`, Plan 284; за границами паника, безопасно `v.get(a..b)`); присваивание как ветка `match` допустимо (`nova.ungrammar`, `MatchArm`), здесь оно записано блоком `=> { x = v }`; длина текста (`.len()` на `str`) нигде не берётся. **Протоколы** (прочитано в `spec/syntax.ru.md`, раздел «Структурные "интерфейсы" — protocol», 2026-10-18; компилятором не проверено): `type Имя protocol { @метод() -> T }`, изменяющий метод — `mut @метод(…)`, обобщённый протокол — `type Next[T] protocol { … }`, соответствие структурное, `impl` не нужен — поэтому `Исполнитель` реализует `Вызываемое` совпадением метода `вызвать`, а машина — `Автомат` совпадением методов. **Эффекты** (прочитано в `spec/effects.md`, 2026-10-18, D61/D142/D434/D456; компилятором не проверено): `type Хранилище effect { fn … -> T }` — операции без `@` и без `mut`, тип возврата обязателен; эффект в сигнатуре между `)` и `->` (`fn … Хранилище -> …`); вызов по имени `Хранилище.сохранить(…)`; обработчик подставляет `with Хранилище = обработчик { … }` один раз у вызывающего кода; прямой эффект объявляется в сигнатуре, транзитивный — предупреждение, при `--strict-effects` ошибка; требование проекта Нова — объявляют все функции цепочки, так в этом файле и записано; единый `with` — на точке запуска. **Записано по выводу, спецификацией не подтверждено:** ошибка операции эффекта через `Result` (форма `Fail[E]` для операции эффекта в спецификации не найдена); форма метода с эффектом `fn Тип @метод(…) Эффект -> Т` (в спецификации — только свободные функции; метод — вывод, не цитата), в том числе у методов протокола; эффекты без параметров типа: обобщённые эффекты в Нове не поддерживаются (`E_EFFECT_GENERIC_UNSUPPORTED`), поэтому через `Связь` ходят конкретные типы `ВходСтороны`, `РезультатСтороны`, `СобытиеСтороны`, а кодирование и раскодирование — методы машины; `Timestamp` и `Time.now()`, `Time.now_monotonic()` (тип результата принят как целое число миллисекунд); подстановка `Time` обработчиком по умолчанию без `with`. **Не подтверждено спецификацией, без пометки в коде:** русские имена параметров типа `[Вход, Выход]`; `return` из `loop` значением функции (`цикл`); `return` в ветке `match` (`=> return None`); протокол с несколькими параметрами типа и параметр типа с границей-протоколом (`ТипМашины Автомат[…]`); охранное условие в ветке `match` (`Some(готовый) if …`); `.insert(0, …)` и `.push(…)` на списке; образец `{ поле, .. }` с остатком (в спецификации — `Occupied { value, .. }`); `.clone()` и `.reverse()` на списке (по образцу std, не проверено); многопривязочный `with Хранилище = …, Журнал = …, …` (в спецификации — одна привязка); оператор `?` для `Option` в теле метода (`общие_события`); обобщённые свободные функции `fn имя[Тип](…)` (в спецификации есть `fn get[K, V, C Index[K, V]]`); параметр типа, который есть только в результате (`отказ_по[Вход, Выход]`: `Выход` выводится из места вызова); **обязательный** метод протокола `при_возобновлении` (необязательный метод, то есть условное соответствие протоколу, в Нове не подтверждено: у машины без подготовки при возобновлении — заглушка `None`); обобщённая запись `ШагЦепочки[Состояние, Событие]` (как `Входящее[Событие]`); поля у вариантов суммы `Набор { …, вложенная bool }`, `Одна { …, возвратов_формы int }` и образец `Одна { сторона, .. }`; список `[]int` в метке инварианта, индексация `после[позиция]`, `.len()` двух списков. **Записано по слову владельца, спецификацией не подтверждено (2026-10-18):** оператор `??` для `Option` — значение либо запасное, правая часть вычисляется только при `None` (`обработать_очередь`). **Тело функции:** блок без стрелки `fn … { … }` (последнее выражение — значение) или `fn … => выражение`; `=> { поле: значение, … }` — литерал записи, так записаны только конструкторы `.new` (спецификация Нова: `FnDecl … (Block | FnExprBody)`, `FnExprBody = "=>" Expr`; проверено оркестратором проекта, 2026-10-18). **Алиасы типов и параметры типов (проверено оркестратором проекта, 2026-10-18):** `type Имя alias Тип` подтверждён (`spec/syntax.md`, `spec/decisions/02-types.md`); алиас с конкретной правой частью пишется без параметров (`type ЗапросРоли alias Запрос[ВходСтороны]`, прецедент `JsonObject` в `std/src/encoding/json.nv`), параметр нужен только у обобщённого алиаса (`type StringMap[V] alias HashMap[str, V]`); имена параметров типов в этом коде — русские слова вместо принятого в Нове одного символа PascalCase (`spec/syntax.md`, таблица соглашений: `T`, `K`, `V`): решение методики, запрета в спецификации нет.
6. **Исполнитель, хранилище, вызываемое.** `Исполнитель` владеет машиной `ТипМашины` и данными движка `СостояниеДвижка`: очередь входящих `очередь`, запрос вызова `вызов`, `готовый_ответ`, `необратимые`, `в_работе`; данные раздела «Данные» первоисточника машины, которые пишет исполнитель (`трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `запрос_вызова`, `открытые_запросы`, `принятые_запросы`, `к_отправке`, `ожидание` и др.), лежат в `СостояниеДвижка`, остальное — у машины. `Хранилище` — эффект (`type Хранилище effect`) с операциями `загрузить` и `сохранить`, возвращающими `Result[…, ОшибкаХранилища]`; вызов по имени `Хранилище.сохранить(…)`, обработчик подставляет вызывающий код (`with Хранилище = …`) — любой, вне файла; так же `Журнал` (`записать`), `Связь` (`отправить`, `принять` без ожидания) и `Объекты` (необратимые действия над объектами и чтение для отпечатка); эффекты `Хранилище`, `Журнал`, `Связь`, `Объекты`, `Time` объявляют все функции цепочки в своей сигнатуре (от `начать`, `возобновить`, `вызвать`, `цикл` до обёрток), единый `with` — на точке запуска; «нет ответа в срок» рождается из сравнения сроков запросов со `Time` (срок — данные запроса, `Ожидание`); после перезапуска `Ожидание` сбрасывается, потому что моменты монотонного времени несравнимы: запросы к ролям без принятого ответа отменяются, повторённые запросы к вложенным получают срок заново при отправке; внешний мир закрыт эффектами — `Хранилище`, `Журнал`, `Связь` (отправка, приём, отмена, сигналы вложенным, ответ вызвавшему), `Объекты`, `Time`; ответ покидает машину только через `Связь.ответить` (повторяемое необратимое действие последнего этапа фиксации; `вызвать` отдаёт вызвавшему тот же `готовый_ответ` как значение и второй раз не шлёт: поле `ответ_отправлен` в снимке ставится отдельной фиксацией, `возобновить` повторяет отправку, если ответ не ушёл); если `сохранить` не удалось — исполнитель аварийно прерывается (`недостижимо`), шаг не считается зафиксированным, запросы не отправляются. `Снимок` — две строки: данные движка (`СрезИсполнителя`) и данные машины (`снять` машины); `зафиксировать` вызывает `сохранить` в конце шага, ДО отправки запросов (правило 13). Входов два: `начать(запрос)` — состояние движка, фиксация, цикл; `возобновить(идентификатор_запроса)` — загрузка снимка и продолжение с сохранённого `состояние` (запросы без принятого ответа уходят повторно, пауза остаётся до «продолжить»; перед этим метод машины `при_возобновлении` — подготовка при каждом старте, только если сохранённое состояние не конец, до фиксации перезапуска и идемпотентная — может не пустить в сохранённое состояние и дать переход в другое; различие веток: при переходе вложенным идёт сигнал «отмена» и их запросы отменяются, без перехода их запросы повторяются тем же идентификатором (правило 35, п. 4); принятие файла попытки завершается на обеих ветках; правила 12, 14, 22); остановка исполнителя — завершение процесса: состояние уже сохранено. Запрос вызова всегда есть (`запрос_вызова` = `запрос.идентификатор_запроса`): через `Вызываемое` машину вызывают только запросом; решение, оставлять ли `""` у верхнего уровня, открыто (владелец не решил). Событие `ПросроченЗапрос` исполнитель порождает как `Входящее` с `запрос: Some(идентификатор)` и стороной по `сторона_запроса(идентификатор)`. `Вызываемое[Вход, Выход]` с методом `вызвать(запрос) -> Исход[Выход]` реализует `Исполнитель`; повтор запроса с тем же идентификатором возвращает готовый ответ или, если прогон идёт, ждёт его (правило 35, п. 4); при перезапуске запросы к вложенным машинам не отменяются, а повторяются тем же идентификатором.
7. **Граница с машиной.** Движок требует от машины протокол `Автомат` (методы `начальное`, `перейти`, `вид`, `общее`, `состояние_по_имени`, `причина_остановки_в_паузе`, `обращение`, `вход_запроса`, `следующая_попытка`, `при_приёме`, `записать_результат`, `событие_ответа`, `выполнить_операцию`, `при_возобновлении`, `при_входе_в_конец`, `ответ_по_концу` и вспомогательные) и даёт ей `Среду` (журнал, слова человека, сигналы вложенным, необратимые действия, данные движка `к_отправке`, `открытые_запросы`, `предыдущее`, `запрос_вызова`, `запись_перехода`). Машина сводит свои события к `ОбщееСобытие` методом `общее`; движок разбирает «стоп человека», «стоп от родителя», «отмена_запроса» и «продолжить вне ПАУЗЫ» до строк состояний. Результат операции — событие (`выполнить_операцию`): его получает переход операции и следующая развилка цепочки (`ШагЦепочки`); событие с данными из результата роли даёт `событие_ответа`; метка инварианта — список чисел, движок сравнивает покомпонентно. Предел одновременных запросов отдаёт машина (`предел_запросов`); срок бездействия роли — данные запроса, задаёт машина (`обращение`).
8. **`недостижимо(текст)`** — тип `never`: ничего не отдаёт и аварийно прерывает исполнителя. Ветка невозможна при соблюдении инвариантов — это ошибка программы. Дефект самой машины (развилка, у которой ни одно условие не подошло) идёт иначе: строка «иначе → ОШИБКА», состояние ошибки, ответ-отказ `НетРезультата`. В движке `недостижимо` стоит: в `получатель` (запрос вызова не принят), в `вызвать` (снимок только что загружен), в `сохранить_снимок` и `загрузить_снимок` (хранилище не ответило); в реализации машины — по её описанию.

```nova
/// Ответ
type Исход[Результат] enum
  | СРезультатом(ОтветСРезультатом[Результат])
  | Отказ(ОтветОтказ)

/// Ответ (с результатом)
type ОтветСРезультатом[Результат] { запрос str, сторона str, результат Результат, трасса str, номер_шага int }

/// Ответ (отказ)
type ОтветОтказ { запрос str, сторона str, причина КодСбоя, текст str, трасса str, номер_шага int }

/// КодСбоя
type КодСбоя enum
  | НетРезультата
  | ОтказМодели
  | СоединениеОборвалось
  | ФормаНеИсправлена
  | НетОтветаВСрок
  | ОстановленоЧеловеком  // остановлено человеком
  | ПотолокЗаходов  // потолок заходов с открытыми находками
  | ОтмененоРодителем  // отменено родителем

/// Запись движка: событие с конвертом (правила 13 и 31 спецификации); `Событие` — тип событий машины
type Входящее[Событие] {
  идентификатор str,        // «<вид>-<номер по счётчику событий>»
  сторона str,              // «событие.сторона»; у событий ворот и общих событий не читается
  запрос Option[str],       // идентификатор запроса, чьим исходом событие пришло (механика закрытия запроса)
  тело Событие              // вариант события машины и его данные
}

/// Запись движка: вид состояния (четыре вида первоисточника, раздел «Состояния»)
type Вид enum
  | Обращение
  | Операция
  | Развилка
  | Конец

/// Запись движка: то, что исполнитель обрабатывает при приходе — типизированно, типами машины: ответ или отказ роли, слово человека, сигнал, срок (правила 14, 16, 23)
type Получено[Событие, РезультатРоли] enum
  | ПолученОтвет(Исход[РезультатРоли])  // результат или отказ открытого запроса
  | ПолученоСлово(Событие)              // слово ворот человека или общий сигнал
  | ПросроченЗапрос(str)                // «нет ответа в срок»: идентификатор запроса; порождает исполнитель сравнением со сроком

/// Запись движка: куда ведёт строка
type Переход[Состояние] enum
  | Куда(Состояние)         // «Куда»: состояние
  | Заново(Состояние)       // «Куда»: состояние, запуск заново (правило 18)
  | Остаться                // «Куда»: то же состояние
  | НеЖдёт                  // событие этого состояния не ждёт: остаётся в очереди (правило 13)

/// Запись движка: шаг цепочки — переход, который дал вход в состояние, и событие, которое несёт то, что сделано при входе: результат операции или «сразу» (у развилки);
/// следующая развилка цепочки получает это событие вместо `событие_сразу` (данные операции читает развилка после неё)
type ШагЦепочки[Состояние, Событие] { переход Переход[Состояние], тело Событие }

/// Запись движка: общее событие — то, что разбирается до строк состояний любой машины (правила 17, 23, 35);
/// машина сводит к нему свои события методом `общее`
type ОбщееСобытие enum
  | ЧеловекСтоп { слово_человека str, автор str, источник str }   // «стоп человека»
  | РодительСтоп { идентификатор_запроса str }                    // «стоп от родителя»
  | ЗапросОтменён { идентификатор_запроса str }                   // «отмена_запроса»
  // события ПАУЗЫ (фрагмент «Пауза», state-machine-pause-states.md): разбирает движок, у машины строк состояния ПАУЗА нет
  | ПаузаПродолжить { слово_человека str, автор str, источник str }   // ПАУЗА: «продолжить»; вне ПАУЗЫ отбрасывается
  | ПаузаОстановить                                               // ПАУЗА: «остановить» (слово остановки — параметр фрагмента); вне ПАУЗЫ остаётся в очереди
  | ПаузаПродолжитьОтРодителя { идентификатор_запроса str }       // ПАУЗА: «продолжить от родителя»
  | ПаузаОстановитьОтРодителя { идентификатор_запроса str }       // ПАУЗА: «остановить от родителя»

/// Запись движка: вход запроса к стороне, закодированный машиной (`кодировать_вход`): через эффект `Связь` ходят конкретные типы,
/// обобщённые эффекты в Нове не поддерживаются (`E_EFFECT_GENERIC_UNSUPPORTED`)
type ВходСтороны { данные str }

/// Запись движка: результат стороны, закодированный стороной; машина раскодирует его в `РезультатРоли`
type РезультатСтороны { данные str }

/// Запись движка: событие стороны (слово человека, сигнал), закодированное; машина раскодирует его в `Событие`
type СобытиеСтороны { данные str }

/// Запись движка: выход машины (её итог как вызываемой), закодированный машиной (`кодировать_выход`)
type ВыходСтороны { данные str }

/// Запись движка: запрос к стороне, как он уходит через `Связь`
type ЗапросРоли alias Запрос[ВходСтороны]

/// Запись движка: то, что приходит через `Связь`: ответ или отказ стороны, слово человека или сигнал «стоп»/«продолжить»/«остановить»/«отмена» (человека и родителя)
type Сообщение enum
  | ОтветРоли(Исход[РезультатСтороны])
  | Слово(СобытиеСтороны)

/// Запись движка: сколько запрос ждёт ответа — для «нет ответа в срок» (срок бездействия — данные запроса, правило 19)
type Ожидание { отправлено int, срок int }

/// Запись журнала: конверт трассировки и текст строки (правило 31); `счёт_по_моделям` — буфер строк счёта по моделям, пишется при фиксации
type ЗаписьЖурнала { трасса str, номер_шага int, причина_шага str, состояние str, идентификатор_запроса str, время Timestamp, текст str, счёт_по_моделям str }

/// Запись движка: как состояние-обращение обращается к сторонам (правила 15, 21, 35).
/// `вложенная` — сторона запроса вложенная машина: ей идут сигналы «стоп», «продолжить», «остановить», «отмена», её запрос после перезапуска повторяется тем же идентификатором;
/// `возвратов_формы` — сколько раз ответ не по форме возвращается стороне в том же запросе, прежде чем это сбой «форма не исправлена» (число — данные описания: возврат и сбой после него — у обработчика роли, движок сбой формы не порождает)
type ОписаниеОбращения enum
  | Набор { срок_бездействия int, порядок []str, вложенная bool, возвратов_формы int }   // набор сторон из `к_отправке`, запросов одновременно не больше `предел_запросов` машины
  | Одна { сторона str, срок_бездействия int, вложенная bool, возвратов_формы int }     // одна сторона
```

## Данные

```nova
/// Данные движка любой машины: конверт трассировки, очередь запросов, журнал и хранилища слов; поля названы как переменные раздела «Данные» первоисточника.
/// Сохраняются целиком вместе с состоянием машины, после перезапуска исполнитель входит заново в «состояние» (правило 22).
type СостояниеДвижка[Состояние] {
  трасса str,                                  // назначается при старте, не меняется; конверт трассировки, в Вход не входит
  номер_шага int,                              // число фиксаций шагов; растёт на 1 внутри фиксации, откат возвращает; перезапуск и пауза не сбрасывают
  счётчик_событий int,                         // +1 при приходе любого события; перезапуск и пауза не сбрасывают
  причина_шага str,                            // идентификатор события, с которого начался шаг
  запрос_вызова str,                           // идентификатор запроса вызова; пишет исполнитель при начале (запрос.идентификатор_запроса)
  состояние Состояние,                         // где машина ждёт (обращение или конец); пишет исполнитель при фиксации шага (правило 13)
  предыдущее str,                              // имя состояния, прерванного «стоп человека» или «стоп от родителя»; пишут только они
  открытые_запросы []str,                      // идентификаторы запросов, не закрытых переходом (правила 16, 21)
  принятые_запросы []str,                      // идентификаторы запросов с принятым ответом, ждущим перехода (правило 14)
  к_отправке []str,                            // стороны набора, которым запрос ещё не отправлен
  сигналы_вложенным []СигналВложенному,        // сигналы вложенным машинам («стоп», «продолжить», «остановить», «отмена») с идентификаторами их запросов, поставленные шагом; после фиксации их передаёт и очищает исполнитель (правило 35)
  ожидание HashMap[str, Ожидание],             // открытые запросы и их сроки: «нет ответа в срок» рождается из сравнения с `Time`; в снимок не входит осмысленно: после перезапуска сбрасывается
  счёт_по_моделям str,                         // буфер строк счёта по моделям: пишется в журнал при фиксации
  запись_перехода str,                         // текст журнала перехода в ОШИБКУ; пишет ошибка_машины
  слова_человека str,                          // слово человека с автором и источником, ключ — идентификатор события; никакой шаг не читает
  тексты_сбоев str,                            // свободный текст отказа, ключ — идентификатор события сбоя; никакой шаг не читает, в журнал не идёт
  вложенные []str,                             // идентификаторы запросов к вложенным машинам (по `вложенная` описания обращения): пишет отправка; открытыми считаются те из них, что лежат в открытые_запросы
}

/// Начальные значения данных движка; состояние — начальное состояние машины.
fn СостояниеДвижка.new(начальное Состояние) -> СостояниеДвижка[Состояние] => {
  трасса: "",
  номер_шага: 0,
  счётчик_событий: 0,
  причина_шага: "",
  запрос_вызова: "",
  состояние: начальное,
  предыдущее: "",
  открытые_запросы: []str.new(),
  принятые_запросы: []str.new(),
  к_отправке: []str.new(),
  сигналы_вложенным: []СигналВложенному.new(),
  ожидание: HashMap[str, Ожидание].new(),
  счёт_по_моделям: "",
  запись_перехода: "",
  слова_человека: "",
  тексты_сбоев: "",
  вложенные: []str.new(),
}
```

## Протоколы и хранилище

```nova
/// Среда: что движок даёт машине внутри перехода — служебные операции и данные движка (правила 8, 13, 14, 17, 18, 19, 21, 35).
/// Машина меняет данные движка только через неё.
type Среда[Состояние, Событие, Действие] protocol {
  mut @писать_журнал(текст str) Журнал Time -> ()                                   // строка журнала с конвертом: трасса, номер_шага, причина_шага, состояние, идентификатор запроса, время (правило 31)
  mut @ошибка_машины(текст str) Журнал Time -> Переход[Состояние]             // писать_журнал(текст); запись_перехода = текст; Куда(состояние ошибки)
  mut @записать_слово_человека(событие Входящее[Событие], слово str, автор str, источник str) Журнал Time -> ()
  mut @отбросить(событие Входящее[Событие]) Журнал Time -> ()                       // чужой или поздний сигнал: строка журнала, состояние то же (правило 17)
  mut @передать_вложенным(сигнал str)
  mut @добавить_необратимое(действие Действие)                    // выполняется после сохранения (правило 13)
  @к_отправке() -> []str
  mut @установить_к_отправке(стороны []str)
  mut @вернуть_первой_в_отправку(сторона str)
  @открытые_запросы() -> []str
  @предыдущее() -> str
  @запрос_вызова() -> str
  @запись_перехода() -> str
}

/// Автомат: что движок требует от машины. Любая машина, у которой есть эти методы, подходит (соответствие структурное, `impl` не нужен).
/// Параметры: `Состояние` и `Событие` — перечисления машины, `Вход` и `Выход` — вход и итог машины как вызываемой, `ВходРоли` и `РезультатРоли` — вход запроса к стороне и результат стороны, `Действие` — необратимое действие машины.
type Автомат[Состояние, Событие, Вход, Выход, ВходРоли, РезультатРоли, Действие] protocol {
  @начальное() -> Состояние
  mut @перейти(текущее Состояние, тело_события Событие, событие Входящее[Событие], среда Среда[Состояние, Событие, Действие]) Журнал Объекты Time -> Переход[Состояние]
  @вид(состояние Состояние) -> Вид
  @общее(текущее Состояние, тело_события Событие) -> Option[ОбщееСобытие]
  @состояние_паузы() -> Состояние
  @состояние_по_имени(имя str) -> Состояние   // обратная к `имя_состояния`: для «Куда: предыдущее» и «Куда: возврат_подготовки» (правило 24)
  @причина_остановки_в_паузе() -> str         // значение «остановка» при «остановить» у ПАУЗЫ: «ПАУЗА: <слово остановки>» (фрагмент «Пауза»)
  @состояние_остановлено() -> Состояние
  @состояние_ошибки() -> Состояние
  @имя_состояния(состояние Состояние) -> str
  @обращение(текущее Состояние) -> Option[ОписаниеОбращения]
  @вход_запроса(текущее Состояние, сторона str, среда Среда[Состояние, Событие, Действие]) Объекты -> ВходРоли
  @предел_запросов() -> int
  @кодировать_вход(вход ВходРоли) -> ВходСтороны
  @раскодировать_результат(результат РезультатСтороны) -> РезультатРоли
  @раскодировать_событие(событие СобытиеСтороны) -> Событие
  @кодировать_выход(выход Выход) -> ВыходСтороны
  mut @следующая_попытка(сторона str) -> int
  mut @при_приёме(текущее Состояние, ответ Исход[РезультатРоли])
  mut @записать_результат(текущее Состояние, ответ Исход[РезультатРоли])
  @событие_ответа(текущее Состояние, результат РезультатРоли) -> Событие   // событие с данными из результата роли («ответ: требования» несёт цикл и источник)
  mut @выполнить_операцию(операция Состояние, среда Среда[Состояние, Событие, Действие]) Журнал Объекты Time -> Событие   // результат операции — событие: его принимает переход операции и следующая развилка цепочки
  @событие_сразу() -> Событие
  @событие_сбоя(причина КодСбоя) -> Событие
  mut @при_входе_в_конец(конец Состояние, среда Среда[Состояние, Событие, Действие]) Журнал Time -> ()
  @ответ_по_концу(вызов Запрос[Вход], конец Состояние, среда Среда[Состояние, Событие, Действие]) -> Исход[Выход]
  mut @записать_остановку(причина str)
  @метка_инварианта() -> []int   // по компоненту на счётчик, который не должен убывать: движок сравнивает покомпонентно
  @объект_менялся_с_начала_попытки(текущее Состояние) Объекты -> bool
  mut @выполнить(действие Действие) Объекты -> ()
  mut @принять_файл_попытки(идентификатор str) Объекты -> ()
  @снять() -> str
  mut @восстановить(данные str)
  // подготовка при каждом старте, до входа в сохранённое состояние (`сохранённое`; зовётся, только если оно не конец): None — войти в него, Some — перейти в другое (у машины без подготовки — None).
  // Подготовка выполняется до фиксации перезапуска (до коммита) и обязана быть идемпотентной: при падении до фиксации она выполнится снова
  mut @при_возобновлении(сохранённое Состояние, среда Среда[Состояние, Событие, Действие]) Журнал Объекты Time -> Option[Переход[Состояние]]
}

/// Событие: машина как вызываемое событие другой машины (правило 35). Вход и выход — типы запроса и итога.
type Вызываемое[Вход, Выход] protocol {
  mut @вызвать(запрос Запрос[Вход]) Хранилище Журнал Связь Объекты Time -> Исход[Выход]
}

/// Снимок: всё состояние движка и машины на конец шага — две строки: данные движка (`СрезИсполнителя`) и данные машины (`снять` машины); кодирует их сторона-владелец.
type Снимок { данные_движка str, данные_машины str }

/// Ошибка операции хранилища (запись движка): минимальный текст причины.
type ОшибкаХранилища { текст str }

/// Объект хранилища машины (рабочий документ, находки и т. п.): имя, по которому обработчик находит файл (запись движка, конкретный тип)
type Объект { имя str }

/// Ошибка операции над объектом (запись движка): минимальный текст причины
type ОшибкаОбъекта { текст str }

/// Журнал — эффект: куда писать строки журнала с конвертом; обработчик — любой (файл `log.md`, база).
type Журнал effect {
  fn записать(запись ЗаписьЖурнала) -> ()
}

/// Связь — эффект: как запрос уходит стороне и как приходят ответы и сигналы; обработчик — любой (файлы и процесс, очередь сообщений, чат).
/// `принять` не ждёт (по образцу `try_recv`): нет сообщения — `None`. Ворота человека — не эффект: машина фиксирует состояние, отправляет вопрос
/// через `отправить`, завершает шаг; слово приходит позже сообщением, после перезапуска состояние берётся из `Хранилище.загрузить`.
type Связь effect {
  fn отправить(запрос ЗапросРоли) -> ()                        // запрос стороне (и повтор того же запроса с тем же идентификатором)
  fn принять() -> Option[Сообщение]                            // пришедшее сообщение без ожидания
```

```nova
fn Исполнитель mut @передать_вложенным_накопленные_сигналы() Журнал Связь Time -> () {
  for сигнал in @состояние_движка.сигналы_вложенным {
    // «отмена» доставляется всегда (отмена уже вынула запрос из открытые_запросы); «стоп», «продолжить», «остановить» — только запросам, ещё лежащим в открытые_запросы
    if сигнал.сигнал == "отмена" || @состояние_движка.открытые_запросы.contains(сигнал.запрос) {
      Связь.сигнал(сигнал.запрос, сигнал.сигнал)
      @писать_журнал("${сигнал.сигнал} передан ${сигнал.запрос}")   // «стоп передан <идентификатор_запроса>», «продолжить передано <идентификатор_запроса>»
    }
  }
  @состояние_движка.сигналы_вложенным = []СигналВложенному.new()
}
fn Исполнитель mut @отдать_ответ(ответ Исход[Выход]) Хранилище Связь -> () {
  @готовый_ответ = Some(ответ)
  @сохранить_снимок()   // готовый ответ переживает остановку: повтор запроса с тем же идентификатором возвращает его (правило 35, п. 4)
  @отправить_ответ()
}
// ответ покидает машину только через `Связь.ответить` — повторяемое необратимое действие последнего этапа фиксации; ушёл — отдельная фиксация с `ответ_отправлен`
fn Исполнитель mut @отправить_ответ() Хранилище Связь -> () {
  match @готовый_ответ {
    Some(ответ) => {
      Связь.ответить(@кодировать_ответ(ответ))        // идемпотентно по запрос_вызова
      @ответ_отправлен = true
      @сохранить_снимок()
    }
    None => ()
  }
}
// ответ машины — в конкретные типы `Связи`
fn Исполнитель @кодировать_ответ(ответ Исход[Выход]) -> Исход[ВыходСтороны] => match ответ {
  СРезультатом(успех) => СРезультатом(ОтветСРезультатом {
    запрос: успех.запрос, сторона: успех.сторона, результат: @машина.кодировать_выход(успех.результат), трасса: успех.трасса, номер_шага: успех.номер_шага })
  Отказ(отказ) => Отказ(отказ)
}
fn Исполнитель mut @отправить(запрос Запрос[ВходРоли]) Связь Time -> () {
  @состояние_движка.ожидание.insert(запрос.идентификатор_запроса, Ожидание { отправлено: Time.now_monotonic(), срок: запрос.срок_бездействия })
  Связь.отправить(Запрос {
    идентификатор_запроса: запрос.идентификатор_запроса, номер_попытки: запрос.номер_попытки, сторона: запрос.сторона,
    вход: @машина.кодировать_вход(запрос.вход), срок_бездействия: запрос.срок_бездействия, трасса: запрос.трасса, номер_шага: запрос.номер_шага })
}
// принимает пришедшие сообщения без ожидания и обрабатывает их при приходе
fn Исполнитель mut @принять_сообщения() Хранилище Журнал Связь Объекты Time -> () {
  loop {
    match Связь.принять() {
      Some(сообщение) => @при_приходе(@типизировать(сообщение))
      None => break
    }
  }
}
// сообщение через `Связь` — в типы машины
fn Исполнитель @типизировать(сообщение Сообщение) -> Получено[Событие, РезультатРоли] => match сообщение {
  ОтветРоли(СРезультатом(успех)) => ПолученОтвет(СРезультатом(ОтветСРезультатом {
    запрос: успех.запрос, сторона: успех.сторона, результат: @машина.раскодировать_результат(успех.результат), трасса: успех.трасса, номер_шага: успех.номер_шага }))
  ОтветРоли(Отказ(отказ)) => ПолученОтвет(Отказ(отказ))
  Слово(слово) => ПолученоСлово(@машина.раскодировать_событие(слово))
}
// «нет ответа в срок» (правило 19): запрос ждёт дольше своего срока; у обращения человека срока нет
fn Исполнитель mut @проверить_сроки() Хранилище Журнал Связь Объекты Time -> () {
  ro сейчас = Time.now_monotonic()
  for идентификатор in @состояние_движка.открытые_запросы {
    match @состояние_движка.ожидание.get(идентификатор) {
      Some(ожидающий) => {
        if !@состояние_движка.принятые_запросы.contains(идентификатор) && ожидающий.срок > 0 && сейчас - ожидающий.отправлено > ожидающий.срок {
          @состояние_движка.ожидание.remove(идентификатор)                // срок наступает один раз
          @при_приходе(ПросроченЗапрос(идентификатор))
        }
      }
      None => ()
    }
  }
}
// повторяет запрос к вложенной машине с прежним идентификатором (правило 35, п. 4)
fn Исполнитель mut @повторить_вложенный(идентификатор str) Связь Time -> () {
  @отправить(@прежний_запрос(идентификатор))        // тот же идентификатор: вложенная вернёт готовый ответ или продолжит (правило 35, п. 4); срок ожидания отсчитывается заново
}
// запрос к вложенной машине по идентификатору, восстановленный из снимка (у этой машины вложенных запросов сейчас нет)
fn Исполнитель @прежний_запрос(идентификатор str) -> Запрос[ВходРоли]
// снимок всего состояния движка и машины на конец шага
fn Исполнитель @снимок() -> Снимок => Снимок {
  данные_движка: кодировать(СрезИсполнителя { состояние_движка: @состояние_движка, очередь: @очередь, вызов: @вызов, готовый_ответ: @готовый_ответ, ответ_отправлен: @ответ_отправлен, необратимые: @необратимые }),
  данные_машины: @машина.снять() }
// сохраняет снимок в хранилище: прямой вызов операции эффекта, `Хранилище` объявлен в сигнатуре; не удалось — машина не идёт дальше
fn Исполнитель mut @сохранить_снимок() Хранилище -> () => match Хранилище.сохранить(@получатель().идентификатор_запроса, @снимок()) {
  Ok(_) => ()
  Err(ошибка) => недостижимо("снимок не сохранён: шаг не зафиксирован, запросы не отправляются, исполнитель остановлен")
}
// загружает снимок; не удалось — исполнитель аварийно прерывается
fn Исполнитель @загрузить_снимок(идентификатор_запроса str) Хранилище -> Option[Снимок] => match Хранилище.загрузить(идентификатор_запроса) {
  Ok(снимок) => снимок
  Err(ошибка) => недостижимо("снимок не загружен: исполнитель остановлен")
}
```

## Помощники машин

```nova
// Функции, одинаковые у всех машин: записаны один раз здесь, а не копиями в каждой машине; машина зовёт их по имени.
// Таблица «остановка → код» и тексты журнала остаются у машины: движок их не знает.

/// Результат операции над объектом: ошибка — машина не идёт дальше (необратимые действия повторяются без вреда)
```

## Фрагмент «Пауза»

Состояние ПАУЗА, общие события «стоп человека», «стоп от родителя», «отмена_запроса», события ПАУЗЫ («продолжить», «остановить», «продолжить от родителя», «остановить от родителя») и передача сигналов вложенным записаны один раз — фрагментом «Пауза» ([state-machine-pause-states.md](state-machine-pause-states.md), правило 36 спецификации). Здесь, в разделе «Общие события», движок реализует фрагмент для любой машины; машина даёт только значения параметров фрагмента — хуки `Автомат`:

| Параметр фрагмента | Хук `Автомат` |
|---|---|
| имя состояния ПАУЗА | `состояние_паузы()` |
| названия концов ОСТАНОВЛЕНО и ОШИБКА (остальные концы — по `вид`: «стоп» в них отбрасывается) | `состояние_остановлено()`, `состояние_ошибки()` |
| слово остановки (значение «остановка») | `причина_остановки_в_паузе()` («ПАУЗА: <слово остановки>») |
| возврат в «предыдущее» (правило 24) | `состояние_по_имени(имя)` — обратная к `имя_состояния` |
| какие события машины — события паузы | `общее(...)`: сводит события машины к `ОбщееСобытие`, включая четыре события ПАУЗЫ |
| вложенные машины, отмена запросов, право записи | `вложенная`, `возвратов_формы` описания обращения; `отменить_открытые_без_принятого`; запись машины (необратимые действия концов) |

«Остановить» и «остановить от родителя» ждёт только ПАУЗА: вне неё `общее` машины даёт для них `None` (при `текущее == ПАУЗА` — `Some`), событие не сигнал и отправку запросов не блокирует; «продолжить» вне ПАУЗЫ — сигнал, который движок отбрасывает с записью в журнал (правило 17). Строк состояния ПАУЗА у машины нет: в `перейти` у неё одна ветка «`НеЖдёт`» (остальные события ПАУЗА не ждёт).

## Общие события

```nova
/// Разбираются до строк состояний (правило 23): сначала общие события, затем машина (`перейти`).
/// «Стоп человека» в ПАУЗЕ и в концах и «продолжить» вне ПАУЗЫ отбрасываются с записью в журнал (правила 17, 23);
/// в таблицах первоисточника для них строки нет, формат строки там не задан.
fn Исполнитель mut @общие_события(событие Входящее[Событие]) Журнал Связь Time -> Option[Переход[Состояние]] {
  ro общее = @машина.общее(@состояние_движка.состояние, событие.тело)?       // None — не общее событие: его разбирает машина
  match общее {

    ЧеловекСтоп { слово_человека, автор, источник } => {
      // ОБЩ стоп_человека #1: в любом состоянии, кроме ОСТАНОВЛЕНО, ОШИБКА, КОНЕЦ и ПАУЗА
      if @в_конце_или_паузе(@состояние_движка.состояние) { @отбросить(событие); return Some(Остаться) }
      @записать_слово_человека(событие, слово_человека, автор, источник)
      @писать_журнал("стоп человека: ${автор}, ${источник}, запись ${событие.идентификатор}")
      @состояние_движка.предыдущее = @машина.имя_состояния(@состояние_движка.состояние)
      // открытые_запросы без принятого ответа отменены (правило 18), кроме запросов к вложенным машинам
      @отменить_открытые_без_принятого(true)
      // вложенные получают сигнал «стоп» после фиксации шага; журнал «стоп передан <идентификатор_запроса>» на каждого (правило 35, пункт 8)
      @передать_вложенным("стоп")
      Some(Куда(@машина.состояние_паузы()))
    }

    РодительСтоп { идентификатор_запроса } => {
      // ОБЩ стоп_от_родителя #1: те же состояния, если идентификатор_запроса события = запрос_вызова, иначе сигнал отброшен (правило 17)
      if @в_конце_или_паузе(@состояние_движка.состояние) { @отбросить(событие); return Some(Остаться) }
      if идентификатор_запроса != @состояние_движка.запрос_вызова { @отбросить(событие); return Some(Остаться) }
      @писать_журнал("пауза: причина — стоп от родителя, ${идентификатор_запроса}, запись ${событие.идентификатор}")
      // слова человека не записываются (""): слов_человека не пишется
      @состояние_движка.предыдущее = @машина.имя_состояния(@состояние_движка.состояние)
      @отменить_открытые_без_принятого(true)
      @передать_вложенным("стоп")
      Some(Куда(@машина.состояние_паузы()))
    }

    ЗапросОтменён { идентификатор_запроса } => {
      // событие приходит в любом состоянии
      // ОБЩ отмена_запроса #1: идентификатор_запроса события не равен запрос_вызова
      if идентификатор_запроса != @состояние_движка.запрос_вызова {
        @писать_журнал("отмена отброшена: чужой запрос ${идентификатор_запроса}, запись ${событие.идентификатор}")
        return Some(Остаться)
      }
      // ОБЩ отмена_запроса #2: = запрос_вызова, и ответ уже отдан (состояние — ОСТАНОВЛЕНО, ОШИБКА или КОНЕЦ)
      if идентификатор_запроса == @состояние_движка.запрос_вызова && @в_конце(@состояние_движка.состояние) {
        @писать_журнал("отмена отброшена: ответ уже отдан, ${идентификатор_запроса}, запись ${событие.идентификатор}")
        return Some(Остаться)
      }
      // ОБЩ отмена_запроса #3: = запрос_вызова, и ответ не отдан
      if идентификатор_запроса == @состояние_движка.запрос_вызова && !@в_конце(@состояние_движка.состояние) {
        @писать_журнал("отмена запроса: ${идентификатор_запроса}, запись ${событие.идентификатор}")
        @машина.записать_остановку("отмена_запроса")
        // сигнал ставится ДО отмены: вложенные ещё лежат в открытые_запросы (правило 35, п. 10)
        @передать_вложенным("отмена")
        @отменить_открытые_без_принятого(false)    // правило 18
        return Some(Куда(@машина.состояние_остановлено()))
      }
      // ОБЩ отмена_запроса #4: иначе
      Some(@ошибка_машины("ошибка машины: разбор отмены_запроса, ни одно условие не подошло"))
    }

    // события ПАУЗЫ — фрагмент «Пауза» (state-machine-pause-states.md, состояние ПАУЗА): строк состояния у машины нет, разбирает движок
    ПаузаПродолжить { слово_человека, автор, источник } => {
      // «продолжить» вне ПАУЗЫ отбрасывается с записью в журнал (правила 17, 23)
      if @состояние_движка.состояние != @машина.состояние_паузы() { @отбросить(событие); return Some(Остаться) }
      // ПАУЗА #1: «продолжить»
      @записать_слово_человека(событие, слово_человека, автор, источник)
      @писать_журнал("продолжение с ${@состояние_движка.предыдущее}: ${автор}, ${источник}, запись ${событие.идентификатор}")
      @передать_вложенным("продолжить")                // после фиксации шага, журнал «продолжить передано <идентификатор_запроса>»
      Some(Куда(@машина.состояние_по_имени(@состояние_движка.предыдущее)))   // «предыдущее» при этом не пишется (правила 13 и 24)
    }
    ПаузаОстановить => {
      // вне ПАУЗЫ `общее` машины даёт для «остановить» None (событие не сигнал и очередь не блокирует); ветка защитная: лишнее событие отбрасывается
      if @состояние_движка.состояние != @машина.состояние_паузы() { @отбросить(событие); return Some(Остаться) }
      // ПАУЗА #2: «остановить»
      @машина.записать_остановку(@машина.причина_остановки_в_паузе())
      @передать_вложенным("остановить")                // правило 35, пункты 8 и 10
      Some(Куда(@машина.состояние_остановлено()))
    }
    ПаузаПродолжитьОтРодителя { идентификатор_запроса } => {
      if @состояние_движка.состояние != @машина.состояние_паузы() { @отбросить(событие); return Some(Остаться) }
      // ПАУЗА #3: «продолжить от родителя» (если идентификатор_запроса события = запрос_вызова, иначе отброшено)
      if идентификатор_запроса != @состояние_движка.запрос_вызова { @отбросить(событие); return Some(Остаться) }
      @писать_журнал("продолжение с ${@состояние_движка.предыдущее}: от родителя ${идентификатор_запроса}, запись ${событие.идентификатор}")
      // слова человека не записываются ("")
      @передать_вложенным("продолжить")
      Some(Куда(@машина.состояние_по_имени(@состояние_движка.предыдущее)))
    }
    ПаузаОстановитьОтРодителя { идентификатор_запроса } => {
      if @состояние_движка.состояние != @машина.состояние_паузы() { @отбросить(событие); return Some(Остаться) }   // защитная ветка, как у ПаузаОстановить
      // ПАУЗА #4: «остановить от родителя» (если идентификатор_запроса события = запрос_вызова, иначе отброшено)
      if идентификатор_запроса != @состояние_движка.запрос_вызова { @отбросить(событие); return Some(Остаться) }
      @машина.записать_остановку(@машина.причина_остановки_в_паузе())
      @передать_вложенным("остановить")
      Some(Куда(@машина.состояние_остановлено()))
    }
  }
}
```

## Цикл исполнителя

```nova
/// Исполнитель: ведёт машину `ТипМашины` по правилам 13–24 и 35 спецификации; единственный пишет в хранилище и отправляет запросы.
/// Данные поступают только через события; запросы отправляются только после фиксации шага; снимок сохраняется до открытия ворот.
/// Исполнитель с машиной реализует `Вызываемое[Вход, Выход]` структурно (метод `вызвать`) и подаёт себя машине как `Среда`.
// псевдокод: параметры типа `Исполнитель` перечислены в объявлении и в методах не повторяются
type Исполнитель[Состояние, Событие, Вход, Выход, ВходРоли, РезультатРоли, Действие, ТипМашины Автомат[Состояние, Событие, Вход, Выход, ВходРоли, РезультатРоли, Действие]] {
  машина ТипМашины,                                  // данные и логика автомата
  состояние_движка СостояниеДвижка[Состояние],                // данные движка
  вызов Option[Запрос[Вход]],                  // запрос, которым машину вызвали (конверт исполнителя)
  очередь []Входящее[Событие],                 // входящие события в порядке прихода (правило 13)
  готовый_ответ Option[Исход[Выход]],          // ответ, отданный вызвавшей стороне; машина отвечает один раз; повторная отправка по `Связь` после сбоя допустима, получатель дедуплицирует по `запрос_вызова` (правило 35)
  ответ_отправлен bool,                        // ответ ушёл через `Связь.ответить`: ставится после успешной отправки отдельной фиксацией
  необратимые []Действие,                      // действия шага, которые выполняются после сохранения; в снимке, чтобы повториться после перезапуска
  в_работе bool,                               // цикл идёт: повтор запроса не запускает вторую машину (исполнитель на запрос один; исключение процессов — вне файла)
}

/// Исполнитель над готовой машиной; хранилище — эффект `Хранилище`, обработчик подставляет вызывающий код.
fn Исполнитель.new(машина ТипМашины) -> Исполнитель => {
  машина: машина,
  состояние_движка: СостояниеДвижка.new(машина.начальное()),
  вызов: None,
  очередь: []Входящее.new(),
  готовый_ответ: None,
  ответ_отправлен: false,
  необратимые: []Действие.new(),
  в_работе: false,
}

/// Событие `Вызываемое[Вход, Выход]`: повтор запроса с тем же идентификатором возвращает готовый ответ или продолжает прерванную работу (правило 35, п. 4).
fn Исполнитель mut @вызвать(запрос Запрос[Вход]) Хранилище Журнал Связь Объекты Time -> Исход[Выход] {
  // прогон идёт: повтор не поднимает вторую машину поверх живой, а ждёт готовый ответ идущего прогона
  if @в_работе { return @ждать_готовый_ответ() }
  match @загрузить_снимок(запрос.идентификатор_запроса) {
    None => @начать(запрос)
    Some(снимок) => match раскодировать(снимок.данные_движка).готовый_ответ {   // псевдокод: раскодирование среза исполнителя
      Some(готовый) if раскодировать(снимок.данные_движка).ответ_отправлен => готовый   // уже ушёл по `Связь.ответить`: второй раз не шлётся
      _ => match @возобновить(запрос.идентификатор_запроса) {
        Some(ответ) => ответ
        None => недостижимо("снимок только что загружен: возобновить его находит")
      }
    }
  }
}

/// Новый запрос: входит в начальное состояние машины, фиксирует шаг и входит в цикл. Машину по входу запроса создаёт вызывающий код.
fn Исполнитель mut @начать(запрос Запрос[Вход]) Хранилище Журнал Связь Объекты Time -> Исход[Выход] {
  @в_работе = true
  @вызов = Some(запрос)
  @состояние_движка = СостояниеДвижка.new(@машина.начальное())
  @очередь = []Входящее.new()
  @готовый_ответ = None
  @ответ_отправлен = false
  @необратимые = []Действие.new()
  @состояние_движка.запрос_вызова = запрос.идентификатор_запроса
  @состояние_движка.трасса = @новая_трасса()                  // дочерняя от внешней (запрос.трасса)
  @выполнить_шаг(@новое_событие("старт"), Куда(@машина.начальное()))
  @цикл()
}

/// Продолжение после остановки исполнителя: загружает снимок и продолжает с сохранённого `состояние`; None — снимка нет.
/// Ждавшая обращения машина повторно получает только запросы без принятого ответа; на ПАУЗЕ остаётся, пока человек не скажет «продолжить» (правила 12, 14, 22).
/// Перед этим машина делает подготовку (`при_возобновлении`): она может не пустить в сохранённое состояние и дать переход в другое.
fn Исполнитель mut @возобновить(идентификатор_запроса str) Хранилище Журнал Связь Объекты Time -> Option[Исход[Выход]] {
  match @загрузить_снимок(идентификатор_запроса) {
    None => None
    Some(снимок) => {
      ro срез = раскодировать(снимок.данные_движка)      // псевдокод: раскодирование среза исполнителя
      @состояние_движка = срез.состояние_движка
      @очередь = срез.очередь
      @вызов = срез.вызов
      @готовый_ответ = срез.готовый_ответ
      @ответ_отправлен = срез.ответ_отправлен
      @необратимые = срез.необратимые
      @состояние_движка.ожидание = HashMap[str, Ожидание].new()      // моменты `Time.now_monotonic()` после перезапуска несравнимы: сроки открытых запросов отсчитываются заново при повторной отправке
      @машина.восстановить(снимок.данные_машины)
      match @готовый_ответ {
        Some(готовый) => {                           // ответ уже отдан
          if !@ответ_отправлен { @отправить_ответ() }   // не успел уйти: повторяется, идемпотентно по запрос_вызова; ушёл — ничего не шлётся
          Some(готовый)
        }
        None => {
          @в_работе = true
          // подготовка при каждом старте, до входа в сохранённое состояние; Some — в него войти нельзя, шаг ведёт по переходу;
          // у конца (ответ не успел уйти) подготовка не нужна и ответ не подменяет
          ro подготовка = if @в_конце(@состояние_движка.состояние) { None } else { @машина.при_возобновлении(@состояние_движка.состояние, @среда()) }
          @после_перезапуска(подготовка)
          Some(@цикл())
        }
      }
    }
  }
}

/// Цикл: берёт события по одному, пока ответ не отдан. Остановка исполнителя — завершение процесса в любой точке цикла:
/// состояние уже сохранено фиксацией шага, дописывать ничего не нужно.
fn Исполнитель mut @цикл() Хранилище Журнал Связь Объекты Time -> Исход[Выход] {
  loop {
    match @готовый_ответ {
      Some(ответ) => {
        if !@ответ_отправлен { @отправить_ответ() }   // повторяемо: идемпотентно по запрос_вызова
        @в_работе = false
        return ответ
      }
      None => {
        @принять_сообщения()                   // `Связь.принять` без ожидания
        @проверить_сроки()                     // «нет ответа в срок» — из сравнения со `Time`
        @обработать_очередь()
      }
    }
  }
}

/// Приём при приходе: в порядке прихода и в любом состоянии (правило 14).
fn Исполнитель mut @при_приходе(сообщение Получено[Событие, РезультатРоли]) Хранилище Журнал Связь Объекты Time -> () {
  @состояние_движка.счётчик_событий += 1                               // +1 при приходе любого события
  match сообщение {
    // ответ роли или отказ (Исход от открытой стороны)
    ПолученОтвет(ответ) => {
      ro идентификатор = запрос_ответа(ответ)
      // чужой или поздний ответ: неизвестный идентификатор, закрытый или отменённый запрос, повторная доставка (правило 17)
      if !@состояние_движка.открытые_запросы.contains(идентификатор) || @состояние_движка.принятые_запросы.contains(идентификатор) {
        // отбрасывание — отдельная фиксация со своей строкой журнала и номером шага (правило 31)
        ro лишнее = @событие_из_сообщения(сообщение)
        @начать_фиксацию_приёма(лишнее)
        @отбросить(лишнее)
        @зафиксировать()
        return
      }
      // форма: ответ не по форме исполнитель возвращает стороне в том же запросе; число возвратов задаёт состояние
      if !форма_верна(ответ) { @вернуть_стороне(ответ); return }     // сколько раз и что после — по описанию роли (`возвратов_формы`); счёт и исход — у обработчика роли
      // объект, куда пишется результат (у машины — рабочий документ), изменился с начала попытки — результат не принимается,
      // запрос отменяется и отправляется заново (новая попытка, вход прочитан заново)
      if @машина.объект_менялся_с_начала_попытки(@состояние_движка.состояние) { @повторить_запрос(идентификатор); return }
      // приём — одна фиксация: идентификатор в принятые_запросы, «При приёме», запись результата в хранилище, событие в очередь (правила 14, 31)
      ro событие = @событие_приёма(ответ)
      @начать_фиксацию_приёма(событие)
      @состояние_движка.принятые_запросы.push(идентификатор)
      @машина.при_приёме(@состояние_движка.состояние, ответ)
      @машина.записать_результат(@состояние_движка.состояние, ответ)
      @положить_в_очередь(событие)
      @зафиксировать()
      // последним, повторяемым без вреда этапом — принятие файла попытки (при старте завершается по принятые_запросы)
      @машина.принять_файл_попытки(идентификатор)
    }
    // слово человека или сигнал
    ПолученоСлово(_) => {
      ro событие = @событие_из_сообщения(сообщение)
      @начать_фиксацию_приёма(событие)                // слово человека — своя фиксация: не теряется при сбое (правила 19, 31)
      @записать_слово_ворот(сообщение)                // на воротах (правило 19)
      @положить_в_очередь(событие)
      @зафиксировать()
    }
    // «нет ответа в срок»: порождает исполнитель по таймеру, код НетОтветаВСрок; у обращения человека срока нет (правило 19)
    ПросроченЗапрос(идентификатор) => {
      // запрос уже закрыт или принят: срок поздний (правило 17) — отдельная фиксация со строкой журнала
      if !@состояние_движка.открытые_запросы.contains(идентификатор) || @состояние_движка.принятые_запросы.contains(идентификатор) {
        ro лишнее = @событие_из_сообщения(сообщение)
        @начать_фиксацию_приёма(лишнее)
        @отбросить(лишнее)
        @зафиксировать()
        return
      }
      ro событие = Входящее {
        идентификатор: "сбой-${@состояние_движка.счётчик_событий}", сторона: сторона_запроса(идентификатор), запрос: Some(идентификатор), тело: @машина.событие_сбоя(НетОтветаВСрок) }
      @начать_фиксацию_приёма(событие)
      @положить_в_очередь(событие)
      @зафиксировать()
    }
  }
}

/// Обработка очереди: первое событие, которое ждёт текущее состояние; остальные остаются в очереди (правило 13).
fn Исполнитель mut @обработать_очередь() Хранилище Журнал Связь Объекты Time -> () {
  match @взять_первое_ожидаемое() {                   // сигналы ждёт любое состояние, кроме концов
    None => @ждать_прихода()
    Some(событие) => {
      ro переход = @общие_события(событие) ?? @машина.перейти(@состояние_движка.состояние, событие.тело, событие, @среда())
      @выполнить_шаг(событие, переход)
    }
  }
}

/// Шаг — одна фиксация (правило 13): переходы, записи в хранилище, строки журнала, новые значения «состояние», «открытые_запросы»,
/// «принятые_запросы», «к_отправке» и счётчиков попыток пишутся вместе; незавершённый шаг откатывается.
fn Исполнитель mut @выполнить_шаг(событие Входящее[Событие], переход Переход[Состояние]) Хранилище Журнал Связь Объекты Time -> () {
  @начать_фиксацию()
  ro метка_до = @машина.метка_инварианта()
  @состояние_движка.номер_шага += 1                                    // растёт внутри фиксации; откат возвращает
  @состояние_движка.причина_шага = событие.идентификатор
  mut текущий_переход = переход
  match текущий_переход {
    НеЖдёт => {                                  // событие остаётся в очереди
      @откатить()
      return
    }
    _ => ()
  }
  // принятый запрос закрывается переходом по своему событию: убирается из открытые_запросы и из принятые_запросы
  match событие.запрос {
    Some(идентификатор) => @закрыть_запрос(идентификатор)
    None => ()
  }

  // цепочка операций и развилок и их переходов «сразу» до первого обращения или конца;
  // `тело_цепочки` — событие последнего входа: результат операции или «сразу»; его получает следующая развилка
  mut тело_цепочки = @машина.событие_сразу()
  loop {
    match текущий_переход {
      Остаться => break                                  // то же состояние
      НеЖдёт => break                            // первое событие проверено выше; в цепочке не встречается
      Куда(цель) => match @войти_в(цель, событие, тело_цепочки) {
        Some(шаг) => {
          текущий_переход = шаг.переход
          тело_цепочки = шаг.тело
        }
        None => break                                // ждёт события или конец
      }
      Заново(цель) => {
        @отменить_открытый_запрос_обращения(цель)        // «запуск заново» (правило 18): прежний запрос сначала отменяется
        match @войти_в(цель, событие, тело_цепочки) {
          Some(шаг) => {
            текущий_переход = шаг.переход
            тело_цепочки = шаг.тело
          }
          None => break
        }
      }
    }
    // инвариант машины: ни один компонент её метки не уменьшается
    проверить_инвариант(метка_не_уменьшилась(@машина.метка_инварианта(), метка_до))
  }
  // последний вход цепочки (обращение или конец) выходит из цикла через `break`: его метка проверяется здесь
  проверить_инвариант(метка_не_уменьшилась(@машина.метка_инварианта(), метка_до))
  @зафиксировать()                                    // запись шага: снимок сохранён, необратимые действия лежат в нём
  @выполнить_необратимые()                            // последний, повторяемый без вреда этап: переименование в архив, смена права записи
  @после_фиксации()
}

/// Вход в состояние: запись «состояние» подразумевается у каждого перехода; None — обращение или конец, цепочка заканчивается.
/// Операция выполняется, её результат — событие: оно идёт в переход операции и дальше, следующей развилке цепочки; развилка получает событие предыдущего входа (`тело_цепочки`),
/// а если до неё была не операция — «сразу».
fn Исполнитель mut @войти_в(куда Состояние, событие Входящее[Событие], тело_цепочки Событие) Журнал Объекты Time -> Option[ШагЦепочки[Состояние, Событие]] {
  @состояние_движка.состояние = куда
  match @машина.вид(куда) {
    Обращение | Конец => None                        // ждёт события или конец
    Операция => {
      ro исход = @машина.выполнить_операцию(куда, @среда())
      Some(ШагЦепочки { переход: @машина.перейти(куда, исход, событие, @среда()), тело: исход })
    }
    Развилка => Some(ШагЦепочки { переход: @машина.перейти(куда, тело_цепочки, событие, @среда()), тело: @машина.событие_сразу() })
  }
}

/// После фиксации шага: сначала очередь, потом запросы (правило 13).
fn Исполнитель mut @после_фиксации() Хранилище Журнал Связь Объекты Time -> () {
  @передать_вложенным_накопленные_сигналы()           // «стоп», «продолжить», «остановить», «отмена»; журнал «… передан(о) <идентификатор_запроса>»
  // конец: ответ вызвавшей стороне отдаётся всегда, даже если в очереди сигнал, и один раз (повторная отправка по `Связь` после сбоя допустима, получатель дедуплицирует по `запрос_вызова`; правило 35, «один запрос — один ответ»);
  // сигналы в концах отбрасываются по правилам 17 и 23 уже после ответа
  match @машина.вид(@состояние_движка.состояние) {
    Конец => match @готовый_ответ {
      None => {
        @отменить_все_открытые_запросы()              // вход в любой конец (правило 22)
        @машина.при_входе_в_конец(@состояние_движка.состояние, @среда())
        @выполнить_необратимые()
        @отдать_ответ(@машина.ответ_по_концу(@получатель(), @состояние_движка.состояние, @среда()))
      }
      Some(_) => ()                                    // ответ уже отдан
    }
    _ => ()
  }
  // перед отправкой смотрит во входящую очередь: «стоп человека», «стоп от родителя» или «отмена_запроса» — запросы не отправляются,
  // а сигнал разбирается (правила 23, 35)
  if @в_очереди_есть_сигнал() { return }
  match @машина.вид(@состояние_движка.состояние) {
    Обращение => @отправить_запросы(@состояние_движка.состояние)
    _ => ()                                          // операции и развилки до сюда не доходят: цепочка идёт до обращения или конца
  }
}

/// Отправка запросов по состоянию. Состояние сохранено до открытия ворот; повторный вход ничего не отправляет стороне,
/// чей запрос открыт или лежит в принятых (правила 12, 14, 21). Как обращается состояние, говорит машина (`обращение`).
fn Исполнитель mut @отправить_запросы(обращение Состояние) Хранилище Связь Объекты Time -> () => match @машина.обращение(обращение) {
  None => ()
  Some(Набор { срок_бездействия, вложенная, .. }) => {
    // стороны из к_отправке по порядку, пока открытых запросов меньше предела движка (`предел_запросов` машины, правило 21)
    while @состояние_движка.к_отправке.len() > 0 && @состояние_движка.открытые_запросы.len() < @машина.предел_запросов() {
      ro сторона = @состояние_движка.к_отправке[0]
      // механика контракта — отдельная фиксация со своим номером шага и сохранением ДО отправки (правила 13, 22):
      // перенос из к_отправке в открытые_запросы и рост счётчика попыток; после падения снимок уже содержит новую попытку и открытый запрос,
      // возобновить отменит его (правило 18), а поздний ответ отбросит (правило 17)
      @начать_фиксацию_запроса()
      @состояние_движка.к_отправке = @состояние_движка.к_отправке[1..]
      ro попытка = @машина.следующая_попытка(сторона)
      @состояние_движка.открытые_запросы.push("${сторона}-${попытка}")
      if вложенная { @состояние_движка.вложенные.push("${сторона}-${попытка}") }
      @зафиксировать()
      @отправить(Запрос { идентификатор_запроса: "${сторона}-${попытка}", номер_попытки: попытка, сторона: сторона,
        вход: @машина.вход_запроса(обращение, сторона, @среда()), срок_бездействия: срок_бездействия, трасса: @состояние_движка.трасса, номер_шага: @состояние_движка.номер_шага })
    }
  }
  Some(Одна { сторона, срок_бездействия, вложенная, .. }) => {
    if @есть_открытый_или_принятый(сторона) { return }
    // отдельная фиксация со своим номером шага и сохранением ДО отправки, как у набора (правила 13, 22)
    @начать_фиксацию_запроса()
    ro попытка = @машина.следующая_попытка(сторона)        // фиксируется до отправки вместе с открытые_запросы
    @состояние_движка.открытые_запросы.push("${сторона}-${попытка}")
    if вложенная { @состояние_движка.вложенные.push("${сторона}-${попытка}") }
    @зафиксировать()
    @отправить(Запрос { идентификатор_запроса: "${сторона}-${попытка}", номер_попытки: попытка, сторона: сторона,
      вход: @машина.вход_запроса(обращение, сторона, @среда()), срок_бездействия: срок_бездействия, трасса: @состояние_движка.трасса, номер_шага: @состояние_движка.номер_шага })
  }
}

/// Перезапуск исполнителя: не переход и «состояние» не пишет; шаг со своим номером (правила 22, 31).
/// `подготовка` — ответ `при_возобновлении` машины: `None` — войти в сохранённое состояние; `Some(переход)` — подготовка в него не пустила, шаг ведёт по этому переходу
/// (например, «занята живым процессом» — в ОСТАНОВЛЕНО, нерешённые исходы — к воротам).
fn Исполнитель mut @после_перезапуска(подготовка Option[Переход[Состояние]]) Хранилище Журнал Связь Объекты Time -> () {
  @начать_фиксацию()
  @состояние_движка.номер_шага += 1
  ro событие_перезапуска = @новое_событие("перезапуск")
  @состояние_движка.причина_шага = событие_перезапуска.идентификатор
  // открытые запросы умершего исполнителя к ролям без принятого ответа отменяются; их поздние ответы отбрасываются (правило 18);
  // ветка `None`: запросы к вложенным машинам не отменяются (кроме_вложенных = true), а повторяются тем же идентификатором — вложенная вернёт готовый ответ
  // или продолжит, заново не запускается (правило 35, п. 4); ветка `Some`: в сохранённое состояние не входят, поэтому вложенным идёт сигнал «отмена»
  // (до отмены, как в «отмена_запроса», правило 35, п. 10) и их запросы отменяются тоже
  ro кроме_вложенных = match подготовка {
    Some(_) => false
    None => true
  }
  match подготовка {
    Some(_) => @передать_вложенным("отмена")
    None => ()
  }
  @отменить_открытые_без_принятого(кроме_вложенных)
  @зафиксировать()
  // завершение принятия файла попытки по принятым запросам, не сверяя отпечаток (правило 14): на обеих ветках; повторяется без вреда
  for идентификатор in @состояние_движка.принятые_запросы {
    @машина.принять_файл_попытки(идентификатор)
  }
  match подготовка {
    Some(переход) => @выполнить_шаг(событие_перезапуска, переход)      // шаг со своим номером (правила 12, 22); дальше — как после любого шага
    None => {
      // запросы идут только после фиксации (правило 13)
      for идентификатор in @вложенные_запросы() {
        @повторить_вложенный(идентификатор)
      }
      @выполнить_необратимые()
      // повторный вход в «состояние» (обращение или конец, правило 12); незакрытые ворота показываются человеку снова
      @после_фиксации()
    }
  }
}
```
