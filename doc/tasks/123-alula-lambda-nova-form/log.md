# Журнал задачи 123: лямбда Алулы — форма Новы

2026-11-19 аудит владельца: запись лямбды `x => выр` (спека Алулы п. 361, решение 2.18 от 2026-10-22)
проверена контрпримерами. Причина «GitHub режет строку таблицы по `|`» не различающая: наборы
литералов в тех же ячейках с 2.5 пишутся через `\|` (строка `ход` в данных машин), лямбда Новы
стоила бы того же экранирования; решение 2.18 принято позже появления наборов. Причина «`|` уже
занят наборами и альтернативами выбор» — предпочтение: в Нове роли `|` различимы синтаксически и
перегрузка не мешает, в Алуле различимость та же (лямбда только аргументом функции списка).
Положительная причина — один знак `=>` с телом функции и веткой выбор (сведение к Нове 2026-10-22,
запись 23 history) — стилистическая, не объективная; Нова сама не равномерна (лямбда `|…|`, тело
`=>`). Дефект — подача стилистического решения как вынужденного (критерий 6 agents.md).
2026-11-19 решение владельца (ответ на вопрос «оставить => с честной причиной / свести к Нове»):
«Свести к Нове |…|». Заведена карточка 123 (spec.md AC-L-1..4); слово передано автору пакета:
форма Новы, ломающая 0.31, мигратор автора, честная перепись спеки п. 361 и записи 23 history;
методика переносит свои машины мигратором после приёмки; публикация по слову владельца. Волна 0.30
(Канопус) не смешивается с 0.31.2026-11-19 STATE автора по 0.31 (принят, объём совпадает с AC-L-1..4): контракт — узел lambda
{params, body} и провод НЕ меняются (узел с 2.19/2.21), 13 сигнатур прежние, шов 2.25 сохранён
(2.25-тексты читаются и рендерятся в прежней форме, старые лямбды в них остаются); меняются
синтаксис текста и alula_version 0.31. Старая форма в файле 0.31 — отказ с подсказкой
tools/migrate-alula-231.py; в ячейках `\|x\|`, в блоках кода `|x|`. Объём: парсер/рендер
(одно/двухместная, `_`, тело-блок), версия 0.31, мигратор 231 (--dry-run/--selftest, идемпотентен),
образцы/примеры/тесты пакета, спека п. 361/365/1205/таблицы знаков ru/en, журнал изменений,
запись 23 history с честной перепричиной + запись 0.31, карточка пакета. Ноль-арная `||` не
добавляется: места применения нет (лямбда только аргументом одно/двухместных функций списка) —
причина объективная, автору передана, просит строку в спеке. Ветка lambda-031 (база e86e7ad поверх
cf3c5cb; origin/main пакета cf3c5cb, пушей нет), работа идёт. Candidate SHA — после зелёных гейтов;
приёмка независимая; публикация по слову владельца.
