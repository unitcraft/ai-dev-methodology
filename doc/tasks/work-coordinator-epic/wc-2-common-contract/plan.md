# Проверка результата WC-2

**Статус:** план проверки контрактного документа; runtime-тесты не запускались и не входят в WC-2.

## План

1. Сверить требования и границы с `doc/work-coordinator-epic-spec.md`, `doc/work-coordinator-epic-plan.md`, карточками WC-2/WC-1, WC-1 commit `06a8646` и базой `e19d2f2`; указать один целевой артефакт WC-2, не менять WC-1/088.
2. Сформулировать единый task/epic контракт, циклы, pins принятых версий, сериализацию, lifecycle, reopen и адресную пересверку; покрыть каждое состояние/событие исходом и ответственным.
3. Разделить движок, контракт host/координатора и агентные оболочки; read-only определить доступную точку сопряжения и честно пометить всё неподтверждённое для 0.29.
4. Добавить durable question/effect ledger, trusted owner source, typed controls, unknown effects и WC-2 контрпробы; не выбирать backend и не копировать политику моделей.
5. Проверить ссылки, матрицу REQ/AC, абстрактность и секреты; зафиксировать неподвижный diff одним локальным коммитом.
6. Передать SHA и точный артефакт интегратору на независимый просмотр; после завершения зафиксировать verdict и разрешённую ограниченную доработку отдельным commit, не меняя исходный snapshot.

## DoD и воспроизводимые проверки

- [ ] WC-2 артефакт покрывает REQ-1–9, AC-1–8, AC-10–12; подтверждение: PowerShell считает строки `StartsWith('| REQ-')` и `StartsWith('| AC-')` в `spec.md`: ровно 10 строк — REQ-1–9 и AC-10; AC-11/12 прослеживаются в REQ-5/6.
- [ ] Примеры/контрпримеры плана имеют ожидаемый исход и ответственного; подтверждение: `Select-String -Path doc\tasks\work-coordinator-epic\wc-2-common-contract\spec.md -Pattern 'waiting-owner → stop → paused → resume','paused → input_changed → reconcile → ready → start','task_failure','prepare','owner_decision','compensate'` проверяет добавленные сценарии и event outcomes.
- [ ] Stop/resume/input_changed/reconcile сохраняют самостоятельные owner/pause/HOLD блокировки; отрицательные пробы не позволяют снять их обходом.
- [ ] Есть единый `queued -> prepare -> ready -> start -> running`, единый `waiting-owner`, явные failure/reject/compensation исходы; terminal revision неизменяема.
- [ ] Установлены границы движок/host/оболочки и статус 0.29 без заявления о реализации; подтверждение — раздел «Сопряжение с движком» и внешняя read-only проверка, если предоставлена.
- [ ] Внутренние ссылки существуют; подтверждение: `git diff --check` и проверка целей ссылок в diff.
- [ ] Diff абстрактен и не содержит секретов/персональных данных/путей машины; подтверждение: поиск в diff и файлах сдачи, результат отдельной строкой отчёта.
- [ ] Reverse-probe контрактных отрицательных случаев: при удалённом hold-guard проба должна выявить обход, после возврата — пройти; подтверждение — именованные пробы в разделе «Контрпробы» и проверка ссылок/поиска перед коммитом.
- [ ] Тестовые числа сверены с базовыми: текстовые правки не меняют тестовый набор; подтверждение — тесты не запускались, тестов добавлено 0, пропущено 0, расхождений нет.
- [ ] Индекс до коммита содержит только нужные файлы; подтверждение `git diff --cached --stat`; один коммит с английским сообщением без трейлеров.

## Границы проверки

Требования/AC и примеры излагаются как будущий проверяемый контракт. Никакой runtime, движок, соседний репозиторий, backend или интеграция не изменяются. Подтверждение фактического контракта 0.29 остаётся обязательным входом для WC-4, если источник не будет предоставлен до завершения WC-2. Ограниченная доработка — только router-находки по exact predecessor SHA; после нового коммита выполняется их bounded recheck, новый полный обзор не запускается.
