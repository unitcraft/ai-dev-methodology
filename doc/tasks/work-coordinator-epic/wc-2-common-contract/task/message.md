# WC-2: Общий контракт работы

Эпик: `doc/tasks/work-coordinator-epic`

## Результат и границы

Контракт task/epic, графа, версий, событий, состояний и переходов по принятому плану `doc/work-coordinator-epic-plan.md`. Не выбирать физическую схему хранения, сеть или backend; не перепроектировать контракты движка.

## REQ/AC эпика

REQ-1–9; AC-1–8, AC-10–12.

## Зависимости

Зависит от: `doc/tasks/work-coordinator-epic/wc-1-rules`.

Блокирует: `doc/tasks/work-coordinator-epic/wc-3-acceptance-scenarios`.

Пересекается (файлы): определить при постановке после WC-1.

Начинается после: WC-1 принята; точка сопряжения с эпиком 0.29 и граница задачи 020 сверены.

## Приёмка

Контрпримеры из принятого плана проверяют типы работы, циклы, pins, сериализацию, независимую параллельность, инвалидирование, отмену/компенсацию и вопросы владельцу; граница эпика 0.29 зафиксирована без дублирования контракта. До выполнения предшественников не запускать.

## Полное задание WC-2

Подготовить переносимый общий контракт task/epic, граф работ, версии этапов, события, состояния, переходы и сопряжение с движком. Покрыть REQ-1–9 и AC-1–8, AC-10–12 из `doc/work-coordinator-epic-spec.md`: единый запуск task/epic без одно-child wrapper; рекурсивная вложенность и запрет inclusion/dependency циклов; зависимости по принятым версиям артефактов этапов, stale и pins; последовательные события одного instance и параллельные независимых; изменения вложенной/завершённой работы только новой работой либо явным reopening без переписи истории; явная политика активной работы и адресная пересверка затронутых ветвей; разные stop/cancel/compensation без автоматического rollback; durable question intent, `waiting-owner` только с коррелированным запросом и доказательством доставки, restart recovery, срок, ответственный и идемпотентная эскалация без auto-accept; trusted owner source/полномочия, typed control, durable учёт эффектов, `unknown` и безопасный повтор.

Прочитать AGENTS, опубликованные спецификацию и план эпика, эту карточку, WC-1 (06a8646), дополнение 088 (e19d2f2), `task-runner.md` и спецификацию машины. Быстро read-only сверить фактический контракт движка и статус эпика 0.29 в соседнем проекте; туда не писать, URL/артефакт не выдумывать, целевое поведение не выдавать за реализованное. Разделить движок, контракт хозяина/host и агентные оболочки; указать предоставленный и недостающий контракт 0.29. Если обнаружен подтверждённый разрыв реализации — назвать точную зависимость; спецификацию закончить без выбора backend. Не копировать политику моделей 020.

Обязательны контрпримеры WC-2 из плана и исход/ответственный для каждого состояния и ветки. Не исполнять WC-3–6, CLI-host/runtime, адаптеры или продуктовый код; не выбирать backend/место реализации, не менять модели, настройки, службы, соседние деревья, WC-1/088 или действующие нормы. Не создавать другие harness-задачи/сессии. Не merge/push до приёмки. Передать точный SHA и артефакт интегратору для независимой проверки; файлы во время обзора не менять. Owner gate остаётся отдельным.

При сдаче приложить воспроизводимые DoD-доказательства, трассировку без нерешённых FAIL/NOT VERIFIED, отдельный secrets scan, reverse-probe, сверку тестовых чисел и single-commit статистику индекса до коммита. Если проверка движка 0.29 недоступна, назвать источник/статус и требуемый результат, не обещать совместимый runtime.
