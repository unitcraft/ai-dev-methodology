# Эпик «Тонкий хозяин в пакете»: раздел универсальных примитивов между методикой и пакетом языка

**Статус: целевое решение утверждено владельцем методики (2026-11-16, чат методики: «да, все верно, сохрани это все целевое решение в эпик»).** Документ — целевое состояние и порядок работ; отдельные задачи заводятся по нему с постановками и приёмками. Основа: завершённый эпик «Тонкий хозяин» методики (задачи 110–116, реестр `alula-machines/registry.md` — 72 инструмента, последние 17 строк — примитивы каркаса) и выпущенный пакет языка 0.29.0 (origin/main `acaeb1f`, тег `v0.29.0` → `b7c231e`), содержащий инфраструктуру внешних функций: объявления (AL-123), реестр как данные (AL-113), классы с проверкой места вызова, ActEnv, outbox, pinned restore, локальный контракт, разбор ответа агента (AL-153).

Упоминание репозитория [nv-lang/nova-alula](https://github.com/nv-lang/nova-alula) — согласовано владельцем для этого документа по прецеденту [state-machines/alula-moved.md](../state-machines/alula-moved.md) (согласие действует на этот документ, а не на класс; дата согласия — 2026-11-16).

Проверено вторым мнением перед утверждением (свежий собеседник без аргументов автора, та же семья моделей — совпадение зафиксировано): критических 1, значимых 4, желательных 3; все находки внесены (состав 13+4 вместо «17 универсальных»; связь реестров стражем, а не строками-указателями; пересмотр стража 103; порядок с G; один тестовый хост; негативы из spec-таблиц; судьба host-spec; числа в постановке не фиксируются).

## 1. Принцип раздела

Инструмент живёт там, где его контракт. Контракт универсального примитива не знает ни раннера, ни методики — он описывает среду исполнения (файлы, процессы, замок, хэш, дешёвая модель). Контракт предметного инструмента ссылается на объекты методики (ворота, маршруты, шаблоны журнала). Первый класс — пакет языка; второй — методика. Граница проходит по типам в сигнатуре: если в сигнатуре тип методики — инструмент остаётся в методике.

## 2. Целевые составы

### Пакет — канонический источник 13 универсальных примитивов

- Файлы: `read_file`, `write_file`, `move_file`, `delete_file`, `file_exists`, `list_dir`;
- процессы: `start_process`, `stop_process`, `process_running`, `run_command`;
- замок `acquire_lock`; разбор `parse_agent`; хэш `sha256`.

Сигнатуры — дословно из последних 17 строк таблицы «Primitives» реестра методики (редакция `5633435`), минус ядро-4. Классы — по host-spec задачи 111 (`volatile`/`acting`/`pure`), место вызова проверяет чекер пакета. Все `acting` исполняются только через outbox: интент фиксируется вместе с receipt, устойчивая идентичность эффекта, права на submit и на replay, `unknown ≠ успех`. `sha256` — `pure`, по std.

### Методика — 59 причин (55 предметных строк + ядро-4)

`issue_token`, `verify_token`, `journal_write`, `release_lock` остаются в методике. Основание: их контракты типизированы объектами методики — `verify_token` возвращает `?Opening` с перечислением маршрутов `full/fast/small`; `journal_write` сверяет событие с таблицей шаблонов журнала методики; замок принадлежит раннеру. Обобщение — проектирование универсальных контрактов ворот/журнала/замка в пакете — новая разработка без потребителя вне методики; не делается до появления потребителя (отдельное слово владельца).

## 3. Связь реестров

- Таблица «Primitives» реестра методики **сохраняет 13 универсальных строк**: это контракт, по которому 595 тестов машин скриптуют ответы хозяина; загрузчик (`parse_registry_table`) читает строку примитива ровно из шести ячеек — «строки-указатели» в таблице невозможны.
- Канонический источник этих 13 строк — реестр пакета. Дубль контролирует машина: **страж универсальности (задача 103) расширяется** — сверяет 13 строк методики с реестром пакета построчно (имя, параметры, результат, класс) и краснеет при любом расхождении.
- Шапка реестра методики получает помеченный абзац-указатель по прецеденту `alula-moved.md`: «универсальные примитивы среды исполнения перенесены в пакет языка; канон — реестр пакета; перенос <дата>» — проза, загрузчик её не читает.
- `doc/tasks/111-tonkiy-hozyain-stadiya-1-karkas-17-primi/host-spec.md` — датированный снимок задачи 111, дальше не правится; живой канон — спецификация пакета.

## 4. Хосты пакета

- **Один тестовый хост в пакете:** существующий тест-хост движка расширяется до семантики ScriptedHost методики (scripted-ответы по ключам, StepFailure). ScriptedHost методики остаётся её тестовым артефактом для раннер-машин; пробы, касающиеся 13 универсальных, мигрируют в пакет. Эквивалентность доказывается прогоном одинаковых сценариев с одинаковыми исходами. Двух скриптуемых хостов с разной семантикой сбоя в пакете не будет.
- **Reference-хост над реальной файловой системой** в пакете: дерево хозяина; путь вне дерева — сбой шага; недоступность — сбой шага; хост ничего не знает о раннере.

## 5. Проводка в локальный контракт

`bind` по классам; `acting`-примитивы — через outbox-интенты; `parse_agent` — `volatile`, ответ проходит разбор AL-153 (декодирование текста в тип; невалидный ответ — сбой шага, машина значение не видит).

## 6. Негативы — полный перечень из spec-таблиц

Путь вне дерева; путь-инъекция (`..`); нет файла/папки; scripted-ключ не задан; неизвестный pid; не-JSON у `parse_agent`; `acquire_lock`: занятость чужим токеном — `false` (значение, не сбой), повтор со своим токеном — `true`; `file_exists`/`process_running` — `false` как значение; `acting` без права — отказ на submit и на replay; отзыв права не обходит dedup. Семантика «сбой против значения» — главный предмет переноса; перечень в задаче собирается из spec-таблиц, а не из примеров.

## 7. Порядок работ

| Шаг | Что | Репозиторий | Гейт |
|---|---|---|---|
| П-1 | 13 примитивов + расширение тест-хоста + reference-хост + негативы + проводка в контракт | nova-alula | приёмка чужой сессией: матрица карточки + саботаж-проба; сверка 13 сигнатур с реестром методики (`5633435`) |
| М-1 | Реестр методики: страж 103 ↔ пакет, абзац-указатель, шапка | методика | 595 тестов зелёные **без изменения фикстур**; страж зелёный в обе стороны |
