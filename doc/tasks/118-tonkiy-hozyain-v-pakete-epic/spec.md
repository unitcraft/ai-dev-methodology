# Спецификация: Эпик «Тонкий хозяин в пакете»

**Тип: эпик. Статус: постановка утверждена владельцем (2026-11-16, чат методики: «да, все верно, сохрани это все целевое решение в эпик»).** Вход — одобренное целевое решение [task/thin-host-package-epic.md](task/thin-host-package-epic.md); этот файл — его нормативная выжимка: REQ и AC эпика. Проверено вторым мнением до утверждения (критических 1, значимых 4, желательных 3 — все внесены; отметка в state.json).

## Принцип раздела

Инструмент живёт там, где его контракт. Граница — по типам в сигнатуре: тип методики в сигнатуре → инструмент методики; контракт описывает только среду исполнения → пакет.

## REQ

- **REQ-1. Универсальные примитивы пакета.** 13 примитивов (ФС 6: read_file, write_file, move_file, delete_file, file_exists, list_dir; процессы 4: start_process, stop_process, process_running, run_command; acquire_lock, parse_agent, sha256) — канонический источник в реестре пакета; сигнатуры дословно из последних 17 строк реестра методики (редакция 5633435), минус ядро-4; классы pure/volatile/acting по host-spec задачи 111; все acting — только через outbox (интент+receipt вместе, устойчивая идентичность, права на submit и replay, unknown ≠ успех); sha256 — pure по std.
- **REQ-2. Предметное остаётся в методике.** Ядро-4 (issue_token, verify_token, journal_write, release_lock) и 55 предметных строк — в реестре методики; обобщение ядра — отдельное решение владельца при появлении потребителя вне методики (контракты типизированы объектами методики: Opening с маршрутами full/fast/small, шаблоны журнала).
- **REQ-3. Связь реестров.** Таблица Primitives методики сохраняет 13 универсальных строк (контракт 595 тестов; загрузчик читает шесть ячеек — указателей в таблице нет); канон — реестр пакета; расширенный страж задачи 103 сверяет 13 строк построчно (имя, параметры, результат, класс) и краснеет при расхождении; шапка реестра методики — помеченный абзац-указатель по прецеденту state-machines/alula-moved.md; host-spec задачи 111 — датированный снимок, не правится.
- **REQ-4. Хосты пакета.** Один тестовый хост: существующий хост движка расширяется до семантики ScriptedHost (scripted-ответы, StepFailure), пробы по 13 универсальным мигрируют, эквивалентность — одинаковые сценарии/исходы; двух скриптуемых хостов нет. Reference-хост над реальной ФС: дерево хозяина; путь вне дерева — сбой шага; недоступность — сбой шага; о раннере не знает. Точки монтирования — REQ-9 (П-2а); для одной точки REQ-4 не меняется.
- **REQ-5. Негативы.** Полный перечень из spec-таблиц: путь вне дерева; `..`; нет файла/папки; scripted-ключ не задан; неизвестный pid; не-JSON у parse_agent; acquire_lock: занятость чужим — false, повтор своим — true (значение, не сбой); file_exists/process_running — false как значение; acting без права — отказ на submit и replay; отзыв права не обходит dedup.
- **REQ-6. Проводка в контракт.** bind по классам в локальном контракте; parse_agent — volatile, ответ через разбор AL-153 (невалидный = сбой шага).
- **REQ-7. Миграция машин методики (G).** Машины методики переводятся на 0.29 сразу на связанный реестр (после REQ-1/REQ-3); снимает HOLD 113.
- **REQ-8. Боевой хозяин (П-2).** Группы процессов, метки, журнал боя — переносится в пакет после REQ-1..6.
- **REQ-9. Точки монтирования (П-2а).** Дерево путей хозяина может быть лесом независимых точек (имя → абсолютная папка) внутри одного ToolHost; легаси-конструкторы сохраняют семантику одной точки байт-в-байт. N=1 — прежняя грамматика, префиксы не допускаются; N≥2 — имя точки обязательно первым сегментом каждого пути, включая основную, голый путь — сбой шага. Конфайнмент после canonicalize (ближайший существующий предок; висячая и непроверяемая ссылка — сбой), сравнение вхождения по семантике ОС, имена точек точные; `..` не выходит из точки; move между точками — сбой; идентичность действующих интентов — канонический абсолютный путь (и в N=1); таблица точек — часть идентичности хозяина, replay на другой конфигурации не поддерживается. Формат языка, 13 сигнатур, реестр, фикстуры и 595 машин не меняются; это host API, а не версия языка.

## AC

- **AC-1.** Реестр пакета содержит 13 строк, построчно равные строкам реестра методики (сверка приёмщиком); acting-примитивы в тестах идут через интенты с идентичностью; юниты зелёные; саботаж-проба общего узла ловится тестом.
- **AC-2.** Реестр методики после М-1: 59 причин на месте, 13 универсальных строк не изменены; 595 тестов машин зелёные без изменения фикстур.
- **AC-3.** Страж 103: зелёный на согласованном состоянии; красный на пробном расхождении (саботаж-проба — правка одной строки с откатом).
- **AC-4.** Пробы эквивалентности тест-хостов: одинаковые сценарии дают одинаковые исходы; все негативы REQ-5 — ожидания в тестах, семантика «значение против сбоя» сверена со spec-таблицами.
- **AC-5.** Контракт-сценарий: bind по классам, parse_agent с невалидным ответом — сбой шага, валидным — значение типа.
- **AC-6.** 595 тестов машин методики зелёные на 0.29; файлы 0.28 отвергаются с подсказкой миграции; запись о снятии HOLD 113 — словом владельца.
- **AC-7.** Боевой хозяин: сценарии стадий 4–6 методики (процессы с группами, замки с токенами, журнал) проходят на хосте пакета.
- **AC-8.** Точки монтирования (П-2а): позитивы двух точек (чтение, запись, список, замок, старт процесса с `dir` и `log_path` в разных точках); негативы (абсолютный путь, `..`, `a/../../x`, неизвестная/пустая/невалидная точка, cross-mount move, Windows-формы, голый путь в multi-root, symlink-уход и висячая ссылка, смена регистра на Windows); две точки с одинаковым относительным путём — разные acting-идентичности; паритет N=1 байт-в-байт (единственное исправленное исключение — symlink-уход наружу), 595 машин зелёные; саботаж границы `..` красный.

## Границы

Не входит: обобщение ядра-4 (до потребителя), durable backend, сетевые transport-адаптеры (как в 0.29.0). Каждая дочерняя задача — по слову владельца соответствующего репозитория; упоминание nv-lang/nova-alula согласовано владельцем на документы этой карточки (2026-11-16, прецедент alula-moved.md).
