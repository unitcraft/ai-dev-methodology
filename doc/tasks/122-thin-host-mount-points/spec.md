# Спецификация: точки монтирования (П-2а, эпик 118)

Источник: слово владельца 2026-11-19 — завести отдельного ребёнка П-2а после принятия П-2; корни проекта полностью независимы (разные диски, шары, домашняя папка). Вариант «подпапки одного корня» отвергнут; «несколько хостов + роутер» годится только для разных миров (ToolHost получает лишь имя и аргументы; у каждого хоста свой outbox, права и реестр процессов).

## Решение

- **Аддитивные точки внутри одного ToolHost.** Легаси-конструкторы (`new_tree`, `new_scripted_host`, `new_battle_host`) сохраняют семантику одной основной точки байт-в-байт; новые конструкторы принимают таблицу «имя → абсолютная папка». Один прогон — один outbox, права и реестр процессов; точки — свойство мира проекта, а не отдельные миры.
- **Грамматика.** N=1 — ровно прежняя грамматика, префиксы не допускаются (первый сегмент, совпавший с именем точки, — обычная папка). N≥2 — имя точки обязательно первым сегментом каждого пути, включая основную (имя объявлено в таблице); голый путь — `StepFailure` со списком точек. Теневой маршрутизации нет. Имена точек: непустые, без `/`, `\`, `:`, `.`, `..`; сравнение точное и регистрозависимое.
- **Конфайнмент после canonicalize.** Проверка вхождения — после разрешения ссылок: канонизируется ближайший существующий предок, остаток — только простые имена; висячая и непроверяемая ссылка — `StepFailure`. Сравнение вхождения — по семантике ОС (Windows — без учёта регистра, POSIX — с учётом). `..` не выходит из своей точки; переход в чужую точку через `..` — отказ. Windows-формы (`\`, `C:foo`, `\\?\`, UNC, ADS `a:b`, NUL) — `StepFailure`; `.`, пустые сегменты и `//` нормализуются, `\` не нормализуется, а отказывается.
- **canonicalize и для N=1.** Закрывает сегодняшнюю лексическую дыру symlink; единственное исправленное поведение; паритет AC-4 сохраняется (в его сценариях symlink не используется).
- **Путевые аргументы.** `path` у read/write/delete/exists/list; `from`, `to` у move; `dir` и `log_path` у start_process; `dir` у run_command; `path` у acquire_lock. Move между точками — `StepFailure` (copy+delete — отдельное решение). `command` непрозрачен: конфайнмент только по объявленным путевым аргументам.
- **Идентичность.** Действующие интенты — канонический абсолютный путь (корень + относительный), и в N=1 (внутренние id outbox изменились, тесты обновлены); две точки с одинаковым относительным путём дают разные идентичности. Таблица точек — часть идентичности хозяина; replay на другой конфигурации не поддерживается (явного отказа в коде нет — OPEN-хвост).
- **Корни.** Отсутствующий или несоздаваемый корень в многомонтовом конструкторе — ошибка запуска; исчезнувший в прогоне — `StepFailure`; легаси N=1 — без новых проверок на конструировании.
- **Что не меняется.** Формат языка, 13 сигнатур, реестр, фикстуры и 595 машин методики; это host API, а не версия языка.

## Ограничения (OPEN, не дефекты П-2а)

- Каталоговая symlink на Oracle 0.1.6 через std не канонизируется (EPERM); финальный компонент-ссылка на папку отказывается как «not verifiable»; junction канонизируется.
- Путь лога с пробелами не поддержан в battle host v1 (redirect без кавычек; было сломано и до П-2а).
- TOCTOU `canonicalize` → открытие — граница контракта: хост — среда кооперативного агента, не песочница против враждебного параллельного процесса.
- Replay на другой конфигурации точек не поддерживается; явного отказа в коде нет — формальный зазор, вынести отдельным решением.

## Приёмка (AC-8)

- Позитивы двух точек: чтение, запись, список, замок, старт процесса (`dir` в одной точке, `log_path` в другой).
- Негативы: абсолютный путь; `..`; `a/../../x`; неизвестная, пустая и невалидная точка; cross-mount move; Windows-формы; голый путь в multi-root; symlink-уход и висячая ссылка; смена регистра канонического пути на Windows.
- Две точки с одинаковым относительным путём — разные acting-идентичности.
- Паритет N=1 байт-в-байт (единственное исправленное исключение — symlink-уход наружу), 595 машин зелёные.
- Саботаж: снятая граница `..` краснит пробу, откат чист, живое дерево не тронуто.
- Приёмка — чужая сессия по кандидату с полным SHA.
