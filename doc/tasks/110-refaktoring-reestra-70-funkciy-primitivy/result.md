причина нераскладываемости у каждого из 71 предметного инструмента. Страж
универсальности задачи 103 (`check_host_universality.py`, его пробы

## Сделано

1. Прочитано: `alula-machines/registry.md` (71 строка в таблице «## Primitives»),
   машины `task_runner` и `session_start` (разделы «## Внешние функции»),
   правило 14б `state-machines/state-machine-spec.md`, страж задачи 103,
   загрузчик реестра пакета alula (`src/machine/host.nv`).
2. Подтверждено, почему причины — отдельной таблицей: `parse_registry_table`
   читает строку примитива ровно из шести ячеек («a primitive is
   `name | parameters | result | class | reads | writes`, six cells»), седьмой
   столбец в «Primitives» отвергается; таблица с первой ячейкой заголовка `tool`
   загрузчиком игнорируется, поэтому раздел «## Reasons» загрузку не ломает.
3. Для каждой из 71 функции записана причина: что теряется при разложении на
   универсальные примитивы среды исполнения. Причины сгруппированы по семействам:
   доверенные решения маршрута и ворот (проверка происхождения теряется),
   журнал и служебные записи (писать журнал может только хозяин), управление
   процессами запуска, разбор артефактов (формат знает хозяин), предметные
   документы и хранилища (пути и правила недоступны машине). Ни одна причина
   не называет других инструментов реестра словом целиком — такая декларация
   признала бы разложение (уточнение критерия стража).
4. Страж 103: добавлен разбор таблицы «## Reasons» (`parse_reasons`), причина
   ищется сначала в столбце `reason` таблицы «Primitives», затем в таблице
   «## Reasons»; документация стража обновлена.
5. Пробы стража: сбор — 71 строка (было 70: счёт в шапке реестра уже был
   исправлен задачей 108); добавлена проба «причина из отдельной таблицы зелёная»
   и проба «причина «—» в таблице «## Reasons» — причины нет»; характеризационная
   проба задачи 103 (действующий реестр красный) перевёрнута: действующий реестр
   теперь зелёный, 71 с причиной, 0 без.
6. Машины task_runner и session_start: объявления «## Внешние функции» сверены
   с реестром 1:1 (43 и 7 инструментов, совпадение имён и сигнатур; загрузчик
   это же проверяет при прогоне тестов). Правка объявлений не потребовалась.
7. Строка реестра норм `completeness-check.md` (раздел 7, норма «Универсальность
   инструментов») обновлена: действующий реестр приведён к норме этой задачей.

## Честная оговорка (по требованию интегратора)

Реальной раскладки на универсальные примитивы НЕ произошло. Все 71 функция
остались предметными и получили записанную причину нераскладываемости, что
формально удовлетворяет правило 14б («предметный инструмент допустим, только
если не раскладывается на примитивы без потери смысла, с названной причиной»),
но не достигает цели тонкого хозяина: хозяин по-прежнему знает о машинах
(71 предметный инструмент), страж теперь проверяет наличие причин, а не
универсальность. Два обстоятельства: ни один инструмент не раскладывается без
потери смысла в действующем контракте (проверки доверия, процессы, журнал,
разбор артефактов — знание хозяина; тесты скриптуют ответы хозяина по именам
инструментов, разложение потребовало бы переписать сотни фикстур и логику
машин); расширение закрытого списка универсальных примитивов стража — решение
методики, не стража. Формальное выполнение правила не выдаётся за рефакторинг:
вопрос, достаточно ли это для цели тонкого хозяина, решает владелец.
