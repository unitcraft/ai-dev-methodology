# Спецификация ScriptedHost: тонкий хозяин, стадия 1 (17 примитивов)

Тестовый исполнитель примитивов хозяина (`ScriptedHost`). Боевого хозяина на
стадии 1 нет: машины новые примитивы не зовут (запуск — стадии 2–6), поэтому
исполнитель живёт в папке задачи как эталон контракта: по нему стадия 2 сверит
боевую реализацию, а движок — свой тестовый хост.

## Общие правила (все 17 примитивов)

1. **Дерево хозяина.** Каждый путь (файл, папка, замок, лог, журнал) разрешается
   внутри дерева хозяина. Путь вне дерева — сбой шага (`StepFailure`), никаких
   частичных эффектов до проверки.
2. **Недоступность — сбой шага.** Нет scripted-ответа у скриптуемого примитива,
   нет файла у читающего, чужой токен у замка — всё это `StepFailure`, а не
   значение-заглушка в данных машины.
3. **Никто не знает о раннере.** Ни один примитив не принимает имена документов,
   ворот, номеров задач; входы — пути, тексты, pid, токены.
4. **Классы.** Как в реестре (`alula-machines/registry.md`): читающие —
   `volatile`, пишущие — `acting`, `sha256` — `pure`.

## Состав и поведение

### Файловая система (6)

| примитив | поведение ScriptedHost |
|---|---|
| `read_file` | читает текст файла в дереве; нет файла — `StepFailure` |
| `write_file` | пишет текст (создавая родителей); путь вне дерева — `StepFailure` |
| `move_file` | перемещает; источника нет — `StepFailure` |
| `delete_file` | удаляет; файла нет — `StepFailure` |
| `file_exists` | `true`/`false` без сбоя при отсутствии |
| `list_dir` | имена элементов папки; папки нет — `StepFailure` |

### Процессы (4)

Сценарные: ответы скриптуются по ключу вызова, ключ не задан — `StepFailure`.

| примитив | поведение |
|---|---|
| `start_process` | scripted pid (`int>=1`); запись лога — за сценарием |
| `stop_process` | гасит scripted pid; повторный вызов — no-op (идемпотентно); неизвестный pid — `StepFailure` |
| `process_running` | scripted `true`/`false` |
| `run_command` | scripted `{code: int, stdout: text}` (`ExecResult`) |

### Замки (2)

| примитив | поведение |
|---|---|
| `acquire_lock` | атомарное создание файла замка (O_EXCL): свободен — `true` и запись токена; занят чужим токеном — `false`; повтор со своим токеном — `true` |
| `release_lock` | снимает замок только по своему токену; чужой токен — `StepFailure`; замка нет — no-op |

Действующий без параметров `release_lock` раннера в реестре остаётся; замена его
на версию с токеном — стадия 4 (шапка реестра).

### Разбор и хеш (2)

| примитив | поведение |
|---|---|
| `parse_agent` | scripted текст ответа дешёвого агента; ответ обязан быть JSON-текстом, иначе `StepFailure` (механическая валидация; не для доверенных решений — они у примитивов ядра) |
| `sha256` | реально считается: 64 hex символа, стандартная библиотека ОС (в эталоне — `hashlib` стандартной библиотеки Python: проверенная реализация, поверх системной криптобиблиотеки ОС); класс `pure` |

### Доверенное ядро (3)

| примитив | поведение |
|---|---|
| `issue_token` | scripted токен открытия, идемпотентно по паре «папка, область»: повтор с теми же аргументами возвращает тот же токен, а не второе открытие |
| `verify_token` | scripted запись открытия (`Opening`: автор, дата, источник, содержимое) либо отсутствие; чтение не погашает открытие |
| `journal_write` | дописывает событие `JournalEvent` (код + пары параметров) в журнал хозяина; пустой код или параметр не-пара — `StepFailure` |

## Связь с реестром

Имена и сигнатуры — раздел «## Primitives» `alula-machines/registry.md`
(последние 16 строк — каркас; `release_lock` с токеном войдёт на стадии 4,
считая 17-й примитив). Тест `test_scripted_host.py` сверяет эталон с реестром:
каждый из 17 примитивов есть в реестре, сигнатуры совпадают.
