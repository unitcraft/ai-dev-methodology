# Алула (`Alula`): спецификация языка записи стейт-машины таблицами, версия 2.16

Английская версия: [state-machine-alula-spec.en.md](state-machine-alula-spec.en.md) (перевод; нормативен русский текст).

Имя языка записи — **«Алула»** (`Alula`; слово владельца, 2026-10-21: «Alula - ОК»). Читается «Алу́ла», ударение на «у»; женского рода, склоняется как «Луна»: Алулы, Алуле, Алулу, Алулой, на Алуле. Алула — звезда в лапе Большой Медведицы (имя в каталоге IAU), от арабского *al-qafza al-ūlā*, «первый прыжок» (звёзды «трёх прыжков газели»: Alula, Tania, Talitha); прыжок — переход машины из состояния в состояние. Второе, независимое значение — английское *alula*, «крылышко» (лат. *ala*, «крыло», и уменьшительный суффикс *-ula*): пучок перьев на первом пальце птичьего крыла, которым птица управляет полётом на малой скорости. Файл машины — «таблица машины» на Алуле. Занятость имени проверена 2026-10-21: знаков ALULA на языки и средства разработки не найдено (знаки ALULA в классах 9/42 — у нескольких узких компаний: охранные системы, страхование, онкология; в России в классах 9/42 их нет, TMview); пространства имён `alula-lang` (GitHub, домены, пакеты) свободны; ручная проверка реестра Роспатента — открытый пункт. Прежнее имя языка (версии 2.7–2.13) и почему от него отказались — в истории [doc/alula-history.md](../doc/alula-history.md), раздел 10; там же причины, цели и история языка.

Версия формата: 2.16, 2026-10-22. Статус: **опытный формат; версия 2.2 реализована интерпретатором на другом языке; равенство с автоматом по журналу подтверждено на 39 сценариях одной небольшой машины (машина чата); выразимость «Шага агента» и «Совещания» проверена пилотами; не реализовано: вложенные машины, `Правит`, профиль стороны, `Предел запросов`, `Возвратов формы`, `передать`.** Правила записи машин — [state-machine-spec.md](state-machine-spec.md); этот файл задаёт формальную запись тех же таблиц: типы, выражения, действия, стороны, фрагменты. Журнал — [state-machine-journal.md](state-machine-journal.md); словарь английских имён — [state-machine-glossary.md](state-machine-glossary.md) (словарь автоматических JSON-имён, раздел 1а). При расхождении с правилами спецификации верна спецификация, а этот файл правится вслед за ней.

Цель: машина описывается одним файлом без кода на Нова; исполнитель по описанию даёт то же поведение, что автомат на Нове: те же переходы, тот же структурный журнал, те же данные и очередь. Проверено выразимостью строк автоматов (какие строки записываются без обходов) и прогоном одной небольшой машины интерпретатором (сравнение с автоматом по журналу, шапка).

Примеры взяты из пилотов (выписки «Шага агента» и «Совещания»); под каждым сказано, что изменено против записи пилота. Конструкция, использованная в примере, определена в разделах 2–5, 7–9 или в каталоге (раздел 12). Метки в скобках текста — номера правок: прежних версий (А, АМ, E, T, С, ША, ШМ, ШВ, СГ, ИС) версии 2.3 (Н-…), версии 2.4 (И-…), версии 2.5 (Т-…), версии 2.6 (С-1), версии 2.7 (П-1…П-9), версии 2.8 (Я-1…Я-4), версии 2.9 (Я-5…Я-18) версии 2.10 (Я-19…Я-21), версии 2.11 (Я-22), версии 2.12 (Я-23…Я-37), версии 2.13 (Я-38…Я-49), версии 2.14 (Я-50), версии 2.15 (Я-51…Я-55) и версии 2.16 (Я-56…Я-62, раздел 0). Примеры — выдержки: раздел `## Имена` (1а) в них не показан, кроме примера в разделе 1а; где имя примера получило бы в файле машины не автоматическое JSON-имя, строка `## Имена` названа под примером (образцы несут раздел целиком).

Ключевые слова этого раздела (заголовки разделов, имена столбцов, строки-ключи, виды сторон) — слова русской формы; в английской форме файла их пишут по [таблице слов](alula-keywords.tsv), правила — раздел 1а.

**Расширение.** Файл машины на Алуле называется `*.alula.md` (имя машины — латинское, как в `- machine:`; например `agent_step.alula.md`); прежние имена `*.table.md` и `*.table.txt` не употребляются, переходного периода нет (слово владельца, 2026-10-19: «нету переходного периода»; версия 2.11, Я-22). Расширение разбор не проверяет: проверку расширения выполняет только скрипт проверки форматирования (Я-18). Файл определений и файл фрагмента — тоже `*.alula.md` с шапкой своего вида. **Скомпилированное дерево** (JSON `machine/2`, раздел 6) называется `<имя>.alula.json` (Я-19): `agent_step.alula.md` ↔ `agent_step.alula.json`; это не отдельный формат, а исполняемая форма самого языка — рукописное дерево тоже Алула, записанная в JSON-виде; `format: "machine/2"` внутри дерева не меняется. Прежнее `*.machine.json` не употребляется, переходного периода нет (Я-22). Версию машины (`- machine_version:`) задаёт автор файла; рекомендуется строка вида `alula-<версия формата>` (например `alula-2.16`) — она отвечает на вопрос «на каком языке и какой версии записана машина»; вызывающий сверяет её только на равенство с записью реестра (протокол вызова, раздел B, пункт 6).

**Таблицы** (П-6). Строка-разделитель под заголовком таблицы (`|---|---|`, `|:---|---:|`) — строка из знаков `-`, `:`, пробелов и `|`; разбор её пропускает. Знак `|` внутри ячейки пишется `\|` (набор литералов `"a" \| "b"`, лямбда с `|`); разбор снимает экранирование. В примерах формата разделитель опущен.

**`## Параметры`: передача значений извне** (П-9). Исполнитель принимает переопределения параметров таблицей «ключ → значение»: ключ — `проект.<ключ>` из столбца «переопределение проектом»; значение проверяется по типу параметра (полный словарь — по правилам раздела 2), ключ, которого нет в столбце, — отказ загрузки. Это механизм передачи; откуда исполнитель берёт таблицу (настройки проекта, `params` сценария, раздел 11), формат не задаёт. Ключи `проект.<ключ>` называет продукт, они не часть языка; столбец «переопределение проектом» образца остаётся `—`, потому что источник ключей не называет. Значение по умолчанию, зависящее от внешнего ключа, действует только при наличии ключа в таблице переопределений, иначе работает значение по умолчанию (Я-11).

**`## Вход`.** Тип входа — запись из полей этого раздела (правило 35, пункт 1); `начальное: вход.<поле>` берёт значение из входа. Необязательное поле (тип `?T`), которого во входе нет, равно `пусто` (Я-48). Инвариант проверяет исполнитель при приёме запроса; нарушение — отказ вызова (И-1): исполнитель пишет событие журнала `input_rejected` и завершает вызов отказом `NoResult` с текстом `input rejected: <reason>`; состояние машины не меняется. Тот же отказ — при разборе входа. Параметры события (журнал, подраздел «События формата таблиц»): `reason` — закрытый перечень `json` (вход не JSON), `missing` (нет обязательного поля входа; у необязательного отказа нет, Я-48), `type` (поле другого типа, вне границы типа, вне набора литералов или не `ид` формата UUID, например `число>=0` при −1), `invariant` (нарушен инвариант входа); `field` — имя поля входа (для `missing` и `type`); `index` — номер инварианта с нуля (для `invariant`). `field` и `index` необязательные: при `json` их нет, и шаблон их пропускает. Примеры: `input_rejected(reason=json)`, `input_rejected(reason=missing; field=label)`, `input_rejected(reason=type; field=start)`, `input_rejected(reason=invariant; index=0)`. Идентификатор запроса вызова (`запрос_вызова`) в входе не лежит: его даёт исполнитель (раздел 9).

**Вход вызываемой машины и `вход Тип` вызывающей** (Я-30). Сторона `machine <имя>(вход Тип, …)` называет тип записи, поля которой — ровно поля `## Вход` вызываемой машины: те же имена и типы, порядок не значим; поля запроса — поля этого типа, кроме `профиль` (4.2). Поэтому вход, который вызывающие передают полями (`вид`, `сессия`, `контекст`, …), вызываемая объявляет теми же полями, а не одним полем-записью; запись целиком, если она нужна в данных, собирает `начальное` конструктором записи (`ЗапросАгента { вид: вход.вид, … }`, образец «Шага агента»). Типы полей сравниваются по совместимости раздела 2: `число` и `число>=n` совместимы в обе стороны (Я-47) — поле `число` у вызывающей и `число>=0` у вызываемой (или наоборот) — одно поле, границу проверяет вызываемая при приёме входа (`input_rejected`, `reason=type`). Сверка типов двух файлов — продукт (раздел 14).

**`## Стороны`.** Таблица `| имя | идентификатор | вид | профиль | сигналы | счётчик |`.

| Вид | Что это |
|---|---|
| `agent(итог Тип)` | агент; `итог` — тип результата стороны (ША2) |
| `human(итог ИсходВорот)` | человек: на воротах (со счётчиком) или со свободным вводом (`—` в столбце `счётчик`, Я-52) |
| `enhanced(итог ИсходВорот)` | усиленный вратарь |
| `human или agent по настройке <имя>(итог ИсходВорот)` | вратарь: человек, агент — по настройке проекта (правило 19); `<имя>` — ключ настройки проекта, он выходит из машины: его JSON-имя строится по 1а (Я-53), а где оно неверно, задаётся строкой `## Имена` (`| исполнитель_повышенного_внимания | elevated_attention_executor |`: транслитерация дала бы `ispolnitel_povyshennogo_vnimaniya`; Я-60); английская запись — `human or agent by setting <имя>(result GateOutcome)`; в дереве JSON этот вид называется `gatekeeper` (Я-4) |
| `machine <имя>(вход Тип, итог Тип)[; разбор: <примитив>[("<роль>")] -> Тип]` | вложенная машина (правило 35): имя из реестра вызывающего (правило 35, [протокол вызова](state-machine-call-protocol.md), раздел J, пункт 6), тип входа запроса, тип результата ответа; необязательный разбор результата (см. ниже) |

- `идентификатор` — латинское слово стороны (А6): у сторон машин методики — значение «сторона запроса» словаря ([state-machine-glossary.md](state-machine-glossary.md), раздел 2.14: `agent`, `gatekeeper`, `enhanced`, `witness`, `author`, `session_launch`, `review`, `meeting`, `agent_step`), сторона, которой там нет, берёт своё латинское слово (пример стороны со свободным вводом ниже — `human`); входит в конверт запроса и ответа и в идентификатор запроса (`<идентификатор>-<номер>`), поэтому попадает в журнал. У стороны с набором (4.2) — `—`: идентификатором служит элемент набора. Идентификаторы сторон машины различны.
- **`итог`** (ША2) — тип результата стороны: у `agent` и `machine` — тип из `## Типы`; у `human`, `enhanced` и вратаря — встроенный `ИсходВорот`, вариантами которого служат сигналы столбца «сигналы» (сигнал без данных — вариант без полей, `сигнал(поле тип)` — вариант с полями; правило 19), событие `сигнал(…)` стороны — вариант `ИсходВорот`. `ответ: Вариант` разрешается по `итог` стороны (у `machine` с `разбор` — по результату разбора); допустима квалифицированная форма `ответ: ИтогХода.Закончен(…)`, тип в ней — тип результата стороны; неквалифицированное имя варианта ищется только в этом типе.
- `профиль` — выражение либо `—`; **единственный источник профиля**: поле запроса `профиль` исполнитель берёт отсюда, строка `профиль` в «Запросе» — ошибка проверки (T3). Столбец читает данные машины, константы, параметры, `вход` и (у набора) `сторона`; допустим `вызвать` reading (раздел 7), его скрытые чтения — данные машины; имена `Запрос` состояния столбец не читает: таблица «Сторон» одна на машину, правило 11 к ней не применяется (ША4). Если профиль лежит внутри запроса (у стороны `агент` — `запрос_агента.профиль`), отдельного поля у стороны нет и пишется `—`.
- `счётчик` (СГ1, правило 15) — **обязателен у каждой стороны, кроме стороны со свободным вводом** (Я-52): данное, где лежит счётчик попыток стороны, — имя данного (`попытка_агента`) либо, у стороны с набором, путь поля записи элемента (`линзы[*].попытка`). Данное — `число>=0`, начальное `0`, `не убывает: да`, `пишет: механика`; у пути поля начальное `0` задаёт строка данного с записью элемента (`попытка: 0` в `линзы`, раздел 2), а у пути в таблице «Данных» `начальное` — `—` (Н-5); номер попытки запроса равен значению счётчика после увеличения (механика, до отправки; у ворот человека — до показа ворот, правило 19), идентификатор запроса — `<идентификатор>-<номер>` (у набора — `<элемент набора>-<номер>`). Проверка раздела 10 сверяет данное.
- **Сторона со свободным вводом** (Я-51, Я-52; правило 19) — сторона вида `human` со `—` в столбце `счётчик` (`—` — знак «нет значения», 1б): ворот у неё нет, её сигнал — слово свободного ввода: идентификатора ворот не несёт, принимается по имени сигнала строкой текущего состояния и ведёт переход; записи ворот нет, счётчика нет; вратарь-агент ей не отвечает, поэтому `—` допустим только у вида `human`. Сторона `human` со счётчиком — ворота (правило 19). Пример: `| собеседник | human | human(итог ИсходВорот) | — | сообщение(содержание текст, автор текст, источник текст) | — |`.
- `сигналы` (Я-38) — у видов `human`, `enhanced`, вратаря: **сигналы стороны** — то, что сторона говорит машине на воротах: сигнал или `сигнал(поле тип, …)` — сигнал с данными; сигналы пишутся как в таблицах машины (в том числе из нескольких слов: `остановить совещание`); JSON-имя сигнала и его полей строится по 1а (Я-53), а где оно неверно, задаётся строкой `## Имена` (Я-60): у `засчитан(находки []Находка)` словарь даёт сигналу `counted`, полю `находки` — `findings`, строк не нужно; поле сигнала объявляется через пробел, а в строке перехода привязывается `сигнал(засчитан(находки: новые))` (3.1, Я-8). Объявление и называет, какая сторона может подать сигнал: это **все сигналы стороны**; сигналы состояния — сигналы его строк (4.3). Сигнал стороны — событие стороны из её объявленного набора (у `human`, `enhanced` и вратаря — вариант `ИсходВорот`); он относится к открытому запросу этой стороны, а когда отвечает человек — к её открытым воротам и несёт их идентификатор, так, как говорят правила 15–19 спецификации (счётчик попыток, приём ответа, слова человека); идентификатор ворот `<идентификатор>-<номер>` называет сторону, и сигнал сверяется с сигналами этой стороны: не объявленный ею или пришедший от другой стороны отбрасывается («слово чужой стороны», правила 17, 19); сигнал стороны со свободным вводом идентификатора ворот не несёт и принимается по имени в текущем состоянии (Я-51, правило 19). От сигнала машины (общие события, раздел 9) он отличается объявлением у стороны и тем, кто может его подать. У остальных видов — `—`.
- **`разбор`** (E1, СГ13) — только у вида `machine`: reading-примитив (раздел 7) с параметром типа `итог`, необязательным вторым параметром — текстовым литералом роли (`разобрать_ответ_агента("author")`: один примитив хозяина обслуживает несколько ролей) и результатом указанного типа; у примитива с результатом `по роли {…}` (раздел 7) указанный тип обязан совпасть с типом реестра для этого литерала (Н-12). Исполнитель вызывает его при приёме ответа (правило 14), после проверки «Правит» (4.2) и до «При приёме», и **значением ответа** для `ответ(имя)`, `ответ: Вариант(…)` и «При приёме» становится результат разбора; без `разбор` — сам `итог`. Событие `ответ: Вариант` требует, чтобы значение ответа было вариантом. Скрытые чтения примитива (`читает`) входят в чтения состояния (`Запрос`, правило 11); разбор вызывается один раз за ответ, результат хранится с принятым событием. Разбор по роли — тот же примитив реестра с другим литералом роли (результат `по роли` — раздел 7).
- **Сбой разбора** (Я-33). Разбор либо даёт значение указанного типа, либо отказывает: ответ не по форме (артефакт не читается, нет выдержек, сверка не сошлась); замечания отказа — служебная запись, которую читает возврат стороны. Отказ разбора — ответ не по форме (правило 18): событие не возникает, «При приёме» не выполняется, в `принятые_запросы` ответ не пишется; пока возвратов меньше «Возвратов формы» (4.2), исполнитель возвращает ответ стороне (у `machine` — новым запросом той же стороны с замечанием); после исчерпания, а при `Возвратов формы: 0` сразу, запрос закрывается событием `сбой` с кодом `КодСбоя.ФормаНеИсправлена` (код вне списка состояния исполнитель приводит к `НетРезультата`, 4.3). Возврат и его запись в журнал — механика исполнителя (коды журнала продукта — раздел 5). Значение не того типа, что назван после `->` (у результата `по роли` — не типа роли), — дефект хозяина, то есть дефект программы (3.3), а не ответ не по форме.
- Под таблицей — элемент списка `- Предел запросов: <выражение типа число>=1>` (одна на машину, правило 21; не написана — 1).

## 1а. Язык файла и ключевые слова

Язык Алулы двуязычный (Я-1): файл `*.alula.md` пишется либо по-русски, либо по-английски. Русская форма — основная; все примеры спецификации записаны в ней. Английская форма — те же конструкции с английскими ключевыми словами; английская спецификация и английский образец машины — отдельные работы, на этот раздел они не влияют.

**Ключевые слова** — слова, которые определяет спецификация: заголовки разделов и шапки, строки-ключи, заголовки столбцов таблиц, виды состояний, слова событий и «куда», слова выражений, действия, функции каталога, литералы `истина`/`ложь`/`пусто`, виды сторон-слов, значения `пишет` и `читает`. Они пишутся **целиком на одном языке — языке файла**. Смешивать нельзя: файл с русскими заголовками и английским действием `journal(…)` — ошибка.

**Языков два, объявляется строкой шапки:** `- language: ru` или `- language: en`. Строка необязательна, по умолчанию `ru`. Правила разбора:

- проверка не гадает и не переключается молча: язык берётся только из строки `language` либо по умолчанию;
- файл с английской шапкой (`# Machine:`, `# Definitions:`, `# Fragment:`) без `- language: en` — ошибка проверки («язык шапки английский, а language не объявлен»); так же для русской шапки при `- language: en`;
- ключевое слово не из языка файла — ошибка проверки с номером строки первого постороннего слова.

**Свободно, на любом языке и вперемешку** (это не ключевые слова; вперемешку — по словам, а не внутри слова, Я-59): имена, которые придумывает автор — данные, состояния, определения, типы, поля, сигналы сторон, параметры фрагментов и их значения; проза-комментарии вне таблиц (4.1); значения-строки внутри данных и коды событий журнала (латиницей по конвенции, правило 34(б)); имена примитивов хозяина из реестра (как записаны там); идентификаторы сторон (`agent`, `human` и т. п.). Ключи шапки (`machine`, `machine_version`, `format`, `definitions_version`, `fragment`, `language`) и классы примитивов (`pure`, `reading`, `writing`, `irreversible`) латинские в обоих языках.

**JSON.** Дерево `machine/2` (раздел 6) от языка файла не зависит: ключевые слова обоих языков отвечают одним ключам и значениям, имена входят в дерево JSON-именами (ниже), значения-строки (тексты отказов, сообщения, текстовые литералы) — как их написал автор (Я-10). Поэтому файлы двух языков с одними JSON-именами и значениями-строками дают одно дерево с точностью до внутренних имён (ниже). Сверка образцов ([check-alula-samples.py](check-alula-samples.py)) сравнивает JSON-имена объявлений (у русского образца — автоматические и из `## Имена`, Я-53, Я-60) и не сравнивает значения-строки.

**JSON-имя** (Я-46, Я-53, Я-60) — одно правило и одно место. JSON-имя — имя в дереве `machine/2`, в журнале, в `все_данные` и на проводе. Оно есть у имени, которое объявляет автор и которое выходит из машины: состояние (поле `state` журнала, параметр `fork`, `текст(Состояние)`), данное (`все_данные`, `machine_data`), поле входа, тип, поле записи и варианта, вариант, элемент перечисления (провод, `все_данные`), сигнал стороны и его поле (провод, сценарий), примитив (JSON-имя — имя реестра хозяина), имя настройки вратаря (ключ настройки проекта). JSON-имя — строка раздела `## Имена` (ниже), а у имени без строки оно **строится автоматически** (Я-53):

1. латинское имя (`[A-Za-z_][A-Za-z0-9_]*`) — само имя;
2. иначе, если словарь (ниже) называет всё имя, — английское имя словаря (`число_повторов` → `retry_count`, `ПОВТОР` → `Retry`, `Токены` → `TokenUsage`);
3. иначе — транслитерация имени по таблице ниже с правилом регистра (`оставить правку` → `ostavit_pravku`); каждое слово транслитерируется отдельно, латинское слово остаётся (`запрос_Agent` → `ZaprosAgent` у имени-типа, Я-59).

**Раздел `## Имена`** (Я-60) — **единственный способ** задать JSON-имя, отличное от автоматического. Таблица `| имя | JSON-имя |` (английская — `| name | json_name |`): в первом столбце — имя, объявленное в этом файле (на любом языке, в том числе латинское), во втором — латинское JSON-имя `[A-Za-z_][A-Za-z0-9_]*`. Строка задаёт JSON-имя каждому объявлению с этим именем в файле; если одно имя объявлено в нескольких местах и JSON-имя нужно не всем, первый столбец — **уточнённое имя**: путь объявленных имён через точку от пространства верхнего уровня — `Тип.поле`, `Тип.Вариант`, `Тип.Вариант.поле`, `Тип.Элемент`, `сторона.сигнал`, `сторона.сигнал.поле`; строка с уточнённым именем сильнее строки с простым. Имя без строки получает автоматическое JSON-имя. В таблице — **только** имена, чьё автоматическое имя неверно. Ошибки проверки (раздел 10): строка, которая ничего не меняет (её JSON-имя равно имени, которое объявление получает без неё), — «лишняя строка»; строка для имени или пути, которого среди объявлений этого файла, выходящих из машины, нет (внутреннее имя, читаемое имя, опечатка), — «имя не объявлено»; имя, повторённое в первом столбце; нелатинское JSON-имя; совпадение JSON-имён в одном пространстве (ниже). Автоматическое имя, которое не вышло латинским (знак вне таблицы транслитерации), — тоже ошибка: такому имени нужна строка. **Скобок после имён в объявлениях нет** (`### ОТКРЫТИЕ — операция`, `| расход | ?РасходТранспорта | …`, `тип Утверждение { … }`): способ записи один; скобки `имя (X)` версий 2.9–2.15 — ошибка проверки. Раздел пишут файл машины и файл определений — после `## Типы`, файл фрагмента — после `## Данные` (у него нет `## Типы`); каждый файл — для своих объявлений: JSON-имена подключённого файла определяет он сам. Нет строк — раздела нет. В `## Имена` не пишутся путь поля `имя[*].поле` (он составлен из объявленных имён); ключевые и читаемые имена, в том числе данные контракта и фрагмента «Пауза» (`остановка`, `к_отправке`, `открытые_запросы`, `предыдущее`, `запрос_вызова`) и привязка `причина`, — их JSON-имя — слово `en` таблицы слов (Я-49); **внутренние имена**, которые из машины не выходят, — константы, параметры (их внешнее имя — `проект.<ключ>`), определения и их параметры, имена сторон (их внешнее имя — `идентификатор`), привязки событий и `пусть`, параметры лямбд, переменная `для каждого` — входят в дерево как написаны. Других способов задать JSON-имя нет.

Пример (образец «Совещания»; `Вопрос` — вариант и у `ИтогПравки`, и у `КонтекстРоли`, поэтому имя уточнено; `расход` — образец «Шага агента»: строка без уточнения задаёт имя данному и полю пяти вариантов).

```
## Имена

| имя | JSON-имя |
| Утверждение | Claim |
| ИтогПравки.Вопрос | Asked |
| КонтекстРоли.Вопрос | QuestionContext |
| КонтекстРоли.Свидетель.находки | lens_findings |
| оставить правку | keep_edit |
| расход | transport_usage |
```

**Пространства различимости** (Я-58). JSON-имена внутри одного пространства различны; совпадение — ошибка проверки, а одно JSON-имя в разных пространствах допустимо. Пространства: (1) состояния машины — вместе с состояниями подключённых фрагментов после подстановки (имена фрагмента входят в пространство состояний машины); (2) данные машины (вместе с данными фрагментов); (3) поля входа; (4) типы верхнего уровня — записи, перечисления и варианты вместе; (5) поля одной записи или одного варианта; (6) варианты одного типа; (7) элементы одного перечисления; (8) сигналы одной стороны и, отдельно, поля одного сигнала; общие события машины (сигналы машины) — отдельное пространство; (9) примитивы реестра машины; (10) параметры, константы и имена настроек вратаря; определения — каждое имя в своём пространстве. Коды журнала (`журнал(код)`) и номера общих событий в эти пространства не входят.

**Смешанные имена** (Я-59). Слово имени — часть между `_` и пробелами — пишется буквами одной письменности: только кириллица или только латиница; цифры допустимы в любом слове (`В3`, `v2`). Слово, где смешаны кириллица и латиница (`ЗапросAgent`, `ХодV2`), — ошибка проверки: у такого слова нет однозначной границы для транслитерации и регистра. Смешивать можно только между словами, через `_` или пробел (`запрос_Agent`, `ход_v2`): каждое слово транслитерируется отдельно, латинское слово остаётся как есть (шаг 3).

**Словарь для имён** (Я-53, Я-61, Я-62) — словарь английских имён методики [state-machine-glossary.md](state-machine-glossary.md) (версия 11). Нормативна для имён только его часть «русское имя → английское имя»: строки таблиц разделов 2.1–2.9, 2.11, 2.12 и 2.16 (первый столбец — русское имя, второй — английское, оба в обратных кавычках) и записи `` `русское` → `английское` `` раздела 2.10. Поиск — по всему имени, точным совпадением строки (с регистром, подчёркиваниями и пробелами). **Осторожно:** поиск идёт по всему имени независимо от вида имени, поэтому автоматическое имя латинское, но может оказаться не тем, что задумано (тип `Утверждение` даёт `Approval`, состояние `ИТОГ` — `Totals`, поле `ошибка` — `failure_error`); у машины с английским близнецом расхождение находит сверка образцов, в остальных случаях автор проверяет имя сам и при необходимости пишет строку `## Имена`. Не входят: строковые литералы (2.14), контекстные исключения (2.15), соглашения, заметки и история; имя, которому эти таблицы дают два разных английских имени (одно — `расход`: `usage` и `transport_usage`), записи не имеет: его JSON-имя строится транслитерацией, а нужное пишется в `## Имена`.

**Хеш словаря** (Я-62). Нормативная часть словаря закреплена хешем, а не номером версии. Текст для хеша: пары нормативной части в порядке файла (строки таблиц разделов 2.1–2.9, 2.11, 2.12, 2.16 — по первым двум столбцам; записи раздела 2.10 — по порядку в строке), каждая — строка `русское → английское` (русское имя, пробел, знак `→`, пробел, английское имя, без обратных кавычек), строки соединены LF (`\n`), после последней LF нет, кодировка UTF-8; хеш — первые 12 знаков SHA-256 этого текста, строчными. Формат 2.16 закрепляет **хеш словаря `60383c370415`**. Проверка ([check-alula-keywords.py](check-alula-keywords.py)) пересчитывает хеш из файла словаря; другой хеш — ошибка «словарь изменён без смены формата»: новая или изменённая пара меняет автоматические имена, и одна и та же машина дала бы другое дерево. Версия формата и хеш меняются только вместе; правка вне нормативной части (литералы 2.14, исключения 2.15, столбцы «Где», «Источник», «Заметка», соглашения, история) хеш не меняет и нового формата не требует. Номер версии в шапке словаря — для людей. Переводчику «Алула → JSON» нужна копия нормативной части с тем же хешем.

**Транслитерация** (Я-53, Я-59): буква кириллицы (строчная или заглавная) заменяется латиницей по таблице; латинские буквы, цифры, `_` и пробел остаются, регистр — по правилу ниже; слово, где смешаны кириллица и латиница, — ошибка (выше).

| Буква | Латиница | Буква | Латиница | Буква | Латиница |
|---|---|---|---|---|---|
| а | a | б | b | в | v |
| г | g | д | d | е | e |
| ё | e | ж | zh | з | z |
| и | i | й | y | к | k |
| л | l | м | m | н | n |
| о | o | п | p | р | r |
| с | s | т | t | у | u |
| ф | f | х | kh | ц | ts |
| ч | ch | ш | sh | щ | shch |
| ъ | — (опускается) | ы | y | ь | — (опускается) |
| э | e | ю | yu | я | ya |

**Регистр** транслитерации (шаг 3, Я-53). Слова имени разделены `_` или пробелом; `_` и пробелы в начале, в конце и подряд пустых слов не дают и в имя не переходят (`_ход__агента` → `khod_agenta`). **Имена-типы** — состояние, тип, вариант, элемент перечисления — пишутся слитно, каждое слово с заглавной буквы (`PascalCase`): в слове, написанном без строчных букв (`ХОД`, `В3`), все буквы, кроме первой, сначала становятся строчными; заглавная буква кириллицы даёт латиницу с заглавной первой буквой (`Ж` → `Zh`, `Щ` → `Shch`); первая буква каждого слова — заглавная: `ХОД_АГЕНТА` → `KhodAgenta`, `ВидВызывающего` → `VidVyzyvayushchego`, `НетОтветаВСрок` → `NetOtvetaVSrok`. **Имена-значения** — данное, поле входа, поле записи и варианта, сигнал стороны и его поле, примитив, имя настройки вратаря — пишутся строчными, слова через `_` (`snake_case`): `оставить правку` → `ostavit_pravku`, `находки_В3` → `nakhodki_v3` (если бы словаря не было). Правило взято из образцов и соглашения 1 словаря: типы и варианты — `PascalCase`, поля, данные и функции — `snake_case`.

**Таблица слов — единый нормативный источник:** [alula-keywords.tsv](alula-keywords.tsv). Строки `kind`, `ru`, `en` (табуляция), первая строка — заголовок; вид слова (`kind`) из закрытого перечня:

| `kind` | Слова |
|---|---|
| `header` | слова шапки: `Машина`, `Определения`, `Фрагмент` и ключи шапки |
| `section` | заголовки разделов `##` (включая `Обязывает`, `Общие события` файла фрагмента) |
| `column` | заголовки столбцов таблиц |
| `kind_state` | виды состояний: обращение, операция, развилка, конец |
| `key` | строки-ключи (`Сторона`, `Запрос`, `Читает`, `Правит`, `проверка`, `набор`, `Кроме` и др.), слова строки подключения (`определения`, `версия`, `хеш`), префикс `проект` |
| `kind_party` | виды сторон и слова их записи (`разбор`, `итог`, `вход`, `human или agent по настройке`) |
| `event` | слова событий (`ответ`, `сбой`, `сразу`, `сигнал`), `причина`, `иначе` |
| `destination` | слова «куда»: `предыдущее`, `возврат_подготовки`, `то же`, суффикс `запуск заново` |
| `decl` | слова объявлений: `тип`, `перечисление`, `вариант`, `определение` |
| `type` | слова типов, встроенные типы, виды параметров фрагмента |
| `expr` | слова выражений, литералы, конструкторы `Ответ`, `Отказ` |
| `operator` | операторы и знаки ASCII: в обоих языках одно написание, `ru` и `en` совпадают (Я-42) |
| `action` | слова действий и их аргументов (в том числе `для каждого`) |
| `readable` | читаемые имена исполнителя, данные контракта и привязка `причина` (Я-49) |
| `enum_value` | значения `пишет` и `читает`, `да` столбца «не убывает», значения параметров `поведение`, значения `Сигнал`, классы примитивов |
| `catalog` | функции каталога (раздел 12) |

Слово, подходящее под два вида, записано двумя строками (`иначе` — в `event`, `expr`, `action`; `конец` — в `kind_state` и `catalog`). В пределах вида слова `ru` не повторяются и слова `en` не повторяются: слово, одинаковое в английской форме для двух русских слов, относится к разным видам. Разбор читает слово по `kind` позиции и языку файла. Проверка таблицы и образца — [check-alula-keywords.py](check-alula-keywords.py) (раздел 10).

**Операторы и знаки — только ASCII** (Я-42). Знаки пишутся одинаково в обоих языках (вид `operator` таблицы слов: `ru` и `en` совпадают); других написаний нет:

| Знак | Где |
|---|---|
| `>=` | сравнение; граница типа `число>=n` (английское `int>=n`) |
| `<=` | сравнение; `да, <= выр` столбца «не убывает» |
| `!=` | сравнение |
| `->` | ветка `выбор`, лямбда, тип результата `-> Тип` |
| `...` | спред `{ ...выр, поле: выр }` |
| `in` | `сбой(причина in {…})`, `остановка in {…}` («когда» концов, `Кроме`) |
| `??`, `_` | значение по умолчанию; ненужный параметр лямбды |

Многоточие `…` в описании грамматики (3.1) и в тексте спецификации — метаобозначение пропуска, а не знак языка.

**Английская запись типов и знаков.** `число`→`int`, `число>=n`→`int>=n`, `дробное`→`float`, `текст`→`text`, `да/нет`→`bool`, `словарь[K, V]`→`map[K, V]` (в JSON словарь — `{K: V}`; синонимов у типов нет, `HashMap[K, V]` не принимается, Я-43), `полный словарь[K, V]`→`full map[K, V]`, `ид`→`id`; `?T`, `[]T`, кортеж `(T1, T2)`, `—` и `№` в обоих языках те же (операторы — выше); значение «ничего» — `none` (литерал `пусто`), тип «ничего» в JSON — `nothing`. Например, `выбор … { альт | альт если выр -> выр; иначе -> выр }` — `match … { alt | alt if expr -> expr; else -> expr }`, `для каждого x в xs: …` — `for each x in xs: …`, `ответ: Вариант(…)` — `response: Variant(…)`, `сбой(причина in {…})` — `failure(reason in {…})`.

## 1б. Канонический вид (рекомендуемый для генераторов)

Генератор «дерево → файл» (обратное преобразование JSON `machine/2` → Алула, Я-21) обязан одному (Я-45): написанный им текст переводится обратно в дерево, равное исходному, — круг «md → JSON → md → JSON» даёт равное дерево. Правила этого раздела — **рекомендуемый** канонический вид такого текста: с ним результат предсказуем, и два генератора пишут один текст; генератор, который пишет иначе, требование не нарушает, если дерево равно. При обратном преобразовании теряются абзацы-комментарии, оформление (выравнивание, переносы строк внутри объявлений) и имена, которых в дереве нет (в дереве лежит одно JSON-имя, автоматическое или из `## Имена`, 1а); смысл не теряется. Файл, написанный человеком иначе (порядок строк-ключей, проза, переносы), остаётся допустимым — разбор его принимает.

- **(а) Шапка.** `# Машина: <Имя>` (английская — `# Machine: <Name>`), где `<Имя>` — латинское имя машины (`machine` дерева); пустая строка; список из четырёх элементов в этом порядке: `- machine: <имя>`, `- machine_version: <строка>`, `- format: <версия формата>`, `- language: <ru|en>`; строка `language` пишется всегда, умолчание не используется. `machine_version` — `version` дерева; `format` — версия формата, в которой записан исходник (`table_format` дерева; нет его — версия формата генератора).
- **(б) Разделы.** Одиннадцать разделов раздела 1 по порядку — `## Типы`, `## Константы`, `## Параметры`, `## Вход`, `## Данные`, `## Стороны`, `## Определения`, `## Подключения`, `## Состояния`, `## Концы`, `## Примитивы` — пишутся всегда и по одному разу; пустой раздел — единственная строка `—` под заголовком; необязательный раздел `## Имена` (1а) стоит после `## Типы` и пишется, только если в нём есть строки; между разделами — одна пустая строка. Строки-ключи разделов — элементами списка: `- Инвариант: <выражение>` (по одному на инвариант) — после таблицы `## Вход`; `- Предел запросов: <выражение>` (если в дереве задан `request_limit`) — после таблицы `## Стороны`; `- Результат: <Тип>` — перед таблицей `## Концы`.
- **(в) Состояния.** Первая строка `## Состояния` — `Начальное состояние: ИМЯ` (английская — `Initial state: NAME`), не элементом списка, затем пустая строка; состояния — в порядке `states` дерева. Строки-ключи состояния — элементами списка, подряд, в порядке: `Сторона`, `Срок тишины`, `Правит`, `Возвратов формы`, `Запрос`, `При приёме`, `Читает`, `При входе`, `Кроме` (английские — `Party`, `Idle term`, `Edits`, `Form returns`, `Request`, `On accept`, `Reads`, `On entry`, `Except`); ключ, которого у состояния нет или чьё значение пустое (`—`, `нет`), не пишется (Я-40); ключ с настоящим значением по умолчанию (`Срок тишины: 0`, `Возвратов формы: 0`) генератор может написать. Элемент с таблицей (`Запрос:` обращения, `При приёме:`) стоит перед своей таблицей, между таблицей и следующим блоком — пустая строка; тело «При входе» из нескольких действий — вложенный список, по действию в элементе (4.1).
- **(г) Таблицы.** Заголовок и строки — один пробел с каждой стороны от `|`, без выравнивания ширины столбцов; строка-разделитель — `|---|` по числу столбцов; пустая ячейка — `—`; `|` внутри ячейки — `\|`. В таблице `Запрос` выражение, равное имени поля, пишется `—` (Я-56). Действия в ячейке — в порядке дерева через `; `. Слова заголовков столбцов — по таблице слов языка файла.
- **(д) Объявления.** Типы и определения пишутся в блоках кода под `## Типы` и `## Определения` (Я-13), в порядке дерева, **одно объявление на строку**: `перечисление Имя = Эл "значение" | Эл`, `тип Имя { поле тип, поле тип }`, `определение имя(параметр тип) -> Тип =` и тело определения на следующей строке с отступом в два пробела (одной строкой). Многострочно пишется только `вариант`: `вариант Имя {`, затем по варианту на строке с отступом в два пробела (`Вар { поле тип, поле тип }`, вариант без полей — именем), затем `}`. Пустая строка — между объявлениями разного вида, вокруг `вариант` и между определениями; перечисления подряд и типы подряд пустой строкой не разделяются.
- **(е) Операторы.** Только ASCII в обоих языках (Я-42): `->` в ветках `выбор`, в лямбдах и перед типом результата; `>=`, `<=`, `!=`, `==` в сравнениях; `...` в спреде; `in` в `сбой(причина in {…})`, «когда» и `Кроме`; `число>=n` (`int>=n`); `да, <= выр` (`yes, <= expr`). Знаки — таблица слов, вид `operator` (1а).
- **(ж) Имена.** Генератор пишет каждое имя так, как оно лежит в дереве: у имени с JSON-именем в дереве лежит только оно; внутренние имена лежат как написаны (Я-46); поэтому раздела `## Имена` (1а) такой генератор не пишет — `### Retry — развилка`, `| retry_count | число>=0 | …`; генератор, который пишет другие имена (например, сохранённые русские имена автора), пишет `## Имена` для каждого имени, чьё автоматическое имя не равно JSON-имени дерева, и только для них (Я-60); то же имя состояния стоит в `Начальное состояние` и в столбце «Куда». Виды — слова `обращение`, `операция`, `развилка`, `конец` (английские — `appeal`, `operation`, `fork`, `end`).
- **(з) Язык файла.** Генератор выбирает язык параметром (`ru` или `en`); все ключевые слова берутся из [alula-keywords.tsv](alula-keywords.tsv) по этому языку (1а), смешения нет; имена, придуманные автором (данные, типы, поля, определения), и значения перечислений переносятся из дерева как есть.
- **(и) Значения-строки и коды журнала** переносятся как есть, без перевода и нормализации; строковый литерал — в двойных кавычках, `"` и `\` внутри экранируются знаком `\`.
- **(к) Проза.** Комментарии и проза не генерируются. Допустимо одним абзацем под шапкой (после списка шапки) записать `title` дерева, если он есть; больше ничего.
- **(л) Файл** кончается ровно одним переводом строки (без пустых строк в конце), кодировка UTF-8 без BOM, переводы строк LF.
- **(м) Подключения.** Фрагмент (Я-32): дерево несёт его уже подставленным (раздел 9) и несёт узел подключения с параметрами (раздел 6); генератор пишет строку подключения фрагмента со всеми параметрами, одной строкой, параметры — в порядке таблицы `## Параметры` фрагмента (`Пауза(сигнал_остановки: остановить, код_остановки: "pause_halt", вложенные: [], отмена_запросов: прекратить_ход_транспорта, вход_заново: ничего, право_записи: "…")`), а состояния, данные и общие события фрагмента как собственные не пишет: повтор был бы «объявлено дважды» (П-2), а без строки подключения потерялись бы параметры вида `поведение` (`отмена_запросов`, `вход_заново`) — подстановкой в текст они не выражаются, их эффект лежит на `отменить_открытые` и `Куда: предыдущее`. Файл определений: дерево несёт и ссылку (`includes`), и копию его типов, констант и определений (раздел 6); генератор пишет либо строку подключения (копии тогда не пишет), либо копии (тогда строки подключения нет) — иначе имена объявлены дважды (раздел 8); выбор — параметр генератора, по умолчанию строка подключения.

Образцы [state-machine-agent-step.alula.md](state-machine-agent-step.alula.md) и [state-machine-agent-step.en.alula.md](state-machine-agent-step.en.alula.md) написаны человеком и в рекомендуемый вид не приведены: они несут прозу (к), строку подключения фрагмента с переносами (м), переносы внутри объявлений и многострочные тела определений (д); русский образец, кроме того, — русские имена, чьи JSON-имена строятся автоматически, с разделом `## Имена` там, где автоматическое имя неверно (ж), и не имеет строки `language` (а). Остальное (шапка, порядок разделов и строк-ключей, таблицы, операторы) в образцах соответствует каноническому виду. Круг «md → JSON → md → JSON» проверяет продукт-потребитель; скрипты методики канонический вид не проверяют (раздел 14).

**Набор литералов или перечисление** (Т-1). Набор литералов — когда набор небольшой, локальный для одной машины, значения не нужны журналу как значения перечисления и не пересекают границу машины (`ход`, `остановка` у «Шага агента» — так в источнике). Перечисление со значениями (`перечисление Имя = …`) — когда набор общий для нескольких машин или фрагментов, пересекает границу вызова (вход, ответ, код сбоя — `КодСбоя`), нужны значения для журнала и `текст(x)` либо у элементов есть поля (тогда `вариант`). **Значения набора** (Я-25) — любой текст, в том числе с кириллицей и пробелом (`"наблюдалось" | "не наблюдалось" | "вывод"` — слова артефакта роли): правило 34(б) латиницу в текстовых литералах закрытых наборов допускает, но не требует; значения пишутся как в источнике (слова кода автомата — латиницей, слова артефакта — как в артефакте). Ограничение `[a-z][a-z0-9_]*` действует только для значений перечисления (Я-15, Я-41).

**Тип `ид`** (Т-2). Текст формата UUID: 8-4-4-4-12 шестнадцатеричных знаков через дефисы, строчные (`0192f3a0-7c1e-7b2a-9d4e-5a6b7c8d9e0f`). Проверка — при загрузке данных и при разборе входа: нарушение входа — отказ `input_rejected`, `reason=type`, `field` — имя поля (раздел 1); нарушение данных — ошибка загрузки по правилам формата. Версия UUID формат не фиксирует; для идентификаторов сессий, запросов хозяина и прогонов предпочтительна версия 7 (по времени, сортируемая). `ид` присваивается данному и параметру типа `текст` (тип при этом забывается, как у набора литералов); обратное — только литерал формата UUID. `==` — структурное, `текст(x)` даёт сам текст. Значение выдаёт примитив хозяина `новый_ид` (раздел 7). **Не меняется:** идентификатор запроса `<сторона>-<попытка>` (правило 15, [протокол вызова](state-machine-call-protocol.md)) и конверт трассировки (`трасса`, `номер_шага`, правило 31) остаются как в спецификации — `ид` служит данным машин (идентификаторы сессий, прогонов и т. п.), а не конверту.

**Значения перечисления** (Я-15, Я-41). Значения могут быть заданы не для всех элементов; значение — `[a-z][a-z0-9_]*`. Элемент без значения показывается в `текст(x)` и в `все_данные` JSON-именем (1а, Я-46): в файле имя элемента — на языке файла, в дереве, в `machine_data` и `все_данные` — JSON-имя; сверка `machine_data` идёт по JSON-имени (для `КодСбоя` — по значению, как у движка).

**Нотация объявлений — как в Нове** (решение владельца, 2026-10-19): объявление — `имя тип` через пробел (поле записи и варианта, параметр определения и функции каталога, параметр сигнатуры стороны и поле сигнала, параметр реестра); результат — после `->`. Двоеточие стоит только в литерале записи `Тип { поле: выр }`, в именованном аргументе `имя: выр`, в паре литерала словаря `{к: з}` и в привязке поля образца `поле: имя` (4.3). Таблицы с отдельным столбцом «тип» (`## Вход`, `## Параметры`, `## Данные`) не меняются. **Объявления только в блоке кода** (Я-13): `тип`, `перечисление`, `вариант`, `определение` пишутся внутри блока кода (ограждения ```) под `## Типы` и `## Определения`; строка объявления вне блока кода — комментарий (абзац) и предупреждение проверки: markdown исказил бы `|`, `{}`, `->`.

**Правило стиля: имя поля не совпадает с названием его типа** (Я-54; рекомендация, не ошибка проверки). Правило касается полей записей и вариантов и данных машины (таблица «Данные»). Поле называет роль значения в записи, тип — вид значения: `текст текст`, `токены Токены`, `сверка Сверка` читаются как повтор и не говорят, зачем поле; лучше `ответ текст`, `расход_токенов Токены`. Совпадение — равенство имени поля и имени его типа без учёта регистра, после снятия `?` и `[]` (`текст ?текст` — совпадение). Имена полей образцов («Шаг агента», «Совещание») не меняются: это имена дерева и кода продукта-потребителя, переименование сломало бы их. Предупреждение проверки — позже (раздел 14).

**Записи типов и Нова** (сверено со спецификацией языка и кодом автоматов): как в Нове — `[]T`, кортеж `(T1, T2)` (в позиции типа), `словарь[K, V]` (в Нове — `HashMap[K, V]`; литерал `{к: з}` как в Нове), запись `тип Имя { поле T }`; перевод имён — `число`, `текст`, `дробное`, `да/нет` (`int`, `str`, `f64`, `bool`). **Расширения формата**, которых в Нове нет: `?T` (в Нове `Option[T]`), `число>=n`, набор литералов `"a" | "b"`, `ид`, `полный словарь[K, V]`; остальные расхождения — в перечне раздела 14.

Пример (пилот «Шаг агента»; изменено: значения `КодСбоя` — из `fail_code_word` движка, они в пилоте были в тексте).

```
перечисление КодСбоя = НетРезультата "no_result" | ОтказМодели "model_refused" | СоединениеОборвалось "connection_lost"
                     | ФормаНеИсправлена "form_not_fixed" | НетОтветаВСрок "timeout" | ОстановленоЧеловеком "stopped_by_human"
                     | ПотолокЗаходов "ceiling_reached" | ОтмененоРодителем "cancelled" | ПредельТокенов "max_tokens"
                     | ПредельЗапросовХода "max_turn_requests"

вариант ИтогХода {
  Закончен { текст ?текст, артефакт ?текст, расход РасходТранспорта }
  Обрезан { расход РасходТранспорта }
  ПределЗапросов { расход РасходТранспорта }
  МодельОтказалась { расход РасходТранспорта }
  Отменён { расход РасходТранспорта }
  ВременнаяОшибка
  ПостояннаяОшибка
  НужноРазрешение { запрос_разрешения ЗапросРазрешения }

```

**Данные.** Таблица `| имя | тип | начальное | не убывает | пишет |`.

- `имя` — данное или **путь поля** внутри словаря: `имя[*].поле` (`*` — любой ключ; у вложенного `имя[*].поле.поле`). Строка с путём несёт только `не убывает` и `пишет` и действует на каждое значение словаря; `тип` — тип поля, `начальное` — `—` (значение задаёт строка самого данного) (С11).
- `начальное` — выражение или `вход.<поле>`.
- `не убывает` — `—`, `да` или `да, <= выр`; выражение может быть любым выражением над константами, параметрами и входом (`наибольшее(1, предел)`); границу проверяет исполнитель после перехода (у пути — при записи; нарушение — ошибка машины). Если граница в первоисточнике неверна для части значений, она не пишется.
- `пишет` — кто меняет данное: `строки` (всё, что записано в таблицах машины: действия строк, блок «При приёме», writing-примитивы, вызванные из таблиц; по умолчанию), `механика` (записи исполнителя вне текста машины: счётчики попыток, перенос из `к_отправке`, `открытые_запросы`, правила 14, 15, 21), `строки и механика` (оба; исключение правила 29 называется явно), `фрагмент` (данные подключённого фрагмента), `строки и фрагмент` (строки машины и строки фрагмента: у данного `остановка`) (А3, E5). `пишет` задаётся на данное целиком; у пути — своё значение: запись в поле с `пишет: механика` из строки перехода — ошибка проверки таблицы (С11).
- **Данные контракта** вносятся в таблицу и входят в `все_данные` (АМ8): `открытые_запросы` (`[]текст`, начальное `[]`, `пишет: механика`) вносит фрагмент «Пауза» — его читают `передать` и `отменить_открытые` (раздел 9); у машины без фрагмента, которая читает его сама, вносит машина; объявление в двух местах — конфликт имён (правило 36), ошибка проверки (ША1, ШВ3); `к_отправке` (`[]текст`) — `строки и механика`: строки пишут его (ЗАМОК, ОТКАЗ), механика переносит стороны в `открытые_запросы` (правило 21, СГ5); счётчик попыток стороны — данное из столбца `счётчик` «Сторон» (раздел 1, СГ1).
- **Состав `все_данные`** (СГ2, ША1, Н-1): **каждое** данное, названное в таблицах `## Данные` машины и подключённых фрагментов, и данные контракта (предыдущий пункт); путь поля — внутри своего данного. Признак один и проверяется по таблицам: названо в таблице — входит; исключений среди названных нет. Поэтому входят и данные, которые источник относит к внешним объектам и заданию (у «Совещания» `предложение`, `копия`, `отпечаток_копии`, `ответы_свидетеля`, `находки_линзы`, `свод`, `архив`, `вопрос_автора`, `порядок_линз`), и копия входа (`запрос_агента` у «Шага агента»): первоисточник даёт у ОШИБКИ «все переменные и хранилища», правило 11 спецификации — «все данные машины». Не входит только то, чего в таблицах нет: данные исполнителя и конверт (`состояние`, `трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `принятые_запросы`, журнал) и хранилища правила 31 (`слова_человека`, `тексты_сбоев`; слово человека и текст сбоя в журнал целиком не пишутся). Кодирование — раздел 5.

Пример (пилоты; границы и `пишет` — как в пилотах, кроме `линзы`: путь поля вместо `строки и механика`).

```
| имя | тип | начальное | не убывает | пишет |
| запрос_агента | ЗапросАгента | ЗапросАгента { вид: вход.вид, профиль: вход.профиль, сессия: вход.сессия, вид_диалога: вход.вид_диалога, контекст: вход.контекст, пределы: вход.пределы, трасса: вход.трасса, номер_шага: вход.номер_шага } | — | строки |
| ход | "first" \| "retry" \| "continue" \| "fix" \| "permission" | "first" | — | строки |
| число_повторов | число>=0 | 0 | да, <= ЧИСЛО_ПОВТОРОВ | строки |
| число_ходов | число>=0 | 0 | да | строки |
| ход_до_повтора | ?("first" \| "retry" \| "continue" \| "fix" \| "permission") | пусто | — | строки |
| остановка | "" \| "no_result" \| "max_tokens" \| "pause_halt" \| "cancel_request" | "" | — | строки и фрагмент |
| попытка_агента | число>=0 | 0 | да | механика |

| линзы[*].попытка | число>=0 | — | да | механика |
| ответы_свидетеля | словарь[число>=0, []ОтветСвидетеля] | {} | — | строки |
```
(Типы `ход`, `ход_до_повтора`, `остановка` переписаны на набор литералов, значения те же, что у прежней записи. Первые семь строк — «Шаг агента», остальные — «Совещание»; `запрос_агента` собирается конструктором из полей входа (раздел 1, Я-30); `открытые_запросы` вносит фрагмент «Пауза», в таблицу машины его строка не пишется. В `остановка` показана часть набора; полный набор пилота — двенадцать значений. Строка `линзы` меняет `потери_подряд` и `пробы`, `попытка` — только механика: запись `линзы[к] = { ...л, поле: выр }`, не называющая `попытка`, — копирование, а не запись в него.)

## 3. Выражения

Слова выражений (`если`, `то`, `иначе`, `и`, `или`, `не`, `пусть`, `в`, `выбор`, `истина`, `ложь`, `пусто`, `недостижимо`) и читаемые имена — русская форма; английская форма — по [таблице слов](alula-keywords.tsv), виды `expr` и `readable` (1а).

### 3.1 Грамматика

```
выр := литерал | истина | ложь | пусто | недостижимо | имя | ( выр ) | выр.поле | выр.N | выр[выр]
     | Тип { поле: выр, … } | Тип.Вариант { поле: выр, … } | Тип.Вариант     запись, вариант с полями, вариант без полей
     | { ...выр, поле: выр, … }                        копия записи с заменой полей
     | (выр, выр, …)                                  кортеж (от двух полей)
     | [выр, …] | {выр: выр, …}                       список; словарь (ключ — выражение); [] и {} — пустые
     | не выр | -выр | выр (+|-|*|/|%) выр | выр (==|!=|<|<=|>|>=) выр
     | выр (и|или) выр | выр ?? выр
     | если выр то выр иначе выр | пусть имя = выр в выр
     | выбор выр { альт [| альт]… [если выр] -> выр; … ; иначе -> выр }     исчерпывающий
     | имя(выр, …[, имя: выр, …])                     функция каталога или определение (pure); именованные аргументы — после позиционных
     | макрос(выр, имя -> выр) | свёртка(выр, выр, (имя, имя) -> выр)
     | вызвать(примитив, выр, …)                      reading: только в «Запрос», «профиль» и в «пусть» «При входе»/«При приёме»; в любой позиции этих выражений (раздел 7)
альт := Тип.Значение | Вариант | Вариант(поле, поле: имя, …) | литерал
```

- **Приоритет** (высший первым): скобки `( )`, `.`, `[]`, вызов; унарный `-`; `* / %`; `+ -`; сравнения; `не`; `и`; `или`; `??`. `если`, `пусть`, `выбор` захватывают всё справа.
- **Литералы:** целое `12`, дробное `0.0`, текст `"…"`; `истина`, `ложь`; `пусто` — отсутствие значения `?T`. Слово `нет` литералом не служит (правило 30: «нет» спецификации — `пусто` у `?T`). `недостижимо` — выражение любого типа: дефект программы, вычисление останавливает исполнитель, как `обязательно(пусто)` (3.3, И-3); стоит в ветке `выбор` для варианта, который по контракту не приходит (E1).
- **Имена.** Имя — данные, константа, параметр, определение, привязка. Состояние читает любое имя из своих чтений (`Читает`; у обращения — таблица `Запрос`), каким бы ни было его `читает` (T9). Привязка поля события, `пусть` и параметр лямбды видны только в своей области; привязка поля события с именем данного машины не совпадает (4.3, Я-26). Функция и имя лежат в разных пространствах: привязанное поле `текст` и вызов `текст(x)` не мешают друг другу. **Служебные слова** (СГ12), именем привязки, данного или поля не бывают: `в`, `то`, `иначе`, `и`, `или`, `не`, `пусть`, `выбор`, `если`, `для`, `каждого`, `истина`, `ложь`, `пусто`, `недостижимо`.
- **Привязка поля двоеточием** (Я-8). Объявление поля сигнала или варианта пишется по нотации Новы через пробел (`находки []Находка`, раздел 2); привязка в образце строки перехода — `поле: имя`, двоеточие читается «поле → имя» (`сигнал(засчитан(находки: новые))`, `ответ: Закончен(текст, артефакт, расход: полученный)`); если имя совпадает с полем, пишется одно имя.
- **Лямбда** — одноместная (двухместная только у `свёртка`); параметр, который не нужен, пишется `_`; лямбды стоят только в аргументе макроса.
- **Читаемые имена исполнителя** (не вычисления, правило 11): `вход`; `событие.идентификатор` (у любого события); `событие.<поле>` (поле данных события строки или цепочки, правило 13); `сторона` (у набора — идентификатор стороны события; в «профиле» и «Запросе» набора — текущая сторона); `причина` — код сбоя события `сбой(причина)` (4.3; виден строке и цепочке, Я-49); `состояние` (раздел 9; тип `Состояние`); `запись_перехода` (тип `СобытиеЖурнала`; в «При входе» и «ответе» концов; определена, когда машина вошла в ОШИБКУ, а в ОШИБКУ входят двумя путями: по `ошибка_машины` — запись этого действия (А4) и по ошибке машины исполнителя (3.3) — запись `machine_error`; оба пути дают запись, ША8, СГ6); `все_данные` (запись данных машины; состав — раздел 2; в действии `журнал(все_данные)` то же имя — сокращение события `machine_data`, раздел 5, И-2). `предыдущее` и `запрос_вызова` — не имена исполнителя, а данные фрагмента «Пауза» (раздел 9, T6). JSON-имя читаемого имени — слово `en` таблицы слов, вид `readable` (`сторона` — `party`, `причина` — `reason`; 1а, Я-49). Имена `трасса` и `номер_шага` (конверт, правило 31) доступны **только** в выражениях «Запроса» стороны вида `machine` — это конверт вызова вложенной машины (правило 35, пункт 1); в условиях и действиях конверт не читается.
- **Из подсчёта методики не вводятся:** `contains`, срезы, постфиксный `?`, сортировка, циклы и рекурсия вне `для каждого`.

Пример выражений (пилот «Шаг агента», определения).

```
определение требует_повышенного_внимания(вид ВидДействия) -> да/нет =
  выбор вид { ВидДействия.Удаление | ВидДействия.Перенос | ВидДействия.Исполнение | ВидДействия.Сеть | ВидДействия.СменаРежима -> истина;
            иначе -> ложь }

определение пауза_повтора(п число>=0) -> число =
  свёртка(диапазон(1, п), ПАУЗА_ПОВТОРА, (н, _) -> н * 2)
```

### 3.2 Типы выражений

| Правило | Запись |
|---|---|
| Возведение `T` в `?T` | в присвоении полю `?T`, в поле конструктора записи, в аргументе функции с параметром `?T`, в ветке `если`/`выбор`, справа от `??` |
| `если`, `выбор` | ветки `T` и `?T` (или `пусто`) дают `?T`; ветки одного типа — этот тип |
| `??` | `?T ?? T` — `T`; `?T ?? ?T` — `?T`: правый операнд любого из двух типов, результат `T` только при правом `T` |
| `+` | число, дробное (смешивать нельзя), текст (склейка), список одного типа (склейка: сначала левый) |
| `==`, `!=` | структурные для записей, кортежей, списков, словарей, перечислений, вариантов (вариант без полей — `x == Тип.Вар`, вариант с полями — `x == Тип.Вар { поле: выр }`), наборов литералов, `?T`; `T` с `?T` — через возведение (`пусто` не равно значению) |
| `<`, `<=`, `>`, `>=` | число, дробное |
| `выр[ключ]` | словарь: `?V`, отсутствующий ключ — `пусто` (не ошибка); у полного словаря — `V`. Список: `?T`, индекс вне границ — `пусто` |
| Набор литералов | значение выражения — **набор значений**: литерал — одно; `+` — попарные склейки; `если`/`выбор` — объединение веток; `обязательно(x)` — набор `x` без `пусто`; `непустое(x)` — набор `x` без `""`; `текст(x)` для перечисления или его подмножества — их значения; присвоение и сравнение с данным типа «набор литералов» проверяют вхождение набора. Склеиваемое поле с «пустым» началом объявляется по источнику (E9, СГ3): источник даёт «нет» — `?("a" \| "b")` без `""`, пусто и `обязательно`; источник даёт `""` — `"" \| "a" \| "b"`, начальное `""` и `непустое`. Одно значение другим не заменяется: в снимке данных `""` и `none` различны |
| набор литералов → `текст` | значение набора присваивается данному и передаётся параметру типа `текст`, набор при этом забывается; обратное — по вхождению набора (ША10) |
| `ид` → `текст` | присваивается данному и параметру типа `текст`, тип `ид` при этом забывается; обратное — только литерал формата UUID (раздел 2, Т-2) |
| `число>=n` | присвоение значения, нарушающего границу, — ошибка машины; статически проверяется только для литералов и констант; `число>=n` совместимо с `число` в обе стороны. Результат `+`, `-`, `*` над `число>=n` — `число` (без границы): `номер_захода - 1` — `число`, передача его параметру `число>=0` проверяется при вызове (T8, АМ4) |
| `недостижимо` | тип любой: совместимо с `T` и `?T`; в `выбор` не влияет на тип результата |

Пример (пилоты «Шаг агента» и «Совещание»; `сбойное_обращение` объявлено `"" | "Witness" | "Lenses" | "AuthorFix" | "AuthorQuestion"` (набор литералов), начальное `""`, как в источнике: набор после `непустое` — без пустого значения).

```
остановка = текст(причина)                                     // причина in {СоединениеОборвалось, НетОтветаВСрок, НетРезультата}: набор {"connection_lost","timeout","no_result"}
остановка = непустое(сбойное_обращение) + "_halt_meeting"      // набор: четыре значения «..._halt_meeting», все входят в набор остановка
```

### 3.3 Вычисление

- Вычисление строгое, слева направо: аргументы функции, поля записи, элементы списка и словаря — в порядке записи; ветви `выбор` — сверху вниз, охрана `если` — после совпадения альтернативы; `пусть` — сначала значение, потом тело. **Ленивы** только `если`, `и`, `или`, `??`: невыбранная ветка и правая часть, которая не нужна, не вычисляются.
- **Вызов reading внутри `если`/`выбор`** (E4): выбранная ветка вычисляет вызов, невыбранная — нет (ленивость выше); чтение вызова входит в чтения состояния безусловно, по списку `читает` примитива. Вызовы в аргументах вычисляются в порядке записи.
- **Язык не тотален.** Два рода частичных операций (ША8, СГ6, ШВ1, СВ2).
  - **Дефект программы** (И-3): `обязательно(x)` при пустом `x`, `непустое("")` и `недостижимо` — процесс останавливает исполнитель (не таблица); перехода в ОШИБКА нет, состояние машины не откатывается; ответ вызова — конец с `NoResult`; журнал дефекта — на усмотрение исполнителя (так ведёт себя `required` автоматов).
  - **Ошибка машины:** переполнение `число`, деление на ноль, выход за `число>=n`, `число(x)` вне диапазона, повтор ключа в `словарь(…)`, отсутствующий ключ в `имя[ключ].поле = выр`, индекс вне границ при записи в список. Исполнитель пишет событие журнала `machine_error` с параметром `reason` — словом из закрытого перечня `overflow`, `division_by_zero`, `bound_violation`, `conversion_range`, `duplicate_key`, `missing_key`, `list_index` (журнал, подраздел «События формата таблиц») — и входит в ОШИБКУ; это событие — `запись_перехода` (3.1).
  - Индекс словаря и списка при чтении частичной операцией не является.
- `если` не вкладывается в ветку другого `если` (три и более исхода — `выбор` с охранами или развилка).
- `текст(x)`: целое — десятичная запись; дробное — кратчайшая десятичная запись, обратимая в то же дробное; целое значение пишется с `.0` (`1.0`, `0.0`); без порядка `e`, если `1e-4 <= |x| < 1e16`, иначе порядок вида `1e-7`, `1.5e20` (строчная `e`, без `+` и без ведущих нулей порядка); примеры: `0.0`, `2.0`, `0.42`, `0.0001`, `1e-7`, `1.5e20`; NaN и бесконечность — ошибка машины (А1); перечисление — значение элемента (у элемента без значения — JSON-имя); `Состояние` — JSON-имя; текст — он сам; `пусто` любого из этих типов — `none`. Для `да/нет` и составных типов `текст` не определён.

## 4. Состояния

### 4.1 Общее

Заголовок `### ИМЯ — вид`: вид — `обращение`, `операция`, `развилка`, `конец`; **JSON-имя состояния** (1а, Я-46, Я-53, Я-60) — латинское, для журнала и конверта (поле `state`, параметр `fork`, `текст(Состояние)`): автоматическое (`ПОВТОР` → `Retry` по словарю; у латинского — само имя, `### Retry — развилка`) или, где оно неверно, строка `## Имена` (`| ОТКРЫТИЕ | Opening |`, `| Pass | Gate3 |`); скобок в заголовке нет. Примеры ниже записаны с русским именем в заголовке. Номер `№` строки = метка `// ИМЯ #n` в первоисточнике. Выбирается **первая** подходящая строка. Начальное состояние — первая строка раздела `## Состояния`: `Начальное состояние: ИМЯ` (А8); проверка 34(г) требует, чтобы оно называло состояние раздела. **Чтения состояния** (правило 11, Я-39): у обращения — таблица `Запрос:` (4.2), у операции, развилки и конца — строка-ключ `Читает:` с именами данных, которые читают «При входе», условия и действия состояния, через запятую; состояние, которое ничего не читает, строки `Читает:` не пишет, обращение без полей запроса — строки `Запрос:` (Я-40); чтения reading-примитива (раздел 7) входят в чтения состояния по его списку `читает`; `Читает` ОШИБКИ — `все_данные` (все данные машины без данных исполнителя; имена читаются как данные).

**Строки-ключи состояния** (С-1) — `Сторона`, `Срок тишины`, `Правит`, `Возвратов формы`, `Запрос`, `Читает`, `При входе`, `При приёме`, `Кроме`, а в разделах `## Стороны` и `## Концы` — `Предел запросов` и `Результат` — **элементы маркированного списка**: `- Сторона: агент`, `- Срок тишины: СРОК_БЕЗДЕЙСТВИЯ`, `- Читает: число_повторов, ход`. Маркер `- ` необязателен при разборе (совместимость с версией 2.5), обязателен в записи; причина: markdown склеивает идущие подряд строки в один абзац, и предпросмотр показывает «Сторона: агент Срок тишины: СРОК_БЕЗДЕЙСТВИЯ Запрос:» одной строкой. **Пустые значения не пишутся** (Я-40): ключ с пустым значением (`—`, `нет`: полей запроса нет, читать нечего, срока нет, работы при входе нет) пропускается, и пропуск значит умолчание; `- Срок тишины: —`, `- При входе: —`, `- Вход: нет` не пишутся. Ключ с настоящим значением по умолчанию (`- Срок тишины: 0`, `- Возвратов формы: 0`) может остаться написанным: так он показывает, что значение выбрано, а не забыто. Остальные правила записи:

- таблица (поле запроса | выражение | читает у `Запрос`; событие | действия у `При приёме`; строки состояния) стоит **на уровне блока**, не внутри элемента списка: между последним элементом списка и таблицей, как и между двумя таблицами, — пустая строка; сам элемент (`- Запрос:`, `- При приёме:`) остаётся последним в списке перед своей таблицей;
- значение в одну строку — в самом элементе (`- При входе: пусть момент = вызвать(time_now)`); тело «При входе» из нескольких действий — вложенный список, по действию в элементе (`  - пусть сейчас = вызвать(time_now);`), знак `;` в конце элемента сохраняется, разбор склеивает элементы в тот же список действий через `;`;
- заголовок состояния `### ИМЯ — вид` и строка `Начальное состояние: ИМЯ` (одна на раздел) списком не записываются.

**Проза** (П-1, Я-12). Абзац — одна или несколько строк текста между пустыми строками (пустая строка нужна и до, и после) вне таблиц, вне блоков кода и вне строк-ключей — комментарий для читателя: переводчики и проверки его пропускают, знаки «`» и «« »» внутри него допустимы. Строка текста, прижатая вплотную к таблице, заголовку или элементу списка без пустой строки, абзацем не является (markdown склеивает её с соседним блоком): проверка форматирования предупреждает, разбор читает её как лишнюю строку соседнего блока. Прозой не считаются заголовки `#`, `##`, `###`, таблицы и элементы списков строк-ключей (`- Ключ: …`). Чтобы опечатка в ключе не стала молчаливым комментарием, проверка форматирования (раздел 10) предупреждает о строке-абзаце, которая начинается со слова из перечня ключей (`Сторона`, `Срок тишины`, `Запрос`, `Читает`, `Правит`, `Возвратов формы`, `При входе`, `При приёме`, `Результат`, `Кроме`, `Предел запросов`) без маркера `- ` или с опечаткой в нём.

**«Куда»:** имя состояния; `предыдущее`; `возврат_подготовки` (правило 24); `то же` (остаться в состоянии; у общих событий); суффикс `, запуск заново` (правило 18); `—` у строки с `ошибка_машины`.

**Умолчание развилки и `иначе`** (Я-57). Строка `иначе` по правилу 27 записывается последней, с действием `ошибка_машины("fork_no_match", fork: "<JSON_имя>")` (значение `fork` — текстовый литерал, АМ6, T10) и `Куда` `—`; её метка — следующий номер после последней строки условий. Строка `иначе` **обязательна**, если исчерпание условий не доказано типом; развилка без `иначе` и без доказанного исчерпания — ошибка проверки. **Исчерпание доказано типом**, когда условие каждой строки, кроме `иначе`, — сравнение одного и того же имени `x` (данное, привязка `пусть`, `событие.<поле>`) закрытого типа с одним его значением: `x == Тип.Эл` у перечисления `Тип`, `x == Тип.Вар` у варианта, все варианты которого без полей, `x == "метка"` у набора литералов (`"a" | "b"`, раздел 2) — и строки называют все значения типа (как у `выбор`, раздел 2). Тогда `иначе` необязательна: развилка без неё не может остаться без подходящей строки; написанная `иначе` недостижима — **предупреждение** проверки, а не ошибка (обычно это `иначе` с `ошибка_машины`, оставшаяся по привычке). Исчерпания не доказывают: условие над текстом — имя типа `текст` (`продолжение == "…"` с метками-строками: сколько бы меток ни было, тип их не закрывает; закрыть набор — объявить тип набором литералов или перечислением), над двумя полями (пара перечислений: произведение типов не доказывается, `иначе` — ловушка непредусмотренного сочетания), над `?T` (`пусто` не назван), условие с `и`, `не`, `!=`, `<`; у таких развилок `иначе` остаётся.

### 4.2 Обращение

```
### ИМЯ — обращение
- Сторона: <имя из «Стороны»>[; набор: <выражение-список идентификаторов>]
- Срок тишины: <выражение типа ?число>=0>   необязательно; пустое (`—`) не пишется, не написан — срока нет
- Правит: <данное>; проверка: <reading-примитив>   необязательно (правило 14)
- Возвратов формы: <число>=0>                необязательно, по умолчанию 0 (`0` можно написать)
- Запрос:                                    необязательно: нет полей запроса — строки нет

| поле запроса | выражение | читает |       выражение `—` — то же имя; читает: сторона | исполнитель

- При приёме:                                  необязательно

| событие | действия |
| <событие> | <действия> |

| № | Событие | Условие | Действия | Куда |
```

- **Запрос.** `читает: сторона` — поле запроса стороне; `исполнитель` — имя, которое читают строки состояния, а в запрос оно не идёт (выражение — то же имя, `—`). **Выражение по умолчанию** (Я-56): `—` в ячейке «выражение» значит «то же имя» — выражение поля равно имени поля (`| номер_захода | — | исполнитель |` — то же, что `| номер_захода | номер_захода | исполнитель |`); это не «нет значения», а знак `—` — потому что пустая ячейка теряется при правке и в просмотрщиках. Имя поля при `—` обязано быть именем, которое выражения «Запроса» читают (данное, константа, параметр, `вход`, `сторона` у набора, у стороны `machine` — `трасса`, `номер_шага`), иначе ошибка проверки, как у любого выражения. Явное выражение, равное имени поля, допустимо, но не рекомендуется: проверка предупреждает, канонический вид пишет `—` (1б). Столбец «выражение» остаётся и при `—` во всех строках: шапки таблиц не убираются (без шапки markdown таблицу не показывает). Строки состояния, «При приёме», «Срок тишины» читают **любое** имя из `Запрос`, с каким бы значением `читает` оно ни стояло (T9). Поле запроса `профиль` в «Запросе» не пишется: его даёт столбец `профиль` «Сторон» (T3). Выражения читают данные машины, константы, параметры, `вход`, `сторона` (набор) и — у стороны `machine` — `трасса`, `номер_шага`; допустим `вызвать` reading (вычисляется при входе, до отправки, в порядке строк). Поля запроса стороны `machine` — ровно поля её типа `вход`, кроме `профиль` (его даёт столбец «Сторон», СВ5). Поле запроса может называться как данное при ином выражении (`предыдущее` — `обязательно(предыдущее)` у ПАУЗЫ): строки, условия и «При приёме» читают **данное**, а не поле, поле видно только стороне, и такое поле — только `читает: сторона` (ША3); выражение такого поля — любое выражение «Запроса», в том числе с `вызвать` и `если` (у ИЗМЕНЁН «Совещания» поле `предложение` — `если вызвать(предложение_прочитано) то предложение иначе пусто`), строки его не читают (Я-28). Условия, «При приёме» и «Действия» читают только имена из `Запрос`, `событие.…`, привязки, константы и параметры (правило 11).
- **`читает` по умолчанию** (Я-27). Если источник не говорит, кто читает поле (в его таблице «Вход» состояния нет столбца «Кто читает»), пишется `сторона`: поле уходит в запрос, как в источнике; `исполнитель` — только для имён, которые источник называет не идущими в запрос.
- **Обращение без полей запроса** (Я-23, Я-40). Если стороне не нужны поля запроса (ворота «повторить / остановить» без данных), строка `Запрос:` и таблица не пишутся: запрос несёт только то, что даёт исполнитель (конверт, `профиль` из столбца «Сторон»); строки, «При приёме» и «Срок тишины» такого состояния данных машины не читают — только `событие.…`, привязки, константы и параметры. У стороны `machine` запрос без полей допустим, только если у типа `вход` нет полей (раздел 1, Я-30).
- **Обращение со свободным вводом** (Я-51, Я-52; правило 19). `Сторона` — сторона вида `human` без счётчика (раздел 1): ворот и запроса нет, исполнитель ничего не отправляет и не показывает, машина ждёт слова. Поэтому у такого обращения нет `Запрос`, `набор`, `Срок тишины`, `Правит`, `Возвратов формы`, строк `ответ` и `сбой` (проверка раздела 10); строки — по сигналам стороны (`сигнал(сообщение(содержание, автор, источник))`); слово принимается по имени сигнала в текущем состоянии, слово, для которого строки нет, отбрасывается (правило 17); «стоп человека» — общее событие (правило 23).
- **Срок тишины.** Строка не написана (пустое значение `—` не пишется, Я-40), `пусто` или `0` — срока нет ( у человека срока нет — открытые ворота, правило 19; у вратаря срок в состоянии не пишется: срок вратаря-агента — параметр вратаря, правило 19; у вызова машины срока нет, правило 35, пункт 5). Выражение читает те же имена, что выражения «Запроса» (данные, константы, параметры, `вход`, `сторона` у набора), без `вызвать` (функции каталога допустимы, ША5); эти имена названы в `Запрос` состояния (А7). Вычисляется при входе, после «Запроса», до отправки запроса.
- **Правит** (E3, правило 14). `Правит: <данное>; проверка: <примитив>` — ответ стороны правит объект, который отражает данное (`предложение`), и результат нельзя принять, если объект изменился с начала попытки. `проверка` — reading-примитив без параметров с результатом `да/нет`; исполнитель вызывает его при приёме ответа, после проверки открытости запроса и формы и до `разбор` и «При приёме». `истина` — результат не принимается (в `принятые_запросы` не пишется, «При приёме» не выполняется, события нет), запрос отменяется и уходит заново: новая попытка, `Запрос` вычисляется заново; запись об этом в журнал — механика исполнителя. «Началом попытки» и сравнением владеет исполнитель, примитив читает его служебную запись и объект (`читает`). Данное из `Правит` обязано записываться в «При приёме» этого состояния (проверка таблицы).
- **Набор** (правило 21): `Сторона: линза; набор: порядок_линз` — по запросу на каждый идентификатор; `сторона` в «Запросе» — идентификатор, для которого строится запрос; `Предел запросов` — раздел «Стороны». `к_отправке` — данное `строки и механика`, `открытые_запросы` — `механика` (раздел 2, СГ5), счётчик попыток стороны — столбец `счётчик` «Сторон» (раздел 1, СГ1).
- **Возвратов формы** — сколько раз исполнитель возвращает стороне ответ не по форме или не по сверке, которую делает `разбор` (например, выдержек; правило 18, СГ14). У видов, кроме `machine`, — в том же запросе. У стороны `machine` — новым запросом той же стороны с новым идентификатором и замечанием: тот же идентификатор вернул бы готовый ответ (правила 14, 35, пункт 4). Сверку (например, выдержек) делает примитив `разбор` при приёме, сам возврат — механика исполнителя (E7). Возвраты исчерпаны — запрос закрывается событием `сбой` с кодом `ФормаНеИсправлена` (сбой разбора, раздел 1, Я-33).
- **Условие** в строке события — только у общих событий и сигналов фрагмента (правила 23, 35); у строк обращения `—`. Событие, чьё условие ложно, отбрасывается (правило 17, запись в журнал — механика). Условие `иначе` (E11) допустимо у сигнала: последняя строка того же события, берётся, если условия предыдущих строк этого события не истинны; у остальных событий `иначе` нет.

Пример (пилот «Совещание», ЛИНЗЫ). Изменено: выражение, равное имени поля, — `—` (Я-56); ключ находок — кортеж вместо записи пилота; имена `трасса`, `номер_шага` вместо reading-примитивов `трасса_вызова`, `номер_шага_вызова`; строки `профиль` нет (T3); показаны не все строки «Запроса».

### 4.3 События обращения

Таблица строк `| № | Событие | Условие | Действия | Куда |`. Виды событий:

| Событие | Смысл |
|---|---|
| `ответ`, `ответ(имя)` | значение ответа (результат стороны или результат её `разбор`, раздел 1); `имя` привязывает его целиком |
| `ответ: Вариант(поле, поле: имя, …)`, `ответ: Вариант`, `ответ: Тип.Вариант(…)` | значение ответа — вариант типа `итог` стороны (у `machine` с `разбор` — результата разбора, E1, ША2); поля привязываются как имена (`поле: имя` — с переименованием); вариант без полей — без скобок |
| `сбой`, `сбой(причина)`, `сбой(причина in {…})` | отказ или «нет ответа» (правило 16); закрытое подмножество кодов — **список состояния**: объединение наборов его строк `сбой` (строка без набора — все `КодСбоя`). Код вне списка исполнитель приводит к `КодСбоя.НетРезультата` (правило 16), событие несёт уже его; если и `НетРезультата` вне списка — `недостижимо` (набор объявлен полным для состояния) (СВ3) |
| `сигнал(<сигнал>)`, `сигнал(<сигнал>(поле, поле: имя, …))` | **сигнал стороны** обращения (`human`, `enhanced`, вратарь; Я-38): сигнал — из столбца «сигналы» стороны, поля и их типы — оттуда же; либо **сигнал машины** вне контракта (стоп, отмена, сигналы от родителя) — только в общих событиях и ПАУЗЕ фрагмента (раздел 9); у строки сигнала машины допустимо условие `иначе` (4.2) |
| `сразу` | у операции: переход без события после работы при входе (правило 26) |

- **Привязки.** Любое поле события доступно и как `событие.<поле>`; привязка нужна для краткости. Имя привязки, совпавшее с именем данных машины без переименования, — ошибка проверки (затенения нет). Привязывать можно часть полей.
- **Поле, названное как данное** (Я-26). Поле сигнала или варианта может называться как данное машины (сигнал `подтвердил(подтверждение текст)` при данном `подтверждение`): затеняет не объявление поля, а привязка; такое поле привязывается с переименованием (`сигнал(подтвердил(подтверждение: слово_подтверждения))`) или читается как `событие.подтверждение`. Данные машины здесь — вместе с данными подключённых фрагментов, и проверка идёт после подстановки фрагмента: привязки строк фрагмента «Пауза» (`слово_человека`, `автор`, `источник`, `идентификатор_запроса`; в английском файле — имена английского файла фрагмента) не совпадают ни с одним данным машины, поэтому данное машины так не называют (словарь версии 10: `источник_запуска` → `launch_source`, а не `source`, Я-37).
- **Набор.** События набора несут `сторона`; цепочка развилок за строкой события читает её как `событие.сторона` (правило 13).
- **Сигналы стороны** (Я-38). Сигналы состояния — сигналы его строк. Сигнал стороны принимается строкой обращения, чья `Сторона` его объявила; сигнал человека несёт идентификатор открытых ворот, а с идентификатором не открытых ворот отбрасывается (правила 17, 19); при воротах нескольких сторон в одном состоянии сигнал принадлежит стороне, названной в идентификаторе, а сигнал, которого она не объявила, или сигнал от другой стороны отбрасывается («слово чужой стороны», правило 19); сигнал человека на ворота, принятые ответом вратаря-агента, до перехода по этому ответу заменяет его (окно 2, правило 19); слово свободного ввода (сторона `human` без счётчика, 4.2, Я-51, Я-52; правило 19) идентификатора ворот не несёт и принимается строкой текущего состояния по имени сигнала, без записи ворот; сигнал, которого сторона не объявила, — ошибка проверки строки. Объявленный сигнал стороны, для которого у текущего состояния строки нет, строкой состояния не принимается; он отбрасывается, а ворота остаются открытыми (правила 14, 17, 19; пункт раздела 14 закрыт). Каждый сигнал стороны используется хотя бы в одной строке машины (или фрагмента); сигнал события строки обращения входит в список сигналов его стороны. Поле сигнала объявляется в столбце «сигналы» через пробел, а в строке привязывается `поле: имя` (3.1, Я-8).
- «При приёме» — действия ДО перехода (правило 14), раздел 4.4.

Пример (пилоты). Изменено: сигналы с данными — запись `сигнал(засчитан(находки: новые))` вместо неопределённой привязки пилота; поля, совпавшие с данными, переименованы; к В3 добавлена выдержка таблицы «Стороны»: сигналы `не засчитан` и `засчитан(находки []Находка)` объявлены в столбце «сигналы» вратаря, стороны обращения (Я-7, Я-38).

### 4.4 При приёме

Блок обращения `При приёме:` — таблица `| событие | действия |`. Событие — `ответ`, `ответ(имя)`, `ответ: Вариант(…)` или `сбой`; доступны привязки события и `сторона`; значение ответа — результат `разбор` стороны (раздел 1). Исполнитель выполняет блок при приёме ответа, до перехода, одной фиксацией с записью в `принятые_запросы` (правило 14); привязки блока (`пусть`) сохраняются вместе с принятым событием и видны его строке и цепочке. Порядок приёма: открытость запроса и форма, «Правит» (4.2), `разбор`, блок.

В блоке допустимы: присваивания данным, `+=`, `поле[ключ] = выр`, `поле[ключ].поле = выр` (5), `для каждого`, `если`, `пусть имя = выр` и `пусть имя = вызвать(reading, …)` (в любой позиции выражения, 3.1). Недопустимы: `журнал`, `ошибка_машины`, `вызвать` writing и irreversible, переход; writing-вызовы после приёма (например, отметка времени и проверка кеша) пишутся в действиях строки (АМ9). Данные, которые пишет блок, — `пишет: строки` (2).

Пример (пилот «Совещание», ЛИНЗЫ). Изменено: значение `итог` — результат `разбор` стороны `линза` (`ИтогЛинзы`, раздел 1), а не запись пилота; запись в линзу — копия записи с заменой полей через `обязательно(линзы[сторона])` (Н-11): в коде `@lenses(lens_id)` при отсутствии линзы — `unreachable` (линзы созданы при старте), то есть дефект программы, `обязательно(пусто)` (3.3); краткая запись `линзы[сторона].поле = выр` дала бы ошибку машины `missing_key` (3.3), расходясь с кодом.

```
- При приёме:

| событие | действия |
| ответ(итог) | пусть л = обязательно(линзы[сторона]) в (линзы[сторона] = { ...л, потери_подряд: 0, пробы: итог.пробы }); ответившие += 1; находки_линзы[(сторона, номер_захода)] = итог.находки |

### 4.5 Операция

```
### ИМЯ — операция
- Читает: <имена>                         необязательно
- При входе: <пусть-привязки и вызовы>

| № | Событие | Условие | Действия | Куда |
| 1 | сразу | — | <изменения данных, журнал> | ... |
```

«При входе» — работа с внешним миром (правило 10): `пусть имя = <выражение>` и `пусть имя = вызвать(primitive, …)` (reading и writing), вызовы writing и irreversible без результата. Привязка видна дальше в «При входе» и во всех строках состояния; вычисляется один раз за вход. Запись writing-примитива (его `пишет`) видна следующим за ним привязкам «При входе» и строкам: порядок записи — порядок исполнения (T7). Изменения данных и журнал — в строке `сразу` (правило 29). Событие у операции одно — `сразу`.

Пример (пилот «Шаг агента», СТАРТ и УЧЁТ; «Совещание», ЗАМОК, ВОЗВРАТ, ФИЛЬТР, СВОД). ### 4.6 Развилка

```
### ИМЯ — развилка
- Читает: <имена>                         необязательно
- При входе: пусть имя = <выражение, в том числе с вызовом reading в любой позиции>      необязательно

| № | Условие | Действия | Куда |
```

Развилка ничего не делает и не ждёт (правило 9): «При входе» — только `пусть`-привязки (выражение; вызов reading допустим в любой позиции выражения, в том числе в ветке `если`, 3.3), каждая вычисляется один раз за вход; действия строки меняют данные только в её переходе. Условия не вызывают примитивы через `вызвать`: результат reading-примитива читается по привязке `пусть` «При входе»; `pure`-примитив (раздел 7) и определение зовутся в условии как функции `имя(арг)`, функции каталога — тоже (Я-29).

Пример (пилот «Шаг агента»). Изменено: строка `иначе` записана (обязательна: исчерпание не доказано типом, условия — над числом и над парой полей, 4.1, Я-57); латинское имя ПРОВЕРКИ_ОТВЕТА — `ReplyValidation`, как в словаре (П-4); пример ПРОВЕРКА_ОТВЕТА не передаёт несуществующий аргумент: чтения `reply_validation` названы в реестре (раздел 7) и входят в `Читает`.

```
### ПОВТОР — развилка
- Читает: число_повторов, ход

| 1 | число_повторов < ЧИСЛО_ПОВТОРОВ и ход != "retry" | число_повторов += 1; ход_до_повтора = ход; ход = "retry"; журнал(agent_transient_error, retry: текст(число_повторов)) | БЮДЖЕТ |
| 2 | число_повторов < ЧИСЛО_ПОВТОРОВ и ход == "retry" | число_повторов += 1; журнал(agent_transient_error, retry: текст(число_повторов)) | БЮДЖЕТ |
| 3 | число_повторов >= ЧИСЛО_ПОВТОРОВ | остановка = "no_result"; журнал(agent_transient_error_exhausted, retries: текст(ЧИСЛО_ПОВТОРОВ)) | УЧЁТ |
| 4 | иначе | ошибка_машины("fork_no_match", fork: "Retry") | — |

- Читает: число_возвратов, текст_ответа, артефакт_ответа, запрос_агента
- При входе: пусть проверка = вызвать(reply_validation)

| 1 | проверка == ПроверкаОтвета.Верна | — | УЧЁТ |
| 2 | проверка == ПроверкаОтвета.Пуста | остановка = "no_result"; журнал(agent_no_result) | УЧЁТ |

### 4.7 Конец

```

- Кроме: <значение in {…}>                необязательно
```

«При входе» конца — работа с внешним миром и журнал: `пусть`-привязки, `вызвать` (reading, writing, irreversible), `журнал`, условные `если`, `для каждого` с телом из `журнал(…)` и `если` (E2); данные конец не меняет (правило 29). `Кроме:` — значения набора, с которыми в этот конец не входят: исчерпанность «Концов» проверяется по набору без них; вход с таким значением — `недостижимо`.

**Таблица «Концы»** (правило 35, пункт 2, «конец → ответ»): сначала элемент списка `- Результат: <тип ответа машины>`, затем (через пустую строку) таблица

```
| конец | № | когда | ответ |
```

- `когда` — условие входа: `истина`, `остановка == "…"`, `остановка in {…}`; строки одного конца взаимоисключающи и покрывают набор, по которому ветвятся (кроме `Кроме`); не покрытое значение — ошибка проверки таблицы.
- `ответ` — `Ответ(<значение типа результата>)` или `Отказ(<код КодСбоя>, <текст>)`; конверт ответа (запрос, сторона, трасса, шаг) собирает исполнитель; код отказа берётся из конструктора, отдельного столбца нет.

## 5. Действия

Слова действий (`журнал`, `ошибка_машины`, `вызвать`, `передать`, `отменить_открытые`, `для каждого`) — русская форма; английская форма — по [таблице слов](alula-keywords.tsv), вид `action` (1а).

Список через `;` в порядке записи (правило 29); **каждое действие видит результаты предыдущих** (после `число_повторов += 1` журнал читает новое значение). Действия `вызвать` irreversible записываются в порядке, но исполняются последним этапом фиксации, после сохранения (правило 13); их аргументы вычисляются в точке записи.

| Действие | Смысл | Где |
|---|---|---|
| `поле = выр`; `поле += выр` | присваивание; прибавление (число, дробное, текст, список) | строки, «При приёме» |
| `поле[ключ] = выр` | словарь: вставка или замена; список: существующий индекс, иначе ошибка машины | строки, «При приёме» |
| `поле[ключ].поле = выр` | краткая запись `поле[ключ] = { ...поле[ключ], поле: выр }` (С11); ключа нет — ошибка машины, запись не создаётся; поле с `пишет: механика` — ошибка проверки. Где источник называет отсутствие ключа дефектом программы (`unreachable`, `required`), пишется `поле[ключ] = { ...обязательно(поле[ключ]), поле: выр }` (4.4, Н-11) | строки, «При приёме» |
| `поле = без_ключа(поле, ключ)`; `поле = убрать(поле, элемент)` | удаление ключа и элементов | строки, «При приёме» |
| `журнал(код, имя: выр, …)` | событие журнала: `код` — латинский из таблицы шаблонов, значения параметров — `текст` | строки, «При входе» конца, тело `для каждого` в «При входе» конца |
| `журнал(значение)` | событие, собранное `событие_журнала(…)` или `запись_перехода` | строки, «При входе» конца |
| `журнал(все_данные)` | сокращение `журнал(machine_data, data: <запись данных>)`: событие `machine_data` с **одним** параметром `data`; кодирование — ниже (И-2); состав — раздел 2. Имя `все_данные` в выражении — значение-запись (3.1) | «При входе» ОШИБКИ |
| `пусть имя = выр` | привязка до конца «При входе» и на все строки состояния; также `пусть имя = вызвать(…)` | «При входе», «При приёме» |
| `пусть имя = выр в действия` | локальная привязка | везде |
| `если выр то (действия) [иначе (действия)]` | условное; условие — выражение без `вызвать` (функции каталога допустимы, ША5) | строки, «При приёме», «При входе» конца |
| `для каждого имя в выр: действия` | конечный список или диапазон; тело — присваивания, `+=` и краткая запись (в строках, «При приёме»); `журнал(…)` и `если` (в «При входе» конца); **граница тела** (Я-24): тело — одно действие, до ближайшей `;` списка, или список действий в круглых скобках `для каждого x в xs: (а; б)`, как у `если`; действие после `;` вне скобок в тело не входит | строки, «При приёме», «При входе» конца |
| `вызвать(примитив, арг, …)` | writing и irreversible примитив без результата (допустимость по классам — раздел 7) | по классу |
| `ошибка_машины(код, имя: выр, …)` | журнал `код` и конец ОШИБКА; «Куда» — `—`; единственный вход в ОШИБКУ по воле таблицы (второй — ошибка машины исполнителя, 3.3); после обоих определено `запись_перехода` (А4, ША8) | строки, общие события |
| `передать(вложенные, сигнал)` | сигнал `Сигнал` машинам `вложенные` (параметр фрагмента, раздел 9) из `открытые_запросы` на момент действия (адресаты берутся в точке записи, до `отменить_открытые` той же строки), отправка — после фиксации; журнал `signal_passed` на каждого (T4) | только фрагмент |
| `отменить_открытые[(кроме: вложенные)]` | отменить открытые запросы без принятого ответа (правило 18): с `кроме: вложенные` — кроме запросов к названным вложенным, без аргумента — все, включая вложенные; эффект — по параметру `отмена_запросов` (раздел 9); возврат сторон отменённых запросов набора в `к_отправке` — правило 18, при любом значении параметра; отключает его только `без_возврата_в_к_отправке`, и только в ОБЩ 1, 2 (Н-2); изменение `открытые_запросы` и `к_отправке` — механика контракта (правило 29), «запись ⊆ `пишет`» его не считает записью строки | только фрагмент |

**Коды журнала продукта** (Я-31). Код в `журнал(код, …)` и `ошибка_машины(код, …)` берётся из таблицы шаблонов [журнала](state-machine-journal.md) (раздел 2 и подраздел «События формата таблиц») — это коды методики. Продукт, которому нужны свои события (запись механики исполнителя: правка ответа при «Правит», возврат формы, повтор запроса, заказ сигнала — например `answer_edited`, `form_returned`, `request_repeated`, `signal_ordered`), объявляет их **таблицей шаблонов продукта** той же формы (`Машина | Код события | Русский шаблон | Параметры`) рядом с таблицей методики; где она лежит, называет реестр хозяина (как файлы определений, раздел 8). Правила: код продукта — латинский `snake_case` по правилам кода журнала; он не повторяет код методики (совпадение — ошибка проверки, даже при том же шаблоне); код, который пишет сам формат или механика контракта (`signal_passed` у `передать`, `input_rejected`, `machine_error`, `machine_data`, коды фрагмента «Пауза»), продукт своим кодом не заменяет: своё событие (например, `signal_ordered` при заказе сигнала до фиксации) пишется рядом с кодом методики, а не вместо него. Проверка (раздел 10) сверяет код и параметры строки с объединением двух таблиц; код вне объединения — ошибка. Скрипт методики [check-tables.py](check-tables.py) читает только таблицу методики; таблицу продукта читает проверка продукта. В таблицу методики коды продукта не вносятся.

**Кодирование `журнал(все_данные)`** (И-2; ША1; проверено реализацией). Событие `machine_data` с **одним** параметром `data`. Значение параметра — пары `имя=значение` (имя — JSON-имя данного, 1а), разделитель — `; ` (точка с запятой и пробел); порядок — порядок строк таблицы «Данные» машины (сначала данные подключённых фрагментов в порядке подключений, затем данные машины); пути полей внутри словаря (`имя[*].поле`) в состав не входят — они часть значения словаря. Значение пары:

| Значение | Запись |
|---|---|
| целое | десятичная запись |
| дробное | `текст(x)` (кратчайшая обратимая запись, целое с `.0`; 3.3) |
| текст, набор литералов, `ид` | как есть, без кавычек; пустой текст — пусто после `=` (`stop=`) |
| `да/нет` | `yes`, `no` |
| необязательное `пусто` | `none` |
| перечисление | значение элемента (латинский текст кода); у элемента без значения — его JSON-имя (Я-15, Я-46) |
| `Состояние` | JSON-имя состояния |
| список | JSON-массив `[…]`; пустой — `[]` |
| словарь | JSON-объект `{…}`; пустой — `{}`; у словаря с нетекстовыми ключами — массив пар `[[ключ,значение],…]` в порядке первой записи ключа |
| запись | JSON-объект; ключи — JSON-имена полей, порядок — порядок полей типа |
| вариант | с полями — `{"Вар":{поля}}`; без полей — строка `"Вар"` (JSON-имена) |
| кортеж | массив; позиции по порядку |

Составные значения кодируются JSON без потерь: без пробелов (разделители `,` и `:`), UTF-8, не-ASCII знаки не экранируются, экранирование текста — по RFC 8259 (`\"`, `\\`, `\b`, `\f`, `\n`, `\r`, `\t`, прочие управляющие знаки — `\u00xx` строчными); внутри составного текст — JSON-строка, `пусто` — `null`, `да/нет` — `true`, `false`, дробное — число по `текст(x)`, перечисление и `Состояние` — строка по строкам таблицы. Кодирование и разбор туда и обратно без потерь: кириллица и 4-байтные буквы сохраняются, целое и дробное различаются (`1` и `1.0`).

Примеры (`data=` — имя параметра события): `data=count=0; label=abc; began=1000; log=[]; table={}; stop=` и `data=total=99; label=; log=[]; counts={}; items={}; p_attempt=0`; словарь `линзы словарь[текст, Линза]` (JSON-имя `lenses`; поля `Линза` с JSON-именами `id`, `lost`, `probes`, `attempt`) — `lenses={"л1":{"id":"л1","lost":0,"probes":0,"attempt":2}}`; `turn_before_retry=none` — пустое необязательное `ход_до_повтора` (JSON-имя `turn_before_retry`).

## 6. Дерево JSON

**Имя файла дерева** (Я-19). Дерево, скомпилированное из `<имя>.alula.md`, лежит рядом в `<имя>.alula.json` (`agent_step.alula.md` ↔ `agent_step.alula.json`). JSON — исполняемая форма самого языка, а не другой формат: рукописное дерево — тоже Алула в JSON-виде; ключ `format: "machine/2"` внутри дерева не меняется. Прежнее имя `*.machine.json` не употребляется, загрузка его не принимает (Я-22). Правила, по которым дерево пишется обратно в файл Алулы, — раздел 1б.

Дерево JSON и его схема — вне этого файла: версию схемы ведёт продукт, ключи в ней английские. Дерево одинаково для русского и английского файла: слова обоих языков отвечают одному ключу и одному значению (таблица слов, 1а); вид стороны «человек или агент по настройке» называется в дереве `gatekeeper` (раздел 1). Здесь перечислены конструкции версий 2, 2.1, 2.2 и 2.5 (у версий 2.8–2.16 новых узлов нет: дерево от языка файла не зависит, 1а; `—` в ячейке «выражение» таблицы «Запрос» (Я-56) даёт в дереве выражение-имя поля, как прежняя запись; у версии 2.7 один новый ключ — `words`, в версии 2.13 он называется `values`, ниже; у версий 2.3, 2.4 и 2.6 новых узлов машины нет: результат по роли — запись реестра хозяина; у версии 2.5 новые узлы — набор литералов и тип `id`), которым нужны узлы (у части из них в версии 1 узлов не было): `in` у `сбой`, «когда» и «Кроме» у концов, «При входе» развилки, операции и конца, альтернативы `|` в `выбор`, наборы литералов `"a" | "b"` (в схеме — перечень строк, `enum`), тип `id` (строка формата UUID: `^[0-9a-f]{8}(-[0-9a-f]{4}){3}-[0-9a-f]{12}$`), `число>=n`, `?`, кортеж, полный словарь, `не убывает, <= выр`, `пишет` (пять значений), путь поля `имя[*].поле` в «Данных» и краткая запись `имя[ключ].поле = выр`, `недостижимо`, скобки группировки, вызов с именованными аргументами, идентификатор стороны, `разбор` стороны `machine`, `Правит` с `проверка`, `Начальное состояние`, `для каждого` с `журнал` в конце, подключение с параметрами, `сигнал(…)` с полями (сигнал стороны и сигнал машины), привязка поля с переименованием, «При приёме», `пусть` в «При входе», условное действие, `событие_журнала`, `журнал(значение)`, набор сторон, сторона `machine`, `## Вход` машины с инвариантами, значения перечислений; из версии 2.2 — `итог` стороны и `ИсходВорот`, столбец `счётчик`, литерал роли у `разбор`, квалифицированное `ответ: Тип.Вариант`, `отменить_открытые` без аргумента, `непустое`, шапка файла определений. **Значения перечислений** (П-7, Я-41). У перечисления со значениями (раздел 2) узел перечисления несёт ключ `values` (до версии 2.13 — `words`) — список пар «JSON-имя элемента → значение» в порядке объявления (`[["NoResult", "no_result"], …]`); у перечисления без значений ключа нет. Кодирование `все_данные` (раздел 5) и `текст(x)` берут значение из `values`; у элемента без значения — его JSON-имя (Я-15). **Имена в дереве** — JSON-имена (1а, Я-46): автоматические (Я-53) или из `## Имена` (Я-60), дерево не зависит от того, как имя получено; раздел `## Имена` своего узла в дереве не имеет. **Счётчик стороны** (Я-52): у стороны ключ счётчика может отсутствовать — так дерево несёт сторону вида `human` со свободным вводом (`—` в столбце `счётчик`, раздел 1); как это выражено в схеме, решает продукт. таблица `Запрос` обращения — ключ `inputs`, строка `Читает` — ключ `reads` (Я-39). Подключение файла определений — `includes: [{ "name", "version", "hash" }]` и копия его типов, констант и определений в дереве машины: интерпретатору хватает одного дерева (С30).

## 7. Реестр примитивов и допустимость классов

Запись реестра: `имя`, `параметры` с типами, `результат`, `класс`, `читает`, `пишет`, примечание. JSON-имя примитива — имя в реестре хозяина: у нелатинского имени оно строится автоматически (1а, Я-53; `профиль_стороны` → `party_profile` по словарю), а если имя реестра другое — задаётся строкой `## Имена` (Я-60). Чистые функции над данными пишутся не здесь, а в «Определениях»; примитивами остаются разбор текста, чтение объектов, время, закрытие хода, эффекты.

| Класс | Что делает | Вызов `вызвать(имя, …)` допустим |
|---|---|---|
| `pure` | чистая функция хозяина | как функция `имя(арг)` везде |
| `reading` | читает объект, хранилище, время; данные машины не меняет | в «Запрос» обращения, в `профиль`, в `пусть` «При входе» (операции, развилки, конца) и «При приёме» (в любой позиции выражения, 3.1), как `разбор` стороны `machine` и `проверка` свойства «Правит» (4.2); не в условиях и не в действиях строк; `новый_ид` — только в `пусть` «При входе» операции (ниже) |
| `writing` | пишет внутри фиксации (данные машины, объекты, буфер) | в «При входе» операции и конца (в том числе `пусть имя = вызвать(…)`) и в действиях строк; не в условиях, не в «Запрос», не в «При входе» развилки |
| `irreversible` | внешнее действие, которое нельзя откатить; последний этап фиксации, повторяем без вреда (правило 13) | там же, где `writing` |

- `читает:` — данные машины, объекты, служебные записи, которые читает примитив скрыто (не через аргументы). Эти имена входят в чтения состояния (`Запрос`, `Читает`) в точке вызова (правило 11).
- `пишет:` у `writing` — данные машины, которые примитив меняет на месте; проверка «записи ⊆ данные» его учитывает. У `reading` — только служебные записи исполнителя (не данные машины, не объекты); запись называет, кто её читает (примитив или механика хода), чтобы зависимость была видна (например, замечания проверки формы для хода «исправить»).

**`новый_ид`** (Т-2; встроенный примитив хозяина, как `time_now`; латинское имя в реестре хозяина и в JSON — `new_id`, слово таблицы слов, вид `catalog`; хозяин реализует его через `Uuid.v7()` с эффектами времени и случайности — это деталь хозяина). Без параметров, результат `ид` (раздел 2), класс `reading`, `читает` и `пишет` — `—`; результат недетерминирован: значение выдаёт исполнитель. Недетерминированность снимается так же, как у времени (СТАРТ, раздел 4.5): значение входит в привязку `пусть` и фиксируется в событии `сразу` шага; при повторе шага (правила 12–13) берётся из сохранённого события, а не выдаётся заново. Поэтому `вызвать(новый_ид)` допустим **только** в `пусть` «При входе» операции с записью привязки в данные строкой `сразу`. Консервативное решение: в «Запрос» обращения не допустим даже при `читает: исполнитель` — «Запрос» вычисляется заново при повторном входе и новом запросе (4.2, правило 12), и значение сменилось бы; в развилке, конце, условиях, действиях, `профиль` — тоже нет (раздел 10).

Пример (иллюстрация; данное `ид_сессии` — `?ид`, начальное `пусто`; состояние не из пилота; его JSON-имя `Opening` — строка `| ОТКРЫТИЕ | Opening |` раздела `## Имена`, транслитерация дала бы `Otkrytie`).

```
### ОТКРЫТИЕ — операция
- При входе: пусть новая = вызвать(новый_ид)

| 1 | сразу | — | ид_сессии = новая | ХОД_АГЕНТА |
```

**Результат по роли** (Н-12). Результат, зависящий от литерала роли `разбор`, пишется в реестре записью `по роли { "<роль>": Тип, … }` — закрытая таблица «роль → тип» в самом реестре, других результатов у примитива нет. Проверка (раздел 10) берёт литерал роли из `разбор` стороны, ищет его в таблице реестра и сверяет найденный тип с типом после `->` у `разбор`: литерала нет в таблице или типы различны — ошибка проверки; первый параметр примитива (`итог ОтветАгента`) обязан совпасть с типом `итог` стороны. Запись `по роли` стоит только в графе `результат` реестра и нигде больше типом не служит.

**Смысл таблицы «по роли»** (Я-33). Тип выбирается при проверке, а не при исполнении: у стороны с `разбор` литерал роли постоянен, поэтому значение ответа этой стороны имеет один тип — тип её строки таблицы; события `ответ: Вариант` и «При приёме» стороны проверяются по нему. При исполнении исполнитель зовёт примитив с литералом роли вторым аргументом и получает значение этого типа либо отказ (сбой разбора, раздел 1). Таблица — запись реестра хозяина: в дерево машины (раздел 6) она не входит, дерево несёт у стороны литерал роли и тип после `->`. `читает` примитива может различаться по роли (у `разобрать_ответ_агента` роль `"witness"` ещё читает предложение): в чтения состояния входят чтения той роли, с которой вызван разбор его стороны.

Остальные примитивы примеров (`профиль_стороны`, `контекст_роли`, `закрыть_для_записи`) записываются так же; определения `сложить_расход`, `собрать_использование` в примерах не расписаны, их записи — в выписках пилотов. У `убрать_несостоятельные` скрытые чтения — `порядок_линз`, `находки_линзы`, `ответы_свидетеля` (СВ6).

**Функция без тела в источнике** (ИС6, Н-3, Н-4; решение методики 2026-10-19): функция, у которой в источнике нет тела (в коде автомата только сигнатура), записывается **примитивом хозяина** с классом и описанием по таблицам первоисточника; определением на языке она станет, когда тело появится в источнике (тогда запись переносится в `## Определения`). Правило одно для всех таких функций, чистых и нет; **класс — по сигнатуре источника**: свободная функция без `mut` и без `Objects` — `pure` (вызов как `имя(арг)` везде); метод данных машины без `mut` или функция с `Objects` без `mut` — `reading` (читает данные или объекты, ничего не меняет); с `mut` — `writing` (пишет данные, объекты или буфер); `irreversible` из сигнатуры не выводится, его называет тело или комментарий источника. Сюда входят все такие функции автоматов, которые зовут таблицы «Совещания»: `pure` — `merge_unique` (`объединить_без_повторов`), `not_included_in` (`не_вошедшие_в`), `has_critical`, `desirable`, `desirable_and_significant`, `desirable_and_significant_repeated`, `critical_and_significant_not_repeated`; `reading` — `has_reviewer_questions`, `reviewer_questions`, `all_lens_findings`, `lenses_without_critical`, `build_summary` (`собрать_свод`: записывает `свод[…]` строка СВОДА по результату, сама функция данных не меняет), `proposal_changed_since_attempt`; `writing` — `remove_unsound` (`убрать_несостоятельные`: пишет `находки_линзы`) и `count_in_model_tally` (таблицы её не зовут). Журнал-примитивы без тела (`journal_findings`, `journal_decision`, `journal_machine_data`) формат записывает строками журнала (4.7). Пилотный подсчёт считает такие функции записанными как примитивы. Тела в автоматы этим не вносятся.

## 8. Определения, константы, параметры

`определение имя(арг тип, …) -> тип = выр` — чистая функция; арность 0 допустима; рекурсии нет. Константа — именованное значение с типом. Параметр — значение по умолчанию и переопределение проектом (`проект.<ключ>`).

Пример (пилоты; изменено: `событие_расхода` вместо функции-события кода, ключ-кортеж вместо записи пилота; `слово_да_нет` — для значений параметров журнала, 4.7; `объединить_без_повторов` убрана: у неё в источнике нет тела, она примитив хозяина, раздел 7, Н-4).

```
определение сумма_целых(а ?число, б ?число) -> ?число =
  если есть(а) и есть(б) то (а ?? 0) + (б ?? 0) иначе а ?? б

определение слово_да_нет(б да/нет) -> текст =
  если б то "yes" иначе "no"

определение событие_расхода(u Использование) -> СобытиеЖурнала =
  событие_журнала("agent_usage", session: u.сессия, result: u.результат, model: u.модель.идентификатор,
                  input: текст(u.токены.вход), output: текст(u.токены.выход), reasoning: текст(u.токены.рассуждение),
                  cache_read: текст(u.токены.кэш_чтение), cache_write: текст(u.токены.кэш_запись), cost: текст(u.стоимость))
```

**Файлы определений** (С30). Определения, общие у нескольких машин, лежат в подключаемом файле и подключаются строкой раздела `## Подключения`:

```
определения: <имя> версия <N> хеш <hex12>
```

- **Реестр** (СГ4, СЖ4). `<имя>` — имя файла определений по реестру подключаемых файлов (не путь). Реестр — часть реестра хозяина, того же, где записаны примитивы (раздел 7) и машины (правило 35, [протокол вызова](state-machine-call-protocol.md), раздел J, пункт 6): запись `имя → файл` (путь относительно реестра). Формат файла реестра задаёт хозяин; формат таблиц требует одного: по имени находится ровно один файл, иначе — ошибка проверки таблицы.
- **Шапка файла определений:** `# Определения: <имя>`, элементы списка `- definitions_version: <N>` (целое), `- format: 2.16` и необязательно `- language: ru`/`en` (1а). `версия` строки подключения — точное совпадение с `definitions_version`.
- **Разделы** — `## Типы`, `## Константы`, `## Определения` по порядку, **все три обязательны**; пустой раздел — строка `—`; необязательный `## Имена` (1а, Я-60) — после `## Типы`, только если в нём есть строки. Только чистые определения, типы и константы; без `## Состояния`, без `вызвать` классов reading, writing, irreversible, без `## Подключения`: файл определений других файлов не подключает (циклов нет по построению).
- **Хеш** — первые 12 знаков SHA-256 содержимого файла в UTF-8 после нормализации (Н-8): ведущий BOM отбрасывается (файл с BOM и без него дают один хеш); переводы строк — LF (CRLF и одиночный CR заменяются на LF); у каждой строки убраны пробелы и табуляции в конце; в конце файла ровно один LF (пустые строки в конце убраны, недостающий LF добавлен); 12 знаков хеша — шестнадцатеричные, строчными буквами. Нормализация однозначна: файл без завершающего LF и файл с ним дают один хеш.
- Имена из подключённого файла видны без префикса; совпадение с локальным именем или с именем другого подключённого файла — ошибка проверки таблицы; несовпадение версии или хеша — ошибка проверки таблицы, а не предупреждение.

Пример («Совещание»: арифметика цикла общая у совещания и проверки цикла). Изменено: `потолок_исчерпан` пилота — копия в файле машины, здесь — из подключённого файла; шапка дополнена строкой `format`, поэтому хеш не равен хешу файла пилота (тот без `format`). Хеш ниже — SHA-256 приведённого файла (12 знаков); при переходе 2.15 → 2.16 пересчитан (метод проверен: для файла с `format: 2.15` он даёт прежний `6f718b982246`, с `format: 2.14` — прежний `e7df8843f017`, с `format: 2.13` — прежний `f2075d080095`, для файла с `format: 2.12` и прежней записью `число≥n` — прежний `51e15e557120`).

## 9. Подключаемые фрагменты

Фрагмент (правило 36) — файл формата `fragment`: шапка `# Фрагмент: <Имя>`, элементы списка `- fragment: <латинское_имя>`, `- format: 2.16` (необязательно `- language: ru`/`en`, 1а) и разделы по порядку: `## Параметры`, `## Обязывает`, `## Данные`, необязательный `## Имена` (1а, Я-60), `## Общие события`, `## Состояния`. В тексте параметр стоит как `<параметр>` и подставляется до проверки (правило 34).

**Параметры** — `имя`, `вид`, допустимые значения. Виды: `сигнал` (сигнал стороны, Я-38), `текст`, `[]машина` (имена вложенных машин), `поведение` (закрытый перечень слов фрагмента; смысл — описание исполнителя в тексте фрагмента), `примечание` (текст для читателя). Подключение называет все параметры; пропущенный — ошибка.

**Обязывает** — что фрагмент требует от машины: значения `остановка`, строки «Концов», концы ОСТАНОВЛЕНО и ОШИБКА, сторону `усиленный` вида `enhanced` в «Сторонах» с сигналами `продолжить(слово_человека текст, автор текст, источник текст)` и `<сигнал_остановки>` (к ней обращается ПАУЗА); значение `предыдущее` — всегда обращение: машина стоит только в обращениях и концах, а в концах и ПАУЗЕ ОБЩ 1 и 2 условием отброшены (правило 24; ШМ2).

**Имена фрагмента:** `состояние` (текущее состояние, тип `Состояние`), `предыдущее` (`?Состояние`), `запрос_вызова` (текст; идентификатор запроса, которым запущена машина, даёт исполнитель), `событие.идентификатор`, `конец(состояние)` (каталог), `вложенные`. `состояние` — имя исполнителя (тип `Состояние`); `предыдущее` (`?Состояние`) и `запрос_вызова` (текст; идентификатор запроса, которым запущена машина, значение задаёт исполнитель при запуске) — **данные фрагмента** (таблица «Данные» ниже), а не имена исполнителя (T6). Общие события читают данные фрагмента, `состояние` и `событие.…` без строки чтений; состояния фрагмента — только свои чтения (`Запрос`, `Читает`).

**Значения параметров вида `поведение`** (А5, E10) — закрытые перечни слов; значение вне перечня — ошибка проверки. Эффект называется формально и применяется там, где указано; `право_записи` — примечание для читателя, исполнитель его не вычисляет.

Состояния, события и данные фрагмента входят в машину и в её разделах не повторяются (П-2): в `## Подключения` стоит **только** строка подключения; в `## Состояния` заголовок состояния фрагмента (`### ПАУЗА — обращение`) писать запрещено — повтор состояния, которое принесло подключение, — ошибка проверки («объявлено дважды»). - JSON-имена фрагмента (1а, Я-46): данные фрагмента (`предыдущее`, `запрос_вызова`, `открытые_запросы`) — читаемые имена таблицы слов; JSON-имена сигналов машины называет словарь версии 11 (раздел 2.16, Я-61): `стоп человека` → `human_stop`, `стоп от родителя` → `parent_stop`, `отмена_запроса` → `cancel_request`, `продолжить от родителя` → `parent_continue`, `остановить от родителя` → `parent_halt`; поля сигналов — `слово_человека` → `human_word`, `автор` → `author`, `источник` → `source`, `идентификатор_запроса` → `id` (разделы 2.9, 2.12 словаря); их и параметры фрагмента строит по правилу 1а (Я-53) файл фрагмента, переопределения — его разделом `## Имена` (Я-35, Я-60); сигналы машины — отдельное пространство различимости (1а, Я-58), состояния фрагмента входят в пространство состояний машины.
- Привязки строк фрагмента (`слово_человека`, `автор`, `источник`, `идентификатор_запроса`) — внутренние имена (1а, Я-46): их английские имена задаст английский файл фрагмента, в таблице слов их нет. После подстановки они — привязки строк машины: данное машины с таким именем — ошибка проверки (4.3, Я-26).
- Слова человека (`слова_человека`) — хранилище правила 31, его пишет механика контракта (правило 19); в таблицу «Данные» оно не вносится (раздел 2) и в `все_данные` не входит; в строках его нет. `открытые_запросы` вносит фрагмент (его читают `передать` и `отменить_открытые`); машина строку не повторяет (раздел 2, ША1).

## 10. Проверки таблицы

Таблица слов и язык (Я-1…Я-3): слова `ru` и `en` таблицы [alula-keywords.tsv](alula-keywords.tsv) уникальны в пределах вида; строка `language` ∈ {`ru`, `en`}; язык шапки совпадает с объявленным; ключевое слово не из языка файла — ошибка с номером строки первого постороннего слова (1а); скрипт [check-alula-keywords.py](check-alula-keywords.py) проверяет таблицу (виды слов, в том числе `operator`), сверяет с ней образцы машин и проверяет в них знаки операторов (только ASCII, Я-42), JSON-имена (Я-53, Я-58…Я-60: автоматическое имя; раздел `## Имена` — лишняя строка, имя не объявлено, повтор, нелатинское JSON-имя; коллизия в пространстве; смешанное слово; скобки после имени) и хеш словаря (Я-62); [check-alula-samples.py](check-alula-samples.py) сверяет JSON-имена объявлений двух образцов «Шага агента».

Расширение [check-tables.py](check-tables.py): имена полей, типов и состояний; чтения выражений ⊆ чтений состояния (`Запрос`, `Читает`) по правилу 11 (по обоим значениям `читает`, по спискам `читает` примитивов, у ОШИБКИ — `все_данные`), записи ⊆ данные (включая `пишет` writing-примитивов); границы `число>=n`, «не убывает» и `<=`; достижимость состояний; полнота развилок: строка `иначе` обязательна, если исчерпание не доказано типом (перечисление, вариант без полей, набор литералов — все значения названы), а после доказанного исчерпания написанная `иначе` — предупреждение (4.1, Я-57); исчерпанность «Концов» с учётом `Кроме`; значения `Куда`; события обращения ⊆ события машины; сигналы сторон (Я-38): сигнал события строки обращения ∈ список сигналов стороны обращения, каждый сигнал стороны используется (сигнал без строки в текущем состоянии строкой не принимается и отбрасывается, правила 14, 17, 19; значение параметра `поведение` ∈ перечню; строка `определения:`: имя находится в реестре ровно в одном файле, версия и хеш (по нормализации раздела 8) совпадают с файлом, имена не повторяются, в файле нет `вызвать`, `## Состояния`, `## Подключения`, три раздела на месте; - **Форматирование** (С-1): строка-ключ состояния (4.1) без маркера `- ` допустима при разборе (запись версии 2.5), но проверка форматирования предупреждает — это предупреждение, а не ошибка таблицы; так же предупреждает таблица, стоящая вплотную к элементу списка или к другой таблице (без пустой строки). Проза (П-1): строка-абзац, начинающаяся со слова из перечня ключей (4.1) без маркера `- ` или с опечаткой в нём (`-Сторона:`, `– Читает:`), — предупреждение, иначе опечатка осталась бы молчаливым комментарием. Остальная проза проверок не вызывает. Абзац (Я-12): строка текста вплотную к таблице, заголовку или списку без пустой строки — предупреждение. Объявление (`тип`, `перечисление`, `вариант`, `определение`) вне блока кода — предупреждение (Я-13). Расширение файла проверяет только этот скрипт (Я-18).
- **Подключения и фрагменты** (П-2): в `## Подключения` — только строки подключения (проза, список — ошибка проверки); состояние фрагмента, объявленное заголовком в разделе `## Состояния` машины, — ошибка «объявлено дважды».

**Выпуск для интерпретатора** (И-3). `недостижимо` и `обязательно(пусто)` — дефект программы: процесс останавливает исполнитель (не таблица); состояние машины не откатывается; ответ вызова — конец с `NoResult`; журнал дефекта — на усмотрение исполнителя. Это не ошибка машины (3.3): в ОШИБКУ дефект не ведёт. Отказ вызова при неверном входе — отдельный случай: событие `input_rejected` (раздел 1, И-1).

## 11. Сценарии

Сценарий — события и ожидание: событие (`старт` с входом, `ответ`, `сбой`, `сигнал` стороны или машины с данными, срок) → состояние, структурный журнал (код и параметры, правило 31), подмножество данных, очередь. Сравнение — по этим четырём; прогонщик — в продукте; тот же сценарий прогоняется на автомате методики. Форма записи сценария здесь в целом не задаётся (формат прогонщика — в продукте); формат фиксирует три вещи. **Имя файла** (Я-20): сценарий (`scenario/0`) называется `<имя>.scenario.test.json`; формат сценария не меняется. **Данные события** (П-8): сигнал (стороны или машины) с одним полем данных несёт значение этого поля — текст (например, `продолжить` с полем `автор` — значение `"ivan"`, а не объект); с несколькими полями — объект `{поле: значение}`; без полей — только имя. **Параметры** (П-9): сценарий может нести `params` — таблицу «ключ → значение» с ключами `проект.<ключ>` (раздел 1, «передача значений извне»); не названный параметр остаётся со значением по умолчанию.

## 12. Каталог встроенных функций

## 14. Открытое

- **Эквивалентность по журналу подтверждена частично.** Версия 2.2 реализована интерпретатором; равенство с автоматом по журналу подтверждено на 39 сценариях одной небольшой машины (машина чата); выразимость «Шага агента» и «Совещания» проверена пилотами, прогон их сценариев на автомате и на описании не делался; не реализованы вложенные машины, `Правит`, профиль стороны, `Предел запросов`, `Возвратов формы`, `передать`. Запись дробного (`0.0`, `2.0`, `0.42`, `1e-7`) формат определил, а код её не определяет: совпадение с исполнителем кода проверяется сценарием (ША11).
- **Расхождения источников пилота «Совещание»:** ИС2 — исправлено в источнике: АННУЛ переносит объекты захода в архив и очищает находки, ответы свидетеля и свод аннулированного захода (`без_ключа`), как первоисточник («АННУЛ», «При входе») и код (`Void`); прежний текст пункта («в данных остаются») устарел и заменён (Я-36); ИС6 — у функций `merge_unique`, `not_included_in`, `has_critical`, `desirable*`, `critical_and_significant_not_repeated`, `has_reviewer_questions`, `reviewer_questions`, `all_lens_findings`, `lenses_without_critical`, `build_summary`, `remove_unsound`, `proposal_changed_since_attempt` (полный перечень по классам — раздел 7) в коде только сигнатуры: по правилу раздела 7 они записываются примитивами хозяина с классом по сигнатуре и описанием по таблицам первоисточника, определением на языке станут, когда тело появится в источнике (что считать «линзой» при отброшенной линзе, четыре признака несостоятельного мнения, источник не говорит); ИС8 — запретные идентификаторы линз: инвариант источника называет русские «свидетель», «автор», «вратарь», «человек», а код различает стороны латинскими `witness`, `author`, `gatekeeper`, `enhanced`; ИС9, ИС10 — журнал причины сбоя пишет `"${reason}"` вместо слова кода сбоя, текст отказа ОШИБКИ из `JournalEvent` не определён; ключи `проект.<ключ>` параметров в источниках не названы.
- **Определения, которые не код.** Тела reading-примитивов (`предложение_менялось_с_начала_попытки`, `контекст_роли`, `разобрать_ответ_агента`); четыре признака несостоятельного мнения в `убрать_несостоятельные`; K и P в `собрать_свод`; тексты ворот. Смысл `право_записи` — только текст.
- **Журнал.** Коды `input_rejected`, `machine_data`, `machine_error`, `unclosed_finding`, `meeting_decision`, `open_finding` определены форматом ([state-machine-journal.md](state-machine-journal.md)), но автоматы пока пишут часть этих событий примитивами без тела (`journal_machine_data`, `journal_findings`, `journal_decision`) и ошибки машины кодом не помечают: сверка кода с таблицей их не видит.
- **Предложения реализации, не включённые в формат** (И-4; прогон интерпретатором, версия 2.2):
  - **Часть ответа и срок.** События обращения «часть ответа» (Progress: запрос остаётся открытым, срок продлевается) и «срок» (Expired) с отдельным кодом журнала. В движке и протоколе методики промежуточных частей нет ([протокол](state-machine-call-protocol.md), раздел «Что контракт не покрыл», пп. 15, 17); `RequestExpired` порождает `сбой(Timeout)`.
