# Формат записи стейт-машины таблицами, версия 2

Версия формата: 2, 2026-10-19. Статус: **опытный формат: выразимость проверена пилотами на «Шаге агента» и «Совещании», эквивалентность по журналу не подтверждена.** Правила записи машин — [state-machine-spec.md](state-machine-spec.md); этот файл задаёт формальную запись тех же таблиц: типы, выражения, действия, стороны, фрагменты. Журнал — [state-machine-journal.md](state-machine-journal.md); имена и слова значений — [state-machine-glossary.md](state-machine-glossary.md). При расхождении с правилами спецификации верна спецификация, а этот файл правится вслед за ней.

Цель: машина описывается одним файлом без кода на Нова; исполнитель по описанию даёт то же поведение, что автомат на Нове: те же переходы, тот же структурный журнал, те же данные и очередь. Пока это проверено только выразимостью строк (какие строки автоматов записываются без обходов), а не прогоном по журналу.

Примеры взяты из пилотов (выписки «Шага агента» и «Совещания»); под каждым сказано, что изменено против записи пилота. Конструкция, использованная в примере, определена в разделах 2–5, 7–9 или в каталоге (раздел 12).

## 1. Файл машины

Markdown, разделы по порядку:

| Раздел | Содержимое |
|---|---|
| шапка | `# Машина: <Имя>`; строки `machine: <латинское_имя>`, `machine_version: <строка>`, `format: 2` |
| `## Типы` | записи, варианты, перечисления (раздел 2) |
| `## Константы` | `имя`, `тип`, `значение` |
| `## Параметры` | `имя`, `тип`, `по умолчанию`, `переопределение проектом` (`проект.<ключ>`); значение по умолчанию обязательно: если источник даёт заглушку, пишется она с пометкой «заглушка источника» |
| `## Вход` | поля входа вызова: `имя`, `тип`, примечание; строки `Инвариант: <выражение да/нет над полями>`; значение входа — имя `вход` |
| `## Данные` | `имя`, `тип`, `начальное`, `не убывает`, `пишет` (раздел 2) |
| `## Стороны` | см. ниже |
| `## Определения` | чистые функции (раздел 8) |
| `## Подключения` | подключаемые фрагменты (раздел 9) |
| `## Состояния` | начальное состояние и состояния (раздел 4) |
| `## Концы` | таблица «конец → ответ» (4.7) |
| `## Примитивы` | примитивы хозяина, которые зовёт машина (раздел 7) |

**`## Вход`.** Тип входа — запись из полей этого раздела (правило 35, пункт 1); `начальное: вход.<поле>` берёт значение из входа. Инвариант проверяет исполнитель при приёме запроса; нарушение — отказ вызова (код — в «Открытом»). Идентификатор запроса вызова (`запрос_вызова`) в входе не лежит: его даёт исполнитель (раздел 9).

**`## Стороны`.** Таблица `| имя | вид | профиль | слова ворот |`.

| Вид | Что это |
|---|---|
| `agent` | агент |
| `human` | человек на воротах |
| `enhanced` | усиленный вратарь |
| `human или agent по настройке <имя>` | вратарь: человек, агент — по настройке проекта (правило 19) |
| `machine <имя>(вход: Тип, итог: Тип)` | вложенная машина (правило 35): имя из реестра вызывающего, тип входа запроса, тип результата ответа |

- `профиль` — выражение (допустим `вызвать` reading, раздел 7; доступно имя `сторона` у набора) либо `—`.
- `слова ворот` — у видов `human`, `enhanced`, вратаря: слово или `слово(поле: тип, …)` — слово с данными; слова пишутся как в таблицах машины (в том числе из нескольких слов: `остановить совещание`). Это **все слова стороны**; слова состояния — слова его строк (4.3). У остальных видов — `—`.
- Под таблицей — строка `Предел запросов: <выражение типа число≥1>` (одна на машину, правило 21; не написана — 1).

Пример (пилоты; `human или agent по настройке` и слова — «Шаг агента», `machine` и слова с данными — «Совещание»). Изменено: слова ворот — столбец; слова усиленного — по фрагменту «Пауза» (раздел 9); для «Совещания» вид `lens` заменён `machine`.

## 2. Типы и данные

| Тип | Запись | Замечания |
|---|---|---|
| целое | `число`; `число≥n` (n — целый литерал: `число≥0`, `число≥1`) | выход за границу, как и переполнение, — ошибка машины |
| дробное | `дробное` | с числом не смешивается: `дробное(x)`, `число(x)` явны |
| текст | `текст`; `текст из {"first","retry"}` — закрытый набор значений | сравнение побуквенное; литерал вне набора — ошибка проверки |
| да/нет | `да/нет` | |
| необязательное | `?T` | `?` и `[]` относятся ко всему типу справа, включая `из {…}`: `?текст из {"allow","deny"}` = `?(текст из {"allow","deny"})` |
| список, словарь | `[]T`, `{K: V}` | ключ: текст, число, перечисление, кортеж или запись из таких (структурное равенство) |
| полный словарь | `полный {K: V}` | `K` — перечисление: ключи — все его значения, индекс даёт `V`, а не `?V`; неполный литерал или переопределение проектом — ошибка проверки |
| кортеж | `(T1, T2, …)` — от двух полей | анонимная запись с позиционными полями; значение `(a, b)`, поле — `к.1`, `к.2` |
| запись | `тип Имя { поле: T, … }` | |
| вариант | `вариант Имя { Вар { поле: T, … } Вар }` | вариант без полей — `Вар` без скобок |
| перечисление | `перечисление Имя = Зн "слово" \| Зн "слово" …` | слово — по таблице слов значений словаря; `текст(Имя.Зн)` даёт слово; без слов `текст` перечисления запрещён |
| состояние | `Состояние` | встроенное перечисление имён состояний машины (литерал — имя состояния); слово — латинское имя из заголовка |
| сигнал | `Сигнал` | встроенное перечисление `стоп`, `продолжить`, `остановить`, `отмена` |
| событие журнала | `СобытиеЖурнала` | запись `{ код: текст, параметры: список пар имя–текст }` |

**Данные.** Таблица `| имя | тип | начальное | не убывает | пишет |`.

- `начальное` — выражение или `вход.<поле>`.
- `не убывает` — `—`, `да` или `да, ≤ выр`; выражение может быть любым выражением над константами, параметрами и входом (`наибольшее(1, предел)`); границу проверяет исполнитель после перехода. Если граница в первоисточнике неверна для части значений, она не пишется.
- `пишет` — кто меняет данное: `строки` (строки таблиц состояний, по умолчанию), `механика` (контракт: счётчики попыток, `открытые_запросы`, запрос агента и т. п., правила 14, 15, 21), `строки и механика` (оба; исключение правила 29 называется явно), `фрагмент` (данные подключённого фрагмента). `пишет` задаётся на данное целиком.
- Данные исполнителя (`состояние`, `трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `принятые_запросы`, журнал и хранилища правила 31) в таблицу не вносятся; в `все_данные` (3.1) они не входят.

Пример (пилот «Шаг агента»; границы и `пишет` — как в пилоте).

```
| имя | тип | начальное | не убывает | пишет |
| запрос_агента | ЗапросАгента | вход.запрос_агента | — | строки |
| ход | текст из {"first","retry","continue","fix","permission"} | "first" | — | строки |
| число_повторов | число≥0 | 0 | да, ≤ ЧИСЛО_ПОВТОРОВ | строки |
| число_ходов | число≥0 | 0 | да | строки |
| ход_до_повтора | ?текст из {"first","retry","continue","fix","permission"} | пусто | — | строки |
```

## 3. Выражения

### 3.1 Грамматика

```
выр := литерал | истина | ложь | пусто | имя | выр.поле | выр.N | выр[выр]
     | Тип { поле: выр, … } | Тип.Вариант { поле: выр, … } | Тип.Вариант     запись, вариант с полями, вариант без полей
     | { …выр, поле: выр, … }                        копия записи с заменой полей
     | (выр, выр, …)                                  кортеж (от двух полей)
     | [выр, …] | {выр: выр, …}                       список; словарь (ключ — выражение); [] и {} — пустые
     | не выр | -выр | выр (+|-|*|/|%) выр | выр (==|!=|<|<=|>|>=) выр
     | выр (и|или) выр | выр ?? выр
     | если выр то выр иначе выр | пусть имя = выр в выр
     | выбор выр { альт [| альт]… [если выр] → выр; … ; иначе → выр }       исчерпывающий
     | имя(выр, …)                                    функция каталога или определение (pure)
     | макрос(выр, имя → выр) | свёртка(выр, выр, (имя, имя) → выр)
     | вызвать(примитив, выр, …)                      reading: только в «Вход», «профиль» и в «пусть» «При входе»/«При приёме» (раздел 7)
альт := Тип.Значение | Вариант | Вариант(поле, поле: имя, …) | литерал
```

- **Приоритет** (высший первым): `.`, `[]`, вызов; унарный `-`; `* / %`; `+ -`; сравнения; `не`; `и`; `или`; `??`. `если`, `пусть`, `выбор` захватывают всё справа.
- **Литералы:** целое `12`, дробное `0.0`, текст `"…"`; `истина`, `ложь`; `пусто` — отсутствие значения `?T`. Слово `нет` литералом не служит (правило 30: «нет» спецификации — `пусто` у `?T`).
- **Имена.** Имя — данные, константа, параметр, определение, привязка. Привязка поля события, `пусть` и параметр лямбды видны только в своей области. Функция и имя лежат в разных пространствах: привязанное поле `текст` и вызов `текст(x)` не мешают друг другу.
- **Лямбда** — одноместная (двухместная только у `свёртка`); параметр, который не нужен, пишется `_`; лямбды стоят только в аргументе макроса.
- **Читаемые имена исполнителя** (не вычисления, правило 11): `вход`; `событие.идентификатор` (у любого события); `событие.<поле>` (поле данных события строки или цепочки, правило 13); `сторона` (у набора — идентификатор стороны события; в «профиле» и «Входе» набора — текущая сторона); `состояние`, `предыдущее`, `запрос_вызова` (раздел 9); `запись_перехода` (тип `СобытиеЖурнала`; в «При входе» и «ответе» концов); `все_данные` (запись всех данных машины, без данных исполнителя). Имена `трасса` и `номер_шага` (конверт, правило 31) доступны **только** в выражениях «Входа» стороны вида `machine` — это конверт вызова вложенной машины (правило 35, пункт 1); в условиях и действиях конверт не читается.
- **Из подсчёта методики не вводятся:** `contains`, срезы, постфиксный `?`, сортировка, циклы и рекурсия вне `для каждого`.

Пример выражений (пилот «Шаг агента», определения).

```
определение требует_внимания(в: ВидДействия) -> да/нет =
  выбор в { ВидДействия.Удаление | ВидДействия.Перенос | ВидДействия.Исполнение | ВидДействия.Сеть | ВидДействия.СменаРежима → истина;
            иначе → ложь }

определение пауза_повтора(п: число≥0) -> число =
  свёртка(диапазон(1, п), ПАУЗА_ПОВТОРА, (н, _) → н * 2)
```

### 3.2 Типы выражений

| Правило | Запись |
|---|---|
| Возведение `T` в `?T` | в присвоении полю `?T`, в поле конструктора записи, в аргументе функции с параметром `?T`, в ветке `если`/`выбор`, справа от `??` |
| `если`, `выбор` | ветки `T` и `?T` (или `пусто`) дают `?T`; ветки одного типа — этот тип |
| `??` | `?T ?? T` — `T`; `?T ?? ?T` — `?T`: правый операнд любого из двух типов, результат `T` только при правом `T` |
| `+` | число, дробное (смешивать нельзя), текст (склейка), список одного типа (склейка: сначала левый) |
| `==`, `!=` | структурные для записей, кортежей, списков, словарей, перечислений, `?T`; `T` с `?T` — через возведение (`пусто` не равно значению) |
| `<`, `<=`, `>`, `>=` | число, дробное |
| `выр[ключ]` | словарь: `?V`, отсутствующий ключ — `пусто` (не ошибка); у полного словаря — `V`. Список: `?T`, индекс вне границ — `пусто` |
| Закрытый набор текста | значение выражения — **набор значений**: литерал — одно; `+` — попарные склейки; `если`/`выбор` — объединение веток; `обязательно(x)` — набор `x` без `пусто`; `текст(x)` для перечисления или его подмножества — их слова; присвоение и сравнение с полем `текст из {…}` проверяют вхождение набора |
| `число≥n` | присвоение значения, нарушающего границу, — ошибка машины; статически проверяется там, где значение известно |

Пример (пилот «Шаг агента» и «Совещание»; в «Совещании» `сбойное_обращение` объявлено `?текст из {…}` без `""`: набор после `обязательно` — без пустого значения).

```
остановка = текст(причина)                                     // причина ∈ {СоединениеОборвалось, НетОтветаВСрок, НетРезультата}: набор {"connection_lost","timeout","no_result"}
остановка = обязательно(сбойное_обращение) + "_halt_meeting"   // набор: четыре значения «..._halt_meeting», все входят в набор остановка
```

### 3.3 Вычисление

- Вычисление строгое, слева направо: аргументы функции, поля записи, элементы списка и словаря — в порядке записи; ветви `выбор` — сверху вниз, охрана `если` — после совпадения альтернативы; `пусть` — сначала значение, потом тело. **Ленивы** только `если`, `и`, `или`, `??`: невыбранная ветка и правая часть, которая не нужна, не вычисляются.
- **Язык не тотален.** Частичные операции: `обязательно(x)` при пустом `x` — `недостижимо` (дефект программы: исполнитель останавливается, журнала и перехода в ОШИБКА нет; так ведёт себя `required` автоматов); переполнение `число`, деление на ноль, выход за `число≥n`, `число(x)` вне диапазона — ошибка машины (журнал, переход в ОШИБКА). Индекс словаря и списка частичной операцией не является.
- `если` не вкладывается в ветку другого `если` (три и более исхода — `выбор` с охранами или развилка).
- `текст(x)`: целое — десятичная запись; дробное — кратчайшая запись, перечисление — слово значения; `Состояние` — латинское имя из заголовка; текст — он сам; `пусто` любого из этих типов — `none`. Для `да/нет` и составных типов `текст` не определён.

## 4. Состояния

### 4.1 Общее

Заголовок `### ИМЯ — вид (Latin_имя)`: вид — `обращение`, `операция`, `развилка`, `конец`; латинское имя — для журнала и конверта (поле `state`, параметр `fork`, `текст(Состояние)`), совпадает со словарём ([state-machine-glossary.md](state-machine-glossary.md)). Номер `№` строки = метка `// ИМЯ #n` в первоисточнике. Выбирается **первая** подходящая строка. У каждого состояния — строка `Вход:` (правило 11): у обращения таблица (4.2), у остальных — имена данных, которые читают «При входе», условия и действия состояния, через запятую, или `нет`; чтения reading-примитива (раздел 7) входят в `Вход` по его списку `читает`; `Вход` ОШИБКИ — `все_данные` (все данные машины без данных исполнителя; имена читаются как данные).

**«Куда»:** имя состояния; `предыдущее`; `возврат_подготовки` (правило 24); `то же` (остаться в состоянии; у общих событий); суффикс `, запуск заново` (правило 18); `—` у строки с `ошибка_машины`.

**Умолчание развилки.** Развилка без подходящей строки — `ошибка_машины("fork_no_match", fork: <Latin_имя>)`. Строка `иначе` по правилу 27 допустима: она записывается последней с тем же действием и ведёт `—`; она равна умолчанию. Метка умолчания — следующий номер после последней строки.

### 4.2 Обращение

```
### ИМЯ — обращение (Latin_имя)
Сторона: <имя из «Стороны»>[; набор: <выражение-список идентификаторов>]
Срок тишины: <выражение ?число≥0>
Возвратов формы: <число≥0>                 необязательно, по умолчанию 0
Вход:
| поле запроса | выражение | читает |       читает: сторона | исполнитель
При приёме:                                  необязательно
| событие | действия |
| <событие> | <действия> |
| № | Событие | Условие | Действия | Куда |
```

- **Вход.** `читает: сторона` — поле запроса стороне; `исполнитель` — имя, которое читают строки состояния, а в запрос оно не идёт (`поле запроса` = выражение = имя). Выражения читают данные машины, константы, параметры, `вход`, `сторона` (набор) и — у стороны `machine` — `трасса`, `номер_шага`; допустим `вызвать` reading (вычисляется при входе, до отправки, в порядке строк). Поля запроса стороны `machine` — ровно поля её типа `вход`. Условия, «При приёме» и «Действия» читают только имена из `Вход`, `событие.…`, привязки, константы и параметры (правило 11).
- **Срок тишины.** `пусто`, `0` и `—` — срока нет (у человека и вратаря срока нет, правило 19; у вызова машины срока нет, правило 35, пункт 5).
- **Набор** (правило 21): `Сторона: линза; набор: порядок_линз` — по запросу на каждый идентификатор; `сторона` в «Входе» — идентификатор, для которого строится запрос; `Предел запросов` — раздел «Стороны». Переменные набора (`к_отправке`, `открытые_запросы`) и счётчики попыток — данные с `пишет: механика`.
- **Возвратов формы** — сколько раз исполнитель возвращает стороне ответ не по форме в том же запросе (правило 18).
- **Условие** в строке события — только у общих событий и сигналов фрагмента (правила 23, 35); у строк обращения `—`. Событие, чьё условие ложно, отбрасывается (правило 17, запись в журнал — механика).

Пример (пилот «Совещание», ЛИНЗЫ). Изменено: ключ находок — кортеж вместо записи пилота; имена `трасса`, `номер_шага` вместо reading-примитивов `трасса_вызова`, `номер_шага_вызова`; показаны не все строки «Входа».

```
### ЛИНЗЫ — обращение (Lenses)
Сторона: линза; набор: порядок_линз
Срок тишины: 0
Вход:
| поле запроса | выражение | читает |
| вид | ВидВызывающего.Линза | сторона |
| профиль | вызвать(профиль_стороны, сторона) | сторона |
| сессия | сторона | сторона |
| контекст | вызвать(контекст_роли, КонтекстРоли.Линза { предложение: предложение, ответы_свидетеля: ответы_свидетеля[номер_захода] }) | сторона |
| трасса | трасса | сторона |
| номер_шага | номер_шага | сторона |
| номер_захода | номер_захода | исполнитель |
| к_отправке | к_отправке | исполнитель |
| линзы | линзы | исполнитель |
| ответившие | ответившие | исполнитель |
```

### 4.3 События обращения

Таблица строк `| № | Событие | Условие | Действия | Куда |`. Виды событий:

| Событие | Смысл |
|---|---|
| `ответ`, `ответ(имя)` | результат стороны; `имя` привязывает его целиком |
| `ответ: Вариант(поле, поле: имя, …)`, `ответ: Вариант` | результат — вариант; поля привязываются как имена (`поле: имя` — с переименованием); вариант без полей — без скобок |
| `сбой`, `сбой(причина)`, `сбой(причина ∈ {…})` | отказ или «нет ответа» (правило 16); закрытое подмножество кодов; причина вне набора — `недостижимо` (набор объявлен полным для состояния) |
| `слово(<слово>)`, `слово(<слово>(поле, поле: имя, …))` | слово ворот стороны `human`, `enhanced`, вратаря; слово — из столбца «слова ворот» стороны, поля и их типы — оттуда же |
| `сигнал(<имя>(поле, …))` | сигнал вне контракта (стоп, отмена, сигналы от родителя): только в общих событиях и ПАУЗЕ фрагмента (раздел 9) |
| `сразу` | у операции: переход без события после работы при входе (правило 26) |

- **Привязки.** Любое поле события доступно и как `событие.<поле>`; привязка нужна для краткости. Имя привязки, совпавшее с именем данных машины без переименования, — ошибка проверки (затенения нет). Привязывать можно часть полей.
- **Набор.** События набора несут `сторона`; цепочка развилок за строкой события читает её как `событие.сторона` (правило 13).
- **Слова ворот.** Слова состояния — слова его строк; слово стороны вне строк состояния отвергается как чужое (правило 17). Каждое слово стороны используется хотя бы в одной строке машины (или фрагмента); слово события входит в список стороны.
- «При приёме» — действия ДО перехода (правило 14), раздел 4.4.

Пример (пилоты). Изменено: слова с данными — запись `слово(засчитан(находки: новые))` вместо неопределённой привязки пилота; поля, совпавшие с данными, переименованы.

```
### ХОД_АГЕНТА — обращение (AgentTurn)       // строки 1, 3, 6, 8, 9 пилота «Шаг агента»
| № | Событие | Условие | Действия | Куда |
| 1 | ответ: Закончен(текст, артефакт, расход: полученный) | — | расход = сложить_расход(расход, полученный); текст_ответа = текст; артефакт_ответа = артефакт | ПРОВЕРКА_ОТВЕТА |
| 3 | ответ: ПределЗапросов(расход: полученный) | — | расход = сложить_расход(расход, полученный); остановка = "max_turn_requests"; журнал(turn_requests_exhausted) | УЧЁТ |
| 6 | ответ: ВременнаяОшибка | — | — | ПОВТОР |
| 8 | ответ: НужноРазрешение(запрос_разрешения: запрос) | — | запрос_разрешения = запрос | ПОЛИТИКА |
| 9 | сбой(причина ∈ {КодСбоя.СоединениеОборвалось, КодСбоя.НетОтветаВСрок, КодСбоя.НетРезультата}) | — | остановка = текст(причина); журнал(turn_failed, reason: текст(причина)) | УЧЁТ |

### В3 — обращение (Gate3)                      // строки 1, 2 пилота «Совещание»
| 1 | слово(не засчитан) | — | журнал(pass_probes_not_probes, pass: текст(номер_захода)); номер_захода += 1 | ЗАХОД |
| 2 | слово(засчитан(находки: новые)) | — | номер_захода += 1; находки_В3 = новые | ИТОГ |
```

### 4.4 При приёме

Блок обращения `При приёме:` — таблица `| событие | действия |`. Событие — `ответ`, `ответ(имя)`, `ответ: Вариант(…)` или `сбой`; доступны привязки события и `сторона`. Исполнитель выполняет блок при приёме ответа, до перехода, одной фиксацией с записью в `принятые_запросы` (правило 14); привязки блока (`пусть`) сохраняются вместе с принятым событием и видны его строке и цепочке.

В блоке допустимы: присваивания данным, `+=`, `поле[ключ] = выр`, `для каждого`, `если`, `пусть имя = выр` и `пусть имя = вызвать(reading, …)` (например, разбор артефакта ответа). Недопустимы: `журнал`, `ошибка_машины`, `вызвать` writing и irreversible, переход.

Пример (пилот «Совещание», ЛИНЗЫ; `линзы[сторона]` — `?Линза`, поэтому `обязательно`: в коде записи нет — `недостижимо`). `итог` здесь — разобранный результат линзы (`ИтогЛинзы`), как в пилоте; как он получается из `ОтветАгента` стороны `machine` — в «Открытом».

```
При приёме:
| событие | действия |
| ответ(итог) | пусть л = обязательно(линзы[сторона]) в линзы[сторона] = { …л, потери_подряд: 0, пробы: итог.пробы }; ответившие += 1; находки_линзы[(сторона, номер_захода)] = итог.находки |
| сбой | пусть л = обязательно(линзы[сторона]) в линзы[сторона] = { …л, потери_подряд: л.потери_подряд + 1, пробы: 0 } |
```

### 4.5 Операция

```
### ИМЯ — операция (Latin_имя)
Вход: <имена>
При входе: <пусть-привязки и вызовы>
| № | Событие | Условие | Действия | Куда |
| 1 | сразу | — | <изменения данных, журнал> | ... |
```

«При входе» — работа с внешним миром (правило 10): `пусть имя = <выражение>` и `пусть имя = вызвать(primitive, …)` (reading и writing), вызовы writing и irreversible без результата. Привязка видна дальше в «При входе» и во всех строках состояния; вычисляется один раз за вход. Изменения данных и журнал — в строке `сразу` (правило 29). Событие у операции одно — `сразу`.

Пример (пилот «Шаг агента», СТАРТ и УЧЁТ; «Совещание», ЗАМОК, ВОЗВРАТ, ФИЛЬТР, СВОД). Изменено: запись данных перенесена из «При входе» в строку; `сразу(данные)` заменено привязкой; в ВОЗВРАТЕ условное действие — в строке.

```
### СТАРТ — операция (Start)
Вход: нет
При входе: пусть момент = вызвать(time_now)
| 1 | сразу | — | начато = момент; число_ходов = 1 | ХОД_АГЕНТА |

### УЧЁТ — операция (Accounting)
Вход: запрос_агента, остановка, расход, начато
При входе: пусть сейчас = вызвать(time_now);
           пусть собранное = собрать_использование(запрос_агента, остановка, расход, начато, сейчас)
| 1 | сразу | — | использование = собранное; журнал(событие_расхода(собранное)) | ИТОГ_ШАГА |

### ЗАМОК — операция (Lock)
Вход: порядок_линз
При входе: пусть отпечаток = вызвать(предложение_с_отпечатком); вызвать(закрыть_для_записи, "proposal")
| 1 | сразу | — | копия = отпечаток; к_отправке = порядок_линз; ответившие = 0 | ЛИНЗЫ |

### ВОЗВРАТ — операция (CopyRestore)
Вход: копия
При входе: —
| 1 | сразу | — | если есть(копия) то (предложение = обязательно(копия)) иначе (журнал(copy_restore_no_copy)) | АННУЛ |

### ФИЛЬТР — операция (Filter)
Вход: номер_захода, порядок_линз, находки_линзы, линзы
При входе: вызвать(убрать_несостоятельные, номер_захода);
           пусть без_критических = линзы_без_критических(порядок_линз, находки_линзы, номер_захода)
| 1 | сразу | — | для каждого л в без_критических: линзы[л] = { …обязательно(линзы[л]), пробы: 0 } | СВОД |

### СВОД — операция (Summary)
Вход: номер_захода
При входе: пусть итог = вызвать(собрать_свод, номер_захода)
| 1 | сразу | — | если есть(итог) то (свод[номер_захода] = обязательно(итог)) | РАЗБОР |
```

(`событие_расхода` и `собрать_использование` — определения, пример в разделе 8.)

### 4.6 Развилка

```
### ИМЯ — развилка (Latin_имя)
Вход: <имена>
При входе: пусть имя = <выражение> | пусть имя = вызвать(reading, …)      необязательно
| № | Условие | Действия | Куда |
```

Развилка ничего не делает и не ждёт (правило 9): «При входе» — только `пусть`-привязки (выражение или вызов reading), каждая вычисляется один раз за вход; действия строки меняют данные только в её переходе. Условия не вызывают примитивы: результат вызова читается по привязке.

Пример (пилот «Шаг агента»). Изменено: умолчание без строки `иначе`; пример ПРОВЕРКА_ОТВЕТА не передаёт несуществующий аргумент: чтения `reply_validation` названы в реестре (раздел 7) и входят в `Вход`.

```
### ПОВТОР — развилка (Retry)
Вход: число_повторов, ход
| 1 | число_повторов < ЧИСЛО_ПОВТОРОВ и ход != "retry" | число_повторов += 1; ход_до_повтора = ход; ход = "retry"; журнал(agent_transient_error, retry: текст(число_повторов)) | БЮДЖЕТ |
| 2 | число_повторов < ЧИСЛО_ПОВТОРОВ и ход == "retry" | число_повторов += 1; журнал(agent_transient_error, retry: текст(число_повторов)) | БЮДЖЕТ |
| 3 | число_повторов >= ЧИСЛО_ПОВТОРОВ | остановка = "no_result"; журнал(agent_transient_error_exhausted, retries: текст(ЧИСЛО_ПОВТОРОВ)) | УЧЁТ |

### ПРОВЕРКА_ОТВЕТА — развилка (ReplyCheck)
Вход: число_возвратов, текст_ответа, артефакт_ответа, запрос_агента
При входе: пусть проверка = вызвать(reply_validation)
| 1 | проверка == ПроверкаОтвета.Верна | — | УЧЁТ |
| 2 | проверка == ПроверкаОтвета.Пуста | остановка = "no_result"; журнал(agent_no_result) | УЧЁТ |
| 3 | проверка == ПроверкаОтвета.Нарушена и число_возвратов < ЧИСЛО_ВОЗВРАТОВ_ФОРМЫ | число_возвратов += 1; ход = "fix"; журнал(reply_form_violated) | БЮДЖЕТ |
| 4 | проверка == ПроверкаОтвета.Нарушена и число_возвратов >= ЧИСЛО_ВОЗВРАТОВ_ФОРМЫ | остановка = "form_not_fixed"; журнал(reply_form_not_fixed) | УЧЁТ |
```

Пример развилки цепочки набора (пилот «Совещание», ОТКАЗ): `событие.сторона` — из события ЛИНЗЫ #2.

```
### ОТКАЗ — развилка (Refusal)
Вход: линзы, к_отправке, номер_захода
| 1 | обязательно(линзы[событие.сторона]).потери_подряд == 1 | журнал(lens_dropped, party: событие.сторона, pass: текст(номер_захода)) | ВСЕ_ЗАКРЫТЫ |
| 2 | обязательно(линзы[событие.сторона]).потери_подряд == 2 | сбойное_обращение = "Lenses"; к_отправке = [событие.сторона] + к_отправке | СБОЙ |
```

### 4.7 Конец

```
### ИМЯ — конец (Latin_имя)
Вход: <имена> | все_данные
При входе: <действия>
Кроме: <значение ∈ {…}>        необязательно
```

«При входе» конца — работа с внешним миром и журнал: `пусть`-привязки, `вызвать` (reading, writing, irreversible), `журнал`, условные `если`; данные конец не меняет (правило 29). `Кроме:` — значения набора, с которыми в этот конец не входят: исчерпанность «Концов» проверяется по набору без них; вход с таким значением — `недостижимо`.

**Таблица «Концы»** (правило 35, пункт 2, «конец → ответ»): сначала строка `Результат: <тип ответа машины>`, затем таблица

```
| конец | № | когда | ответ |
```

- `когда` — условие входа: `истина`, `остановка == "…"`, `остановка ∈ {…}`; строки одного конца взаимоисключающи и покрывают набор, по которому ветвятся (кроме `Кроме`); не покрытое значение — ошибка проверки таблицы.
- `ответ` — `Ответ(<значение типа результата>)` или `Отказ(<код КодСбоя>, <текст>)`; конверт ответа (запрос, сторона, трасса, шаг) собирает исполнитель; код отказа берётся из конструктора, отдельного столбца нет.
- В «ответе» доступны данные, `запись_перехода` (поля `код`, `параметры`) и функции каталога.

Пример (пилот «Шаг агента»). Изменено: условное действие и значение-событие закрывают то, что пилот записать не смог (в коде `Time.now()` читается внутри ветки, здесь — до неё; чтение времени следов не оставляет).

```
### ОСТАНОВЛЕНО — конец (Halted)
Вход: использование, запрос_агента, остановка, расход, начато
При входе: пусть сейчас = вызвать(time_now);
           вызвать(close_agent_turn);
           если не есть(использование) то (журнал(событие_расхода(собрать_использование(запрос_агента, остановка, расход, начато, сейчас)))));
           журнал(agent_step_stopped, reason: остановка)
Кроме: остановка ∈ {""}

### ОШИБКА — конец (Errored)
Вход: все_данные
При входе: пусть сейчас = вызвать(time_now);
           вызвать(close_agent_turn);
           если не есть(использование) то (журнал(событие_расхода(собрать_использование(запрос_агента, остановка, расход, начато, сейчас)))));
           журнал(запись_перехода);
           журнал(все_данные)

## Концы
Результат: ОтветАгента
| конец | № | когда | ответ |
| КОНЕЦ | 1 | истина | Ответ(ОтветАгента { текст: текст_ответа, артефакт: артефакт_ответа, использование: обязательно(использование), начало_запроса: если есть(расход) то обязательно(расход).начало_запроса иначе пусто }) |
| ОШИБКА | 1 | истина | Отказ(КодСбоя.НетРезультата, "дефект шага агента: " + запись_перехода.код) |
| ОСТАНОВЛЕНО | 1 | остановка == "no_result" | Отказ(КодСбоя.НетРезультата, остановка) |
| ОСТАНОВЛЕНО | 2 | остановка == "model_refused" | Отказ(КодСбоя.ОтказМодели, остановка) |
| ОСТАНОВЛЕНО | 7 | остановка == "cost_limit" | Отказ(КодСбоя.ПредельТокенов, остановка) |
| ОСТАНОВЛЕНО | 10 | остановка == "pause_halt" | Отказ(КодСбоя.ОстановленоЧеловеком, остановка) |
| ОСТАНОВЛЕНО | 11 | остановка == "cancel_request" | Отказ(КодСбоя.ОтмененоРодителем, остановка) |
```

(В таблице «Концов» показаны не все строки ОСТАНОВЛЕНО; в пилоте их 11. Для «Совещания» четыре строки `остановка == "Witness_halt_meeting"` … `"AuthorQuestion_halt_meeting"` ведут к `Отказ(КодСбоя.ОстановленоЧеловеком, остановка)`, значения вычисляет СБОЙ #2, раздел 3.2.)

## 5. Действия

Список через `;` в порядке записи (правило 29); **каждое действие видит результаты предыдущих** (после `число_повторов += 1` журнал читает новое значение). Действия `вызвать` irreversible записываются в порядке, но исполняются последним этапом фиксации, после сохранения (правило 13); их аргументы вычисляются в точке записи.

| Действие | Смысл | Где |
|---|---|---|
| `поле = выр`; `поле += выр` | присваивание; прибавление (число, дробное, текст, список) | строки, «При приёме» |
| `поле[ключ] = выр` | словарь: вставка или замена; список: существующий индекс, иначе ошибка машины | строки, «При приёме» |
| `поле = без_ключа(поле, ключ)`; `поле = убрать(поле, элемент)` | удаление ключа и элементов | строки, «При приёме» |
| `журнал(код, имя: выр, …)` | событие журнала: `код` — латинский из таблицы шаблонов, значения параметров — `текст` | строки, «При входе» конца |
| `журнал(значение)` | событие, собранное `событие_журнала(…)` или `запись_перехода` | строки, «При входе» конца |
| `журнал(все_данные)` | диагностическая запись всех данных (форма события — «Открытое») | «При входе» ОШИБКИ |
| `пусть имя = выр` | привязка до конца «При входе» и на все строки состояния; также `пусть имя = вызвать(…)` | «При входе», «При приёме» |
| `пусть имя = выр в действия` | локальная привязка | везде |
| `если выр то (действия) [иначе (действия)]` | условное; условие — выражение без вызовов | строки, «При приёме», «При входе» конца |
| `для каждого имя в выр: действия` | конечный список или диапазон; тело — только присваивания и `+=` | строки |
| `вызвать(примитив, арг, …)` | writing и irreversible примитив без результата (допустимость по классам — раздел 7) | по классу |
| `ошибка_машины(код, имя: выр, …)` | журнал `код` и конец ОШИБКА; «Куда» — `—` | строки |
| `передать(вложенным, сигнал)` | сигнал `Сигнал` вложенным из `открытые_запросы`, после фиксации; журнал `signal_passed` на каждого | только фрагмент |
| `отменить_открытые(кроме: вложенные)` | отменить открытые запросы без принятого ответа (правило 18), кроме запросов к названным вложенным | только фрагмент |

## 7. Реестр примитивов и допустимость классов

Запись реестра: `имя`, `параметры` с типами, `результат`, `класс`, `читает`, `пишет`, примечание. Имя — как в реестре хозяина. Чистые функции над данными пишутся не здесь, а в «Определениях»; примитивами остаются разбор текста, чтение объектов, время, закрытие хода, эффекты.

| Класс | Что делает | Вызов `вызвать(имя, …)` допустим |
|---|---|---|
| `pure` | чистая функция хозяина | как функция `имя(арг)` везде |
| `reading` | читает объект, хранилище, время; данные машины не меняет | в «Вход» обращения, в `профиль`, в `пусть` «При входе» (операции, развилки, конца) и «При приёме»; не в условиях и не в действиях строк |
| `writing` | пишет внутри фиксации (данные машины, объекты, буфер) | в «При входе» операции и конца (в том числе `пусть имя = вызвать(…)`) и в действиях строк; не в условиях, не в «Вход», не в «При входе» развилки |
| `irreversible` | внешнее действие, которое нельзя откатить; последний этап фиксации, повторяем без вреда (правило 13) | там же, где `writing` |

- `читает:` — данные машины, объекты, служебные записи, которые читает примитив скрыто (не через аргументы). Эти имена входят в `Вход` состояния в точке вызова (правило 11).
- `пишет:` у `writing` — данные машины, которые примитив меняет на месте; проверка «записи ⊆ данные» его учитывает. У `reading` — только служебные записи исполнителя (не данные машины, не объекты); запись называет, кто её читает (примитив или механика хода), чтобы зависимость была видна (например, замечания проверки формы для хода «исправить»).

Пример реестра (пилоты). Изменено: у `reply_validation` названы скрытые чтения и запись; у `убрать_несостоятельные` — записываемые данные.

```
| имя | параметры | результат | класс | читает | пишет |
| time_now | — | число | reading | — | — |
| reply_validation | — | ПроверкаОтвета | reading | текст_ответа, артефакт_ответа, запрос_агента; объекты: файлы сессии | служебная запись «замечания формы» (читает ход «исправить») |
| close_agent_turn | — | — | irreversible | — | — |
| убрать_несостоятельные | номер_захода: число≥0 | — | writing | находки_линзы | находки_линзы |
```

Остальные примитивы примеров (`профиль_стороны`, `контекст_роли`, `предложение_с_отпечатком`, `закрыть_для_записи`, `собрать_свод`) записываются так же; определения `сложить_расход`, `собрать_использование`, `не_входящие`, `линзы_без_критических` в примерах не расписаны, их записи — в выписках пилотов.

## 8. Определения, константы, параметры

`определение имя(арг: тип, …) -> тип = выр` — чистая функция; арность 0 допустима; рекурсии нет. Константа — именованное значение с типом. Параметр — значение по умолчанию и переопределение проектом (`проект.<ключ>`).

Пример (пилоты; изменено: `событие_расхода` вместо функции-события кода, ключ-кортеж вместо записи пилота).

```
определение сумма_целых(а: ?число, б: ?число) -> ?число =
  если есть(а) и есть(б) то (а ?? 0) + (б ?? 0) иначе а ?? б

определение объединить_без_повторов(а: []Находка, б: []Находка) -> []Находка =
  а + не_входящие(б, а)

определение находки_захода(порядок: []текст, находки: {(текст, число≥0): []Находка}, н: число≥0) -> []Находка =
  свёртка(порядок, [], (акк, л) → акк + (находки[(л, н)] ?? []))

определение событие_расхода(u: Использование) -> СобытиеЖурнала =
  событие_журнала("agent_usage", session: u.сессия, result: u.результат, model: u.модель.идентификатор,
                  input: текст(u.токены.вход), output: текст(u.токены.выход), reasoning: текст(u.токены.рассуждение),
                  cache_read: текст(u.токены.кэш_чтение), cache_write: текст(u.токены.кэш_запись), cost: текст(u.стоимость))
```

## 9. Подключаемые фрагменты

Фрагмент (правило 36) — файл формата `fragment`: шапка `# Фрагмент: <Имя>`, `fragment: <латинское_имя>`, `format: 2` и разделы по порядку: `## Параметры`, `## Обязывает`, `## Данные`, `## Общие события`, `## Состояния`. В тексте параметр стоит как `<параметр>` и подставляется до проверки (правило 34).

**Параметры** — `имя`, `вид`, допустимые значения. Виды: `слово` (слово ворот), `текст`, `[]машина` (имена вложенных машин), `поведение` (закрытый перечень слов фрагмента; смысл — описание исполнителя в тексте фрагмента), `примечание` (текст для читателя). Подключение называет все параметры; пропущенный — ошибка.

**Обязывает** — что фрагмент требует от машины: значения `остановка`, строки «Концов», концы ОСТАНОВЛЕНО и ОШИБКА.

**Имена фрагмента:** `состояние` (текущее состояние, тип `Состояние`), `предыдущее` (`?Состояние`), `запрос_вызова` (текст; идентификатор запроса, которым запущена машина, даёт исполнитель), `событие.идентификатор`, `конец(состояние)` (каталог), `вложенные`.

Подключение в машине (раздел `## Подключения`): `Пауза(слово_остановки: остановить, код_остановки: "pause_halt", вложенные: [], отмена_запросов: прекратить_ход_транспорта, вход_заново: ничего, право_записи: "файлы, которые правит агент; пауза их права не трогает")` — «Шаг агента»; «Совещание» — `слово_остановки: остановить совещание`, `код_остановки: "pause_halt_meeting"`, `вложенные: [шаг_агента]`, `отмена_запросов: без_возврата_в_к_отправке`, `вход_заново: запросы_из_к_отправке`. Состояния, события и данные фрагмента входят в машину и в её разделах не повторяются.

Определение фрагмента «Пауза» в формате. Составлено по раскрытию фрагмента в пилоте «Совещание» и тексту [state-machine-pause-states.md](state-machine-pause-states.md); сам файл фрагмента на формате пилотом не проверялся, его сверка с текстом правил 23, 24, 35 — по строкам. ## 10. Проверки таблицы

## 14. Открытое

- **Эквивалентность по журналу не подтверждена.** Формат проверен только на выразимость строк автоматов двух машин; прогон одних и тех же сценариев на автомате и на описании не делался.
- **Расхождения источников пилота «Совещание»:** ИС2 — АННУЛ переносит объекты захода в архив, но находки, ответы свидетеля и свод этого захода в данных остаются (формат даёт `без_ключа`, что делать — решает первоисточник); ИС6 — у функций `has_reviewer_questions`, `reviewer_questions`, `all_lens_findings`, `lenses_without_critical`, `build_summary`, `remove_unsound`, `proposal_changed_since_attempt` в коде только сигнатуры, определения записаны по описанию, что считать «линзой» при отброшенной линзе, не сказано; ИС7 — вид вызывающего код определяет по записи линз, выписка — константой, равенство держится на инварианте различных идентификаторов; ИС1 — что лежит в `копия` (текст или отпечаток).
- **Определения, которые не код.** Параметры фрагмента `отмена_запросов`, `вход_заново`, `право_записи` — слова закрытого перечня и текст: смысл описывает исполнитель и текст фрагмента, не формат; тела reading-примитивов (`предложение_изменено_с_начала_попытки`, `контекст_роли`, `разобрать_ответ_агента`); четыре признака несостоятельного мнения в `убрать_несостоятельные`; K и P в `собрать_свод`; тексты ворот.
- **Признак «правит объект X»** (правило 14: объект изменился с начала попытки — результат не принимается, запрос идёт заново): у обращения нет свойства и точки вызова проверки.
- **`пишет` для поля внутри записи словаря** (попытка линзы в `линзы[…].попытка`): `пишет` задаётся на данное целиком; обход — отдельное данное `{текст: число≥0}`.
- **Общие определения между файлами** (арифметика цикла общая у совещания и проверки цикла): подключаются только фрагменты, определения копируются.
- **Разбор результата стороны `machine` в варианты** (ПРАВКА, ВОПРОС): событие `ответ: Вариант` требует, чтобы вариантом был сам результат стороны; разбор артефакта (`вызвать(разобрать_ответ_агента, …)` при приёме) и выбор строки по разобранному варианту через развилку `выбор` формат не показывает.
- **Журнал.** Для `журнал(все_данные)` и `журнал_находок` нет кода и шаблона в [state-machine-journal.md](state-machine-journal.md); нет кода журнала для ошибок машины, не связанных с развилкой (переполнение, деление на ноль, выход за `число≥n`) и для нарушения инварианта входа; код отказа вызова при нарушении `Инварианта` `## Вход` не выбран.
- **Запись дробного в `текст(x)`:** целые значения (`0.0`) и малые порядки (`1e-7`) пишет Нова как есть; формат не уточняет, `0.0` или `0`.
- **Порядок `ключи` и `значения`** — порядок первой записи ключа; код автоматов на хеш-таблицах порядка не гарантирует, пока вывод не должен зависеть от порядка.
- **Имена примитивов:** пилоты писали их по-разному (латиницей по реестру хозяина и по-русски); имя берётся из реестра, правило перевода не задано.
- **Источник, не формат.** Инвариант «счётчики ограничены» шага агента неверен для числа ходов при пределе меньше 1 (СТАРТ ставит 1); граница `≤` у него не пишется.
- **JSON-схема и интерпретатор** — вне этого файла (раздел 6).
