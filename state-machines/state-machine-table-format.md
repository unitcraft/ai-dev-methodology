# Формат записи стейт-машины таблицами, версия 2.1

Версия формата: 2.1, 2026-10-19. Статус: **опытный формат; эквивалентность по журналу не подтверждена; выразимость проверена пилотами на версии 2 — «Шаг агента» 123 из 138 единиц подсчёта записаны без оговорок, «Совещание» 222 из 271; после этой версии пилоты прогоняются заново.** Правила записи машин — [state-machine-spec.md](state-machine-spec.md); этот файл задаёт формальную запись тех же таблиц: типы, выражения, действия, стороны, фрагменты. Журнал — [state-machine-journal.md](state-machine-journal.md); имена и слова значений — [state-machine-glossary.md](state-machine-glossary.md). При расхождении с правилами спецификации верна спецификация, а этот файл правится вслед за ней.

Цель: машина описывается одним файлом без кода на Нова; исполнитель по описанию даёт то же поведение, что автомат на Нове: те же переходы, тот же структурный журнал, те же данные и очередь. Пока это проверено только выразимостью строк (какие строки автоматов записываются без обходов), а не прогоном по журналу.

Примеры взяты из пилотов (выписки «Шага агента» и «Совещания»); под каждым сказано, что изменено против записи пилота. Конструкция, использованная в примере, определена в разделах 2–5, 7–9 или в каталоге (раздел 12). Метки в разделе 0 и в скобках текста — номера правок против версии 2.

Markdown, разделы по порядку:

| Раздел | Содержимое |
|---|---|
| шапка | `# Машина: <Имя>`; строки `machine: <латинское_имя>`, `machine_version: <строка>`, `format: 2.1` |
| `## Типы` | записи, варианты, перечисления (раздел 2) |
| `## Константы` | `имя`, `тип`, `значение` |
| `## Параметры` | `имя`, `тип`, `по умолчанию`, `переопределение проектом` (`проект.<ключ>`); значение по умолчанию обязательно: если источник даёт заглушку, пишется она с пометкой «заглушка источника»; ключ проекта, которого источник не называет, — `—` (АМ10) |
| `## Вход` | поля входа вызова: `имя`, `тип`, примечание; строки `Инвариант: <выражение да/нет над полями>`; значение входа — имя `вход` |
| `## Данные` | `имя`, `тип`, `начальное`, `не убывает`, `пишет` (раздел 2) |
| `## Стороны` | см. ниже |
| `## Определения` | чистые функции (раздел 8) |
| `## Подключения` | подключаемые фрагменты (раздел 9) и файлы определений: строки `определения: <имя> версия <N> хеш <hex12>` (раздел 8) |
| `## Состояния` | первая строка `Начальное состояние: ИМЯ`, затем состояния (раздел 4) (А8) |
| `## Концы` | таблица «конец → ответ» (4.7) |
| `## Примитивы` | примитивы хозяина, которые зовёт машина (раздел 7) |

**`## Вход`.** Тип входа — запись из полей этого раздела (правило 35, пункт 1); `начальное: вход.<поле>` берёт значение из входа. Инвариант проверяет исполнитель при приёме запроса; нарушение — отказ вызова (код — в «Открытом»). Идентификатор запроса вызова (`запрос_вызова`) в входе не лежит: его даёт исполнитель (раздел 9).

**`## Стороны`.** Таблица `| имя | идентификатор | вид | профиль | слова ворот |`.

| Вид | Что это |
|---|---|
| `agent` | агент |
| `human` | человек на воротах |
| `enhanced` | усиленный вратарь |
| `human или agent по настройке <имя>` | вратарь: человек, агент — по настройке проекта (правило 19) |
| `machine <имя>(вход: Тип, итог: Тип)[; разбор: <примитив> -> Тип]` | вложенная машина (правило 35): имя из реестра вызывающего, тип входа запроса, тип результата ответа; необязательный разбор результата (см. ниже) |

- `идентификатор` — латинское слово стороны (А6): значение «сторона запроса» словаря ([state-machine-glossary.md](state-machine-glossary.md), раздел 2.14: `agent`, `gatekeeper`, `enhanced`, `witness`, `author`, `session_launch`, `review`, `meeting`, `agent_step`); входит в конверт запроса и ответа и в идентификатор запроса (`<идентификатор>-<номер>`), поэтому попадает в журнал. У стороны с набором (4.2) — `—`: идентификатором служит элемент набора. Идентификаторы сторон машины различны.
- `профиль` — выражение (допустим `вызвать` reading, раздел 7; доступно имя `сторона` у набора) либо `—`; **единственный источник профиля**: поле запроса `профиль` исполнитель берёт отсюда, строка `профиль` во «Входе» — ошибка проверки (T3).
- `слова ворот` — у видов `human`, `enhanced`, вратаря: слово или `слово(поле: тип, …)` — слово с данными; слова пишутся как в таблицах машины (в том числе из нескольких слов: `остановить совещание`). Это **все слова стороны**; слова состояния — слова его строк (4.3). У остальных видов — `—`.
- **`разбор`** (E1) — только у вида `machine`: reading-примитив (раздел 7) с одним параметром типа `итог` и результатом указанного типа. Исполнитель вызывает его при приёме ответа (правило 14), после проверки «Правит» (4.2) и до «При приёме», и **значением ответа** для `ответ(имя)`, `ответ: Вариант(…)` и «При приёме» становится результат разбора; без `разбор` — сам `итог`. Событие `ответ: Вариант` требует, чтобы значение ответа было вариантом. Скрытые чтения примитива (`читает`) входят в `Вход` состояния (правило 11); разбор вызывается один раз за ответ, результат хранится с принятым событием. Разбор по роли — разные примитивы реестра хозяина.
- Под таблицей — строка `Предел запросов: <выражение типа число≥1>` (одна на машину, правило 21; не написана — 1).

## 2. Типы и данные

| Тип | Запись | Замечания |
|---|---|---|
| целое | `число`; `число≥n` (n — целый литерал: `число≥0`, `число≥1`) | выход за границу, как и переполнение, — ошибка машины; `число≥n` и `число` совместимы в обе стороны (границу при присвоении проверяет исполнитель) (АМ4) |
| дробное | `дробное` | с числом не смешивается: `дробное(x)`, `число(x)` явны |
| текст | `текст`; `текст из {"first","retry"}` — закрытый набор значений | сравнение побуквенное; литерал вне набора — ошибка проверки |
| да/нет | `да/нет` | |
| необязательное | `?T` | `?` и `[]` относятся ко всему типу справа, включая `из {…}`: `?текст из {"allow","deny"}` = `?(текст из {"allow","deny"})` |
| список, словарь | `[]T`, `{K: V}` | ключ: текст, число, перечисление, кортеж или запись из таких (структурное равенство) |
| полный словарь | `полный {K: V}` | `K` — перечисление: ключи — все его значения, индекс даёт `V`, а не `?V`; неполный литерал или переопределение проектом — ошибка проверки |
| кортеж | `(T1, T2, …)` — от двух полей | анонимная запись с позиционными полями; значение `(a, b)`, поле — `к.1`, `к.2` |
| запись | `тип Имя { поле: T, … }` | |
| вариант | `вариант Имя { Вар { поле: T, … } Вар }` | вариант без полей — `Вар` без скобок |
| перечисление | `перечисление Имя = Зн "слово" \| Зн "слово" …` | слово — по таблице слов значений словаря; `текст(Имя.Зн)` даёт слово; без слов `текст` перечисления запрещён |

**Данные.** Таблица `| имя | тип | начальное | не убывает | пишет |`.

- `имя` — данное или **путь поля** внутри словаря: `имя[*].поле` (`*` — любой ключ; у вложенного `имя[*].поле.поле`). Строка с путём несёт только `не убывает` и `пишет` и действует на каждое значение словаря; `тип` — тип поля, `начальное` — `—` (значение задаёт строка самого данного) (С11).
- `начальное` — выражение или `вход.<поле>`.
- `не убывает` — `—`, `да` или `да, ≤ выр`; выражение может быть любым выражением над константами, параметрами и входом (`наибольшее(1, предел)`); границу проверяет исполнитель после перехода (у пути — при записи; нарушение — ошибка машины). Если граница в первоисточнике неверна для части значений, она не пишется.
- `пишет` — кто меняет данное: `строки` (всё, что записано в таблицах машины: действия строк, блок «При приёме», writing-примитивы, вызванные из таблиц; по умолчанию), `механика` (записи исполнителя вне текста машины: счётчики попыток, переменные набора, `открытые_запросы`, правила 14, 15, 21), `строки и механика` (оба; исключение правила 29 называется явно), `фрагмент` (данные подключённого фрагмента), `строки и фрагмент` (строки машины и строки фрагмента: у данного `остановка`) (А3, E5). `пишет` задаётся на данное целиком; у пути — своё значение: запись в поле с `пишет: механика` из строки перехода — ошибка проверки таблицы (С11).
- Данные контракта, которые читает машина (`открытые_запросы`, `к_отправке`, счётчики попыток), вносятся в таблицу с `пишет: механика` и входят в `все_данные` (АМ8). Данные исполнителя (`состояние`, `трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `принятые_запросы`, журнал и хранилища правила 31) в таблицу не вносятся и в `все_данные` (3.1) не входят.

Пример (пилоты; границы и `пишет` — как в пилотах, кроме `линзы`: путь поля вместо `строки и механика`).

```
| имя | тип | начальное | не убывает | пишет |
| запрос_агента | ЗапросАгента | вход.запрос_агента | — | строки |
| ход | текст из {"first","retry","continue","fix","permission"} | "first" | — | строки |
| число_повторов | число≥0 | 0 | да, ≤ ЧИСЛО_ПОВТОРОВ | строки |
| число_ходов | число≥0 | 0 | да | строки |
| ход_до_повтора | ?текст из {"first","retry","continue","fix","permission"} | пусто | — | строки |
| остановка | текст из {"", "no_result", "max_tokens", "pause_halt", "cancel_request"} | "" | — | строки и фрагмент |
| попытка_агента | число≥0 | 0 | — | механика |
| номер_захода | число≥1 | 1 | да | строки |
| линзы | {текст: Линза} | словарь(вход.порядок_линз, л → л, л → Линза { идентификатор: л, потери_подряд: 0, пробы: 0, попытка: 0 }) | — | строки |
| линзы[*].попытка | число≥0 | — | да | механика |
| ответы_свидетеля | {число≥0: []ОтветСвидетеля} | {} | — | строки |
```
(Первые семь строк — «Шаг агента», остальные — «Совещание». В `остановка` показана часть набора; полный набор пилота — двенадцать значений. Границы `≤` у `число_ходов` нет: при пределе ходов меньше 1 код даёт 1. `номер_захода` — `число≥1`: в коде `Cycle.new()` и `MachineData.new()` дают 1, меняется только `+= 1` (инвариант «не уменьшается»); `номер_захода - 1` — `число`, 3.2. Строка `линзы` меняет `потери_подряд` и `пробы`, `попытка` — только механика: запись `линзы[к] = { …л, поле: выр }`, не называющая `попытка`, — копирование, а не запись в него.)

## 3. Выражения

### 3.1 Грамматика

```
выр := литерал | истина | ложь | пусто | недостижимо | имя | ( выр ) | выр.поле | выр.N | выр[выр]
     | Тип { поле: выр, … } | Тип.Вариант { поле: выр, … } | Тип.Вариант     запись, вариант с полями, вариант без полей
     | { …выр, поле: выр, … }                        копия записи с заменой полей
     | (выр, выр, …)                                  кортеж (от двух полей)
     | [выр, …] | {выр: выр, …}                       список; словарь (ключ — выражение); [] и {} — пустые
     | не выр | -выр | выр (+|-|*|/|%) выр | выр (==|!=|<|<=|>|>=) выр
     | выр (и|или) выр | выр ?? выр
     | если выр то выр иначе выр | пусть имя = выр в выр
     | выбор выр { альт [| альт]… [если выр] → выр; … ; иначе → выр }       исчерпывающий
     | имя(выр, …[, имя: выр, …])                     функция каталога или определение (pure); именованные аргументы — после позиционных
     | макрос(выр, имя → выр) | свёртка(выр, выр, (имя, имя) → выр)
     | вызвать(примитив, выр, …)                      reading: только в «Вход», «профиль» и в «пусть» «При входе»/«При приёме»; в любой позиции этих выражений (раздел 7)
альт := Тип.Значение | Вариант | Вариант(поле, поле: имя, …) | литерал
```

- **Приоритет** (высший первым): скобки `( )`, `.`, `[]`, вызов; унарный `-`; `* / %`; `+ -`; сравнения; `не`; `и`; `или`; `??`. `если`, `пусть`, `выбор` захватывают всё справа.
- **Литералы:** целое `12`, дробное `0.0`, текст `"…"`; `истина`, `ложь`; `пусто` — отсутствие значения `?T`. Слово `нет` литералом не служит (правило 30: «нет» спецификации — `пусто` у `?T`). `недостижимо` — выражение любого типа: дефект программы, вычисление останавливает исполнитель, как `обязательно(пусто)` (3.3); стоит в ветке `выбор` для варианта, который по контракту не приходит (E1).
- **Имена.** Имя — данные, константа, параметр, определение, привязка. Состояния читают любое имя из своего `Вход`, каким бы ни было его `читает` (T9). Привязка поля события, `пусть` и параметр лямбды видны только в своей области. Функция и имя лежат в разных пространствах: привязанное поле `текст` и вызов `текст(x)` не мешают друг другу.
- **Лямбда** — одноместная (двухместная только у `свёртка`); параметр, который не нужен, пишется `_`; лямбды стоят только в аргументе макроса.
- **Читаемые имена исполнителя** (не вычисления, правило 11): `вход`; `событие.идентификатор` (у любого события); `событие.<поле>` (поле данных события строки или цепочки, правило 13); `сторона` (у набора — идентификатор стороны события; в «профиле» и «Входе» набора — текущая сторона); `состояние` (раздел 9; тип `Состояние`); `запись_перехода` (тип `СобытиеЖурнала`; в «При входе» и «ответе» концов; определена, только когда в ОШИБКУ вошли по `ошибка_машины`, а иных входов в ОШИБКУ нет, А4); `все_данные` (запись всех данных машины, включая данные подключённых фрагментов и данные контракта, 2; без данных исполнителя). `предыдущее` и `запрос_вызова` — не имена исполнителя, а данные фрагмента «Пауза» (раздел 9, T6). Имена `трасса` и `номер_шага` (конверт, правило 31) доступны **только** в выражениях «Входа» стороны вида `machine` — это конверт вызова вложенной машины (правило 35, пункт 1); в условиях и действиях конверт не читается.
- **Из подсчёта методики не вводятся:** `contains`, срезы, постфиксный `?`, сортировка, циклы и рекурсия вне `для каждого`.

Пример выражений (пилот «Шаг агента», определения).

```
определение требует_внимания(в: ВидДействия) -> да/нет =
  выбор в { ВидДействия.Удаление | ВидДействия.Перенос | ВидДействия.Исполнение | ВидДействия.Сеть | ВидДействия.СменаРежима → истина;
            иначе → ложь }

определение пауза_повтора(п: число≥0) -> число =
  свёртка(диапазон(1, п), ПАУЗА_ПОВТОРА, (н, _) → н * 2)
```

### 3.2 Типы выражений

| Правило | Запись |
|---|---|
| Возведение `T` в `?T` | в присвоении полю `?T`, в поле конструктора записи, в аргументе функции с параметром `?T`, в ветке `если`/`выбор`, справа от `??` |
| `если`, `выбор` | ветки `T` и `?T` (или `пусто`) дают `?T`; ветки одного типа — этот тип |
| `??` | `?T ?? T` — `T`; `?T ?? ?T` — `?T`: правый операнд любого из двух типов, результат `T` только при правом `T` |
| `+` | число, дробное (смешивать нельзя), текст (склейка), список одного типа (склейка: сначала левый) |
| `==`, `!=` | структурные для записей, кортежей, списков, словарей, перечислений, `?T`; `T` с `?T` — через возведение (`пусто` не равно значению) |
| `<`, `<=`, `>`, `>=` | число, дробное |
| `выр[ключ]` | словарь: `?V`, отсутствующий ключ — `пусто` (не ошибка); у полного словаря — `V`. Список: `?T`, индекс вне границ — `пусто` |
| Закрытый набор текста | значение выражения — **набор значений**: литерал — одно; `+` — попарные склейки; `если`/`выбор` — объединение веток; `обязательно(x)` — набор `x` без `пусто`; `текст(x)` для перечисления или его подмножества — их слова; присвоение и сравнение с полем `текст из {…}` проверяют вхождение набора. Поле, значение которого склеивается под `обязательно`, объявляется `?текст из {…}` без `""`; пустая строка источника записывается для него `пусто` (в источнике — «нет»), расхождение снимка данных исправляется в источнике (E9) |
| `число≥n` | присвоение значения, нарушающего границу, — ошибка машины; статически проверяется только для литералов и констант; `число≥n` совместимо с `число` в обе стороны. Результат `+`, `-`, `*` над `число≥n` — `число` (без границы): `номер_захода - 1` — `число`, передача его параметру `число≥0` проверяется при вызове (T8, АМ4) |
| `недостижимо` | тип любой: совместимо с `T` и `?T`; в `выбор` не влияет на тип результата |

Пример (пилоты «Шаг агента» и «Совещание»; `сбойное_обращение` объявлено `?текст из {…}` без `""`: набор после `обязательно` — без пустого значения).

```
остановка = текст(причина)                                     // причина ∈ {СоединениеОборвалось, НетОтветаВСрок, НетРезультата}: набор {"connection_lost","timeout","no_result"}
остановка = обязательно(сбойное_обращение) + "_halt_meeting"   // набор: четыре значения «..._halt_meeting», все входят в набор остановка
```

### 3.3 Вычисление

- Вычисление строгое, слева направо: аргументы функции, поля записи, элементы списка и словаря — в порядке записи; ветви `выбор` — сверху вниз, охрана `если` — после совпадения альтернативы; `пусть` — сначала значение, потом тело. **Ленивы** только `если`, `и`, `или`, `??`: невыбранная ветка и правая часть, которая не нужна, не вычисляются.
- **Вызов reading внутри `если`/`выбор`** (E4): выбранная ветка вычисляет вызов, невыбранная — нет (ленивость выше); чтение вызова входит в `Вход` состояния безусловно, по списку `читает` примитива. Вызовы в аргументах вычисляются в порядке записи.
- **Язык не тотален.** Частичные операции: `обязательно(x)` при пустом `x` и `недостижимо` — `недостижимо` (дефект программы: исполнитель останавливается, журнала и перехода в ОШИБКА нет; так ведёт себя `required` автоматов); переполнение `число`, деление на ноль, выход за `число≥n`, `число(x)` вне диапазона — ошибка машины (журнал, переход в ОШИБКА). Индекс словаря и списка частичной операцией не является.
- `если` не вкладывается в ветку другого `если` (три и более исхода — `выбор` с охранами или развилка).
- `текст(x)`: целое — десятичная запись; дробное — кратчайшая десятичная запись, обратимая в то же дробное; целое значение пишется с `.0` (`1.0`, `0.0`); без порядка `e`, если `1e-4 <= |x| < 1e16`, иначе порядок вида `1e-7`, `1.5e20` (строчная `e`, без `+` и без ведущих нулей порядка); NaN и бесконечность — ошибка машины (А1); перечисление — слово значения; `Состояние` — латинское имя из заголовка; текст — он сам; `пусто` любого из этих типов — `none`. Для `да/нет` и составных типов `текст` не определён.

## 4. Состояния

### 4.1 Общее

Заголовок `### ИМЯ — вид (Latin_имя)`: вид — `обращение`, `операция`, `развилка`, `конец`; латинское имя — для журнала и конверта (поле `state`, параметр `fork`, `текст(Состояние)`), совпадает со словарём ([state-machine-glossary.md](state-machine-glossary.md)). Номер `№` строки = метка `// ИМЯ #n` в первоисточнике. Выбирается **первая** подходящая строка. Начальное состояние — первая строка раздела `## Состояния`: `Начальное состояние: ИМЯ` (А8); проверка 34(г) требует, чтобы оно называло состояние раздела. У каждого состояния — строка `Вход:` (правило 11): у обращения таблица (4.2), у остальных — имена данных, которые читают «При входе», условия и действия состояния, через запятую, или `нет`; чтения reading-примитива (раздел 7) входят в `Вход` по его списку `читает`; `Вход` ОШИБКИ — `все_данные` (все данные машины без данных исполнителя; имена читаются как данные).

**«Куда»:** имя состояния; `предыдущее`; `возврат_подготовки` (правило 24); `то же` (остаться в состоянии; у общих событий); суффикс `, запуск заново` (правило 18); `—` у строки с `ошибка_машины`.

**Умолчание развилки.** Развилка без подходящей строки — `ошибка_машины("fork_no_match", fork: "<Latin_имя>")` (значение `fork` — текстовый литерал, АМ6, T10). Строка `иначе` по правилу 27 допустима: она записывается последней с тем же действием (и тем же литералом `fork`) и ведёт `—`; она равна умолчанию. Метка умолчания — следующий номер после последней строки.

### 4.2 Обращение

```
### ИМЯ — обращение (Latin_имя)
Сторона: <имя из «Стороны»>[; набор: <выражение-список идентификаторов>]
Срок тишины: <выражение ?число≥0>
Правит: <данное>; проверка: <reading-примитив>   необязательно (правило 14)
Возвратов формы: <число≥0>                 необязательно, по умолчанию 0
Вход:
| поле запроса | выражение | читает |       читает: сторона | исполнитель
При приёме:                                  необязательно
| событие | действия |
| <событие> | <действия> |
| № | Событие | Условие | Действия | Куда |
```

- **Вход.** `читает: сторона` — поле запроса стороне; `исполнитель` — имя, которое читают строки состояния, а в запрос оно не идёт (`поле запроса` = выражение = имя). Строки состояния, «При приёме», «Срок тишины» читают **любое** имя из `Вход`, с каким бы значением `читает` оно ни стояло (T9). Поле запроса `профиль` во «Входе» не пишется: его даёт столбец `профиль` «Сторон» (T3). Выражения читают данные машины, константы, параметры, `вход`, `сторона` (набор) и — у стороны `machine` — `трасса`, `номер_шага`; допустим `вызвать` reading (вычисляется при входе, до отправки, в порядке строк). Поля запроса стороны `machine` — ровно поля её типа `вход`. Условия, «При приёме» и «Действия» читают только имена из `Вход`, `событие.…`, привязки, константы и параметры (правило 11).
- **Срок тишины.** `пусто`, `0` и `—` — срока нет (у человека и вратаря срока нет, правило 19; у вызова машины срока нет, правило 35, пункт 5). Выражение читает те же имена, что выражения «Входа» (данные, константы, параметры, `вход`, `сторона` у набора), без вызовов; эти имена названы в `Вход` состояния (А7). Вычисляется при входе, после «Входа», до отправки запроса.
- **Правит** (E3, правило 14). `Правит: <данное>; проверка: <примитив>` — ответ стороны правит объект, который отражает данное (`предложение`), и результат нельзя принять, если объект изменился с начала попытки. `проверка` — reading-примитив без параметров с результатом `да/нет`; исполнитель вызывает его при приёме ответа, после проверки открытости запроса и формы и до `разбор` и «При приёме». `истина` — результат не принимается (в `принятые_запросы` не пишется, «При приёме» не выполняется, события нет), запрос отменяется и уходит заново: новая попытка, `Вход` вычисляется заново; запись об этом в журнал — механика исполнителя. «Началом попытки» и сравнением владеет исполнитель, примитив читает его служебную запись и объект (`читает`). Данное из `Правит` обязано записываться в «При приёме» этого состояния (проверка таблицы).
- **Набор** (правило 21): `Сторона: линза; набор: порядок_линз` — по запросу на каждый идентификатор; `сторона` в «Входе» — идентификатор, для которого строится запрос; `Предел запросов` — раздел «Стороны». Переменные набора (`к_отправке`, `открытые_запросы`) и счётчики попыток — данные с `пишет: механика`.
- **Возвратов формы** — сколько раз исполнитель возвращает стороне ответ не по форме (правило 18). У видов, кроме `machine`, — в том же запросе. У стороны `machine` — новым запросом той же стороны с новым идентификатором и замечанием: тот же идентификатор вернул бы готовый ответ (правила 14, 35, пункт 4). Сверку (например, выдержек) делает примитив `разбор` при приёме, сам возврат — механика исполнителя (E7).
- **Условие** в строке события — только у общих событий и сигналов фрагмента (правила 23, 35); у строк обращения `—`. Событие, чьё условие ложно, отбрасывается (правило 17, запись в журнал — механика). Условие `иначе` (E11) допустимо у сигнала: последняя строка того же события, берётся, если условия предыдущих строк этого события не истинны; у остальных событий `иначе` нет.

Пример (пилот «Совещание», ЛИНЗЫ). Изменено: ключ находок — кортеж вместо записи пилота; имена `трасса`, `номер_шага` вместо reading-примитивов `трасса_вызова`, `номер_шага_вызова`; строки `профиль` нет (T3); показаны не все строки «Входа».

Срок тишины: 0

### 4.3 События обращения

Таблица строк `| № | Событие | Условие | Действия | Куда |`. Виды событий:

| Событие | Смысл |
|---|---|
| `ответ`, `ответ(имя)` | значение ответа (результат стороны или результат её `разбор`, раздел 1); `имя` привязывает его целиком |
| `ответ: Вариант(поле, поле: имя, …)`, `ответ: Вариант` | значение ответа — вариант (у стороны `machine` с `разбор` — вариант результата разбора, E1); поля привязываются как имена (`поле: имя` — с переименованием); вариант без полей — без скобок |
| `сбой`, `сбой(причина)`, `сбой(причина ∈ {…})` | отказ или «нет ответа» (правило 16); закрытое подмножество кодов; причина вне набора — `недостижимо` (набор объявлен полным для состояния) |
| `слово(<слово>)`, `слово(<слово>(поле, поле: имя, …))` | слово ворот стороны `human`, `enhanced`, вратаря; слово — из столбца «слова ворот» стороны, поля и их типы — оттуда же |
| `сигнал(<имя>(поле, …))` | сигнал вне контракта (стоп, отмена, сигналы от родителя): только в общих событиях и ПАУЗЕ фрагмента (раздел 9); у строки сигнала допустимо условие `иначе` (4.2) |
| `сразу` | у операции: переход без события после работы при входе (правило 26) |

- **Привязки.** Любое поле события доступно и как `событие.<поле>`; привязка нужна для краткости. Имя привязки, совпавшее с именем данных машины без переименования, — ошибка проверки (затенения нет). Привязывать можно часть полей.
- **Набор.** События набора несут `сторона`; цепочка развилок за строкой события читает её как `событие.сторона` (правило 13).
- **Слова ворот.** Слова состояния — слова его строк; слово стороны вне строк состояния отвергается как чужое (правило 17). Каждое слово стороны используется хотя бы в одной строке машины (или фрагмента); слово события входит в список стороны.
- «При приёме» — действия ДО перехода (правило 14), раздел 4.4.

Пример (пилоты). Изменено: слова с данными — запись `слово(засчитан(находки: новые))` вместо неопределённой привязки пилота; поля, совпавшие с данными, переименованы.

```
### ХОД_АГЕНТА — обращение (AgentTurn)       // строки 1, 3, 6, 8, 9 пилота «Шаг агента»
| № | Событие | Условие | Действия | Куда |
| 1 | ответ: Закончен(текст, артефакт, расход: полученный) | — | расход = сложить_расход(расход, полученный); текст_ответа = текст; артефакт_ответа = артефакт | ПРОВЕРКА_ОТВЕТА |
| 3 | ответ: ПределЗапросов(расход: полученный) | — | расход = сложить_расход(расход, полученный); остановка = "max_turn_requests"; журнал(turn_requests_exhausted) | УЧЁТ |
| 6 | ответ: ВременнаяОшибка | — | — | ПОВТОР |
| 8 | ответ: НужноРазрешение(запрос_разрешения: запрос) | — | запрос_разрешения = запрос | ПОЛИТИКА |
| 9 | сбой(причина ∈ {КодСбоя.СоединениеОборвалось, КодСбоя.НетОтветаВСрок, КодСбоя.НетРезультата}) | — | остановка = текст(причина); журнал(turn_failed, reason: текст(причина)) | УЧЁТ |

### В3 — обращение (Gate3)                      // строки 1, 2 пилота «Совещание»
| 1 | слово(не засчитан) | — | журнал(pass_probes_not_probes, pass: текст(номер_захода)); номер_захода += 1 | ЗАХОД |
| 2 | слово(засчитан(находки: новые)) | — | номер_захода += 1; находки_В3 = новые | ИТОГ |
```

### 4.4 При приёме

Блок обращения `При приёме:` — таблица `| событие | действия |`. Событие — `ответ`, `ответ(имя)`, `ответ: Вариант(…)` или `сбой`; доступны привязки события и `сторона`; значение ответа — результат `разбор` стороны (раздел 1). Исполнитель выполняет блок при приёме ответа, до перехода, одной фиксацией с записью в `принятые_запросы` (правило 14); привязки блока (`пусть`) сохраняются вместе с принятым событием и видны его строке и цепочке. Порядок приёма: открытость запроса и форма, «Правит» (4.2), `разбор`, блок.

В блоке допустимы: присваивания данным, `+=`, `поле[ключ] = выр`, `поле[ключ].поле = выр` (5), `для каждого`, `если`, `пусть имя = выр` и `пусть имя = вызвать(reading, …)` (в любой позиции выражения, 3.1). Недопустимы: `журнал`, `ошибка_машины`, `вызвать` writing и irreversible, переход; writing-вызовы после приёма (например, отметка времени и проверка кеша) пишутся в действиях строки (АМ9). Данные, которые пишет блок, — `пишет: строки` (2).

Пример (пилот «Совещание», ЛИНЗЫ). Изменено: значение `итог` — результат `разбор` стороны `линза` (`ИтогЛинзы`, раздел 1), а не запись пилота; запись в линзу — краткая запись `линзы[сторона].поле = выр` (5): отсутствующая линза — ошибка машины, а не `недостижимо` по `обязательно`.

```
При приёме:
| событие | действия |
| ответ(итог) | линзы[сторона].потери_подряд = 0; линзы[сторона].пробы = итог.пробы; ответившие += 1; находки_линзы[(сторона, номер_захода)] = итог.находки |
| сбой | пусть л = обязательно(линзы[сторона]) в (линзы[сторона].потери_подряд = л.потери_подряд + 1; линзы[сторона].пробы = 0) |
```

Пример (пилот «Совещание», ПРАВКА): свойство «Правит», разбор в вариант `ИтогПравки` и строки по варианту. Изменено: пилот не мог записать ни проверку правила 14, ни выбор строки по варианту результата роли.

```
### ПРАВКА — обращение (AuthorFix)
Сторона: автор
Срок тишины: 0
Правит: предложение; проверка: предложение_изменено_с_начала_попытки
Возвратов формы: 0
Вход:
| поле запроса | выражение | читает |
| контекст | вызвать(контекст_роли, КонтекстРоли.Правка { предложение: предложение, находки_В3: находки_В3, указание_автору: если указание_автору == "" то пусто иначе указание_автору }) | сторона |
| вопрос_автора | вопрос_автора | исполнитель |
При приёме:
| событие | действия |
| ответ(итог) | предложение = выбор итог { Закончена(предложение: п) → п; Вопрос(предложение: п) → п }; вопрос_автора = выбор итог { Закончена → вопрос_автора; Вопрос(вопрос: в) → в } |
| № | Событие | Условие | Действия | Куда |
| 1 | ответ: Закончена | — | указание_автору = "" | ЗАХОД |
| 2 | ответ: Вопрос | — | указание_автору = "" | В7 |
```
(Показаны не все строки «Входа» и строки сбоя. Чтения примитивов `проверка` и `разбор` входят в `Вход` по их спискам `читает`, раздел 7.)

### 4.5 Операция

```
### ИМЯ — операция (Latin_имя)
Вход: <имена>
При входе: <пусть-привязки и вызовы>
| № | Событие | Условие | Действия | Куда |
| 1 | сразу | — | <изменения данных, журнал> | ... |
```

«При входе» — работа с внешним миром (правило 10): `пусть имя = <выражение>` и `пусть имя = вызвать(primitive, …)` (reading и writing), вызовы writing и irreversible без результата. Привязка видна дальше в «При входе» и во всех строках состояния; вычисляется один раз за вход. Запись writing-примитива (его `пишет`) видна следующим за ним привязкам «При входе» и строкам: порядок записи — порядок исполнения (T7). Изменения данных и журнал — в строке `сразу` (правило 29). Событие у операции одно — `сразу`.

Пример (пилот «Шаг агента», СТАРТ и УЧЁТ; «Совещание», ЗАМОК, ВОЗВРАТ, ФИЛЬТР, СВОД). Изменено: запись данных перенесена из «При входе» в строку; `сразу(данные)` заменено привязкой; в ВОЗВРАТЕ условное действие — в строке; в ЗАМКЕ `копия` — текст предложения, `отпечаток_копии` — отпечаток (T1; в источнике исправлено, ИС1); в ФИЛЬТРЕ запись в линзу — краткая запись (С11).

```
### СТАРТ — операция (Start)
Вход: нет
При входе: пусть момент = вызвать(time_now)
| 1 | сразу | — | начато = момент; число_ходов = 1 | ХОД_АГЕНТА |

### УЧЁТ — операция (Accounting)
Вход: запрос_агента, остановка, расход, начато
При входе: пусть сейчас = вызвать(time_now);
           пусть собранное = собрать_использование(запрос_агента, остановка, расход, начато, сейчас)
| 1 | сразу | — | использование = собранное; журнал(событие_расхода(собранное)) | ИТОГ_ШАГА |

### ЗАМОК — операция (Lock)
Вход: предложение, порядок_линз
При входе: пусть отпечаток = вызвать(отпечаток_предложения); вызвать(закрыть_для_записи, "proposal")
| 1 | сразу | — | копия = предложение; отпечаток_копии = отпечаток; к_отправке = порядок_линз; ответившие = 0 | ЛИНЗЫ |

### ВОЗВРАТ — операция (CopyRestore)
Вход: копия
При входе: —
| 1 | сразу | — | если есть(копия) то (предложение = обязательно(копия)) иначе (журнал(copy_restore_no_copy)) | АННУЛ |

### ФИЛЬТР — операция (Filter)
Вход: номер_захода, порядок_линз, находки_линзы, линзы
При входе: вызвать(убрать_несостоятельные, номер_захода);
           пусть без_критических = линзы_без_критических(порядок_линз, находки_линзы, номер_захода)
| 1 | сразу | — | для каждого л в без_критических: линзы[л].пробы = 0 | СВОД |

### СВОД — операция (Summary)
Вход: номер_захода
При входе: пусть итог = вызвать(собрать_свод, номер_захода)
| 1 | сразу | — | если есть(итог) то (свод[номер_захода] = обязательно(итог)) | РАЗБОР |
```

(`событие_расхода` и `собрать_использование` — определения, пример в разделе 8.)

### 4.6 Развилка

```
### ИМЯ — развилка (Latin_имя)
Вход: <имена>
При входе: пусть имя = <выражение, в том числе с вызовом reading в любой позиции>      необязательно
| № | Условие | Действия | Куда |
```

Развилка ничего не делает и не ждёт (правило 9): «При входе» — только `пусть`-привязки (выражение; вызов reading допустим в любой позиции выражения, в том числе в ветке `если`, 3.3), каждая вычисляется один раз за вход; действия строки меняют данные только в её переходе. Условия не вызывают примитивы: результат вызова читается по привязке.

Пример (пилот «Шаг агента»). Изменено: умолчание без строки `иначе`; пример ПРОВЕРКА_ОТВЕТА не передаёт несуществующий аргумент: чтения `reply_validation` названы в реестре (раздел 7) и входят в `Вход`.

```
### ПОВТОР — развилка (Retry)
Вход: число_повторов, ход
| 1 | число_повторов < ЧИСЛО_ПОВТОРОВ и ход != "retry" | число_повторов += 1; ход_до_повтора = ход; ход = "retry"; журнал(agent_transient_error, retry: текст(число_повторов)) | БЮДЖЕТ |
| 2 | число_повторов < ЧИСЛО_ПОВТОРОВ и ход == "retry" | число_повторов += 1; журнал(agent_transient_error, retry: текст(число_повторов)) | БЮДЖЕТ |
| 3 | число_повторов >= ЧИСЛО_ПОВТОРОВ | остановка = "no_result"; журнал(agent_transient_error_exhausted, retries: текст(ЧИСЛО_ПОВТОРОВ)) | УЧЁТ |

### ПРОВЕРКА_ОТВЕТА — развилка (ReplyCheck)
Вход: число_возвратов, текст_ответа, артефакт_ответа, запрос_агента
При входе: пусть проверка = вызвать(reply_validation)
| 1 | проверка == ПроверкаОтвета.Верна | — | УЧЁТ |
| 2 | проверка == ПроверкаОтвета.Пуста | остановка = "no_result"; журнал(agent_no_result) | УЧЁТ |
| 3 | проверка == ПроверкаОтвета.Нарушена и число_возвратов < ЧИСЛО_ВОЗВРАТОВ_ФОРМЫ | число_возвратов += 1; ход = "fix"; журнал(reply_form_violated) | БЮДЖЕТ |
| 4 | проверка == ПроверкаОтвета.Нарушена и число_возвратов >= ЧИСЛО_ВОЗВРАТОВ_ФОРМЫ | остановка = "form_not_fixed"; журнал(reply_form_not_fixed) | УЧЁТ |

Пример вложенного вызова reading (пилот «Совещание», СВЕРКА; E4): отпечаток читается, только если предложение прочитано; `отпечаток_предложения` при нечитаемом предложении — `недостижимо`, поэтому вызов стоит в ветке `если`, а `Вход` СВЕРКИ включает чтения обоих примитивов.

Пример развилки цепочки набора (пилот «Совещание», ОТКАЗ): `событие.сторона` — из события ЛИНЗЫ #2.

```

| 1 | обязательно(линзы[событие.сторона]).потери_подряд == 1 | журнал(lens_dropped, party: событие.сторона, pass: текст(номер_захода)) | ВСЕ_ЗАКРЫТЫ |

### 4.7 Конец

```
### ИМЯ — конец (Latin_имя)
Вход: <имена> | все_данные
При входе: <действия>
Кроме: <значение ∈ {…}>        необязательно
```

«При входе» конца — работа с внешним миром и журнал: `пусть`-привязки, `вызвать` (reading, writing, irreversible), `журнал`, условные `если`, `для каждого` с телом из `журнал(…)` и `если` (E2); данные конец не меняет (правило 29). `Кроме:` — значения набора, с которыми в этот конец не входят: исчерпанность «Концов» проверяется по набору без них; вход с таким значением — `недостижимо`.

**Таблица «Концы»** (правило 35, пункт 2, «конец → ответ»): сначала строка `Результат: <тип ответа машины>`, затем таблица

```
| конец | № | когда | ответ |
```

- `когда` — условие входа: `истина`, `остановка == "…"`, `остановка ∈ {…}`; строки одного конца взаимоисключающи и покрывают набор, по которому ветвятся (кроме `Кроме`); не покрытое значение — ошибка проверки таблицы.
- `ответ` — `Ответ(<значение типа результата>)` или `Отказ(<код КодСбоя>, <текст>)`; конверт ответа (запрос, сторона, трасса, шаг) собирает исполнитель; код отказа берётся из конструктора, отдельного столбца нет.
- В «ответе» доступны данные, `запись_перехода` (поля `код`, `параметры`; значение есть, потому что в ОШИБКУ входят только через `ошибка_машины`, А4) и функции каталога; текст записи целиком — `текст_записи(запись_перехода)` (E8).

Пример (пилот «Шаг агента»). Изменено: условное действие и значение-событие закрывают то, что пилот записать не смог (в коде `Time.now()` читается внутри ветки, здесь — до неё; чтение времени следов не оставляет).

```

## 5. Действия

Список через `;` в порядке записи (правило 29); **каждое действие видит результаты предыдущих** (после `число_повторов += 1` журнал читает новое значение). Действия `вызвать` irreversible записываются в порядке, но исполняются последним этапом фиксации, после сохранения (правило 13); их аргументы вычисляются в точке записи.

| Действие | Смысл | Где |
|---|---|---|
| `поле = выр`; `поле += выр` | присваивание; прибавление (число, дробное, текст, список) | строки, «При приёме» |
| `поле[ключ] = выр` | словарь: вставка или замена; список: существующий индекс, иначе ошибка машины | строки, «При приёме» |
| `поле[ключ].поле = выр` | краткая запись `поле[ключ] = { …поле[ключ], поле: выр }` (С11); ключа нет — ошибка машины, запись не создаётся; поле с `пишет: механика` — ошибка проверки | строки, «При приёме» |
| `поле = без_ключа(поле, ключ)`; `поле = убрать(поле, элемент)` | удаление ключа и элементов | строки, «При приёме» |
| `журнал(код, имя: выр, …)` | событие журнала: `код` — латинский из таблицы шаблонов, значения параметров — `текст` | строки, «При входе» конца, тело `для каждого` в «При входе» конца |
| `журнал(значение)` | событие, собранное `событие_журнала(…)` или `запись_перехода` | строки, «При входе» конца |
| `журнал(все_данные)` | сокращение `журнал(machine_data, data: <запись данных>)`: `<запись данных>` — текст `имя=значение`, пары через `; ` в порядке `## Данные` (сначала данные подключённых фрагментов в порядке подключений); скаляр — по `текст(x)` (`да/нет` — `yes`/`no`), составное значение — JSON (поля записи по порядку полей, ключи словаря и элементы списка в порядке хранения, кортеж — массив) (А2) | «При входе» ОШИБКИ |
| `пусть имя = выр` | привязка до конца «При входе» и на все строки состояния; также `пусть имя = вызвать(…)` | «При входе», «При приёме» |
| `пусть имя = выр в действия` | локальная привязка | везде |
| `если выр то (действия) [иначе (действия)]` | условное; условие — выражение без вызовов | строки, «При приёме», «При входе» конца |
| `для каждого имя в выр: действия` | конечный список или диапазон; тело — присваивания, `+=` и краткая запись (в строках, «При приёме»); `журнал(…)` и `если` (в «При входе» конца) | строки, «При приёме», «При входе» конца |
| `вызвать(примитив, арг, …)` | writing и irreversible примитив без результата (допустимость по классам — раздел 7) | по классу |
| `ошибка_машины(код, имя: выр, …)` | журнал `код` и конец ОШИБКА; «Куда» — `—`; единственный вход в ОШИБКУ, после него определено `запись_перехода` (А4) | строки, общие события |
| `передать(вложенные, сигнал)` | сигнал `Сигнал` машинам `вложенные` (параметр фрагмента, раздел 9) из `открытые_запросы`, после фиксации; журнал `signal_passed` на каждого (T4) | только фрагмент |
| `отменить_открытые(кроме: вложенные)` | отменить открытые запросы без принятого ответа (правило 18), кроме запросов к названным вложенным; эффект — по параметру `отмена_запросов` (раздел 9) | только фрагмент |

## 7. Реестр примитивов и допустимость классов

Запись реестра: `имя`, `параметры` с типами, `результат`, `класс`, `читает`, `пишет`, примечание. Имя — как в реестре хозяина. Чистые функции над данными пишутся не здесь, а в «Определениях»; примитивами остаются разбор текста, чтение объектов, время, закрытие хода, эффекты.

| Класс | Что делает | Вызов `вызвать(имя, …)` допустим |
|---|---|---|
| `pure` | чистая функция хозяина | как функция `имя(арг)` везде |
| `reading` | читает объект, хранилище, время; данные машины не меняет | в «Вход» обращения, в `профиль`, в `пусть` «При входе» (операции, развилки, конца) и «При приёме» (в любой позиции выражения, 3.1), как `разбор` стороны `machine` и `проверка` свойства «Правит» (4.2); не в условиях и не в действиях строк |
| `writing` | пишет внутри фиксации (данные машины, объекты, буфер) | в «При входе» операции и конца (в том числе `пусть имя = вызвать(…)`) и в действиях строк; не в условиях, не в «Вход», не в «При входе» развилки |
| `irreversible` | внешнее действие, которое нельзя откатить; последний этап фиксации, повторяем без вреда (правило 13) | там же, где `writing` |

- `читает:` — данные машины, объекты, служебные записи, которые читает примитив скрыто (не через аргументы). Эти имена входят в `Вход` состояния в точке вызова (правило 11).
- `пишет:` у `writing` — данные машины, которые примитив меняет на месте; проверка «записи ⊆ данные» его учитывает. У `reading` — только служебные записи исполнителя (не данные машины, не объекты); запись называет, кто её читает (примитив или механика хода), чтобы зависимость была видна (например, замечания проверки формы для хода «исправить»).

Пример реестра (пилоты). Изменено: у `reply_validation` названы скрытые чтения и запись; у `убрать_несостоятельные` — записываемые данные; последние три строки — примитивы для `Правит`, `разбор` и вложенного чтения (4.2, 4.6, раздел 1). Журнал-примитивов `журнал_находок`, `журнал_решения` в реестре нет: это строки журнала (4.7).

```
| имя | параметры | результат | класс | читает | пишет |
| time_now | — | число | reading | — | — |
| reply_validation | — | ПроверкаОтвета | reading | текст_ответа, артефакт_ответа, запрос_агента; объекты: файлы сессии | служебная запись «замечания формы» (читает ход «исправить») |

## 8. Определения, константы, параметры

`определение имя(арг: тип, …) -> тип = выр` — чистая функция; арность 0 допустима; рекурсии нет. Константа — именованное значение с типом. Параметр — значение по умолчанию и переопределение проектом (`проект.<ключ>`).

Пример (пилоты; изменено: `событие_расхода` вместо функции-события кода, ключ-кортеж вместо записи пилота; `слово_да_нет` — для значений параметров журнала, 4.7).

```
определение сумма_целых(а: ?число, б: ?число) -> ?число =
  если есть(а) и есть(б) то (а ?? 0) + (б ?? 0) иначе а ?? б

определение слово_да_нет(б: да/нет) -> текст =
  если б то "yes" иначе "no"

определение объединить_без_повторов(а: []Находка, б: []Находка) -> []Находка =
  а + не_входящие(б, а)

определение находки_захода(порядок: []текст, находки: {(текст, число≥0): []Находка}, н: число≥0) -> []Находка =
  свёртка(порядок, [], (акк, л) → акк + (находки[(л, н)] ?? []))

определение событие_расхода(u: Использование) -> СобытиеЖурнала =
  событие_журнала("agent_usage", session: u.сессия, result: u.результат, model: u.модель.идентификатор,
                  input: текст(u.токены.вход), output: текст(u.токены.выход), reasoning: текст(u.токены.рассуждение),
                  cache_read: текст(u.токены.кэш_чтение), cache_write: текст(u.токены.кэш_запись), cost: текст(u.стоимость))
```

**Файлы определений** (С30). Определения, общие у нескольких машин, лежат в подключаемом файле и подключаются строкой раздела `## Подключения`:

```
определения: <имя> версия <N> хеш <hex12>
```

- `<имя>` — имя файла определений по реестру подключаемых файлов (не путь); `версия` — точное совпадение с версией в шапке подключаемого файла (`definitions_version`); `хеш` — первые 12 знаков SHA-256 содержимого файла, нормализованного к LF, без завершающих пробелов строк.
- Подключаемый файл — markdown с разделами `## Типы`, `## Константы`, `## Определения`: только чистые определения и данные без состояния; без `## Состояния` и без `вызвать` классов reading, writing, irreversible.
- Имена из подключённого файла видны без префикса; совпадение с локальным именем или с именем другого подключённого файла — ошибка проверки таблицы; циклические подключения запрещены; несовпадение версии или хеша — ошибка проверки таблицы, а не предупреждение.

## 9. Подключаемые фрагменты

Фрагмент (правило 36) — файл формата `fragment`: шапка `# Фрагмент: <Имя>`, `fragment: <латинское_имя>`, `format: 2.1` и разделы по порядку: `## Параметры`, `## Обязывает`, `## Данные`, `## Общие события`, `## Состояния`. В тексте параметр стоит как `<параметр>` и подставляется до проверки (правило 34).

**Параметры** — `имя`, `вид`, допустимые значения. Виды: `слово` (слово ворот), `текст`, `[]машина` (имена вложенных машин), `поведение` (закрытый перечень слов фрагмента; смысл — описание исполнителя в тексте фрагмента), `примечание` (текст для читателя). Подключение называет все параметры; пропущенный — ошибка.

**Обязывает** — что фрагмент требует от машины: значения `остановка`, строки «Концов», концы ОСТАНОВЛЕНО и ОШИБКА.

**Имена фрагмента:** `состояние` (текущее состояние, тип `Состояние`), `предыдущее` (`?Состояние`), `запрос_вызова` (текст; идентификатор запроса, которым запущена машина, даёт исполнитель), `событие.идентификатор`, `конец(состояние)` (каталог), `вложенные`. `состояние` — имя исполнителя (тип `Состояние`); `предыдущее` (`?Состояние`) и `запрос_вызова` (текст; идентификатор запроса, которым запущена машина, значение задаёт исполнитель при запуске) — **данные фрагмента** (таблица «Данные» ниже), а не имена исполнителя (T6). Общие события читают данные фрагмента, `состояние` и `событие.…` без `Вход`; состояния фрагмента — только свои `Вход`.

**Значения параметров вида `поведение`** (А5, E10) — закрытые перечни слов; значение вне перечня — ошибка проверки. Эффект называется формально и применяется там, где указано; `право_записи` — примечание для читателя, исполнитель его не вычисляет.

| Параметр | Слово | Эффект | Где действует |
|---|---|---|---|
| `отмена_запросов` | `механика` | отмена открытых запросов без принятого ответа — только механика контракта (запросы к человеку закрываются) | `отменить_открытые` (ОБЩ 1, 2, 5) |
| `отмена_запросов` | `без_возврата_в_к_отправке` | как `механика`; отменённые запросы набора в `к_отправке` не возвращаются | то же |
| `отмена_запросов` | `прекратить_ход_транспорта` | как `механика`; кроме того, ход у транспорта агента прекращается, а удержанный ход закрывается при входе в ОСТАНОВЛЕНО | то же |
| `вход_заново` | `ничего` | повторный вход в сохранённое состояние — только по правилу 12 (новый запрос, если по нему нет принятого) | `Куда: предыдущее` (ПАУЗА 1, 3) |
| `вход_заново` | `запросы_из_к_отправке` | после повторного входа в обращение набора уходят запросы сторонам, перечисленным в `к_отправке` | то же |

Подключение в машине (раздел `## Подключения`): `Пауза(слово_остановки: остановить, код_остановки: "pause_halt", вложенные: [], отмена_запросов: прекратить_ход_транспорта, вход_заново: ничего, право_записи: "файлы, которые правит агент; пауза их права не трогает")` — «Шаг агента»; «Совещание» — `слово_остановки: остановить совещание`, `код_остановки: "pause_halt_meeting"`, `вложенные: [шаг_агента]`, `отмена_запросов: без_возврата_в_к_отправке`, `вход_заново: запросы_из_к_отправке`. Состояния, события и данные фрагмента входят в машину и в её разделах не повторяются.

Определение фрагмента «Пауза» в формате. Составлено по раскрытию фрагмента в пилоте «Совещание» и тексту [state-machine-pause-states.md](state-machine-pause-states.md); сам файл фрагмента на формате пилотом не проверялся, его сверка с текстом правил 23, 24, 35 — по строкам. Изменено против пилота: `слово_остановки` и `код_остановки` — параметры; события от родителя — `сигнал(…)`; значения `остановка` — `<код_остановки>`; `передать(вложенные, …)`; ОБЩ 6 — `ошибка_машины`; во «Входе» ПАУЗЫ `обязательно(предыдущее)`.

## 10. Проверки таблицы

Расширение [check-tables.py](check-tables.py): имена полей, типов и состояний; чтения выражений ⊆ `Вход` по правилу 11 (по обоим значениям `читает`, по спискам `читает` примитивов, у ОШИБКИ — `все_данные`), записи ⊆ данные (включая `пишет` writing-примитивов); границы `число≥n`, «не убывает» и `≤`; достижимость состояний; полнота развилок (умолчание, строка `иначе` — допустима); исчерпанность «Концов» с учётом `Кроме`; значения `Куда`; события обращения ⊆ события машины; слова ворот: слово события ∈ список стороны, каждое слово стороны используется; `сбой(причина ∈ …)` ⊆ `КодСбоя`; класс примитива допустим в позиции вызова; закрытые наборы текста (вхождение вычисленного набора, 3.2); привязка поля события не совпадает с данными; полный словарь; типы `T`/`?T`; журнал: код ↔ таблица шаблонов, имена параметров ↔ шаблон (`fork`), значения — `текст`; слова перечислений ↔ словарь; параметры подключённого фрагмента названы и подходят по виду; значения `остановка` фрагмента ∈ набору машины и в «Концах»; нет данных исполнителя и конверта в чтениях условий (правило 31); `Начальное состояние` названо; идентификаторы сторон латинские и различны; `Срок тишины` читает только имена `Вход`; `разбор` — reading-примитив с параметром типа `итог` и результатом названного типа, `ответ: Вариант` — только для варианта; `Правит`: примитив — reading без параметров, результат `да/нет`, данное записывается в «При приёме» состояния; запись по пути `имя[*].поле` сверяется с пометками `пишет` и `не убывает` по шаблону `[*]`, запись в поле с `пишет: механика` из строки — ошибка; значение параметра `поведение` ∈ перечню; строка `определения:`: версия и хеш совпадают с файлом, имена не повторяются, подключения без циклов, в файле нет `вызвать` и `## Состояния`; коды журнала формата таблиц — в таблице шаблонов (подраздел «События формата таблиц» файла журнала).

## 14. Открытое

- **Эквивалентность по журналу не подтверждена.** Формат проверен только на выразимость строк автоматов двух машин; прогон одних и тех же сценариев на автомате и на описании не делался.
- **Расхождения источников пилота «Совещание»:** ИС2 — АННУЛ переносит объекты захода в архив, но находки, ответы свидетеля и свод этого захода в данных остаются (формат даёт `без_ключа`, что делать — решает первоисточник); ИС6 — у функций `has_reviewer_questions`, `reviewer_questions`, `all_lens_findings`, `lenses_without_critical`, `build_summary`, `remove_unsound`, `proposal_changed_since_attempt` в коде только сигнатуры, определения записаны по описанию, что считать «линзой» при отброшенной линзе, не сказано; ИС8 — запретные идентификаторы линз: инвариант источника называет русские «свидетель», «автор», «вратарь», «человек», а код различает стороны латинскими `witness`, `author`, `gatekeeper`, `enhanced`; ключи `проект.<ключ>` параметров в источниках не названы.
- **Определения, которые не код.** Тела reading-примитивов (`предложение_изменено_с_начала_попытки`, `контекст_роли`, `разобрать_ответы_свидетеля`, `разобрать_правку`, `разобрать_итог_линзы`); четыре признака несостоятельного мнения в `убрать_несостоятельные`; K и P в `собрать_свод`; тексты ворот. Смысл `право_записи` — только текст.
- **Журнал.** Нет кода журнала для ошибок машины, не связанных с развилкой (переполнение, деление на ноль, выход за `число≥n`) и для нарушения инварианта входа; код отказа вызова при нарушении `Инварианта` `## Вход` не выбран. Коды `machine_data`, `unclosed_finding`, `meeting_decision`, `open_finding` определены форматом ([state-machine-journal.md](state-machine-journal.md)), но автоматы пока пишут эти события примитивами без тела (`journal_machine_data`, `journal_findings`, `journal_decision`): сверка кода с таблицей их не видит.
- **Реестр подключаемых файлов определений** (С30) не задан: строка `определения:` называет файл по имени из реестра, а где реестр и как он ведётся, формат не говорит; не сказано, может ли сам файл определений подключать другие (запрет циклов предполагает это, а разделы файла — только `## Типы`, `## Константы`, `## Определения`); ключ версии в шапке назван `definitions_version`.
- **Порядок `ключи` и `значения`** — порядок первой записи ключа; код автоматов на хеш-таблицах порядка не гарантирует, пока вывод не должен зависеть от порядка.
- **Имена примитивов:** пилоты писали их по-разному (латиницей по реестру хозяина и по-русски); имя берётся из реестра, правило перевода не задано.
- **Источник, не формат.** Инвариант «счётчики ограничены» шага агента неверен для числа ходов при пределе меньше 1 (СТАРТ ставит 1); граница `≤` у него не пишется.
- **JSON-схема и интерпретатор** — вне этого файла (раздел 6).
