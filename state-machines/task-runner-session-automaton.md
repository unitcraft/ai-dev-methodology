# Запуск сессии: код автомата

Стейт-машина запуска одной сессии агента — ворота профиля и цены (В2), проверка объёма (ОБЪЁМ, В1), вызов вложенной машины «Шаг агента» (СЕССИЯ), разбор итога сессии (РАЗБОР_ИТОГА) и ворота сбоя (В13), — записанная кодом на Нове как реализация протокола `Автомат` движка [state-machine-engine-automaton.md](state-machine-engine-automaton.md): данные машины, перечисления `Состояние` и `Событие`, переход `перейти(состояние, событие)` как `match`, роли (входы и результаты вызова шага агента и обращений к человеку на воротах), работа операции РАЗБОР_ИТОГА, ответ по концу по контракту машины. Всё общее — конверт запроса и ответа, исполнитель, снимок и хранилище, общие события «стоп/продолжить/отмена», цикл, фиксации — в движке и здесь не повторяется. Нормы — [task-runner.md](../task-runner.md) (словарь, ворота В1, В2, В13, профили запуска, форматы файлов) и [task-sessions.md](../task-sessions.md) (коды сессий).

**Первоисточник — [task-runner-session-states.md](task-runner-session-states.md)** (машина «Запуск сессии»: таблицы состояний, общие события, «Контракт машины», «Решения при переводе»); правила формы — [state-machine-spec.md](state-machine-spec.md). Этот файл — производная запись того же автомата, не второй источник истины: при расхождении верен первоисточник, этот файл правится вслед за ним. Язык записи — Нова, https://github.com/nv-lang/nova. **Код не компилировался и не проверялся компилятором Нова:** это псевдокод в синтаксисе Нова; соглашения записи, помеченные места (`// псевдокод:`), подтверждённое и неподтверждённое спецификацией — в [state-machine-engine-automaton.md](state-machine-engine-automaton.md), здесь только относящееся к запуску сессии. Опытный статус и отличия от ранее написанной схемы — в шапке первоисточника; раннером эта машина не исполняется (раннер исполняет [task-runner-pseudocode.md](task-runner-pseudocode.md), помеченный устаревшим). Вызывают эту машину верхняя машина раннера — [task-runner-automaton.md](task-runner-automaton.md) (первоисточник — [task-runner-states.md](task-runner-states.md); состояние ЗАПУСК_СЕССИИ) и проверка цикла — [task-runner-review-automaton.md](task-runner-review-automaton.md) (первоисточник — [task-runner-review-states.md](task-runner-review-states.md); то же состояние). Оба вызова идут по контракту вызова движка (`Вызываемое`, эффект `Связь`: запрос уходит как `ЗапросРоли`, ответ приходит сообщением), не прямым вызовом функций; сама машина из состояния СЕССИЯ так же зовёт вложенную машину шага агента — [state-machine-agent-step-automaton.md](state-machine-agent-step-automaton.md) (первоисточник — [state-machine-agent-step-states.md](state-machine-agent-step-states.md)); общие типы (`ИтогСессии`, `Находка`, `Свод`, `ВходЗапускаСессии`, `ИтогЗапускаСессии`, `ЗапросАгента`, `ОтветАгента`, `ВидВызывающего`, `ПрофильАгента`, `ПределыАгента`) объявлены в слое методики — [state-machine-methodology-automaton.md](state-machine-methodology-automaton.md). Имя файла — по `AGENTS.md`, «Вынесенные алгоритмы», форма `automaton`.

## Соглашения записи

1. **Типы и идентификаторы** — по [движку](state-machine-engine-automaton.md), пункты 1–3: русские имена. Общие типы данных (`ИтогСессии`, `Находка`, `Свод`, `ВходЗапускаСессии`, `ИтогЗапускаСессии`, `ЗапросАгента`, `ОтветАгента`, `ВидВызывающего`, `ПрофильАгента`, `ПределыАгента`) объявлены один раз в слое методики [state-machine-methodology-automaton.md](state-machine-methodology-automaton.md) и подключены здесь; их таблица соответствия именам блока «Типы на Нове» — там же. Вход паузы (`ВходПаузы`) и сигнатуры `объём_запуска`, `остановить_группу_агента` — тоже из слоя; вариант `ВходРоли` для входа паузы — `ВходПаузыРоли`. Собственных типов данных у этой машины нет. Запись автомата `РазборСессии` — итог разбора артефакта сессии для операции РАЗБОР_ИТОГА. **Значения перечислений** с совпадающими именами в разных перечнях (`План`, `Требования`, `Вопрос`, `Готово`) пишутся с именем типа (`ИтогСессии.План`).
2. **Данные события.** Поля варианта события берутся образцом в `match`: `Сбой { причина } => …`; при совпадении имени поля с переменной машины поле переименовывается: `Ответ_сессии { итог_сессии: итог }`. «Сторона события» и идентификатор события — `событие.сторона`, `событие.идентификатор` (конверт `Входящее` движка, правила 13 и 31). Служебные операции переходу даёт `среда` (журнал, слова человека, сигналы вложенным, данные движка `открытые_запросы`, `предыдущее`, `запрос_вызова`).
3. **Строка таблицы — ветка кода.** Перед каждой строкой первоисточника (условие или событие, «Что меняется», «Куда») стоит комментарий `// <СОСТОЯНИЕ> #<номер строки>: …` с её текстом; у обращения в скобках — данные события; порядок строк как в первоисточнике. «Куда» записано как `Куда(<СОСТОЯНИЕ>)`; «запуск заново» — `Заново(<СОСТОЯНИЕ>)`; «Куда: предыдущее» — у ПАУЗЫ в движке (`Куда(@машина.состояние_по_имени(предыдущее))`). Строка «иначе» развилки — последняя ветка, ведёт в `ОШИБКА` через `среда.ошибка_машины(…)`. Строки «Вход», «Выход», «При входе», «Сторона» и одна строка простыми словами на состояние — комментарии `//` у состояния. Общие события (две строки «стоп» и четыре строки «отмена_запроса») записаны в движке (`общие_события`); `общее` машины сводит к ним её события. Состояние ПАУЗА и его четыре строки подключены фрагментом «Пауза» ([state-machine-pause-states.md](state-machine-pause-states.md)): события паузы разбирает движок (`общие_события`), у машины остаются ветка `ПАУЗА => НеЖдёт`, хуки `состояние_паузы`, `причина_остановки_в_паузе`, `состояние_по_имени` и сведение событий паузы в `общее`.
4. **Строки `// псевдокод:`** и перечень подтверждённого спецификацией — в [движке](state-machine-engine-automaton.md), пункт 5. Здесь дополнительно: функции без тела (сигнатуры механики и чтения внешних объектов); алиас `type Окружение alias Среда[…]` (как в машине проверки цикла); импорт `use` общих типов из слоя методики — разрешение вне записи; значения перечислений с именем типа. Неподтверждённое спецификацией Нова, используемое здесь (как и в машине проверки цикла): объявление `module`, `ro` на уровне модуля (константы), `return` внутри `if` в теле функции. Срок бездействия не задан: у обращений этой машины `0` (исполнитель «нет ответа» не порождает).
5. **Уточнения записи автомата сверх первоисточника:** (а) метод `событие_ответа` — метод протокола `Автомат`: отображение результата роли в событие; (б) вложенная сторона — поле `вложенная` описания обращения (`Одна`): у СЕССИИ `true` (вложенная машина шага агента), у остальных обращений `false`; число возвратов ответа не по форме — поле `возвратов_формы`: `0` у всех (форму проверяет и исправляет шаг агента); метод `при_возобновлении` — заглушка (подготовки при возобновлении нет); (в) `ЗапросАгентаРоли` — вариант `ВходРоли` для обращения СЕССИЯ: запрос вложенной машины шага агента (`ЗапросАгента`, его собирает `вход_запроса` по входу СЕССИИ); код сессии — поле `сессия` (Текст); по коду ветвятся запуск сессии, профиль и промпт — механика исполнителя («Реализация на файлах» первоисточника), машина по нему не ветвится (правило 6), суммы по видам сессий не заводятся; (г) `запрос_вызова` — всегда `запрос.идентификатор_запроса` (решение о `""` у верхнего уровня открыто, см. движок, пункт 6); (д) `состояние_по_имени` записано полным `match` по именам обращений; (е) необязательные поля входа вызова (`источник_запуска`, `фаза`, `заход_запуска`) — `Option`: тип входа один на раннер и проверку цикла.
6. **Данные машины — поля типа `Машина`**: поля названы как переменные раздела «Данные» первоисточника (правило 25), начальные значения — в `Машина.new()`, по входу запуска — `Машина.из_входа` (код сессии, источник, фаза, номер захода и задание приходят в запросе). Данные движка (конверт, очереди запросов, журнал, слова человека, тексты сбоев) — в `СостояниеДвижка` движка. Внешние объекты: `свод` и `находки_проверки` — поля (их пишет операция РАЗБОР_ИТОГА в `выполнить_операцию`, правило 29), остальные читаются через `Объекты` (`объём_запуска()`). **Именование читателей по ключу:** читатель элемента поля называется по полю (`@свод(номер)`, `@находки_проверки(номер)`). **Поле и метод с одним именем** (`свод`, `находки_проверки`) — сознательное решение: в Нове допустимо (`spec/decisions/03-syntax.md`, правило `@name`), правило 25 соблюдено (имя одной сущности одно).
7. **`недостижимо(текст)`** (определено в движке, пункт 8): в реализации стоит: у концов КОНЕЦ, ОСТАНОВЛЕНО, ОШИБКА в `перейти` (переходов нет); в `ответ_по_концу` (значение `остановка` вне таблицы; ответ не из конца; итог сессии пуст в КОНЦЕ); в `выполнить_операцию` (состояние без операции); в `вход_запроса` и `следующая_попытка` (состояние не обращение; сторона вне «шаг_агента», «человек»); в `состояние_по_имени`, `сторона_обращения` (имя вне перечня).

## Типы

```nova
module автомат_запуска_сессии

// псевдокод: общие типы и сигнатуры операций из слоя методики; импорт модулей — вне записи (соглашения, п. 4)
use автомат_методики.{Находка, ИтогСессии, Свод, ВходЗапускаСессии, ИтогЗапускаСессии, ВидВызывающего, ПрофильАгента, ПределыАгента, ЗапросАгента, ОтветАгента, ВходПаузы, объём_запуска, остановить_группу_агента}

/// Запись автомата: итог разбора артефакта сессии (операция РАЗБОР_ИТОГА): итог сессии; свод и находки захода — только у сессий проверки
type РазборСессии { итог_сессии ИтогСессии, свод Option[Свод], находки_проверки Option[[]Находка] }

/// Запись автомата: результат роли — по варианту на обращение первоисточника, где сторона возвращает результат (раздел «Состояния»: Выход);
/// у ворот человека результата роли нет: слово человека приходит событием, а не исходом запроса.
type РезультатРоли enum
  | РезультатШага(ОтветАгента)                  // СЕССИЯ: ответ_агента (ответ вложенной машины «Шаг агента»)

/// Запись автомата: вход запроса — по варианту на обращение первоисточника; поля — строки таблицы «Вход» состояния, читаемые стороной
/// (у ворот без столбца «Кто читает» — вся таблица); необязательное поле — Option. Режим «показывать и продолжать» (исход по умолчанию даёт исполнитель) — на стороне исполнителя.
type ВходРоли enum
  | ЗапросАгентаРоли(ЗапросАгента)                                                                                            // СЕССИЯ (вложенная машина «Шаг агента»); остальные строки «Вход» СЕССИИ исполнитель подставляет в `контекст`
  | ВходВ2 { сессия str, фаза Option[str] }                                                                                   // В2
  | ВходВ1 { сессия str }                                                                                                     // В1
  | ВходВ13Сессия { сессия str, текст_отказа str }                                                                                              // В13_СЕССИЯ
  | ВходПаузыРоли(ВходПаузы)                                                                                                  // ПАУЗА

/// Необратимое действие во внешнем мире: последний этап фиксации, повторяемый без вреда (правило 13).
type Необратимое enum
  | ОстановитьГруппуАгента        // ОСТАНОВЛЕНО, ОШИБКА: группа процессов агента останавливается целиком, проверяется, что в ней не осталось процессов

/// Окружение перехода запуска сессии: `Среда` движка с типами запуска.
type Окружение alias Среда[Состояние, Событие, Необратимое]
```

```nova
/// шагу агента запуск сессии передаёт срок тишины `нет` и бюджеты `нет` (решение 12 первоисточника)

/// Машина запуска сессии: данные запуска в одной записи (раздел «Данные» первоисточника); поля названы как переменные первоисточника.
/// Машина — данные и логика запуска: методы этого типа с ресивером `@` читают и пишут только эти поля; данные движка и служебные операции — через `среда`.
/// Машина реализует `Автомат[Состояние, Событие, ВходЗапускаСессии, ИтогЗапускаСессии, ВходРоли, РезультатРоли, Необратимое]` структурно.
type Машина {
  // Переменные машины (состояние машины); сохраняются целиком вместе со снимком (правило 22); данные движка (конверт, очереди запросов, журнал) — в `СостояниеДвижка`
  сессия str,                                  // код запускаемой сессии; из запроса вызова, не меняется
  источник_запуска str,                        // источник правок для запускаемой сессии; `""` — источника нет; из запроса вызова, не меняется
  заход_запуска Option[int],                   // номер захода сессии проверки цикла; None у вызова из раннера; из запроса вызова, не меняется
  фаза Option[str],                            // фаза цикла задачи для профиля; None у вызова из проверки цикла; из запроса вызова, не меняется
  маршрут str,                                 // маршрут задачи: у быстрого хвост промптов получает строку про постановку вместо plan.md; из запроса вызова, не меняется
  перечень_источников Option[str],             // перечень источников из постановки (быстрый маршрут): читать только его и то, что нужно для правки; None — перечня нет; из запроса вызова, не меняется
  сдача_сжата bool,                            // сжата ли сдача: подставляется в промпты С7, С7п и С8; из запроса вызова, не меняется
  ответ_агента Option[ОтветАгента],            // ответ вложенной машины «Шаг агента»: текст или артефакт сессии и запись расхода; None — ответа ещё не было
  итог_сессии Option[ИтогСессии],              // чем кончилась сессия; None — сессия ещё не кончалась
  остановка str,                               // почему запуск останавливается: исход ворот
  текст_отказа str,                            // текст отказа вложенной машины «Шаг агента»; показывается человеку у В13; на ветвление не влияет (решение 15 первоисточника)
  попытка_шага int,                            // счётчики попыток одноадресных обращений: к вложенной машине «Шаг агента», к человеку (правило 15)
  попытка_человека int,
  // Внешние объекты (хранилище и задание): пишет операция РАЗБОР_ИТОГА при входе (правило 29); роль и переходы их не пишут
  свод HashMap[int, Свод],                     // [заход_запуска]; итоговая строка файла проверки захода; в заходе без неё итога нет (записи нет)
  находки_проверки HashMap[int, []Находка],    // [заход_запуска]; находки файла проверки захода; данные прежних заходов не смешиваются
  // Задание и вход вызова: из запроса, не меняются
  папка_задачи str,
  рабочее_дерево str,
  режим_сдачи str,
}

/// Начальные значения данных машины — раздел «Данные» первоисточника; поля «из запроса» заполняет `Машина.из_входа`.
fn Машина.new() -> Машина => {
  сессия: "",
  источник_запуска: "",
  заход_запуска: None,
  фаза: None,
  маршрут: "",
  перечень_источников: None,
  сдача_сжата: false,

  остановка: "",
  текст_отказа: "",
  попытка_шага: 0,
  попытка_человека: 0,
  свод: HashMap[int, Свод].new(),

  папка_задачи: "",
  рабочее_дерево: "",
  режим_сдачи: "",
}

/// Машина по входу запуска: код сессии, источник правок, фаза, номер захода, маршрут, перечень источников, сдача_сжата и задание.
fn Машина.из_входа(вход ВходЗапускаСессии) -> Машина {
```

```nova
  _ => недостижимо("сторона вне «шаг_агента», «человек»")
}

    трасса: трасса_вызова(среда), номер_шага: номер_шага_вызова(среда) })
  В2 => ВходВ2 { сессия: @сессия, фаза: @фаза }
  В1 => ВходВ1 { сессия: @сессия }
  В13_СЕССИЯ => ВходВ13Сессия { сессия: @сессия, текст_отказа: @текст_отказа }
```

## Переходы

```nova
/// Переход по событию. тело_события — событие, которое ждёт состояние `текущее` (у развилки — Сразу без данных);
/// событие — исходное событие шага: его данные (сторона, идентификатор, тело) доступны всей цепочке до ближайшего обращения (правило 13).
/// Состояние пишется при фиксации; в «Что меняется» оно не повторяется.
fn Машина mut @перейти(текущее Состояние, тело_события Событие, событие Входящее[Событие], среда Окружение) Журнал Объекты Time -> Переход[Состояние] {
  match текущее {

  // ===================== В2 — обращение =====================
  // Показывает человеку профиль запуска сессии и оценку цены и просит подтвердить, чтобы дорогой запуск не начинался без него. Вход в запуск любой
  //   сессии.
  // При входе: ворота В2: профиль запуска (класс модели, усилие, размышление, бюджет), выбранный по умолчаниям фазы и подсказке агента из прошлой
  //   сессии (`task-runner.md`, «Профили запуска»), и оценка цены по токенам слоёв; при расшифровке диалога автора больше примерно вдвое слоёв 0–3
  //   человек выбирает, продолжать диалог или начать новый; совет ниже по классу или усилию показывается всегда. В режиме «показывать и продолжать»
  //   (профиль равен умолчанию) исполнитель сам даёт исход «подтвердить» и пишет это в журнал. Выбор профиля и подсказка — механика запуска (служебные
  //   хранилища), в данные машины не входят.
  // Сторона: человек.
  // Вход: сессия; фаза? (обязательна у вызова из раннера: без неё профиль выбрался бы по умолчаниям другой фазы; у вызова из проверки цикла не передаётся — профиль по коду сессии)
  // Выход: исход ворот
  В2 => match тело_события {
    // В2 #1: В2: «подтвердить»
    В2_подтвердить => Куда(ОБЪЁМ)
    _ => НеЖдёт
  }

  // ===================== ОБЪЁМ — развилка =====================
  // Смотрит, помещается ли диалог сессии в предел входа: помещается — запускает сессию, не помещается — человек решает.
  // Вход: объём_запуска (измерено исполнителем: для продолжаемого диалога — расшифровка плюс ход (не помещается — диалог закрывается, идёт новый),
  //   для нового — префикс плюс промпт)
  ОБЪЁМ => {
    // ОБЪЁМ #1: объём_запуска = «помещается»
    if объём_запуска() == "помещается" { return Куда(СЕССИЯ) }
    // ОБЪЁМ #2: объём_запуска = «не помещается»
    if объём_запуска() == "не помещается" { return Куда(В1) }
    // ОБЪЁМ #3: иначе
    среда.ошибка_машины("ошибка машины: развилка ОБЪЁМ, ни одно условие не подошло")
  }

  // ===================== В1 — обращение =====================
  // Сообщает человеку, что новый диалог не помещается в предел входа модели, и спрашивает: после его правки (разбить задачу, поднять класс, убрать
  //   лишнее из материалов) повторить запуск или остановить его.
  // При входе: ворота В1: материалы и промпт не помещаются в предел входа профиля; программа молча не режет (`task-runner.md`, «Объём»); исходы ворот
  //   в источниках не перечислены, взяты два («Решения при переводе», решение 3).
  // Сторона: человек.
  // Вход: сессия
  // Выход: исход ворот
  В1 => match тело_события {
    // В1 #1: В1: «повторить»
    В1_повторить => Куда(В2)
    // В1 #2: В1: «остановить»
    В1_остановить => {
      @остановка = "В1: остановить"
      Куда(ОСТАНОВЛЕНО)
    }
    _ => НеЖдёт
  }

  // ===================== СЕССИЯ — обращение =====================
  // Просит вложенную машину «Шаг агента» выполнить модельный вызов одной сессии (разбор, план, реализацию, проверку, правку, сдачу, коммит, пуш или разбор
  //   обратной связи) и принимает её ответ: текст или артефакт сессии и запись расхода.
  // Запись автомата: событие «ответ» несёт ответ шага агента (`Ответ_сессии`); итог сессии, свод и находки захода читает следующая операция РАЗБОР_ИТОГА.
  // При входе: исполнитель строит запрос `ЗапросАгента` (state-machine-agent-step-states.md) и отправляет его вложенной машине «Шаг агента»: вид — «сессия цикла»; профиль —
  //   профиль запуска, подтверждённый у В2 (служебное хранилище); сессия — код сессии; контекст — промпт сессии (`run` псевдокода: сборка промпта с подстановками по входу
  //   ниже) и диалог (новый или ход живого диалога автора), собранные исполнителем; пределы — срок тишины и бюджеты `нет` (решение 12); трасса и номер_шага — конверт
  //   этой машины. Перед отправкой исполнитель заводит группу процессов агента, пишет запись запуска и отметки логов; пока идёт запрос, читает k/N из `progress.log`.
  //   Повтор временной ошибки (до 3 раз), продолжение обрезанного выхода, проверка формы артефакта с одним ходом «исправь форму файла», запросы разрешений и запись
  //   расхода идут внутри шага агента; отсутствие артефакта и вторая ошибка формы приходят отказом с кодом. Расход и `check_cache` ведёт шаг агента (на любом исходе);
  //   после любого исхода вызова исполнитель разбирает подсказку из `profile.log`, а после принятого ответа — проверку журнала `progress.log` и запись расшифровки диалога автора.
  //   Подробности — «Реализация на файлах».
  // Сторона: шаг агента (вложенная машина, state-machine-agent-step-states.md).
  // Вход (сторона): сессия (поле `сессия` запроса агента)
  // Вход (исполнитель; подставляется в `контекст`): источник_запуска?; заход_запуска? (номер захода файла проверки: у проверяющего — номер файла, который он напишет, у
  //   правщика — номер файла с находками; у вызова из раннера не передаётся); режим_сдачи (подставляется в промпты сдачи (С7, С7п)); папка_задачи (агент запускается из неё);
  //   рабочее_дерево; маршрут (у быстрого маршрута к сессионной части хвоста добавляется строка про постановку вместо plan.md); перечень_источников? (подставляется
  //   `<перечень источников>`: исполнитель читает только перечень и то, что нужно для правки); сдача_сжата (у С7, С7п и С8 — сжатая сдача); план_задачи? (из строки «Ветка:»
  //   раздела «План» берётся подстановка <ветка из plan.md>)
  // Выход: ответ_агента (текст или ссылка на артефакт сессии и запись расхода)
  СЕССИЯ => match тело_события {
    // СЕССИЯ #1: ответ (ответ_агента: ОтветАгента — текст или артефакт сессии и запись расхода)
    Ответ_сессии { ответ_агента: ответ } => {
      @ответ_агента = Some(ответ)
      Куда(РАЗБОР_ИТОГА)
    }
    // СЕССИЯ #2: сбой (причина: КодСбоя)
    Сбой { причина, текст_отказа: текст } => {
      @текст_отказа = текст
      среда.писать_журнал("сессия ${@сессия} не завершилась: ${слово_кода(причина)}")
      Куда(В13_СЕССИЯ)
    }
    _ => НеЖдёт
  }

  // ===================== РАЗБОР_ИТОГА — операция =====================
  // Читает артефакт сессии из ответа агента и определяет, чем сессия кончилась (готово или слово остановки); у сессии проверки записывает итоговую строку и находки захода.
  // При входе: исполнитель читает артефакт из `ответ_агента` и разбирает его по формату (`task-runner.md`, «Машинные форматы»): слово остановки последнего абзаца — итог
  //   сессии (`готово`, если стоп-слова нет; у КОММИТ и ПУШ итог всегда `готово`); у сессий проверки — итоговая строка «Заход N: …» (`parse_summary`: строки нет — итога нет)
  //   и находки файла захода: исполнитель записывает их в `свод[заход_запуска]` и `находки_проверки[заход_запуска]` (запись во внешние объекты — работа при входе операции,
  //   правило 29). Форму артефакта проверил шаг агента, поэтому разбор отказа не даёт.
  // Вход: ответ_агента; сессия; заход_запуска?
  // Выход: итог_сессии (у КОММИТ и ПУШ — готово: стоп-слова у них нет); свод[заход_запуска]? (только у сессий проверки); находки_проверки[заход_запуска]? (только у сессий проверки)
  РАЗБОР_ИТОГА => match тело_события {
    // РАЗБОР_ИТОГА #1: сразу (итог_сессии: ИтогСессии — готово, ревизия, план, требования или вопрос)
    Сразу_РАЗБОР_ИТОГА { итог_сессии: итог } => {
      @итог_сессии = Some(итог)
      Куда(КОНЕЦ)
    }
    _ => НеЖдёт
  }

  // ===================== В13_СЕССИЯ — обращение =====================
  // Спрашивает человека, что делать, когда сессия не завершилась: повторить её или остановить запуск.
  // При входе: ворота В13: сессия не завершилась — шаг агента отказал с кодом (нет результата, отказ модели, соединение оборвалось, форма не исправлена со второй
  //   попытки, предел токенов, предел запросов хода и др.); причина — в журнале. «Повторить» — исполнитель останавливает группу процессов агента, убеждается, что в ней
  //   нет процессов, и запускает тот же запрос к шагу агента заново; «остановить» — запуск сессии кончается отказом, вызывающая машина останавливается.
  // Сторона: человек.
  // Вход: сессия
  // Выход: исход ворот
  В13_СЕССИЯ => match тело_события {
    // В13_СЕССИЯ #1: В13: «повторить»
    В13_повторить => Заново(СЕССИЯ)
    // В13_СЕССИЯ #2: В13: «остановить»
    В13_остановить => {
      @остановка = "В13: остановить"
      Куда(ОСТАНОВЛЕНО)
    }
    _ => НеЖдёт
  }

  // ===================== ПАУЗА — обращение =====================
  // Подключено фрагментом «Пауза» (state-machine-pause-states.md): события ПАУЗЫ разбирает движок (`общие_события`), строк состояния у машины нет;
  //   остальные события ПАУЗА не ждёт.
  ПАУЗА => НеЖдёт

  // ===================== КОНЕЦ — конец =====================
  // Возвращает вызывающей машине итог сессии (и у сессии проверки — итоговую строку и находки захода): запуск закончен.
  // При входе: в журнал — код сессии и итог сессии; ответ `Answer` с итогом запуска уходит вызывающей машине.
  // Вход: сессия; итог_сессии; заход_запуска?; свод[заход_запуска]?; находки_проверки[заход_запуска]?
  КОНЕЦ => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  // ===================== ОСТАНОВЛЕНО — конец =====================
  // Заканчивает запуск без итога сессии и записывает, почему; что делать дальше, решает вызывающая машина.
  // При входе: группа процессов агента останавливается целиком и проверяется, что в ней не осталось процессов; в журнал — «запуск сессии остановлен:
  //   <остановка>»; вызывающая машина получает `Refusal` (таблица «конец → ответ»).
  // Вход: остановка
  ОСТАНОВЛЕНО => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  // ===================== ОШИБКА — конец =====================
  // Заканчивает запуск, если сама машина попала в непредусмотренное положение; это дефект машины или реализации, его разбирает человек.
  // При входе: группа процессов агента останавливается; в журнал — запись из перехода и данные машины; вызывающая машина получает `Refusal`; решает
  //   человек вне машины.
  // Вход: все данные машины ((в журнал))
  ОШИБКА => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  }
}
```

## Работа операций

```nova
/// Работа операций при входе (в одном шаге с переходом; отказа и «нет ответа» у операции нет). Результат — событие: `Сразу_РАЗБОР_ИТОГА` с данными.
fn Машина mut @выполнить_операцию(операция Состояние, среда Окружение) Журнал Объекты Time -> Событие => match операция {
  РАЗБОР_ИТОГА => {
    // слово остановки — итог; у сессий проверки итоговая строка и находки захода пишутся в хранилище (правило 29)
    ro разбор = разобрать_артефакт_сессии(@сессия, обязательное(@ответ_агента, "РАЗБОР_ИТОГА: ответ агента записан в СЕССИИ"))
    match разбор.свод {
      Some(найденный) => { @свод.insert(обязательное(@заход_запуска, "РАЗБОР_ИТОГА: итоговая строка приходит только у сессий проверки, у них есть номер захода"), найденный) }
      None => {}                                        // итога нет: записи в `свод` нет
    }
    match разбор.находки_проверки {
      Some(найденные) => { @находки_проверки.insert(обязательное(@заход_запуска, "РАЗБОР_ИТОГА: находки приходят только у сессий проверки, у них есть номер захода"), найденные) }
      None => {}                                        // сессия правки или раннера: файла находок нет
    }
    Сразу_РАЗБОР_ИТОГА { итог_сессии: разбор.итог_сессии }
  }
  _ => недостижимо("у остальных состояний нет работы операции")
}
```

## Приём ответа и запись результата

```nova
/// При приёме (правило 14): у обращений запуска записи стороны нет (счётчики попыток ведёт механика контракта).
```

## Концы и ответ

```nova
/// Работа концов при входе (в последнем, повторяемом без вреда этапе фиксации) и ответ вызвавшей стороне.
/// Вход в любой конец отменяет все открытые запросы (правило 22); машина отвечает ровно один раз (правило 35).
fn Машина mut @при_входе_в_конец(конец Состояние, среда Окружение) Журнал Time -> () => match конец {
  // ОСТАНОВЛЕНО: группа процессов агента останавливается целиком и проверяется, что в ней не осталось процессов; в журнал — «запуск сессии остановлен: <остановка>»;
  //   вызывающая машина получает `Refusal` (таблица «конец → ответ»).
  ОСТАНОВЛЕНО => {
    среда.добавить_необратимое(Необратимое.ОстановитьГруппуАгента)
    среда.писать_журнал("запуск сессии остановлен: ${@остановка}")
  }
  // ОШИБКА: группа процессов агента останавливается; в журнал — запись из перехода и данные машины; вызывающая машина получает `Refusal`; решает человек вне машины.
  ОШИБКА => {
    среда.добавить_необратимое(Необратимое.ОстановитьГруппуАгента)
    среда.писать_журнал(среда.запись_перехода())
    @журнал_данных_машины(среда)
  }
  // КОНЕЦ: в журнал — код сессии и итог сессии; ответ `Answer` с итогом запуска уходит вызывающей машине.
  КОНЕЦ => {
    ro итог = обязательное(@итог_сессии, "КОНЕЦ: итог сессии записан в СЕССИИ")
    среда.писать_журнал("запуск сессии: сессия ${@сессия}, итог ${слово_итога(итог)}")
  }
  _ => ()
}
// запись для диагностики: все переменные и хранилища (Вход ОШИБКИ) — сигнатура объявлена в разделе «Механика машины»

/// Таблица «конец → ответ» первоисточника (раздел «Контракт машины»): каждый конец и каждое значение остановка — одна строка.
fn Машина @ответ_по_концу(вызов Запрос[ВходЗапускаСессии], конец Состояние, среда Окружение) -> Исход[ИтогЗапускаСессии] {
  match конец {
    // КОНЕЦ, условие входа: всегда → СРезультатом: итог сессии; у сессий проверки — свод и находки захода
    КОНЕЦ => СРезультатом(ОтветСРезультатом {
      запрос: вызов.идентификатор_запроса, сторона: вызов.сторона, трасса: вызов.трасса, номер_шага: вызов.номер_шага,
      результат: ИтогЗапускаСессии {
        итог_сессии: обязательное(@итог_сессии, "КОНЕЦ: итог сессии записан в СЕССИИ"),
        свод: @свод_запуска(),
        находки_проверки: @находки_запуска() } })
    // ОШИБКА, условие входа: всегда (дефект машины) → Отказ, НетРезультата; текст — запись из перехода
    ОШИБКА => отказ_по(вызов, НетРезультата, среда.запись_перехода())
    ОСТАНОВЛЕНО => match @остановка {
      // ОСТАНОВЛЕНО: остановка = «В13: остановить» или «В1: остановить» → Отказ, ОстановленоЧеловеком
      "В13: остановить" | "В1: остановить" => отказ_по(вызов, ОстановленоЧеловеком, @остановка)
      // ОСТАНОВЛЕНО: остановка = «ПАУЗА: остановить» (слово человека; у вызванной машины — сигнал «остановить от родителя» в ПАУЗЕ) → Отказ, ОстановленоЧеловеком
      "ПАУЗА: остановить" => отказ_по(вызов, код_сбоя_общей_остановки(@остановка), @остановка)
      // ОСТАНОВЛЕНО: остановка = «отмена_запроса» → Отказ, ОтмененоРодителем
      "отмена_запроса" => отказ_по(вызов, код_сбоя_общей_остановки(@остановка), @остановка)
      _ => недостижимо("значение остановка вне таблицы «конец → ответ»: новое значение добавляет строку таблицы")
    }
    _ => недостижимо("ответ отдают только концы")
  }
}

/// Точка подстановки эффектов: обработчики выбирает вызывающий код, один раз (`with`), и вне этого файла — любые (`Time` — стандартный, обработчик по умолчанию).
/// Все функции цепочки от `начать`, `возобновить`, `вызвать` объявляют эффекты в своей сигнатуре; здесь они подставлены. Машину по входу запроса создаёт вызывающий код
/// (обработчик `Связь` верхней машины — раннера или проверки цикла — при запросе `ЗапросРоли` с входом `ВходЗапускаСессии`).
fn запуск_сессии(запрос Запрос[ВходЗапускаСессии]) Time -> Исход[ИтогЗапускаСессии] =>
  with Хранилище = обработчик_хранилища, Журнал = обработчик_журнала, Связь = обработчик_связи, Объекты = обработчик_объектов {   // псевдокод: обработчики (база, файл поверх Fs/Db, очередь сообщений) — любые, вне файла
    mut исполнитель = Исполнитель.new(Машина.из_входа(запрос.вход))
    исполнитель.вызвать(запрос)
  }
```

## Что движок не покрыл

Места, где запуску сессии нужно то, чего движок [state-machine-engine-automaton.md](state-machine-engine-automaton.md) не давал: записано обходом внутри этой машины или функцией без тела. Номера пунктов в каждом файле свои, общей нумерации нет: здесь открыты 3–5, 7–13, в проверке цикла — 3–5 и 7–12, в раннере — 6, 8, 9 и 11–15; одно и то же место имеет в файлах разные номера (ворота человека — здесь 7, в проверке цикла 7, в раннере 11; «каркас вложенной машины» — здесь 8, в проверке цикла 8, в раннере 12). Пункт «цепочка запуска сессии — копия в раннере и проверке цикла» закрыт самой этой машиной (шаг 6 выделения слоя): в раннере это пункт 10, в проверке цикла — пункт 6. Пункт 13 — текст отказа в событии «сбой» и хук «при входе в ПАУЗУ» (остановить группу процессов агента). Пункт 12 — обращение к агенту как вызов вложенной машины «Шаг агента» ([state-machine-agent-step-automaton.md](state-machine-agent-step-automaton.md)); часть пункта 5 (возврат ответа не по форме, число возвратов, повтор временной ошибки) перешла в её описание (там пункты 1–10).
