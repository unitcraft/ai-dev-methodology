# Слой методики: код общих типов и операций для машин задачи

Слой между движком и машинами методики задачи — раннером, проверкой цикла, запуском сессии и совещанием, — записанный кодом на языке Нова: типы данных, общие для нескольких машин методики (перечень — в таблице соответствия ниже), общий вход паузы, ворота человека как данные, сигнатуры операций над объектами задачи и арифметика цикла проверки. Движок — [state-machine-engine-automaton.md](state-machine-engine-automaton.md) — методики не знает, обобщён по типам машины и слой не подключает; слой подключают сами машины (`use`). Машины слоя: раннер — [task-runner-automaton.md](task-runner-automaton.md), проверка цикла — [task-runner-review-automaton.md](task-runner-review-automaton.md), запуск сессии — [task-runner-session-automaton.md](task-runner-session-automaton.md) (её зовут раннер и проверка цикла), шаг агента — [archive/state-machine-agent-step-automaton.md](archive/state-machine-agent-step-automaton.md) (его зовёт запуск сессии), совещание — [task-runner-meeting-automaton.md](task-runner-meeting-automaton.md). Идентификаторы кода английские, словарь — [state-machine-glossary.md](state-machine-glossary.md); русские имена — в описаниях и комментариях.

**Первоисточники.** Методика — [task-runner.md](../task-runner.md) (словарь, ворота, форматы файлов, профили запуска) и [task-sessions.md](../task-sessions.md), «Правила» (коды сессий, потолок заходов, чистая серия, пробы); типы блока «Типы на Нове» — в первоисточниках машин: [task-runner-states.md](task-runner-states.md), [task-runner-review-states.md](task-runner-review-states.md), [task-runner-session-states.md](task-runner-session-states.md), [archive/state-machine-agent-step-states.md](archive/state-machine-agent-step-states.md), [task-runner-meeting-states.md](task-runner-meeting-states.md). Правила формы машины — [state-machine-spec.md](state-machine-spec.md). Файл — производная запись, а не второй источник истины: при расхождении верны первоисточники, файл правится вслед за ними. Язык записи — Нова, https://github.com/nv-lang/nova. **Код не компилировался и не проверялся компилятором Нова:** это псевдокод в синтаксисе Нова; помеченные места (`// псевдокод:`), подтверждённое и неподтверждённое спецификацией Нова — в [движке](state-machine-engine-automaton.md), пункт 5 соглашений, здесь только то, что добавляет слой. Имя файла — по `AGENTS.md`, «Вынесенные алгоритмы» (документ `state-machine`, часть `methodology`, форма `automaton`).

**Запись обращения к агенту.** Один вызов агента — линза, запуск сессии цикла, ход чата, вратарь — описан одним запросом (`ЗапросАгента`) и одним ответом (`ОтветАгента`) с единой записью расхода (`Использование`): статистика токенов, моделей и стоимости собирается в одном месте, а транспорт (сегодня — обработчик на файлах и процессах, позже — клиент ACP) реализует обращение, не меняя машин. Здесь записаны только типы и коды сбоя; машина «Шаг агента» — в [archive/state-machine-agent-step-states.md](archive/state-machine-agent-step-states.md) (первоисточник; типы запроса, ответа и расхода объявлены там один раз) и [archive/state-machine-agent-step-automaton.md](archive/state-machine-agent-step-automaton.md) (код автомата). **Поля `контекст` запроса — свои у каждого вызывающего:** собирает их вызывающий (раннер, проверка цикла, совещание, чат), слой хранит их непрозрачным текстом и не разбирает. **Виды вызывающего у совещания:** линза — «линза» (человека у её ворот нет), свидетель и автор — «ход чата» (человек может ответить на ворота разрешений); `сессия` запроса — идентификатор стороны («Л2», «свидетель», «автор»), профиль — по стороне (настройка проекта); типы запроса и ответа совещание берёт отсюда, своих не заводит ([task-runner-meeting-automaton.md](task-runner-meeting-automaton.md)). Сбой обращения — обычный отказ конверта (`ОтветОтказ`) с кодом `КодСбоя`; к существующим кодам добавлены два — `ПредельТокенов` и `ПредельЗапросовХода` (отдельные коды, не `НетРезультата`): **их порождает только машина «Шаг агента», а таблица «конец → ответ» существующих машин не менялась** (запуск сессии и совещание получают их от шага агента как обычный сбой — запуск сессии ведёт его к воротам В13, совещание теряет линзу или открывает ворота СБОЙ; наружу они не вытекают). Соответствие остановки ACP коду сбоя (**описание, реализация — продукт**) — таблица «Остановка ACP → код» ниже.

## Соглашения записи

1. **Типы и идентификаторы** — по [движку](state-machine-engine-automaton.md), пункты 1–3: английские имена по [словарю](state-machine-glossary.md), поля и функции — змеиный регистр (правило 25 спецификации: имя одной сущности одно). Сокращений в именах нет.
2. **Что в слое.** (а) Типы данных первоисточника, общие у нескольких машин методики. Сюда же вынесены `Свод` проверки цикла (его возвращает запуск сессии, читает проверка цикла) и вход и итог запуска сессии — `ВходЗапускаСессии`, `ИтогЗапускаСессии`: раннер и проверка цикла зовут вложенную машину запуска сессии ([task-runner-session-automaton.md](task-runner-session-automaton.md)), строят её вход и разбирают её итог одними типами. (б) `ВходПаузы` — вход обращения ПАУЗА, у раннера, проверки цикла и совещания один и тот же (предыдущее состояние, запрос вызова); каждая машина оборачивает его в свой вариант `ВходРоли` (`ВходПаузыРоли`). (в) `Ворота` — данные ворот человека: их читает обработчик `Связь`; слова ворот остаются событиями машины (по варианту на слово, как в таблицах состояний), в одно событие не сводятся. (г) Сигнатуры операций над объектами задачи: тело даёт обработчик эффекта `Объекты`; сам эффект движка не расширен. (д) Арифметика цикла: функции над `Цикл` — `потолок_исчерпан`, `сброс_отсчёта`, `шаг_без_проб` — одинаковы у машины совещания и машины проверки цикла (развилки ПОТОЛОК и БЕЗ_ПРОБ, исходы В9 со сдвигом отсчёта); раннер держит `Цикл` по стадиям и берёт `сброс_отсчёта` для правки владельца. Машина оставляет тонкую ветку таблицы с тем же комментарием `// СОСТОЯНИЕ #n`, а счёт — здесь; значение предела приходит аргументом: у проверки цикла предел потолка и числа чистых заходов и проб — данные задачи из `ВходПроверки` (`потолок_заходов`, `чистых_подряд`, `проб_в_чистом`; их записывает раннер по маршруту задачи), у совещания — константы (`ПОТОЛОК_ЗАХОДОВ` и др., параметры проекта). (е) Поля маршрута задачи во входах `ВходПроверки` и `ВходЗапускаСессии` (состав — в таблице соответствия; слово владельца, 2026-10-18; решения 27–52 [task-runner-states.md](task-runner-states.md)); типы маршрута (`Риск`, `Оценка`, `ПризнакиМаршрута`, `ПорогиМаршрута`, `ПараметрыМаршрута`, `ПараметрыПроекта`) нужны только раннеру и объявлены в его файле.
3. **Одноимённые типы разных машин.** `Находка` и `Критичность` раннера и проверки цикла (`Находка { критичность, уровень, доказательство }`; `Критичность`: `Существенная`, `Поверхностная`) объявлены здесь. Одноимённые `Находка` и `Критичность` совещания (`Находка { критичность, доказательство, повтор, вопрос }`; `Критичность`: `Критическая`, `Значимая`, `Желательная`) — **другие типы с тем же именем**: они лежат в файле совещания и в слой не входят, как и `Свод` совещания (`критических`, `проб`; `Свод` слоя — `существенных`, `проб`) и `Утверждение` (у раннера — дата, кто, хеш, у совещания — утверждение свидетеля). Машина называет в `use` только нужные имена: проверка цикла берёт `Находку` слоя, совещание берёт из слоя только `ВходПаузы` и сигнатуры.
4. **Строки `// псевдокод:`.** Функции без тела (сигнатуры операций над объектами задачи, `отпечаток`) — тело даёт обработчик. Не подтверждено спецификацией Нова: объявление `module` и импорт `use <модуль>.{имя, …}` (как в машинах), конструктор-функция `fn Цикл.new()` — как `fn СостояниеДвижка.new` в движке.
5. **Запись расхода и запрос агента.** `Использование`, `МодельАгента`, `Токены` повторяют запись `usage.log` версии 1 (одна JSON-строка на сессию: код сессии, результат, модель, токены, стоимость, время создания и обновления) с поправкой на необязательность (`Option`): число, которого источник не даёт, — «нет», а не `0` (ACP не гарантирует токены и сообщает лишь занятость окна контекста и накопленную стоимость). Времена — целые миллисекунды эпохи, как в журнале. Поля конверта (правило 31) `трасса` и `номер_шага` и `семья` модели добавлены к записи версии 1; в её строке журнала их нет. Новых конструкций Нова, не подтверждённых спецификацией, запись не вводит: `f64` — стандартный вещественный тип, `Option[...]` — как в движке.

## Типы

```nova
module methodology

// псевдокод: тип ошибки операции над объектом — из движка; импорт модулей и разрешение имён — вне записи (соглашения, п. 4)
use engine.{ObjectError}

/// Цикл
type Cycle { number int, origin int, streak int, no_probes int }

/// Начальные счётчики цикла каждой стадии (раздел «Данные» первоисточника)
fn Cycle.new() -> Cycle => { number: 1, origin: 1, streak: 0, no_probes: 0 }

/// Находка
type Finding { severity Severity, level Level, evidence str }

/// Критичность
type Severity enum
  | Essential
  | Superficial

/// Уровень
type Level enum
  | Implementation
  | Plan
  | Requirements
  | OutOfScope
  | Delivery

/// Свод: итоговая строка файла проверки захода (существенных находок и проб); у проверки цикла и запуска сессии; одноимённый `Свод` совещания — другой тип
type Summary { essential int, probes int }

/// ВходЗапускаСессии: вход вложенной машины запуска сессии; один у раннера и проверки цикла; источник правок, фаза, номер захода и перечень источников необязательны (фазы нет у вызова из проверки цикла, номера захода — у вызова из раннера, перечня — у полного маршрута и у вызова из проверки цикла); маршрут и сдача_сжата — данные задачи для подстановок хвоста промптов
type SessionLaunchInput { session str, source Option[str], phase Option[str], launch_pass Option[int], task_dir str, repo_dir str, delivery_mode str, route str, source_list Option[str], delivery_short bool }

/// ИтогЗапускаСессии: итог вложенной машины запуска сессии; свод и находки захода — только у сессий проверки цикла
type SessionLaunchResult { result SessionResult, summary Option[Summary], findings Option[[]Finding] }

/// ИтогСессии
type SessionResult enum
  | Done
  | Revision
  | Plan
  | Requirements
  | Question

/// Стадия
type Stage enum
  | Analysis
  | Plan
  | Implementation
  | Delivery
  | Meeting

/// ВходПроверки; общий у раннера и машины проверки цикла; маршрут и числа цикла — данные задачи (у стадии «совещание» не читаются); предложение, порядок линз и вопрос автора — только у стадии «совещание»
type ReviewInput { stage Stage, cycle Cycle, out_of_scope []Finding, task_dir str, repo_dir str, delivery_mode str, route str, clean_needed int, ceiling int, probes_min int, delivery_short bool, proposal Option[str], lens_order []str, author_question Option[str] }

/// ИтогПроверки
type ReviewResult { verdict Verdict, source str, cycle Cycle, out_of_scope []Finding }

/// Вердикт; «остановлено» — только у стадии «совещание»: раннер её не вызывает, значения не получает
type Verdict enum
  | Clean
  | Requirements
  | Plan
  | Question
  | Restart
  | Stopped

/// Вход обращения ПАУЗА: общий у машин методики; предыдущее — имя состояния, прерванного «стоп человека» или «стоп от родителя», запрос_вызова — идентификатор запроса, которым машину запустили
type PauseInput { previous str, call_request_id str }

/// Вид вызывающего агента: кто просит ответ; поле `контекст` запроса у каждого вида своё; линза совещания — `Линза`, свидетель и автор совещания — `ХодЧата`: человек может ответить на их ворота разрешений, а у линзы человека нет; `Вратарь` — вратарь-агент (`task-runner.md`, «Параметры маршрута»): отвечает на ворота вместо человека, человека у его вызова нет, как у линзы
type CallerKind enum
  | Lens
  | CycleSession
  | ChatTurn
  | Gatekeeper

/// Модель агента: как в записи `usage.log` версии 1 (идентификатор, поставщик, вариант)
type AgentModel { id str, provider str, variant Option[str] }

/// Токены вызова; каждое число необязательно — «нет», где источник его не даёт (ACP токены не гарантирует)
type TokenUsage { input Option[int], output Option[int], reasoning Option[int], cache_read Option[int], cache_write Option[int] }

/// Использование: единая запись расхода одного вызова агента; поля версии 1 журнала плюс `семья` и конверт трассировки (правило 31); `занято_контекста` — число токенов в занятом окне контекста, которую сообщает ACP; времена — миллисекунды эпохи
type Usage { session str, result str, family str, model AgentModel, tokens TokenUsage, cost Option[f64], created int, updated int, context_used Option[int], trace str, step int }

/// Профиль агента: семья модели, модель и усилие (вариант)
type AgentProfile { family str, model str, effort Option[str] }

/// Пределы вызова агента: срок тишины (миллисекунды без вывода до кода `НетОтветаВСрок`) и бюджеты; отсутствие предела — «нет»
type AgentLimits { silence_term Option[int], token_budget Option[int], cost_budget Option[f64], turn_limit Option[int] }

/// Запрос агента: вызывающий собирает `контекст` сам и непрозрачным текстом; слой его не разбирает
type AgentRequest { kind CallerKind, profile AgentProfile, session str, dialog_kind str, context str, limits AgentLimits, trace str, step int }

/// Ответ агента: текст результата или ссылка на артефакт (хотя бы одно из двух) и запись расхода; сбой — отказ конверта с кодом `КодСбоя`, а не этот тип
type AgentReply { text Option[str], artifact Option[str], usage Usage, request_started Option[int] }

/// Ворота — данные ворот (сторона «вратарь» или «усиленный», решение 54 раннера): их читает обработчик `Связь` (показывает человеку, принимает слово, при «показывать и продолжать» даёт исход по умолчанию и пишет его в журнал; при настройке `исполнитель_повышенного_внимания` = «агент» и допустимом профиле вратаря вместо показа зовёт «Шаг агента» с видом `Вратарь`, где `слова` — закрытый перечень исходов, и принимает слово из ответа с `решил` = «агент»; ворота В14, В15, В5, В10а–г, В12 и продолжение после «стоп человека» имеют сторону «усиленный»: при `усиленный_вратарь` = «да» исполнитель зовёт тот же шаг с усиленными требованиями, иначе показывает человеку).
/// Слова ворот остаются событиями машины (по варианту на слово): в одно событие они не сводятся, строки таблицы состояния различают слова.
type Gate { name str, words []str, default_outcome Option[str], show_and_continue bool }
```

## Арифметика цикла

```nova
// Арифметика цикла проверки: одинакова у машины совещания и машины проверки цикла (task-sessions.md, «Правила»: потолок заходов, чистая серия, пробы).
// Функции чистые: значения предела (поле входа проверки цикла или константа совещания) приходят аргументом, а цикл — записью `Цикл`; машина читает свои поля в `Цикл` и записывает результат обратно.

/// Потолок заходов исчерпан: засчитанных заходов от отсчёта потолка не меньше предела; идущий заход не считается (номер_захода − 1), отсчёт — `заход_отсчёта`
fn ceiling_reached(cycle Cycle, limit int) -> bool => (cycle.number - 1) - cycle.origin + 1 >= limit

/// «заход_отсчёта = номер_захода»: сдвиг отсчёта потолка по решению человека (исходы ворот В9 у совещания и проверки цикла, правка владельца у раннера); остальные счётчики не меняются
fn reset_origin(cycle Cycle) -> Cycle => Cycle { number: cycle.number, origin: cycle.number, streak: cycle.streak, no_probes: cycle.no_probes }

/// Исход развилки БЕЗ_ПРОБ: что делать после чистого захода без проб
type NoProbesDecision enum
  | RepeatReview       // без_проб_подряд = 1: просто ещё один заход (БЕЗ_ПРОБ #1)
  | AskHuman        // без_проб_подряд больше 1: спросить человека у ворот ПОВТОР (БЕЗ_ПРОБ #2)

/// Развилка БЕЗ_ПРОБ: чистые заходы без проб подряд; None — ни одно условие не подошло (строка «иначе» машины ведёт в ОШИБКУ)
fn no_probes_step(cycle Cycle) -> Option[NoProbesDecision] {
  if cycle.no_probes == 1 { return Some(RepeatReview) }
  if cycle.no_probes > 1 { return Some(AskHuman) }
  None
}
```
