# Совещание агентов: стейт-машина

Та же схема, что в [task-runner.md](task-runner.md), «Совещание агентов» (псевдокод `meeting`, `check_meeting` и `loop_review(meeting)`), записанная состояниями и переходами. Нормы — [methodology.md](methodology.md), раздел 18, «Согласование решения несколькими агентами»; при расхождении с `task-runner.md` верен он. Опытный режим: раннером не выполняется.

## Данные

| Имя | Что это | Где хранится |
|---|---|---|
| n | номер текущего захода | `state.pass[meeting]` |
| origin | заход, от которого считается потолок | `state.pass_origin[meeting]` |
| streak | чистых заходов подряд | `state.clean_streak[meeting]` |
| unaccounted | чистых заходов без проб подряд | `state.unaccounted[meeting]` |
| lost[л] | потерянных заходов линзы л подряд | `state.lost[линза]` |
| extra | решение человека у В9 для правки автора | в памяти до ПРАВКИ |
| копия | `proposal.md` с хешем на начало захода | файл рядом с `proposal.md` |

Константы — ПОТОЛОК_ЗАХОДОВ, ЧИСТЫХ_ПОДРЯД, ПРОБ_В_ЧИСТОМ (`task-runner.md`, начало).

## Инварианты

1. **Решает только человек** — на воротах В3, В7, В9, В13 и «принять итог»; секретарь считает, переключает состояния и пишет журнал. Исключение — В3 в режиме «показать и продолжить», если человек так настроил.
2. **Предложение неизменно, пока работают линзы**: в состояниях ЛИНЗА `proposal.md` только для чтения, и любой выход из них возвращает запись; при старте секретаря, если проверка не идёт, запись тоже возвращается; изменение, найденное в СВЕРКЕ, делает заход недействительным.
3. **n не уменьшается**; недействительный заход повторяется под тем же n, его файлы переименованы в `*.void-<k>.md` и в счёт не идут.

## Состояния и переходы

| Состояние | Действие при входе | Событие → следующее состояние |
|---|---|---|
| ФАКТЫ | есть вопросы автора в `proposal.md` или проверяющих в файлах захода n−1 — держатель фактов пишет `facts-n.md`; выдержки сверяются, несовпадение — один ход «исправь выдержку», снова несовпадение — строка помечается «не подтверждено». Вопросов нет — ничего | готово → ЗАМОК; держатель (в том числе на ходе «исправь выдержку»): В13 «повторить» — запуск заново, «остановить совещание» → ОСТАНОВ |
| ЗАМОК | копия `proposal.md` с хешем; `proposal.md` только для чтения; i ← 1 | → ЛИНЗА(1) |
| ЛИНЗА(i) | линза i проверяет `proposal.md` и `facts-n.md`, файлов других линз этого захода не видит (проверка формы внутри запуска) | ответ: lost[i] ← 0 → ЛИНЗА(i+1) или, если линз больше нет, СВЕРКА; отказ: lost[i] + 1; если lost[i] ≥ 2 — В13: «повторить» → ЛИНЗА(i) (lost не сбрасывается, каждый новый отказ снова ведёт на В13), «остановить совещание» → ОСТАНОВ; если lost[i] < 2 — линза отброшена (журнал, её P = 0) → ЛИНЗА(i+1) или СВЕРКА; не ответила ни одна линза → ОСТАНОВ |
| СВЕРКА | запись в `proposal.md` возвращается | файл равен копии → ФИЛЬТР; изменён → В13 с копией и изменённым файлом: «оставить правку» или «вернуть копию» (копия возвращается) — файлы линз и фактов захода в `*.void-<k>.md` → ФАКТЫ; «остановить совещание» → ОСТАНОВ |
| ФИЛЬТР | убираются несостоятельные мнения (четыре признака, `task-runner.md`), каждое — в счёт по моделям; у линзы, потерявшей все существенные находки, P = 0 | → СВОД |
| СВОД | `proposal-review-n.md`: первая строка «Заход n: существенных K, поверхностных M, проб P» (K и M — суммы, P — наименьшее по линзам), затем находки с меткой линзы | → РАЗБОР |
| РАЗБОР | читается итоговая строка; нет её — все находки существенные, в журнал «итоговой строки нет» | K = 0 и P < ПРОБ_В_ЧИСТОМ: журнал «заход n: чистый без проб, не засчитан», n + 1, unaccounted + 1; unaccounted ≥ 2 — В13: «повторить» → ФАКТЫ, «остановить» → ОСТАНОВ; иначе → ФАКТЫ. Остальное: unaccounted ← 0 → В3 |
| В3 | человек читает находки и пробы, может поднять критичность; по настройке — «показать и продолжить» | «не засчитан»: журнал «заход n: пробы — не пробы, не засчитан», n + 1 → ФАКТЫ. Засчитан: n + 1; K = 0 — streak + 1, и при streak = ЧИСТЫХ_ПОДРЯД streak ← 0 → ПРИНЯТИЕ, иначе → ФАКТЫ; K > 0 — streak ← 0 → ПОТОЛОК |
| ПОТОЛОК | заходов с последней правки по решению человека: (n − 1) − origin + 1 | меньше ПОТОЛОК_ЗАХОДОВ → ПРАВКА; иначе В9, origin ← n: «ещё заход» — extra ← решение человека (сузить или разбить) → ПРАВКА; «остановиться» → ПРИНЯТИЕ с незакрытыми находками; «остановить совещание» → ОСТАНОВ |
| ПРАВКА | автор правит `proposal.md` по `proposal-review-(n−1).md` и extra, дописывает «Изменения захода» | готово: extra ← ∅ → ФАКТЫ; остановился (любое стоп-слово читается как «вопрос») → ВОПРОС; В13 «повторить» — запуск заново, «остановить совещание» → ОСТАНОВ |
| ВОПРОС | В7: человек отвечает на вопрос автора; автор продолжает с ответом по находкам захода n − 1 | готово → ФАКТЫ; снова вопрос → ВОПРОС; В13 «повторить» — запуск автора заново с тем же ответом, без В7, «остановить совещание» → ОСТАНОВ |
| ПРИНЯТИЕ | ворота «принять итог»: человек подтверждает решение и запись источника | → КОНЕЦ: в `log.md` решение с источником, числом заходов и незакрытыми находками; тип проверяющего в каждом заходе — по `methodology.md`, раздел 18 |
| ОСТАНОВ | в `log.md` — «совещание остановлено: <причина>», незакрытые находки | конец совещания; итог не принят, программа продолжает остальную работу |

«Запуск заново» у В13 повторяет только запуск роли с теми же входами, без повторного действия при входе в состояние. Бездействие роли дольше срока («Срок бездействия роли», `task-runner.md`) для линзы — отказ в ЛИНЗЕ, для автора и держателя фактов — В13 в их состоянии.

```
ФАКТЫ → ЗАМОК → ЛИНЗА(1…L) → СВЕРКА → ФИЛЬТР → СВОД → РАЗБОР → В3 ─┬→ ПРИНЯТИЕ → КОНЕЦ
  ↑                            │ изменён                  │ без проб  ├→ ФАКТЫ  (чистый, серия не набрана; не засчитан)
  ├────────────────────────────┘                          │           └→ ПОТОЛОК ─┬→ ПРАВКА ⇄ ВОПРОС
  ├───────────────────────────────────────────────────────┘                       └→ В9 → ПРАВКА | ПРИНЯТИЕ | ОСТАНОВ
  └──────────────────────────────────── ПРАВКА / ВОПРОС: готово
ОСТАНОВ — из любого состояния с запуском роли или воротами В13.
```
