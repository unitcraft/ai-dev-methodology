# Раннер задачи: код автомата

Стейт-машина раннера задачи — фазы РАЗБОР, ПЛАН, РЕАЛИЗАЦИЯ, СДАЧА, ОБРАТНАЯ_СВЯЗЬ и ворота между ними, — записанная кодом на языке Нова как реализация протокола `Автомат` движка [state-machine-engine-automaton.md](state-machine-engine-automaton.md): данные машины, перечисления `Состояние` и `Событие`, переход `перейти(состояние, событие)` как `match` по состоянию и событию, роли (входы и результаты обращений к вложенным машинам запуска сессии и проверки цикла и к человеку на воротах), ответ по концу по контракту машины, работа операций над документами задачи. Всё общее — конверт запроса и ответа, исполнитель, снимок и хранилище, общие события «стоп/продолжить/отмена», цикл, фиксации — в движке и здесь не повторяется. Нормы — [task-runner.md](task-runner.md) (словарь, ворота В1–В14, профили, форматы файлов) и [task-sessions.md](task-sessions.md) (коды сессий и правила цикла).

**Первоисточник — [task-runner-states.md](task-runner-states.md)** (машина «Раннер»: таблицы состояний, общие события, «Контракт машины», «Решения при переводе»); правила формы — [state-machine-spec.md](state-machine-spec.md). Этот файл — производная запись того же автомата, а не второй источник истины: при любом расхождении верен первоисточник, а этот файл правится вслед за ним. Язык записи — Нова, https://github.com/nv-lang/nova. **Код не компилировался и не проверялся компилятором Нова:** это псевдокод в синтаксисе Нова; соглашения записи, помеченные места (`// псевдокод:`), подтверждённое и неподтверждённое спецификацией — в [state-machine-engine-automaton.md](state-machine-engine-automaton.md), здесь только то, что относится к раннеру. Опытный статус и отличия от ранее написанной схемы описаны в шапке первоисточника и здесь не повторяются; раннером эта машина не исполняется (раннер исполняет [task-runner-pseudocode.md](task-runner-pseudocode.md), помеченный устаревшим и этим файлом не заменяемый). Вложенные машины: запуск сессии — [task-runner-session-automaton.md](task-runner-session-automaton.md) (первоисточник — [task-runner-session-states.md](task-runner-session-states.md)), проверка цикла — [task-runner-review-automaton.md](task-runner-review-automaton.md) (первоисточник — [task-runner-review-states.md](task-runner-review-states.md)), совещание — [task-runner-meeting-automaton.md](task-runner-meeting-automaton.md); раннер зовёт запуск сессии и проверку цикла, проверка цикла зовёт запуск сессии и совещание только по контракту вызова движка (`Вызываемое`, эффект `Связь`: запрос уходит как `ЗапросРоли`, ответ приходит сообщением), а не прямым вызовом функций. Имя файла — по `AGENTS.md`, «Вынесенные алгоритмы», форма `automaton`.

## Соглашения записи

1. **Типы и идентификаторы** — по [движку](state-machine-engine-automaton.md), пункты 1–3: русские имена, таблица соответствия именам блока «Типы на Нове» первоисточника — ниже. Типы данных первоисточника, общие у раннера и проверки цикла (`Цикл`, `Находка`, `Критичность`, `Уровень`, `ИтогСессии`, `Стадия`, `ВходПроверки`, `ИтогПроверки`, `Вердикт`, а также `ВходЗапускаСессии` и `ИтогЗапускаСессии`), объявлены один раз в [слое методики](state-machine-methodology-automaton.md) и подключены здесь (`use`); здесь объявлены типы только раннера (`Артефакт`, `Утверждение` и их перечни, `Риск`, `Оценка`, `ПризнакиМаршрута`, `ПорогиМаршрута`, `ПараметрыМаршрута`, `ПараметрыПроекта`, `ВходРаннера`, `ИтогРаннера`). Вход паузы (`ВходПаузы`) тоже в слое; вариант `ВходРоли` для него — `ВходПаузыРоли`. Записи автомата, которых в первоисточнике нет: `РезультатРоли`, `ВходРоли`, `Окружение`, `Необратимое`. **Значения перечислений** с совпадающими именами в разных перечнях (`План`, `Требования`, `Вопрос`, `Готово` и др.) пишутся с именем типа (`ИтогСессии.План`, `Уровень.План`): так же названы значения в блоке «Типы на Нове» первоисточника (`Level.Plan`, `SessionResult.Plan`).
2. **Данные события.** Поля варианта события берутся образцом в `match`: `Сбой { причина } => …`; при совпадении имени поля с переменной машины поле переименовывается: `Ответ_сессии { итог_сессии: итог }`; остаток полей, которые переход не читает, — `{ цикл, .. }`. «Сторона события» и идентификатор события — `событие.сторона`, `событие.идентификатор` (конверт `Входящее` движка, правила 13 и 31); тело исходного события шага — `событие.тело`. Служебные операции переходу даёт `среда` (журнал, слова человека, сигналы вложенным, данные движка `открытые_запросы`, `предыдущее`, `запрос_вызова`).
3. **Строка таблицы — ветка кода.** Перед каждой строкой первоисточника (условие или событие, «Что меняется», «Куда») стоит комментарий `// <СОСТОЯНИЕ> #<номер строки>: …` с её текстом; у обращения и операции в скобках — данные события; порядок строк как в первоисточнике. «Куда» записано как `Куда(<СОСТОЯНИЕ>)`; «запуск заново» — `Заново(<СОСТОЯНИЕ>)`; «Куда: предыдущее» — у ПАУЗЫ в движке (`Куда(@машина.состояние_по_имени(предыдущее))`). Строка «иначе» каждой развилки — последняя ветка, ведёт в `ОШИБКА` через `среда.ошибка_машины(…)`; той же функцией записана строка, чей первоисточник ведёт в `ОШИБКА` с журналом «ошибка машины: …» (РЕАЛИЗАЦИЯ_ПРОВЕРКА, «ответ: перезапуск»). Строки «Вход», «Выход», «При входе», «Сторона» и одна строка простыми словами на состояние — комментарии `//` у состояния. Общие события (две строки «стоп» и четыре строки «отмена_запроса») записаны в движке (`общие_события`); `общее` машины сводит к ним её события. Состояние ПАУЗА и его четыре строки подключены фрагментом «Пауза» ([state-machine-pause-states.md](state-machine-pause-states.md)): события паузы разбирает движок (`общие_события`), у машины остаются ветка `ПАУЗА => НеЖдёт`, хуки `состояние_паузы`, `причина_остановки_в_паузе`, `состояние_по_имени` и сведение событий паузы в `общее`.
4. **Строки `// псевдокод:`** и перечень подтверждённого спецификацией — в [движке](state-machine-engine-automaton.md), пункт 5. Здесь дополнительно: функции без тела (сигнатуры механики и чтения внешних объектов); алиас `type Окружение alias Среда[…]` (как в машине совещания); поле-отображение `HashMap[Стадия, Цикл]` — перечисление как ключ отображения в Нове не подтверждено (запасной вариант — ключ-строка с именем стадии); значения перечислений с именем типа (`ИтогСессии.План`); образец `{ поле, .. }` с остатком и охранное условие в ветке `match` (оба — как в движке и машине совещания). Потолок заходов, число чистых заходов подряд и число проб (бывшие константы `ПОТОЛОК_ЗАХОДОВ`, `ЧИСТЫХ_ПОДРЯД`, `ПРОБ_В_ЧИСТОМ`) — данные задачи (`потолок_заходов`, `чистых_подряд`, `проб_в_чистом`): их пишет МАРШРУТ_ЗАПИСЬ, а во вложенную проверку цикла они уходят полями `ВходПроверки` (решение 36 первоисточника); константы этой машины — только минимумы методики `МИНИМУМ_ЧИСТЫХ_ПОДРЯД` и `МИНИМУМ_ПРОБ_В_ЧИСТОМ`, их читает ПРОВЕРКА_МАРШРУТА. Функции без тела — механика исполнителя и обработчика `Объекты` (в том числе `дописать_как_факт`, читатели документов). Срок бездействия не задан: у обращений раннера `0` (исполнитель «нет ответа» не порождает), для вызова вложенной машины он равен `0` — это значение «без срока» (правило 35, пункт 5): родитель ждёт ответа или отмены. Неподтверждённое спецификацией Нова, используемое здесь (как и в машине совещания): объявление `module`, `ro` на уровне модуля (константы), `return` внутри `if` в ветке `match` и в теле функции.
5. **Уточнения записи автомата сверх первоисточника** (каждое — следствие границы с движком, подробности — «Что движок не покрыл»): (а) результат операции ПОДГОТОВКА — запись `ИтогПодготовки` (итог и счётчики цикла каждой стадии): `выполнить_операцию` отдаёт её событием `Сразу_ПОДГОТОВКА`, а движок передаёт то же событие следующей развилке цепочки, поэтому развилка ПОДГОТОВКА_ИТОГ читает `итог_подготовки` из тела события, как в первоисточнике («итог_подготовки события»; у развилки «Вход: нет»), и поля-моста в данных машины нет; (б) `событие_ответа` — метод протокола `Автомат`: отображение результата роли в событие с данными; (в) варианты события `Проверка_*` несут `вне_задачи` у всех стадий (так устроен `ИтогПроверки`); переходы стадий, кроме реализации, его не читают; (г) метка инварианта — список номеров заходов по четырём стадиям, движок сравнивает покомпонентно (убыль одного номера при росте другого ловится); (д) `при_возобновлении` — метод протокола: подготовка при каждом старте исполнителя, в том числе при возобновлении (решение 25 первоисточника); метод получает сохранённое состояние и `среду`; исходы те же, что у ПОДГОТОВКА_ИТОГ («готова» — войти в сохранённое состояние; «занята живым процессом» — ОСТАНОВЛЕНО; нерешённые — ворота; «иначе» — ОШИБКА через `среда.ошибка_машины`); перед воротами метод пишет `возврат_подготовки` ← имя сохранённого состояния (если сохранённое состояние — ворота подготовки, подготовка не выполняется, метод даёт `None`), и после ворот ПОДГОТОВКА_ИТОГ ведёт в него, а не в СВЕРКА_СПЕЦИФИКАЦИИ (первоисточник, решение 25); (е) вложенная сторона и число возвратов ответа не по форме — поля `вложенная` и `возвратов_формы` описания обращения (`Одна`): вложенные — «проверка» и «запуск сессии», возвратов формы у раннера нет (ответ не по форме возвращает агенту вложенная машина запуска сессии); (ж) `ВходЗапускаСессии` — вход вложенной машины запуска сессии (один тип у раннера и проверки цикла, слой методики): код сессии — поле `сессия` (Текст); по коду ветвятся запуск сессии, профиль и промпт — механика исполнителя («Реализация на файлах» [task-runner-session-states.md](task-runner-session-states.md)), а раннер по нему не ветвится (правило 6), поэтому суммы по видам сессий не заводятся; номер захода раннер не передаёт (`None`); (з) `запрос_вызова` — всегда `запрос.идентификатор_запроса` (решение о `""` у верхнего уровня открыто, см. движок, пункт 6); (и) `состояние_по_имени` записано полным `match` по именам обращений (в машине совещания — сигнатура).
6. **Данные машины — поля типа `Машина`**, а не переменные модуля: поля названы как переменные раздела «Данные» первоисточника (правило 25), начальные значения — в `Машина.new()`, по входу раннера — `Машина.из_входа`. Данные движка (конверт, очереди запросов, журнал, слова человека, тексты сбоев) — в `СостояниеДвижка` движка: `трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `запрос_вызова`, `состояние`, `предыдущее`, `открытые_запросы`, `принятые_запросы`. Внешние объекты раздела «Внешние объекты» читаются через эффект `Объекты` читателями `Машина` (документы задачи — `@спецификация()`, `@план_задачи()`, `@отчёт_реализации()`, письма, отчёт по секретам, различия дерева и т. д.): их содержимое лежит вне машины, а не в её данных; поле — только `утверждения` (запись в данных состояния, `approvals`). **Именование читателей по ключу:** читатель элемента поля называется по полю (`@цикл(стадия)`, `@отложенная_сессия(фаза)`, `@утверждения(документ)`, `@письма_раундов(номер)`) — как в машине совещания. **Поле и метод с одним именем** (`цикл`, `отложенная_сессия`, `источник_отложенной`, `утверждения`) — сознательное решение: в Нове допустимо (`spec/decisions/03-syntax.md`, правило `@name`), правило 25 соблюдено (имя одной сущности одно).
7. **`недостижимо(текст)`** (определено в движке, пункт 8): в реализации стоит: у концов КОНЕЦ, ОСТАНОВЛЕНО, ОШИБКА в `перейти` (переходов нет); в `ответ_по_концу` (значение `остановка` вне таблицы; ответ не из конца); в `выполнить_операцию` (состояние без операции); в `событие_ответа` (вердикт «остановлено»: раннер стадию «совещание» не вызывает); в `вход_запроса` и `следующая_попытка` (обязательное поле входа пусто — `обязательное` движка; состояние не обращение; сторона вне «запуск сессии», «проверка», «человек»); в `цикл`, `документ_задачи`, `состояние_по_имени`, `сторона_обращения` (запись стадии не заведена; имя вне перечня).

| КодСбоя: нет результата, отказ модели, соединение оборвалось, форма не исправлена, нет ответа в срок, остановлено человеком, потолок заходов с открытыми находками, отменено родителем | `КодСбоя`: `НетРезультата`, `ОтказМодели`, `СоединениеОборвалось`, `ФормаНеИсправлена`, `НетОтветаВСрок`, `ОстановленоЧеловеком`, `ПотолокЗаходов`, `ОтмененоРодителем` | `FailCode`: `NoResult`, `ModelRefused`, `ConnectionLost`, `FormNotFixed`, `Timeout`, `StoppedByHuman`, `CeilingReached`, `Cancelled` |
| Записи автомата (не из первоисточника): состояние, событие, вид состояния, сообщение, входящее событие, переход | `Состояние`, `Событие`, `Вид`, `Сообщение`, `Входящее`, `РезультатРоли`, `ВходРоли`, `ОшибкаХранилища`, `Переход`: `Куда`, `Заново`, `Остаться`, `НеЖдёт` | `State`, `Event`, `Kind`, `Incoming`, `Transition`: `Go`, `Rerun`, `Stay`, `NotAwaited`; `РезультатРоли`, `ВходРоли` — запись автомата; `Сообщение`, `ОшибкаХранилища` — типы движка; в блоке «Типы на Нове» их нет |
| ВходЗапускаСессии, ИтогЗапускаСессии | те же имена, объявлены в [слое методики](state-machine-methodology-automaton.md) | `SessionLaunchInput`, `SessionLaunchResult` |
| Функции записи автомата: функция переходов, недостижимая ветка | `перейти`, `недостижимо` | `step`, `unreachable` |
| Параметры типов: вход запроса, результат роли | `Вход`, `Результат` | `T`, `R` |

Имена, которых нет в первоисточнике и которые завела запись автомата (не данные машины): `РезультатРоли`, `ВходРоли`, `Окружение`, `Необратимое`, варианты `Событие` с префиксом ворот (`В13_повторить`, …; один вариант на слово ворот строки первоисточника, одно слово у нескольких ворот — один вариант) и варианты исходов вложенной проверки (`Проверка_чисто`, …); вариант `Ответ_сессии` — исход вложенного запуска сессии, `Машина.из_входа`, методы машины для протокола `Автомат` (`начальное`, `общее`, `обращение`, `следующая_попытка`, `событие_ответа` и др.), функции раздела «Механика машины» (`назначить_запуск`, `правка_владельца` и др.). Типы и функции движка (`Исполнитель`, `Снимок`, `Хранилище`, `Автомат`, `Среда`, `Входящее`, `Переход`, `Куда`, `Заново`, `Остаться`, `НеЖдёт`, `перейти` и др.) — в [state-machine-engine-automaton.md](state-machine-engine-automaton.md).

```nova
// Раздел записывает механику раннера: свободные функции и методы `Машина`; методы `Исполнитель` и общие функции — в движке.
// псевдокод: функции без тела — сигнатуры; тело пишет реализация, в Нове внешняя реализация здесь не показана

// Свободные функции
// статус документа равен заданному; документа нет — нет
fn статус_равен(документ Option[Артефакт], статус СтатусАртефакта) -> bool => match документ {
  Some(найденный) => найденный.статус == статус
  None => false
}

  Some(найденный) => найденный.стоп_слово == слово
  None => false
}

fn итог_равен(итог Option[ИтогСессии], значение ИтогСессии) -> bool => match итог {
  Some(найденный) => найденный == значение
  None => false
}

  стадии.push(Стадия.План)
  стадии.push(Стадия.Реализация)
  стадии.push(Стадия.Сдача)
  стадии
}
// ранг риска для сравнения: низкий < средний < высокий; «не оценён» вне порядка (признаки с ним неполны, до сравнения не доходят)
fn ранг_риска(риск Риск) -> int => match риск {
  Риск.Низкий => 0
  Риск.Средний => 1
  Риск.Высокий => 2
  Риск.НеОценён => 3
}
// «риск выше допустимого_риска»
fn риск_выше(риск Риск, допустимый Риск) -> bool => ранг_риска(риск) > ранг_риска(допустимый)
// список строк через запятую и пробел
// псевдокод: функция без тела — стандартная библиотека
fn соединить_через_запятую(имена []str) -> str
// счётчики стадии после возврата на полный маршрут: серия_чистых и без_проб_подряд — `0`, заход_отсчёта — номер_захода (как `сброс_отсчёта`), номер_захода не меняется
fn сброс_после_возврата(цикл Цикл) -> Цикл => Цикл { номер_захода: цикл.номер_захода, заход_отсчёта: цикл.номер_захода, серия_чистых: 0, без_проб_подряд: 0 }
// «признаки неполны» (термины): цель пуста, или число источников, или число частей не записаны, или риск «не оценён», или любой из трёх признаков «не оценено»
fn признаки_неполны(признаки ПризнакиМаршрута) -> bool =>
  признаки.цель == "" || признаки.число_источников == None || признаки.число_частей == None || признаки.риск == Риск.НеОценён
    || признаки.необратимо == Оценка.НеОценено || признаки.причина_известна == Оценка.НеОценено || признаки.касается_нормы == Оценка.НеОценено
// «перечень неполных признаков» (термины): имена через запятую в порядке цель, число_источников, число_частей, риск, необратимо, причина_известна, касается_нормы
fn перечень_неполных_признаков(признаки ПризнакиМаршрута) -> str {
  mut имена = []str.new()
  if признаки.цель == "" { имена.push("цель") }
  if признаки.число_источников == None { имена.push("число_источников") }
  if признаки.число_частей == None { имена.push("число_частей") }
  if признаки.риск == Риск.НеОценён { имена.push("риск") }
  if признаки.необратимо == Оценка.НеОценено { имена.push("необратимо") }
  if признаки.причина_известна == Оценка.НеОценено { имена.push("причина_известна") }
  if признаки.касается_нормы == Оценка.НеОценено { имена.push("касается_нормы") }
  соединить_через_запятую(имена)
}
// признаки, вышедшие за порог (у полных признаков): имена в порядке число_источников, число_частей, риск, необратимо, причина_известна, касается_нормы
fn признаки_за_порогом(признаки ПризнакиМаршрута, пороги ПорогиМаршрута) -> []str {
  mut имена = []str.new()
  if (признаки.число_источников ?? 0) > пороги.максимум_источников { имена.push("число_источников") }
  if (признаки.число_частей ?? 0) > пороги.максимум_частей { имена.push("число_частей") }
  if риск_выше(признаки.риск, пороги.допустимый_риск) { имена.push("риск") }
  if признаки.необратимо == Оценка.Подтверждено { имена.push("необратимо") }
  if признаки.причина_известна == Оценка.Опровергнуто { имена.push("причина_известна") }
  if признаки.касается_нормы == Оценка.Подтверждено { имена.push("касается_нормы") }
  имена
}
// «признак выходит за порог» (термины)

// «перечень признаков за порогом» (термины)
fn перечень_признаков_за_порогом(признаки ПризнакиМаршрута, пороги ПорогиМаршрута) -> str => соединить_через_запятую(признаки_за_порогом(признаки, пороги))
// «параметры допустимы» (термины): чистых_подряд и проб_в_чистом не меньше минимумов методики, ослаблений нет

// «причина отказа настроек» (термины): первое нарушенное условие допустимости словами

// подготовка при возобновлении (решение 25 первоисточника): та же подготовка, что операция ПОДГОТОВКА при первом старте, до входа в сохранённое состояние (`сохранённое`); счётчики цикла ставятся по файлам на диске.
// Сохранённое состояние — ворота подготовки: подготовка не выполняется, None — ворота показываются человеку снова (правило 22), «готова» закроет их только по ответу человека.
// Исходы те же, что у ПОДГОТОВКА_ИТОГ: «готова» — None (войти в сохранённое состояние), остальные — переход: «занята живым процессом» — в ОСТАНОВЛЕНО, нерешённые — к воротам,
// и перед воротами `возврат_подготовки` ← имя сохранённого состояния; «иначе» — в ОШИБКУ, как строка «иначе»
fn Машина mut @при_возобновлении(сохранённое Состояние, среда Окружение) Журнал Объекты Time -> Option[Переход[Состояние]] {
  match сохранённое {
    В13_ПОДГОТОВКА | ДЕРЕВО_ЗАНЯТО => return None
    _ => ()
  }
  match сохранённое {
    ПАУЗА => ()                                 // возврат через ворота подготовки, прерванные паузой, не теряется
    _ => { @возврат_подготовки = "" }           // устаревшее значение не доживает до новой подготовки
  }
  ro итог = @выполнить_подготовку()
  for стадия in стадии_цикла() { @установить_цикл(стадия, обязательное(итог.циклы.get(стадия), "ПОДГОТОВКА: цикл каждой стадии приходит в итоге подготовки")) }
  match итог.итог_подготовки {
    "готова" => None
    "занята живым процессом" => {
      @остановка = "задача занята живым процессом"
      Some(Куда(ОСТАНОВЛЕНО))
    }
    "дерево занято другой задачей" => {
      @возврат_подготовки = @имя_состояния(сохранённое)
      Some(Куда(ДЕРЕВО_ЗАНЯТО))
    }
    "группа процессов не остановлена" => {
      @возврат_подготовки = @имя_состояния(сохранённое)
      Some(Куда(В13_ПОДГОТОВКА))
    }
    _ => Some(среда.ошибка_машины("ошибка машины: развилка ПОДГОТОВКА_ИТОГ, ни одно условие не подошло"))
  }
}

  В7_ПЛАН_ОЧЕРЕДЬ => ВходВ7ПланОчередь

  В10г => ВходВ10г

  В14_ОТКАЗ => ВходВ14Отказ { основание_маршрута: @основание_маршрута }
  В14 => ВходВ14 { предложение_маршрута: @предложение_маршрута, основание_маршрута: @основание_маршрута, источник_выбора_маршрута: @источник_выбора_маршрута, признаки_маршрута: @признаки_маршрута(), параметры_проекта: @параметры_проекта() }
```

## Переходы

```nova
/// Переход по событию. тело_события — событие, которое ждёт состояние `текущее` (у операции — результат операции, у развилки — Сразу без данных);
/// событие — исходное событие шага: его данные (сторона, идентификатор, тело) доступны всей цепочке до ближайшего обращения (правило 13).
/// Состояние пишется при фиксации; в «Что меняется» оно не повторяется.
fn Машина mut @перейти(текущее Состояние, тело_события Событие, событие Входящее[Событие], среда Окружение) Журнал Объекты Time -> Переход[Состояние] {
  match текущее {

  // ===================== ПОДГОТОВКА — операция =====================
  // Готовит задачу к работе (действие исполнителя при каждом старте, не только при первом): читает сохранённое состояние, проверяет папку и рабочее
  //   дерево, ставит блокировку и останавливает недобитую сессию прошлого запуска; без этого два раннера работали бы в одной папке, а две задачи
  //   смешали бы изменения в одном дереве.
  // При входе: `load_or_init` и `prepare` псевдокода. Исполнитель делает это при КАЖДОМ старте, в том числе при возобновлении после перезапуска, до
  //   входа в сохранённое состояние (как возврат права записи в машине совещания: механика исполнителя, правила 12 и 22, а не шаг, который машина
  //   повторяет); при первом старте итог разбирают ПОДГОТОВКА_ИТОГ и ворота ниже, при возобновлении — исполнитель с теми же исходами: «занята живым
  //   процессом» — в сохранённое состояние не входит и ведёт в ОСТАНОВЛЕНО, остальные нерешённые исходы — те же ворота (В13_ПОДГОТОВКА, ДЕРЕВО_ЗАНЯТО),
  //   после ответа «повторить» исполнитель входит в сохранённое состояние. Содержание: чтение `state.json` или начальное состояние; файл захода,
  //   начатый оборвавшейся сессией, переименовывается в `*.partial.md`; номер следующего захода каждого цикла — не меньше 1 + наибольший номер файла
  //   цикла на диске; проверки раздела «Подготовка» `task-sessions.md`; блокировка `runner.lock` с идентификатором процесса (занята живым процессом —
  //   остановиться); группа процессов агента из записи прошлого запуска останавливается (с проверкой времени старта) и в ней проверяется отсутствие
  //   процессов, без записи группы — ищутся и останавливаются процессы агента этой папки; в служебной папке системы контроля версий рабочего дерева —
  //   файл с путём папки задачи; первый коммит, если кода нет и истории ещё нет.
  // Вход: папка_задачи; рабочее_дерево; цикл[стадия] (по каждой стадии: разбор, план, реализация, сдача)
  // Выход: итог_подготовки («готова», «занята живым процессом», «дерево занято другой задачей» или «группа процессов не остановлена»); цикл[стадия]
  //   (по каждой стадии: номер_захода не меньше 1 + наибольшего номера файла цикла на диске; заход_отсчёта прежний, а если его не было, равен
  //   номеру_захода)
  ПОДГОТОВКА => match тело_события {
    // ПОДГОТОВКА #1: сразу (итог_подготовки: Текст; цикл[стадия]: Цикл — по каждой стадии)
    Сразу_ПОДГОТОВКА { циклы, .. } => {
      for стадия in стадии_цикла() { @установить_цикл(стадия, обязательное(циклы.get(стадия), "ПОДГОТОВКА: цикл каждой стадии приходит в событии")) }
      Куда(ПОДГОТОВКА_ИТОГ)
    }
    _ => НеЖдёт
  }

  // ===================== ПОДГОТОВКА_ИТОГ — развилка =====================
  // Смотрит, чем кончилась подготовка: готова — начинает цикл; занята — останавливается; нужен человек — идёт к воротам.
  // Запись автомата: `итог_подготовки` события читается из тела исходного события развилки: движок передаёт развилке результат предыдущей операции
  //   (ПОДГОТОВКА), а не «сразу»; в данных машины поля для него нет.
  // Вход: возврат_подготовки.
  ПОДГОТОВКА_ИТОГ => match тело_события {
    Сразу_ПОДГОТОВКА { итог_подготовки: итог, .. } => {
      // ПОДГОТОВКА_ИТОГ #1: итог_подготовки события = «готова», и возврат_подготовки = ""
      if итог == "готова" && @возврат_подготовки == "" { return Куда(СВЕРКА_СПЕЦИФИКАЦИИ) }
      // ПОДГОТОВКА_ИТОГ #2: итог_подготовки события = «готова», и возврат_подготовки не ""
      if итог == "готова" && @возврат_подготовки != "" {
        ro возврат = @состояние_по_имени(@возврат_подготовки)         // «куда» читает прежнее значение
        @возврат_подготовки = ""
        return Куда(возврат)
      }
      // ПОДГОТОВКА_ИТОГ #3: итог_подготовки события = «занята живым процессом»
      if итог == "занята живым процессом" {
        @остановка = "задача занята живым процессом"
        return Куда(ОСТАНОВЛЕНО)
      }
      // ПОДГОТОВКА_ИТОГ #4: итог_подготовки события = «дерево занято другой задачей»
      if итог == "дерево занято другой задачей" { return Куда(ДЕРЕВО_ЗАНЯТО) }
      // ПОДГОТОВКА_ИТОГ #5: итог_подготовки события = «группа процессов не остановлена»
      if итог == "группа процессов не остановлена" { return Куда(В13_ПОДГОТОВКА) }
      // ПОДГОТОВКА_ИТОГ #6: иначе
      среда.ошибка_машины("ошибка машины: развилка ПОДГОТОВКА_ИТОГ, ни одно условие не подошло")
    }
    _ => среда.ошибка_машины("ошибка машины: развилка ПОДГОТОВКА_ИТОГ, ни одно условие не подошло")      // события операции ПОДГОТОВКА нет: итога подготовки нет
  }

  // ===================== В13_ПОДГОТОВКА — обращение =====================
  // Спрашивает человека, что делать, если прежнюю группу процессов агента не удалось найти или остановить: повторить подготовку или остановить
  //   раннер.
  // При входе: ворота В13: группа процессов агента прежнего запуска не остановлена или процессы агента этой папки не найдены.
  // Сторона: человек.
  // Вход: нет.
  // Выход: исход ворот
  В13_ПОДГОТОВКА => match тело_события {
    // В13_ПОДГОТОВКА #1: В13: «повторить»
    В13_повторить => Куда(ПОДГОТОВКА)
    // В13_ПОДГОТОВКА #2: В13: «остановить»
    В13_остановить => {
      @остановка = "В13: остановить"
      Куда(ОСТАНОВЛЕНО)
    }
    _ => НеЖдёт
  }

  // ===================== ДЕРЕВО_ЗАНЯТО — обращение =====================
  // Сообщает человеку, что рабочее дерево уже отмечено другой задачей, и спрашивает: повторить проверку (когда дерево освободят) или остановить
  //   раннер.
  // При входе: ворота «дерево занято другой задачей» (ворота без номера): файл-метка в служебной папке системы контроля версий рабочего дерева
  //   называет другую папку задачи; исходы ворот в источниках не перечислены, взяты два, как у В13 («Решения при переводе»).
  // Сторона: человек.
  // Вход: нет.
  // Выход: исход ворот
  ДЕРЕВО_ЗАНЯТО => match тело_события {
    // ДЕРЕВО_ЗАНЯТО #1: ДЕРЕВО_ЗАНЯТО: «повторить»
    ДЕРЕВО_ЗАНЯТО_повторить => Куда(ПОДГОТОВКА)
    // ДЕРЕВО_ЗАНЯТО #2: ДЕРЕВО_ЗАНЯТО: «остановить»
    ДЕРЕВО_ЗАНЯТО_остановить => {
      @остановка = "ДЕРЕВО_ЗАНЯТО: остановить"
      Куда(ОСТАНОВЛЕНО)
    }
    _ => НеЖдёт
  }

  // ===================== СВЕРКА_СПЕЦИФИКАЦИИ — развилка =====================
  // Голова цикла. Проверяет, не правили ли утверждённую спецификацию после утверждения; правили — утверждение надо снять.
  // Вход: спецификация?; утверждения[спецификация]?; маршрут
  СВЕРКА_СПЕЦИФИКАЦИИ => {
    // СВЕРКА_СПЕЦИФИКАЦИИ #1: спецификация есть, и её статус не разобран
    if статус_равен(@спецификация(), СтатусАртефакта.НеРазобран) { return Куда(В13_СТАТУС) }
    // СВЕРКА_СПЕЦИФИКАЦИИ #2: маршрут = «полный», спецификация есть, её статус «утверждено», и утверждение спецификации не действует
    if @маршрут == "полный" && статус_равен(@спецификация(), СтатусАртефакта.Утверждено) && !@утверждение_действует("спецификация") { return Куда(СНЯТИЕ_СПЕЦИФИКАЦИИ) }
    // СВЕРКА_СПЕЦИФИКАЦИИ #3: маршрут = `""`, спецификация есть, её статус «утверждено», и утверждение спецификации не действует
    if @маршрут == "" && статус_равен(@спецификация(), СтатусАртефакта.Утверждено) && !@утверждение_действует("спецификация") { return Куда(СНЯТИЕ_СПЕЦИФИКАЦИИ) }
    // СВЕРКА_СПЕЦИФИКАЦИИ #4: маршрут = «быстрый», спецификация есть, её статус «утверждено», и утверждение спецификации не действует
    if @маршрут == "быстрый" && статус_равен(@спецификация(), СтатусАртефакта.Утверждено) && !@утверждение_действует("спецификация") { return Куда(СНЯТИЕ_КОПИИ) }
    // СВЕРКА_СПЕЦИФИКАЦИИ #5: спецификации нет
    if @спецификация() == None { return Куда(СВЕРКА_ПЛАНА) }
    // СВЕРКА_СПЕЦИФИКАЦИИ #6: спецификация есть, и её статус «черновик»
    if статус_равен(@спецификация(), СтатусАртефакта.Черновик) { return Куда(СВЕРКА_ПЛАНА) }
    // СВЕРКА_СПЕЦИФИКАЦИИ #7: спецификация есть, её статус «утверждено», и утверждение спецификации действует
    if статус_равен(@спецификация(), СтатусАртефакта.Утверждено) && @утверждение_действует("спецификация") { return Куда(СВЕРКА_ПЛАНА) }
    // СВЕРКА_СПЕЦИФИКАЦИИ #8: иначе
    среда.ошибка_машины("ошибка машины: развилка СВЕРКА_СПЕЦИФИКАЦИИ, ни одно условие не подошло")
  }

  // ===================== СНЯТИЕ_СПЕЦИФИКАЦИИ — операция =====================
  // Возвращает спецификацию в черновик: её правили после утверждения, и она заново проходит проверку и утверждение.
  // При входе: `invalidate(spec.md)`: первая строка спецификации ← «Статус: черновик», запись об утверждении удаляется; закрываются диалоги, в слое 3
  //   которых была спецификация (С3 и С5); диалог автора спецификации (С1) не закрывается; префикс основного диалога пересобирается.
  // Вход: спецификация
  // Выход: спецификация (статус «черновик»); утверждения[спецификация]? (снято)
  СНЯТИЕ_СПЕЦИФИКАЦИИ => match тело_события {
    // СНЯТИЕ_СПЕЦИФИКАЦИИ #1: сразу
    Сразу => {
      среда.писать_журнал("правка после утверждения, статус снят: спецификация")
      Куда(СВЕРКА_ПЛАНА)
    }
    _ => НеЖдёт
  }

  // ===================== СНЯТИЕ_КОПИИ — операция =====================
  // Возвращает копию постановки быстрого маршрута в черновик, если её правили после утверждения, и отправляет задачу к утверждению у В5: слово человека нужно заново, а работа
  //   без него не идёт.
  // При входе: `invalidate(spec.md)`, как в СНЯТИЕ_СПЕЦИФИКАЦИИ: первая строка копии ← «Статус: черновик», запись об утверждении удаляется; закрываются диалоги, в слое 3 которых
  //   была спецификация (С3 и С5); диалог автора не закрывается (его у быстрого маршрута нет); префикс основного диалога пересобирается. У полного маршрута такой операции нет:
  //   там после снятия статуса работа продолжается по-прежнему (решение 48).
  // Вход: спецификация
  // Выход: спецификация (статус «черновик»); утверждения[спецификация]? (снято)
  СНЯТИЕ_КОПИИ => match тело_события {
    // СНЯТИЕ_КОПИИ #1: сразу
    Сразу => {
      @фаза = "РАЗБОР"
      среда.писать_журнал("правка копии постановки после утверждения, статус снят: спецификация")
      Куда(СВЕРКА_ПЛАНА)
    }
    _ => НеЖдёт
  }

  // ===================== СВЕРКА_ПЛАНА — развилка =====================
  // Проверяет, не правили ли утверждённый план после утверждения; правили — утверждение надо снять.
  // Вход: план_задачи?; утверждения[план]?
  СВЕРКА_ПЛАНА => {
    // СВЕРКА_ПЛАНА #1: план есть, и его статус не разобран
    if статус_равен(@план_задачи(), СтатусАртефакта.НеРазобран) { return Куда(В13_СТАТУС) }
    // СВЕРКА_ПЛАНА #2: план есть, его статус «утверждено», и утверждение плана не действует
    if статус_равен(@план_задачи(), СтатусАртефакта.Утверждено) && !@утверждение_действует("план") { return Куда(СНЯТИЕ_ПЛАНА) }
    // СВЕРКА_ПЛАНА #3: плана нет
    if @план_задачи() == None { return Куда(ФАЗА) }
    // СВЕРКА_ПЛАНА #4: план есть, и его статус «черновик»
    if статус_равен(@план_задачи(), СтатусАртефакта.Черновик) { return Куда(ФАЗА) }
    // СВЕРКА_ПЛАНА #5: план есть, его статус «утверждено», и утверждение плана действует
    if статус_равен(@план_задачи(), СтатусАртефакта.Утверждено) && @утверждение_действует("план") { return Куда(ФАЗА) }
    // СВЕРКА_ПЛАНА #6: иначе
    среда.ошибка_машины("ошибка машины: развилка СВЕРКА_ПЛАНА, ни одно условие не подошло")
  }

  // ===================== СНЯТИЕ_ПЛАНА — операция =====================
  // Возвращает план в черновик: его правили после утверждения.
  // При входе: `invalidate(plan.md)`: первая строка плана ← «Статус: черновик», запись об утверждении удаляется; закрывается диалог С5 (в его слое 3
  //   был план); диалог автора плана (С3) не закрывается; префикс основного диалога пересобирается.
  // Вход: план_задачи
  // Выход: план_задачи (статус «черновик»); утверждения[план]? (снято)
  СНЯТИЕ_ПЛАНА => match тело_события {
    // СНЯТИЕ_ПЛАНА #1: сразу
    Сразу => {
      среда.писать_журнал("правка после утверждения, статус снят: план")

    _ => НеЖдёт

  //   запустил бы проверку заново поверх утверждённого документа.

  //   утверждено», у отчёта реализации «Статус: в работе» или «Статус: готово» (`task-runner.md`, «Машинные форматы»).

  В13_СТАТУС => match тело_события {

  // ===================== ЗАПУСК_СЕССИИ — обращение =====================
  // Просит вложенную машину запуска сессии выполнить одну сессию агента (разбор, план, реализацию, правку, сдачу, коммит, пуш или разбор обратной
  //   связи) и возвращает, чем она кончилась; профиль и цена, объём, повтор при сбое — дело той машины.
  // При входе: исполнитель отправляет запрос вложенной машине запуска сессии ([task-runner-session-states.md](task-runner-session-states.md)): код сессии,
  //   источник правок, фаза и задание; ворота В2, В1, В13 и обращение к агенту ведёт та машина. Место, откуда сессию запустили, называет `продолжение`:
  //   оно остаётся здесь и запросом не передаётся — по нему ПОСЛЕ_СЕССИИ решает, куда идти дальше.
  // Сторона: запуск сессии (вложенная машина, [task-runner-session-states.md](task-runner-session-states.md)).
  // Вход (сторона): сессия; источник_запуска?; фаза (по умолчаниям фазы выбирается профиль запуска); режим_сдачи (подставляется в промпты сдачи (С7));
  //   папка_задачи (агент запускается из неё); рабочее_дерево; перечень_источников? (у быстрого маршрута — перечень из постановки: исполнитель читает только его и то, что нужно
  //   для правки; `""` — перечня нет, не передаётся); сдача_сжата (подставляется в промпты сдачи (С7)); маршрут (у быстрого маршрута хвост промптов получает строку про постановку
  //   вместо plan.md)
  // Выход: итог_сессии (у КОММИТ и ПУШ — готово: стоп-слова у них нет)
  ЗАПУСК_СЕССИИ => match тело_события {

    Ответ_сессии { итог_сессии: итог } => {

    Сбой { причина } => {

    _ => НеЖдёт
  }

  // ===================== ОТКАЗ_СЕССИИ — развилка =====================
  // Решает, как раннер остановится, если вложенный запуск сессии не вернул итог: по человеку (он остановил на воротах) или по отсутствию результата.
  // Вход: причина_сбоя
  ОТКАЗ_СЕССИИ => {
    // ОТКАЗ_СЕССИИ #1: причина_сбоя = «остановлено человеком»
    if @причина_сбоя == "остановлено человеком" {

      return Куда(ОСТАНОВЛЕНО)
    }
    // ОТКАЗ_СЕССИИ #2: причина_сбоя = «нет результата»
    if @причина_сбоя == "нет результата" {

      return Куда(ОСТАНОВЛЕНО)
    }
    // ОТКАЗ_СЕССИИ #3: иначе
    среда.ошибка_машины("ошибка машины: развилка ОТКАЗ_СЕССИИ, ни одно условие не подошло")
  }

  // ===================== ПОСЛЕ_СЕССИИ — развилка =====================
  // Решает, куда идти после сессии: у каждого места, откуда сессию запустили, свой путь; место называет «продолжение».
  // Вход: продолжение; итог_сессии; цикл[стадия] (по каждой стадии; читают строки с правкой владельца)
  ПОСЛЕ_СЕССИИ => {
    // ПОСЛЕ_СЕССИИ #1: продолжение = «разбор: очередь», и итог_сессии = «вопрос»
    if @продолжение == "разбор: очередь" && итог_равен(@итог_сессии, ИтогСессии.Вопрос) { return Куда(В4_ВОПРОС) }
    // ПОСЛЕ_СЕССИИ #2: продолжение = «разбор: очередь», и итог_сессии отличается от «вопрос»
    if @продолжение == "разбор: очередь" && !итог_равен(@итог_сессии, ИтогСессии.Вопрос) { return Куда(РАЗБОР_ПРОВЕРКА) }
    // ПОСЛЕ_СЕССИИ #3: продолжение = «разбор: первая сессия»
    if @продолжение == "разбор: первая сессия" { return Куда(РАЗБОР_ПРОВЕРКА) }
    // ПОСЛЕ_СЕССИИ #4: продолжение = «разбор: возврат»
    if @продолжение == "разбор: возврат" { return Куда(СВЕРКА_СПЕЦИФИКАЦИИ) }
    // ПОСЛЕ_СЕССИИ #5: продолжение = «разбор: ответы после вопроса»
    if @продолжение == "разбор: ответы после вопроса" {
      @правка_владельца(Стадия.Разбор)
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_СЕССИИ #6: продолжение = «разбор: ответы»
    if @продолжение == "разбор: ответы" {
      @правка_владельца(Стадия.Разбор)
      @документ_на_утверждении = "спецификация"
      return Куда(УТВЕРЖДЕНИЕ)
    }
    // ПОСЛЕ_СЕССИИ #7: продолжение = «разбор: ответы меняют цель»
    if @продолжение == "разбор: ответы меняют цель" {
      @правка_владельца(Стадия.Разбор)
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_СЕССИИ #8: продолжение = «план: очередь», и итог_сессии = «требования»
    if @продолжение == "план: очередь" && итог_равен(@итог_сессии, ИтогСессии.Требования) {
      @источник_маршрута = "последний абзац плана"
      return Куда(К_ТРЕБОВАНИЯМ)
    }
    // ПОСЛЕ_СЕССИИ #9: продолжение = «план: очередь», и итог_сессии = «вопрос»
    if @продолжение == "план: очередь" && итог_равен(@итог_сессии, ИтогСессии.Вопрос) { return Куда(В7_ПЛАН_ОЧЕРЕДЬ) }
    // ПОСЛЕ_СЕССИИ #10: продолжение = «план: очередь», и итог_сессии отличается от «требования» и от «вопрос»
    if @продолжение == "план: очередь" && !итог_равен(@итог_сессии, ИтогСессии.Требования) && !итог_равен(@итог_сессии, ИтогСессии.Вопрос) { return Куда(ПЛАН_СТОП_СЛОВО) }
    // ПОСЛЕ_СЕССИИ #11: продолжение = «план: первая сессия»
    if @продолжение == "план: первая сессия" { return Куда(ПЛАН_СТОП_СЛОВО) }
    // ПОСЛЕ_СЕССИИ #12: продолжение = «план: решено»
    if @продолжение == "план: решено" {
      @правка_владельца(Стадия.План)
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_СЕССИИ #13: продолжение = «реализация: очередь»
    if @продолжение == "реализация: очередь" { return Куда(ИСХОД_РЕАЛИЗАЦИИ) }
    // ПОСЛЕ_СЕССИИ #14: продолжение = «реализация: первая сессия»
    if @продолжение == "реализация: первая сессия" { return Куда(ИСХОД_РЕАЛИЗАЦИИ) }
    // ПОСЛЕ_СЕССИИ #15: продолжение = «реализация: продолжение»
    if @продолжение == "реализация: продолжение" { return Куда(ИСХОД_РЕАЛИЗАЦИИ) }
    // ПОСЛЕ_СЕССИИ #16: продолжение = «сдача: сдача»
    if @продолжение == "сдача: сдача" { return Куда(СДАЧА_ПРОВЕРКА) }
    // ПОСЛЕ_СЕССИИ #17: продолжение = «сдача: коммит»
    if @продолжение == "сдача: коммит" { return Куда(СДАЧА_СООБЩЕНИЕ) }
    // ПОСЛЕ_СЕССИИ #18: продолжение = «сдача: пуш»
    if @продолжение == "сдача: пуш" { return Куда(В10г) }
    // ПОСЛЕ_СЕССИИ #19: продолжение = «обратная связь: разбор»
    if @продолжение == "обратная связь: разбор" {
      for стадия in стадии_цикла() { @правка_владельца(стадия) }
      return Куда(МАРШРУТ_ОБРАТНОЙ_СВЯЗИ)
    }
    // ПОСЛЕ_СЕССИИ #20: иначе
    среда.ошибка_машины("ошибка машины: развилка ПОСЛЕ_СЕССИИ, ни одно условие не подошло")
  }

  // ===================== К_ТРЕБОВАНИЯМ — операция =====================
  // Возвращает работу на уровень требований: и спецификация, и план становятся черновиками, а фаза РАЗБОР начинает с правки спецификации, фаза ПЛАН —
  //   с правки плана.
  // При входе: `to_requirements`: `invalidate(spec.md)` и `invalidate(plan.md)` — первые строки обоих файлов ← «Статус: черновик», записи об
  //   утверждении удаляются; закрываются диалоги, в слое 3 которых были эти файлы (С3 и С5; диалог автора С1 не закрывается); префикс основного диалога
  //   пересобирается.
  // Вход: спецификация?; план_задачи?; источник_маршрута
  // Выход: спецификация? (статус «черновик»); план_задачи? (статус «черновик»); утверждения[документ]? (снято у обоих документов)
  К_ТРЕБОВАНИЯМ => match тело_события {
    // К_ТРЕБОВАНИЯМ #1: сразу
    Сразу => {
      @установить_отложенную_сессию("РАЗБОР", "С1п")
      @установить_источник_отложенной("РАЗБОР", @источник_маршрута)
      @установить_отложенную_сессию("ПЛАН", "С3п")
      @установить_источник_отложенной("ПЛАН", @источник_с_пометками_спецификации(@источник_маршрута))
      @фаза = "РАЗБОР"
      Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    _ => НеЖдёт
  }

  // ===================== К_ПЛАНУ — операция =====================
  // Возвращает работу на уровень плана: план становится черновиком, а фаза ПЛАН начинает с правки.
  // При входе: `to_plan`: `invalidate(plan.md)` — первая строка плана ← «Статус: черновик», запись об утверждении удаляется; закрывается диалог С5;
  //   префикс пересобирается.
  // Вход: план_задачи?; источник_маршрута
  // Выход: план_задачи? (статус «черновик»); утверждения[план]? (снято)
  К_ПЛАНУ => match тело_события {
    // К_ПЛАНУ #1: сразу
    Сразу => {
      @установить_отложенную_сессию("ПЛАН", "С3п")
      @установить_источник_отложенной("ПЛАН", @источник_маршрута)
      @фаза = "ПЛАН"
      Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    _ => НеЖдёт
  }

  // ===================== КЛАССИФИКАЦИЯ_МАРШРУТА — развилка =====================
  // Предлагает маршрут задачи по признакам из постановки и порогам проекта: любое сомнение даёт «полный»; предложение подтверждает или меняет человек на
  //   воротах В14.
  // Вход: признаки_маршрута?; параметры_проекта
  КЛАССИФИКАЦИЯ_МАРШРУТА => {
    ro пороги = @параметры_проекта().пороги
    match @признаки_маршрута() {
      None => {
        // КЛАССИФИКАЦИЯ_МАРШРУТА #1: признаков нет
        @предложение_маршрута = "полный"
        @основание_маршрута = "признаки не записаны"
        @источник_выбора_маршрута = "правило"
        среда.писать_журнал("маршрут предложен: ${@предложение_маршрута}, ${@источник_выбора_маршрута}: ${@основание_маршрута}")
        Куда(В14)
      }
      Some(признаки) => {
        // КЛАССИФИКАЦИЯ_МАРШРУТА #2: признаки есть, и признаки неполны
        if признаки_неполны(признаки) {
          @предложение_маршрута = "полный"
          @основание_маршрута = "признаки неполны: ${перечень_неполных_признаков(признаки)}"
          @источник_выбора_маршрута = "правило"
          среда.писать_журнал("маршрут предложен: ${@предложение_маршрута}, ${@источник_выбора_маршрута}: ${@основание_маршрута}")
          return Куда(В14)
        }
        // КЛАССИФИКАЦИЯ_МАРШРУТА #3: признаки есть, они полны, и предложение_помощника = «полный»
        if !признаки_неполны(признаки) && признаки.предложение_помощника == "полный" {
          @предложение_маршрута = "полный"
          @основание_маршрута = "помощник предложил полный маршрут"
          @источник_выбора_маршрута = "помощник"
          среда.писать_журнал("маршрут предложен: ${@предложение_маршрута}, ${@источник_выбора_маршрута}: ${@основание_маршрута}")
          return Куда(В14)
        }
        // КЛАССИФИКАЦИЯ_МАРШРУТА #4: признаки есть, они полны, предложение_помощника не равно «полный», и признак выходит за порог
        if !признаки_неполны(признаки) && признаки.предложение_помощника != "полный" && признак_выходит_за_порог(признаки, пороги) {
          @предложение_маршрута = "полный"
          @основание_маршрута = "признак выходит за порог: ${перечень_признаков_за_порогом(признаки, пороги)}"
          @источник_выбора_маршрута = "правило"
          среда.писать_журнал("маршрут предложен: ${@предложение_маршрута}, ${@источник_выбора_маршрута}: ${@основание_маршрута}")
          return Куда(В14)
        }
        // КЛАССИФИКАЦИЯ_МАРШРУТА #5: признаки есть, они полны, предложение_помощника не равно «полный», и ни один признак не выходит за порог
        if !признаки_неполны(признаки) && признаки.предложение_помощника != "полный" && !признак_выходит_за_порог(признаки, пороги) {
          @предложение_маршрута = "быстрый"
          @основание_маршрута = "все признаки в пределах порогов"
          @источник_выбора_маршрута = "правило"
          среда.писать_журнал("маршрут предложен: ${@предложение_маршрута}, ${@источник_выбора_маршрута}: ${@основание_маршрута}")
          return Куда(В14)
        }
        // КЛАССИФИКАЦИЯ_МАРШРУТА #6: иначе
        среда.ошибка_машины("ошибка машины: развилка КЛАССИФИКАЦИЯ_МАРШРУТА, ни одно условие не подошло")
      }
    }
  }

  // ===================== В14 — обращение =====================
  // Показывает человеку предложенный маршрут с основанием и просит выбрать маршрут задачи: «быстрый» или «полный»; его слово старше правила.

  // ===================== В5 — обращение =====================
  // Ждёт, пока человек поставит в документе «Статус: утверждено, дата, кто» и подтвердит это в программе: утверждает только человек.
  // При входе: ворота В5: человек просматривает документ на утверждении (спецификацию после В4 или план после В6), ставит строку статуса и
  //   подтверждает.
  //   У быстрого маршрута постановку первый раз утверждает слово владельца «заводи <номер>», принятое у В14 и записанное КОПИЯ_ПОСТАНОВКИ (решение 39; предложение, требует
  //   слова владельца), поэтому сюда быстрый маршрут попадает только после правки копии (она вернулась в «черновик»); исход «полный путь» предлагается только при быстром маршруте.
  // Сторона: человек.
  // Вход: документ_на_утверждении; маршрут (исход «полный путь» предлагается только при «быстрый»)
  // Выход: исход ворот; основание? (только у исхода «полный путь»: слово человека с датой и источником)
  В5 => match тело_события {
    // В5 #1: В5: «подтвердил»
    В5_подтвердил => Куда(ЗАПИСЬ_УТВЕРЖДЕНИЯ)
    // В5 #2: В5: «полный путь» (основание: Текст)
    Полный_путь { основание } => {
      @источник_выбора_маршрута = "человек"
      @основание_маршрута = основание
      Куда(ВОЗВРАТ_ПОЛНОГО_ПУТИ)
    }
    _ => НеЖдёт
  }

  // ===================== ЗАПИСЬ_УТВЕРЖДЕНИЯ — операция =====================
  // Записывает утверждение: когда, кто и хеш текста, чтобы потом заметить правку после утверждения.
  // При входе: `approvals[файл] ← {дата, кто, hash(файл)}`: дата и «кто» берутся из строки статуса, хеш — по тексту документа; префикс основного
  //   диалога пересобирается (слой 3 теперь содержит документ).
  // Вход: документ_на_утверждении; спецификация?; план_задачи?
  // Выход: утверждения[документ] (по документу на утверждении)
  ЗАПИСЬ_УТВЕРЖДЕНИЯ => match тело_события {
    // ЗАПИСЬ_УТВЕРЖДЕНИЯ #1: сразу
    Сразу => Куда(ПОСЛЕ_УТВЕРЖДЕНИЯ)
    _ => НеЖдёт
  }

  // ===================== ПОСЛЕ_УТВЕРЖДЕНИЯ — развилка =====================
  // Переводит задачу в следующую фазу: после спецификации — ПЛАН, после плана — РЕАЛИЗАЦИЯ.
  // Вход: документ_на_утверждении
  ПОСЛЕ_УТВЕРЖДЕНИЯ => {
    // ПОСЛЕ_УТВЕРЖДЕНИЯ #1: документ_на_утверждении = «спецификация»
    if @документ_на_утверждении == "спецификация" {
      @фаза = "ПЛАН"
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_УТВЕРЖДЕНИЯ #2: документ_на_утверждении = «план»
    if @документ_на_утверждении == "план" {
      @фаза = "РЕАЛИЗАЦИЯ"
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_УТВЕРЖДЕНИЯ #3: иначе
    среда.ошибка_машины("ошибка машины: развилка ПОСЛЕ_УТВЕРЖДЕНИЯ, ни одно условие не подошло")
  }

  // ===================== РАЗБОР — развилка =====================
  // Вход в фазу РАЗБОР: маршрут не выбран — идёт выбирать; при быстром маршруте постановка идёт сразу на утверждение; при полном есть отложенная сессия — запускает
  //   её, нет спецификации — запускает первую сессию разбора, иначе идёт к проверке спецификации.
  // Вход: отложенная_сессия[РАЗБОР]; источник_отложенной[РАЗБОР]; спецификация?; утверждения[спецификация]?; маршрут
  РАЗБОР => {
    // РАЗБОР #1: маршрут = `""`
    if @маршрут == "" { return Куда(КЛАССИФИКАЦИЯ_МАРШРУТА) }
    // РАЗБОР #2: маршрут = «быстрый», отложенная_сессия[РАЗБОР] = `""`, спецификация есть, её статус «утверждено», и утверждение спецификации действует
    if @маршрут == "быстрый" && @отложенная_сессия("РАЗБОР") == "" && статус_равен(@спецификация(), СтатусАртефакта.Утверждено) && @утверждение_действует("спецификация") {
      @документ_на_утверждении = "спецификация"
      среда.писать_журнал("быстрый маршрут: копия постановки утверждена словом завода, С1, С2, В4 и В5 пропущены")
      return Куда(ПОСЛЕ_УТВЕРЖДЕНИЯ)
    }
    // РАЗБОР #3: маршрут = «быстрый», отложенная_сессия[РАЗБОР] = `""`, спецификация есть, и её статус «черновик»
    if @маршрут == "быстрый" && @отложенная_сессия("РАЗБОР") == "" && статус_равен(@спецификация(), СтатусАртефакта.Черновик) {
      @документ_на_утверждении = "спецификация"
      среда.писать_журнал("быстрый маршрут: копию правили после утверждения, нужно новое слово человека")
      return Куда(УТВЕРЖДЕНИЕ)
    }
    // РАЗБОР #4: маршрут = «быстрый», отложенная_сессия[РАЗБОР] = `""`, и спецификации нет
    if @маршрут == "быстрый" && @отложенная_сессия("РАЗБОР") == "" && @спецификация() == None {
      @источник_выбора_маршрута = "правило"
      @основание_маршрута = "постановки нет: утверждать нечего"
      среда.писать_журнал("быстрый маршрут: постановки нет")
      return Куда(ВОЗВРАТ_ПОЛНОГО_ПУТИ)
    }
    // РАЗБОР #5: маршрут = «быстрый», и отложенная_сессия[РАЗБОР] не равна `""`
    if @маршрут == "быстрый" && @отложенная_сессия("РАЗБОР") != "" {
      @источник_выбора_маршрута = "правило"
      @основание_маршрута = "правка меняет требования: задача не мала"
      среда.писать_журнал("быстрый маршрут: очередь правки требований")
      return Куда(ВОЗВРАТ_ПОЛНОГО_ПУТИ)
    }
    // РАЗБОР #6: маршрут = «полный», и отложенная_сессия[РАЗБОР] не равна `""`
    if @маршрут == "полный" && @отложенная_сессия("РАЗБОР") != "" {
      @сессия = @отложенная_сессия("РАЗБОР")
      @источник_запуска = @источник_отложенной("РАЗБОР")
      @установить_отложенную_сессию("РАЗБОР", "")
      @установить_источник_отложенной("РАЗБОР", "")
      @продолжение = "разбор: очередь"
      return Куда(ЗАПУСК_СЕССИИ)
    }
    // РАЗБОР #7: маршрут = «полный», отложенная_сессия[РАЗБОР] = `""`, и спецификации нет
    if @маршрут == "полный" && @отложенная_сессия("РАЗБОР") == "" && @спецификация() == None {
      @назначить_запуск("С1", "", "разбор: первая сессия")
      return Куда(ЗАПУСК_СЕССИИ)
    }
    // РАЗБОР #8: маршрут = «полный», отложенная_сессия[РАЗБОР] = `""`, и спецификация есть
    if @маршрут == "полный" && @отложенная_сессия("РАЗБОР") == "" && @спецификация() != None { return Куда(РАЗБОР_ПРОВЕРКА) }
    // РАЗБОР #9: иначе
    среда.ошибка_машины("ошибка машины: развилка РАЗБОР, ни одно условие не подошло")
  }

  // ===================== РАЗБОР_ПРОВЕРКА — обращение =====================
  // Просит вложенную машину проверки цикла проверить спецификацию (повтор «проверка С2 ↔ правка С1п»); возвращает, чисто ли, и куда вернуть работу,
  //   если нет.
  // При входе: исполнитель отправляет запрос вложенной машине проверки цикла (`loop_review(spec)`): стадия «разбор» и счётчики цикла; машина сама
  //   запускает сессии С2 и С1п, ворота В3 и В9.
  // Сторона: проверка (вложенная машина, [task-runner-review-states.md](task-runner-review-states.md)).
  // Вход (сторона): цикл[разбор] (и стадия «разбор» (константа состояния, входит в запрос)); папка_задачи; рабочее_дерево; режим_сдачи; чистых_подряд; потолок_заходов; проб_в_чистом; сдача_сжата (у стадии «разбор» не читается); маршрут (подстановка хвоста промптов)
  // Выход: итог_проверки
  РАЗБОР_ПРОВЕРКА => match тело_события {
    // РАЗБОР_ПРОВЕРКА #1: ответ: чисто (цикл: Цикл)
    Проверка_чисто { цикл, .. } => {
      @установить_цикл(Стадия.Разбор, цикл)
      Куда(В4)
    }
    // РАЗБОР_ПРОВЕРКА #2: ответ: требования (цикл: Цикл; источник: Текст)
    Проверка_требования { цикл, источник, .. } => {
      @установить_цикл(Стадия.Разбор, цикл)
      @назначить_запуск("С1п", источник, "разбор: возврат")
      Куда(ЗАПУСК_СЕССИИ)
    }
    // РАЗБОР_ПРОВЕРКА #3: ответ: вопрос (цикл: Цикл)
    Проверка_вопрос { цикл, .. } => {
      @установить_цикл(Стадия.Разбор, цикл)
      Куда(В4_ВОПРОС)
    }
    // РАЗБОР_ПРОВЕРКА #4: ответ: план (цикл: Цикл)
    Проверка_план { цикл, .. } => {
      @установить_цикл(Стадия.Разбор, цикл)
      Куда(В4)
    }
    // РАЗБОР_ПРОВЕРКА #5: сбой (причина: КодСбоя)
    Сбой { причина } => {
      @причина_сбоя = слово_кода(причина)
      среда.писать_журнал("проверка разбора не дала итога: ${слово_кода(причина)}")
      Куда(ОТКАЗ_ПРОВЕРКИ)
    }
    _ => НеЖдёт
  }

  // ===================== В4 — обращение =====================
  // Отдаёт человеку вопросы и сценарии заказчику и получает ответы с источниками; человек же говорит, меняют ли ответы цель, границы или сценарии.
  // При входе: ворота В4: «Вы после С2» — вопросы и сценарии заказчику, текст и источник каждого ответа (`task-runner.md`, «Ворота»); в режиме
  //   «показывать и продолжать» при пустом списке исполнитель сам даёт исход «ответов нет».
  // Сторона: человек.
  // Вход: спецификация
  // Выход: исход ворот; ответы_заказчика? (только у исходов с ответами: текст и источник каждого)
  В4 => match тело_события {
    // В4 #1: В4: «ответов нет»
    В4_ответов_нет => {
      @документ_на_утверждении = "спецификация"
      Куда(УТВЕРЖДЕНИЕ)
    }
    // В4 #2: В4: «ответы» (ответы_заказчика: Текст)
    В4_ответы { ответы_заказчика: ответы } => {
      @ответы_заказчика = ответы
      @назначить_запуск("С1п", "Ответы", "разбор: ответы")
      Куда(ЗАПИСЬ_ОТВЕТОВ)
    }
    // В4 #3: В4: «ответы меняют цель, границы или сценарии» (ответы_заказчика: Текст)
    В4_ответы_меняют_цель { ответы_заказчика: ответы } => {
      @ответы_заказчика = ответы
      @назначить_запуск("С1п", "Ответы", "разбор: ответы меняют цель")
      Куда(ЗАПИСЬ_ОТВЕТОВ)
    }
    _ => НеЖдёт
  }

  // ===================== В4_ВОПРОС — обращение =====================
  // Те же ворота В4, когда к ним пришли после остановки «вопрос»: ответы нужны, чтобы агент продолжил правку спецификации; что бы человек ни ответил,
  //   правка идёт.
  // При входе: ворота В4 после остановки сессии С1п или проверки разбора словом «вопрос»: человек отвечает заказчику вопросом из последнего абзаца
  //   спецификации; ответы записываются в спецификацию, запускается С1п, работа возвращается в голову цикла (в псевдокоде ответы здесь не проверяются
  //   на пустоту и на смену цели).
  // Сторона: человек.
  // Вход: спецификация
  // Выход: исход ворот; ответы_заказчика? (только у исходов с ответами)
  В4_ВОПРОС => match тело_события {
    // В4_ВОПРОС #1: В4: «ответов нет»
    В4_ответов_нет => {
      @ответы_заказчика = ""
      @назначить_запуск("С1п", "Ответы", "разбор: ответы после вопроса")
      Куда(ЗАПИСЬ_ОТВЕТОВ)
    }
    // В4_ВОПРОС #2: В4: «ответы» (ответы_заказчика: Текст)
    В4_ответы { ответы_заказчика: ответы } => {
      @ответы_заказчика = ответы
      @назначить_запуск("С1п", "Ответы", "разбор: ответы после вопроса")
      Куда(ЗАПИСЬ_ОТВЕТОВ)
    }
    // В4_ВОПРОС #3: В4: «ответы меняют цель, границы или сценарии» (ответы_заказчика: Текст)
    В4_ответы_меняют_цель { ответы_заказчика: ответы } => {
      @ответы_заказчика = ответы
      @назначить_запуск("С1п", "Ответы", "разбор: ответы после вопроса")
      Куда(ЗАПИСЬ_ОТВЕТОВ)
    }
    _ => НеЖдёт
  }

  // ===================== ЗАПИСЬ_ОТВЕТОВ — операция =====================
  // Записывает ответы заказчика в спецификацию, чтобы сессия правки их прочитала.
  // При входе: `write_answers`: в раздел «Ответы» спецификации записываются ответы с текстом и источником каждого.
  // Вход: ответы_заказчика; спецификация?
  // Выход: спецификация
  ЗАПИСЬ_ОТВЕТОВ => match тело_события {
    // ЗАПИСЬ_ОТВЕТОВ #1: сразу
    Сразу => Куда(ЗАПУСК_СЕССИИ)
    _ => НеЖдёт
  }

  // ===================== ПЛАН — развилка =====================
  // Вход в фазу ПЛАН: при быстром маршруте фаза пропускается; при полном есть отложенная сессия — запускает её, нет плана — запускает первую сессию плана, иначе смотрит
  //   стоп-слово плана.
  // Вход: отложенная_сессия[ПЛАН]; источник_отложенной[ПЛАН]; план_задачи?; маршрут
  ПЛАН => {
    // ПЛАН #1: маршрут = «быстрый», и отложенная_сессия[ПЛАН] = `""`
    if @маршрут == "быстрый" && @отложенная_сессия("ПЛАН") == "" {
      @фаза = "РЕАЛИЗАЦИЯ"
      среда.писать_журнал("быстрый маршрут: фаза ПЛАН пропущена, план реализации — в начале отчёта реализации")
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПЛАН #2: маршрут = «быстрый», и отложенная_сессия[ПЛАН] не равна `""`
    if @маршрут == "быстрый" && @отложенная_сессия("ПЛАН") != "" {
      @источник_выбора_маршрута = "правило"
      @основание_маршрута = "правка меняет план: задача не мала"
      среда.писать_журнал("быстрый маршрут: очередь правки плана")
      return Куда(ВОЗВРАТ_ПОЛНОГО_ПУТИ)
    }
    // ПЛАН #3: маршрут = «полный», и отложенная_сессия[ПЛАН] не равна `""`
    if @маршрут == "полный" && @отложенная_сессия("ПЛАН") != "" {
      @сессия = @отложенная_сессия("ПЛАН")
      @источник_запуска = @источник_отложенной("ПЛАН")
      @установить_отложенную_сессию("ПЛАН", "")
      @установить_источник_отложенной("ПЛАН", "")
      @продолжение = "план: очередь"
      return Куда(ЗАПУСК_СЕССИИ)
    }
    // ПЛАН #4: маршрут = «полный», отложенная_сессия[ПЛАН] = `""`, и плана нет
    if @маршрут == "полный" && @отложенная_сессия("ПЛАН") == "" && @план_задачи() == None {
      @назначить_запуск("С3", "", "план: первая сессия")
      return Куда(ЗАПУСК_СЕССИИ)
    }
    // ПЛАН #5: маршрут = «полный», отложенная_сессия[ПЛАН] = `""`, и план есть
    if @маршрут == "полный" && @отложенная_сессия("ПЛАН") == "" && @план_задачи() != None { return Куда(ПЛАН_СТОП_СЛОВО) }
    // ПЛАН #6: иначе
    среда.ошибка_машины("ошибка машины: развилка ПЛАН, ни одно условие не подошло")
  }

  // ===================== ПЛАН_СТОП_СЛОВО — развилка =====================
  // Смотрит, остановилась ли сессия плана словом «требования»: тогда работу надо вернуть на уровень требований, а не проверять план.
  // Вход: план_задачи?
  ПЛАН_СТОП_СЛОВО => {
    // ПЛАН_СТОП_СЛОВО #1: план есть, и его стоп_слово = «требования»
    if @план_задачи() != None && стоп_слово_равно(@план_задачи(), СтопСлово.Требования) {
      @источник_маршрута = "последний абзац плана"
      return Куда(К_ТРЕБОВАНИЯМ)
    }
    // ПЛАН_СТОП_СЛОВО #2: план есть, и его стоп_слово отличается от «требования»
    if @план_задачи() != None && !стоп_слово_равно(@план_задачи(), СтопСлово.Требования) { return Куда(ПЛАН_ПРОВЕРКА) }

    if @различия_дерева() == "" {
      среда.писать_журнал("сдача без изменений кода")
      return Куда(В10г)
    }
    // СДАЧА_ДИФФ #2: различия_дерева не равно `""`
    if @различия_дерева() != "" { return Куда(В10а) }
    // СДАЧА_ДИФФ #3: иначе
    среда.ошибка_машины("ошибка машины: развилка СДАЧА_ДИФФ, ни одно условие не подошло")
  }

  // ===================== В10а — обращение =====================
  // Показывает человеку сообщение коммита, ветку и состояние дерева и просит разрешить коммит.
  // При входе: ворота В10а: коммит — показываются commit.txt, ветка, состояние дерева; у быстрого маршрута возможен ещё исход «полный путь» (человек возвращает полный маршрут до коммита).
  // Сторона: человек.
  // Вход: маршрут (исход «полный путь» предлагается только при «быстрый»)
  // Выход: исход ворот; основание? (только у исхода «полный путь»: слово человека с датой и источником)
  В10а => match тело_события {
    // В10а #1: В10а: «разрешить коммит»
    В10а_разрешить_коммит => {
      @назначить_запуск("КОММИТ", "", "сдача: коммит")
      Куда(ЗАПУСК_СЕССИИ)
    }
    // В10а #2: В10а: «полный путь» (основание: Текст)
    Полный_путь { основание } => {
      @источник_выбора_маршрута = "человек"
      @основание_маршрута = основание
      Куда(ВОЗВРАТ_ПОЛНОГО_ПУТИ)
    }
    _ => НеЖдёт
  }

  // ===================== СДАЧА_СООБЩЕНИЕ — развилка =====================
  // Сверяет сообщение сделанного коммита с подготовленным текстом: расхождение показывается человеку.
  // Вход: сообщение_коммита; текст_коммита
  СДАЧА_СООБЩЕНИЕ => {
    // СДАЧА_СООБЩЕНИЕ #1: сообщение_коммита отличается от текста_коммита побайтно
    if @сообщение_коммита() != @текст_коммита() { return Куда(В10б) }
    // СДАЧА_СООБЩЕНИЕ #2: сообщение_коммита равно тексту_коммита побайтно
    if @сообщение_коммита() == @текст_коммита() { return Куда(В10в) }
    // СДАЧА_СООБЩЕНИЕ #3: иначе
    среда.ошибка_машины("ошибка машины: развилка СДАЧА_СООБЩЕНИЕ, ни одно условие не подошло")
  }

  // ===================== В10б — обращение =====================
  // Сообщает человеку, что сообщение последнего коммита не совпало с подготовленным, и просит продолжить.
  // При входе: ворота В10б: сообщение коммита изменено; исход ворот в источниках не назван — единственный путь дальше («Решения при переводе»).
  // Сторона: человек.
  // Вход: нет.
  // Выход: исход ворот
  В10б => match тело_события {
    // В10б #1: В10б: «продолжить»
    В10б_продолжить => Куда(В10в)
    _ => НеЖдёт
  }

  // ===================== В10в — обращение =====================
  // Показывает человеку сообщение коммита из истории и просит разрешить пуш.
  // При входе: ворота В10в: пуш — показывается сообщение из истории.
  // Сторона: человек.
  // Вход: нет.
  // Выход: исход ворот
  В10в => match тело_события {
    // В10в #1: В10в: «разрешить пуш»
    В10в_разрешить_пуш => {
      @назначить_запуск("ПУШ", "", "сдача: пуш")
      Куда(ЗАПУСК_СЕССИИ)
    }
    _ => НеЖдёт
  }

  // ===================== В10г — обращение =====================
  // Просит человека отправить письмо заказчику (это делает человек) и подтвердить; после этого сдача закончена и ждёт обратной связи.
  // При входе: ворота В10г: отправка текстов заказчику; человек делает это вне программы.
  // Сторона: человек.
  // Вход: нет.
  // Выход: исход ворот
  В10г => match тело_события {
    // В10г #1: В10г: «отправлено»
    В10г_отправлено => {
      @фаза = "ОБРАТНАЯ_СВЯЗЬ"
      Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    _ => НеЖдёт
  }

  // ===================== В11 — обращение =====================
  // Ждёт обратную связь заказчика: она приходит — раунд правки, либо человек завершает задачу.
  // При входе: ворота В11: обратная связь после сдачи или завершение задачи.
  // Сторона: человек.
  // Вход: номер_раунда (раунд, который закончился или начнётся)
  // Выход: исход ворот; обратная_связь? (только у исхода «обратная связь»)
  В11 => match тело_события {
    // В11 #1: В11: «завершить»
    В11_завершить => {
      @фаза = "ЗАВЕРШЕНО"
      Куда(КОНЕЦ)
    }
    // В11 #2: В11: «обратная связь» (обратная_связь: Текст)
    В11_обратная_связь { обратная_связь: связь } => {
      @номер_раунда += 1
      @обратная_связь = связь
      Куда(СОХРАНЕНИЕ_ОБРАТНОЙ_СВЯЗИ)
    }
    _ => НеЖдёт
  }

  // ===================== СОХРАНЕНИЕ_ОБРАТНОЙ_СВЯЗИ — операция =====================
  // Сохраняет обратную связь заказчика в папке раунда: на её основе агент разберёт замечания.
  // При входе: обратная связь записывается в `task/feedback-<номер_раунда>/` (вне префикса: папка раунда в слой 2 не входит).
  // Вход: обратная_связь; номер_раунда
  // Выход: замечания_раундов[номер_раунда]
  СОХРАНЕНИЕ_ОБРАТНОЙ_СВЯЗИ => match тело_события {
    // СОХРАНЕНИЕ_ОБРАТНОЙ_СВЯЗИ #1: сразу
    Сразу => {
      @назначить_запуск("С9", "", "обратная связь: разбор")
      Куда(ЗАПУСК_СЕССИИ)
    }
    _ => НеЖдёт
  }

  // ===================== МАРШРУТ_ОБРАТНОЙ_СВЯЗИ — развилка =====================
  // Читает маршрут из разбора обратной связи и возвращает работу на нужный уровень: требования, план, реализацию или прямо к сдаче.
  // Вход: маршрут_обратной_связи?; номер_раунда
  МАРШРУТ_ОБРАТНОЙ_СВЯЗИ => {
    // МАРШРУТ_ОБРАТНОЙ_СВЯЗИ #1: маршрут_обратной_связи = «Маршрут: С1 правка»
    if @маршрут_обратной_связи() == Some("Маршрут: С1 правка") {
      @установить_отложенную_сессию("РЕАЛИЗАЦИЯ", "С5п")
      @установить_источник_отложенной("РЕАЛИЗАЦИЯ", "файл разбора обратной связи раунда ${@номер_раунда}")
      @источник_маршрута = "файл разбора обратной связи раунда ${@номер_раунда}"
      return Куда(К_ТРЕБОВАНИЯМ)
    }
    // МАРШРУТ_ОБРАТНОЙ_СВЯЗИ #2: маршрут_обратной_связи = «Маршрут: С3 правка»
    if @маршрут_обратной_связи() == Some("Маршрут: С3 правка") {
      @установить_отложенную_сессию("РЕАЛИЗАЦИЯ", "С5п")
      @установить_источник_отложенной("РЕАЛИЗАЦИЯ", "файл разбора обратной связи раунда ${@номер_раунда}")
      @источник_маршрута = "файл разбора обратной связи раунда ${@номер_раунда}"
      return Куда(К_ПЛАНУ)
    }
    // МАРШРУТ_ОБРАТНОЙ_СВЯЗИ #3: маршрут_обратной_связи = «Маршрут: С5 правка»
    if @маршрут_обратной_связи() == Some("Маршрут: С5 правка") {
      @установить_отложенную_сессию("РЕАЛИЗАЦИЯ", "С5п")
      @установить_источник_отложенной("РЕАЛИЗАЦИЯ", "файл разбора обратной связи раунда ${@номер_раунда}")
      @фаза = "РЕАЛИЗАЦИЯ"
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // МАРШРУТ_ОБРАТНОЙ_СВЯЗИ #4: маршрут_обратной_связи = «Маршрут: С7»
    if @маршрут_обратной_связи() == Some("Маршрут: С7") {
      @фаза = "СДАЧА"
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // МАРШРУТ_ОБРАТНОЙ_СВЯЗИ #5: иначе
    среда.ошибка_машины("ошибка машины: развилка МАРШРУТ_ОБРАТНОЙ_СВЯЗИ, ни одно условие не подошло")
  }

  // ===================== ОТКАЗ_ПРОВЕРКИ — развилка =====================
  // Решает, как раннер остановится, если вложенная проверка цикла не вернула итог: по человеку или по отсутствию результата.
  // Вход: причина_сбоя
  ОТКАЗ_ПРОВЕРКИ => {
    // ОТКАЗ_ПРОВЕРКИ #1: причина_сбоя = «остановлено человеком»
    if @причина_сбоя == "остановлено человеком" {
      @остановка = "проверка цикла: остановлено человеком"
      return Куда(ОСТАНОВЛЕНО)
    }
    // ОТКАЗ_ПРОВЕРКИ #2: причина_сбоя = «нет результата»
    if @причина_сбоя == "нет результата" {
      @остановка = "проверка цикла: нет результата"
      return Куда(ОСТАНОВЛЕНО)
    }
    // ОТКАЗ_ПРОВЕРКИ #3: иначе
    среда.ошибка_машины("ошибка машины: развилка ОТКАЗ_ПРОВЕРКИ, ни одно условие не подошло")
  }

  // ===================== ПАУЗА — обращение =====================
  // Подключено фрагментом «Пауза» (state-machine-pause-states.md): события ПАУЗЫ разбирает движок (`общие_события`), строк состояния у машины нет;
  //   остальные события ПАУЗА не ждёт.
  ПАУЗА => НеЖдёт

  // ===================== КОНЕЦ — конец =====================
  // Записывает, что задача завершена, и возвращает занятую блокировку.
  // При входе: блокировка `runner.lock` снимается; в журнал — «задача завершена, раундов обратной связи: <номер_раунда>»; человеку показывается
  //   «задача завершена».
  // Вход: номер_раунда
  КОНЕЦ => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  // ===================== ОСТАНОВЛЕНО — конец =====================
  // Заканчивает работу раннера без завершения задачи и записывает, почему; решение, что делать дальше, — за человеком вне машины.
  // При входе: группа процессов агента останавливается целиком и проверяется, что в ней не осталось процессов; в журнал — «раннер остановлен:
  //   <остановка>»; задача не завершена, фаза и все данные сохранены; блокировка `runner.lock` остаётся (её держал процесс, который кончил работу,
  //   `prepare` занятой её не считает).
  // Вход: остановка
  ОСТАНОВЛЕНО => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  // ===================== ОШИБКА — конец =====================
  // Заканчивает работу раннера, если сама машина попала в непредусмотренное положение; это дефект машины или реализации, его разбирает человек.
  // При входе: группа процессов агента останавливается; в журнал — запись из перехода и данные машины; задача не завершена; решает человек вне
  //   машины.
  // Вход: все данные машины ((в журнал))
  ОШИБКА => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  }
}
```

```nova
/// Работа операций при входе (в одном шаге с переходом; отказа и «нет ответа» у операции нет).
/// Результат операции — событие: `Сразу`; у ПОДГОТОВКИ — `Сразу_ПОДГОТОВКА` с итогом и счётчиками цикла каждой стадии.
/// Записи в документы идут внутри фиксации; смена статуса, переименование письма — необратимые действия последнего этапа.
fn Машина mut @выполнить_операцию(операция Состояние, среда Окружение) Журнал Объекты Time -> Событие => match операция {
  ПОДГОТОВКА => {
    // при первом старте исполнителя: итог и счётчики цикла каждой стадии — результатом операции; при возобновлении ту же подготовку делает `при_возобновлении`
    ro итог = @выполнить_подготовку()
    Сразу_ПОДГОТОВКА { итог_подготовки: итог.итог_подготовки, циклы: итог.циклы }
  }
  СНЯТИЕ_СПЕЦИФИКАЦИИ => {
    @снять_утверждение("спецификация", среда)             // invalidate(spec.md); С3 и С5 закрываются, С1 нет; префикс пересобирается — механика исполнителя
    Сразу
  }
  СНЯТИЕ_ПЛАНА => {
    @снять_утверждение("план", среда)                     // invalidate(plan.md); С5 закрывается, С3 нет; префикс пересобирается
    Сразу
  }
  К_ТРЕБОВАНИЯМ => {
    @снять_утверждение("спецификация", среда)             // to_requirements: оба документа — в черновик, записи об утверждении удаляются
    @снять_утверждение("план", среда)
    Сразу
  }
  К_ПЛАНУ => {
    @снять_утверждение("план", среда)                     // to_plan
    Сразу
  }
  СНЯТИЕ_ЧУЖОГО => {
    среда.добавить_необратимое(Необратимое.ВернутьВЧерновик(@документ_на_утверждении))   // без закрытия диалогов: gate_approve не вызывает invalidate
    Сразу
  }
  ЗАПИСЬ_УТВЕРЖДЕНИЯ => {
    @утверждения.insert(@документ_на_утверждении, @утверждение_по_документу(@документ_на_утверждении))   // approvals[файл] ← {дата, кто, hash(файл)}; префикс пересобирается
    Сразу
  }
  ЗАПИСЬ_ОТВЕТОВ => {
    @записать_ответы_в_спецификацию(@ответы_заказчика)    // write_answers: раздел «Ответы» спецификации
    Сразу
  }
  ЗАПИСЬ_РЕШЕНИЙ => {
    @записать_решения_в_план(@решения_плана)              // write_decisions: раздел «Требует утверждения» плана, пометка «решено:»
    Сразу
  }
  ЗАПИСЬ_РЕШЕНИЙ_ВЛАДЕЛЬЦА => {
    @записать_пометки_владельца(@решения_владельца)       // write_owner_marks: пометка «решение владельца: …, <дата>»
    Сразу
  }
  ПЕРЕИМЕНОВАНИЕ_ПИСЬМА => {
    среда.добавить_необратимое(Необратимое.ПереименоватьПисьмо(@номер_раунда))   // rename(delivery/customer.md → delivery/customer-<номер_раунда>.md)
    Сразу
  }
  СОХРАНЕНИЕ_ОБРАТНОЙ_СВЯЗИ => {
    @сохранить_замечания_раунда(@номер_раунда, @обратная_связь)   // task/feedback-<номер_раунда>/
    Сразу
  }
  КОПИЯ_ПОСТАНОВКИ => {
    @утверждения.insert("спецификация", @утверждение_копии(@слово_завода))   // approvals[spec.md] ← {дата слова, владелец, hash(копия)}: отметка раньше ресурса (правило 13)
    среда.добавить_необратимое(Необратимое.СоздатьУтверждённуюКопию(@слово_завода))   // spec.md ← копия постановки со статусом «утверждено» и словом завода: последний, повторяемый без вреда этап
    Сразу
  }
  СНЯТИЕ_КОПИИ => {
    @снять_утверждение("спецификация", среда)             // invalidate(spec.md): первая строка ← «Статус: черновик», запись удаляется; С3 и С5 закрываются; префикс пересобирается
    Сразу
  }
  ВОЗВРАТ_ПОЛНОГО_ПУТИ => {
    if @спецификация() != None { @снять_утверждение("спецификация", среда) }   // invalidate(spec.md), если спецификация есть: С3 и С5 закрываются, С1 нет; plan.md у быстрого маршрута нет
    Сразу
  }
  _ => недостижимо("у остальных состояний нет работы операции")
}
```

```nova
/// Работа концов при входе (в последнем, повторяемом без вреда этапе фиксации) и ответ вызвавшей стороне.
/// Вход в любой конец отменяет все открытые запросы (правило 22); машина отвечает ровно один раз (правило 35).
fn Машина mut @при_входе_в_конец(конец Состояние, среда Окружение) Журнал Time -> () => match конец {
  // ОСТАНОВЛЕНО: группа процессов агента останавливается целиком и проверяется, что в ней не осталось процессов; в журнал — «раннер остановлен: <остановка>»;
  //   задача не завершена, фаза и все данные сохранены; блокировка остаётся (её держал процесс, который кончил работу).
  ОСТАНОВЛЕНО => {
    среда.добавить_необратимое(Необратимое.ОстановитьГруппуАгента)
    среда.писать_журнал("раннер остановлен: ${@остановка}")
  }
  // ОШИБКА: группа процессов агента останавливается; в журнал — запись из перехода и данные машины; задача не завершена; решает человек вне машины.
  ОШИБКА => {
    среда.добавить_необратимое(Необратимое.ОстановитьГруппуАгента)
    среда.писать_журнал(среда.запись_перехода())
    @журнал_данных_машины(среда)
  }
  // КОНЕЦ: блокировка снимается; в журнал — «задача завершена, раундов обратной связи: <номер_раунда>»; человеку показывается «задача завершена».
  КОНЕЦ => {
    среда.добавить_необратимое(Необратимое.СнятьБлокировку)
    среда.писать_журнал("задача завершена, раундов обратной связи: ${@номер_раунда}")
    среда.добавить_необратимое(Необратимое.ПоказатьЧеловеку("задача завершена"))
  }
  _ => ()
}
// запись для диагностики: все переменные и хранилища (Вход ОШИБКИ)
fn Машина mut @журнал_данных_машины(среда Окружение) Журнал Time -> ()

/// Таблица «конец → ответ» первоисточника (раздел «Контракт машины»): каждый конец и каждое значение остановка — одна строка.
fn Машина @ответ_по_концу(вызов Запрос[ВходРаннера], конец Состояние, среда Окружение) -> Исход[ИтогРаннера] {
  match конец {
    // КОНЕЦ, условие входа: всегда → СРезультатом: задача завершена, число раундов обратной связи
    КОНЕЦ => СРезультатом(ОтветСРезультатом {
      запрос: вызов.идентификатор_запроса, сторона: вызов.сторона, трасса: вызов.трасса, номер_шага: вызов.номер_шага,
      результат: ИтогРаннера { число_раундов: @номер_раунда } })
    // ОШИБКА, условие входа: всегда (дефект машины) → Отказ, НетРезультата; текст — запись из перехода
    ОШИБКА => отказ_по(вызов, НетРезультата, среда.запись_перехода())
    ОСТАНОВЛЕНО => match @остановка {
      // ОСТАНОВЛЕНО: остановка = «задача занята живым процессом» → Отказ, НетРезультата
      "задача занята живым процессом" => отказ_по(вызов, НетРезультата, @остановка)
      // ОСТАНОВЛЕНО: остановка = «проверка цикла: нет результата» → Отказ, НетРезультата
      "проверка цикла: нет результата" => отказ_по(вызов, НетРезультата, @остановка)
      // ОСТАНОВЛЕНО: остановка = «запуск сессии: нет результата» → Отказ, НетРезультата
      "запуск сессии: нет результата" => отказ_по(вызов, НетРезультата, @остановка)
      // ОСТАНОВЛЕНО: остановка = «маршрут: настройки нарушают инварианты методики» → Отказ, НетРезультата
      "маршрут: настройки нарушают инварианты методики" => отказ_по(вызов, НетРезультата, @остановка)
      // ОСТАНОВЛЕНО: остановка = «В13: остановить», «ДЕРЕВО_ЗАНЯТО: остановить», «проверка цикла: остановлено человеком», «запуск сессии: остановлено человеком» или «ПАУЗА: остановить»
      //   (слово человека; у вызванной машины — сигнал «остановить от родителя» в ПАУЗЕ) → Отказ, ОстановленоЧеловеком
      "В13: остановить" | "ДЕРЕВО_ЗАНЯТО: остановить" | "проверка цикла: остановлено человеком" | "запуск сессии: остановлено человеком" => отказ_по(вызов, ОстановленоЧеловеком, @остановка)
      "ПАУЗА: остановить" => отказ_по(вызов, код_сбоя_общей_остановки(@остановка), @остановка)
      // ОСТАНОВЛЕНО: остановка = «отмена_запроса» → Отказ, ОтмененоРодителем
      "отмена_запроса" => отказ_по(вызов, код_сбоя_общей_остановки(@остановка), @остановка)
      _ => недостижимо("значение остановка вне таблицы «конец → ответ»: новое значение добавляет строку таблицы")
    }
    _ => недостижимо("ответ отдают только концы")
  }
}

/// Точка подстановки эффектов: обработчики выбирает вызывающий код, один раз (`with`), и вне этого файла — любые (`Time` — стандартный, обработчик по умолчанию).
/// Все функции цепочки от `начать`, `возобновить`, `вызвать` объявляют эффекты в своей сигнатуре; здесь они подставлены. Машину по входу запроса создаёт вызывающий код.
fn запуск_раннера(запрос Запрос[ВходРаннера]) Time -> Исход[ИтогРаннера] =>
  with Хранилище = обработчик_хранилища, Журнал = обработчик_журнала, Связь = обработчик_связи, Объекты = обработчик_объектов {   // псевдокод: обработчики (база, файл поверх Fs/Db, очередь сообщений) — любые, вне файла
    mut исполнитель = Исполнитель.new(Машина.из_входа(запрос.вход))
    исполнитель.вызвать(запрос)
  }
```
