# Раннер задачи: код автомата

Стейт-машина раннера задачи — фазы РАЗБОР, ПЛАН, РЕАЛИЗАЦИЯ, СДАЧА, ОБРАТНАЯ_СВЯЗЬ и ворота между ними, — записанная кодом на языке Нова как реализация протокола `Автомат` движка [state-machine-engine-automaton.md](state-machine-engine-automaton.md): данные машины, перечисления `Состояние` и `Событие`, переход `перейти(состояние, событие)` как `match` по состоянию и событию, роли (входы и результаты обращений к агенту, к вложенной машине проверки цикла и к человеку на воротах), ответ по концу по контракту машины, работа операций над документами задачи. Всё общее — конверт запроса и ответа, исполнитель, снимок и хранилище, общие события «стоп/продолжить/отмена», цикл, фиксации — в движке и здесь не повторяется. Нормы — [task-runner.md](task-runner.md) (словарь, ворота В1–В13, профили, форматы файлов) и [task-sessions.md](task-sessions.md) (коды сессий и правила цикла).

**Первоисточник — [task-runner-states.md](task-runner-states.md)** (машина «Раннер»: таблицы состояний, общие события, «Контракт машины», «Решения при переводе»); правила формы — [state-machine-spec.md](state-machine-spec.md). Этот файл — производная запись того же автомата, а не второй источник истины: при любом расхождении верен первоисточник, а этот файл правится вслед за ним. Язык записи — Нова, https://github.com/nv-lang/nova. **Код не компилировался и не проверялся компилятором Нова:** это псевдокод в синтаксисе Нова; соглашения записи, помеченные места (`// псевдокод:`), подтверждённое и неподтверждённое спецификацией — в [state-machine-engine-automaton.md](state-machine-engine-automaton.md), здесь только то, что относится к раннеру. Опытный статус и отличия от ранее написанной схемы описаны в шапке первоисточника и здесь не повторяются; раннером эта машина не исполняется (раннер исполняет [task-runner-pseudocode.md](task-runner-pseudocode.md), помеченный устаревшим и этим файлом не заменяемый). Вложенные машины: проверка цикла — [task-runner-review-automaton.md](task-runner-review-automaton.md) (первоисточник — [task-runner-review-states.md](task-runner-review-states.md)), совещание — [task-runner-meeting-automaton.md](task-runner-meeting-automaton.md); раннер зовёт проверку цикла, а та — совещание только по контракту вызова движка (`Вызываемое`, эффект `Связь`: запрос уходит как `ЗапросРоли`, ответ приходит сообщением), а не прямым вызовом функций. Имя файла — по `AGENTS.md`, «Вынесенные алгоритмы», форма `automaton`.

## Соглашения записи

1. **Типы и идентификаторы** — по [движку](state-machine-engine-automaton.md), пункты 1–3: русские имена, таблица соответствия именам блока «Типы на Нове» первоисточника — ниже. Типы данных первоисточника, общие у раннера и проверки цикла (`Цикл`, `Находка`, `Критичность`, `Уровень`, `ИтогСессии`, `Стадия`, `ВходПроверки`, `ИтогПроверки`, `Вердикт`), объявлены один раз в [слое методики](state-machine-methodology-automaton.md) и подключены здесь (`use`); здесь объявлены типы только раннера (`Артефакт`, `Утверждение` и их перечни, `ВходРаннера`, `ИтогРаннера`). Вход паузы (`ВходПаузы`) тоже в слое; вариант `ВходРоли` для него — `ВходПаузыРоли`. Записи автомата, которых в первоисточнике нет: `РезультатРоли`, `ВходРоли`, `Окружение`, `Необратимое`. **Значения перечислений** с совпадающими именами в разных перечнях (`План`, `Требования`, `Вопрос`, `Готово` и др.) пишутся с именем типа (`ИтогСессии.План`, `Уровень.План`): так же названы значения в блоке «Типы на Нове» первоисточника (`Level.Plan`, `SessionResult.Plan`).
2. **Данные события.** Поля варианта события берутся образцом в `match`: `Сбой { причина } => …`; при совпадении имени поля с переменной машины поле переименовывается: `Ответ_сессии { итог_сессии: итог }`; остаток полей, которые переход не читает, — `{ цикл, .. }`. «Сторона события» и идентификатор события — `событие.сторона`, `событие.идентификатор` (конверт `Входящее` движка, правила 13 и 31); тело исходного события шага — `событие.тело`. Служебные операции переходу даёт `среда` (журнал, слова человека, сигналы вложенным, данные движка `открытые_запросы`, `предыдущее`, `запрос_вызова`).
3. **Строка таблицы — ветка кода.** Перед каждой строкой первоисточника (условие или событие, «Что меняется», «Куда») стоит комментарий `// <СОСТОЯНИЕ> #<номер строки>: …` с её текстом; у обращения и операции в скобках — данные события; порядок строк как в первоисточнике. «Куда» записано как `Куда(<СОСТОЯНИЕ>)`; «запуск заново» — `Заново(<СОСТОЯНИЕ>)`; «Куда: предыдущее» — `Куда(состояние_по_имени(среда.предыдущее()))`. Строка «иначе» каждой развилки — последняя ветка, ведёт в `ОШИБКА` через `среда.ошибка_машины(…)`; той же функцией записана строка, чей первоисточник ведёт в `ОШИБКА` с журналом «ошибка машины: …» (РЕАЛИЗАЦИЯ_ПРОВЕРКА, «ответ: перезапуск»). Строки «Вход», «Выход», «При входе», «Сторона» и одна строка простыми словами на состояние — комментарии `//` у состояния. Общие события (две строки «стоп» и четыре строки «отмена_запроса») записаны в движке (`общие_события`); `общее` машины сводит к ним её события.
4. **Строки `// псевдокод:`** и перечень подтверждённого спецификацией — в [движке](state-machine-engine-automaton.md), пункт 5. Здесь дополнительно: функции без тела (сигнатуры механики и чтения внешних объектов); алиас `type Окружение alias Среда[…]` (как в машине совещания); поле-отображение `HashMap[Стадия, Цикл]` — перечисление как ключ отображения в Нове не подтверждено (запасной вариант — ключ-строка с именем стадии); значения перечислений с именем типа (`ИтогСессии.План`); образец `{ поле, .. }` с остатком и охранное условие в ветке `match` (оба — как в движке и машине совещания). Константы `ПОТОЛОК_ЗАХОДОВ`, `ЧИСТЫХ_ПОДРЯД`, `ПРОБ_В_ЧИСТОМ` этой машиной не читаются (она только передаёт их вложенной): объявлены в файле проверки цикла. Функции без тела — механика исполнителя и обработчика `Объекты` (в том числе `дописать_как_факт`, читатели документов). Срок бездействия не задан: у обращений раннера `0` (исполнитель «нет ответа» не порождает), для вызова вложенной машины он равен `0` — это значение «без срока» (правило 35, пункт 5): родитель ждёт ответа или отмены. Неподтверждённое спецификацией Нова, используемое здесь (как и в машине совещания): объявление `module`, `ro` на уровне модуля (константы), `return` внутри `if` в ветке `match` и в теле функции.
5. **Уточнения записи автомата сверх первоисточника** (каждое — следствие границы с движком, подробности — «Что движок не покрыл»): (а) результат операции ПОДГОТОВКА — запись `ИтогПодготовки` (итог и счётчики цикла каждой стадии): `выполнить_операцию` отдаёт её событием `Сразу_ПОДГОТОВКА`, а движок передаёт то же событие следующей развилке цепочки, поэтому развилка ПОДГОТОВКА_ИТОГ читает `итог_подготовки` из тела события, как в первоисточнике («итог_подготовки события»; у развилки «Вход: нет»), и поля-моста в данных машины нет; (б) `событие_ответа` — метод протокола `Автомат`: отображение результата роли в событие с данными; (в) варианты события `Проверка_*` несут `вне_задачи` у всех стадий (так устроен `ИтогПроверки`); переходы стадий, кроме реализации, его не читают; (г) метка инварианта — список номеров заходов по четырём стадиям, движок сравнивает покомпонентно (убыль одного номера при росте другого ловится); (д) `при_возобновлении` — метод протокола: подготовка при каждом старте исполнителя, в том числе при возобновлении (решение 25 первоисточника); её исходы те же, что у ПОДГОТОВКА_ИТОГ («готова» — войти в сохранённое состояние; «занята живым процессом» — ОСТАНОВЛЕНО; нерешённые — ворота), но у метода нет `среды`, поэтому строка «иначе» ПОДГОТОВКА_ИТОГ при возобновлении — ошибка программы (`недостижимо`), а не переход в ОШИБКУ; (е) вложенная сторона и число возвратов ответа не по форме — поля `вложенная` и `возвратов_формы` описания обращения (`Одна`): вложенная — «проверка», возврат один у СЕССИИ; (ж) `ВходСессии` — один вариант на обращение СЕССИЯ, как у обращений совещания (`ВходСвидетеля`, `ВходЛинзы`): код сессии — поле `сессия` (Текст); по коду ветвятся запуск сессии, профиль и промпт — механика исполнителя («Реализация на файлах» первоисточника), а машина по нему не ветвится (правило 6), поэтому суммы по видам сессий не заводятся; (з) `запрос_вызова` — всегда `запрос.идентификатор_запроса` (решение о `""` у верхнего уровня открыто, см. движок, пункт 6); (и) `состояние_по_имени` записано полным `match` по именам обращений (в машине совещания — сигнатура).
6. **Данные машины — поля типа `Машина`**, а не переменные модуля: поля названы как переменные раздела «Данные» первоисточника (правило 25), начальные значения — в `Машина.new()`, по входу раннера — `Машина.из_входа`. Данные движка (конверт, очереди запросов, журнал, слова человека, тексты сбоев) — в `СостояниеДвижка` движка: `трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `запрос_вызова`, `состояние`, `предыдущее`, `открытые_запросы`, `принятые_запросы`. Внешние объекты раздела «Внешние объекты» читаются через эффект `Объекты` читателями `Машина` (документы задачи — `@спецификация()`, `@план_задачи()`, `@отчёт_реализации()`, письма, отчёт по секретам, различия дерева и т. д.): их содержимое лежит вне машины, а не в её данных; поле — только `утверждения` (запись в данных состояния, `approvals`). **Именование читателей по ключу:** читатель элемента поля называется по полю (`@цикл(стадия)`, `@отложенная_сессия(фаза)`, `@утверждения(документ)`, `@письма_раундов(номер)`) — как в машине совещания. **Поле и метод с одним именем** (`цикл`, `отложенная_сессия`, `источник_отложенной`, `утверждения`) — сознательное решение: в Нове допустимо (`spec/decisions/03-syntax.md`, правило `@name`), правило 25 соблюдено (имя одной сущности одно).
7. **`недостижимо(текст)`** (определено в движке, пункт 8): в реализации стоит: у концов КОНЕЦ, ОСТАНОВЛЕНО, ОШИБКА в `перейти` (переходов нет); в `ответ_по_концу` (значение `остановка` вне таблицы; ответ не из конца); в `выполнить_операцию` (состояние без операции); в `событие_ответа` (вердикт «остановлено»: раннер стадию «совещание» не вызывает); в `при_возобновлении` (итог подготовки вне перечня); в `вход_запроса` и `следующая_попытка` (обязательное поле входа пусто — `обязательное` движка; состояние не обращение; сторона вне «агент», «проверка», «человек»); в `цикл`, `документ_задачи`, `состояние_по_имени`, `сторона_обращения` (запись стадии не заведена; имя вне перечня).

```nova
  //   автора, группа процессов агента, запись запуска, вызов модели); принятый артефакт исполнитель проверяет по формату: нарушение — один ход «исправь
  //   форму файла» в том же запросе, снова нарушение — сбой «форма не исправлена»; нет артефакта — сбой «нет результата»; постоянная ошибка или отказ
  //   модели — сбой; повтор временной ошибки (до 3 раз) и продолжение обрезанного выхода идут внутри запроса. Подробности — «Реализация на файлах».
  // Сторона: агент.
  // Вход (сторона): сессия; источник_запуска?; режим_сдачи (подставляется в промпты сдачи (С7)); папка_задачи (агент запускается из неё);
  //   рабочее_дерево
  // Вход (исполнитель): план_задачи? (из строки «Ветка:» раздела «План» берётся подстановка <ветка из plan.md>)
  // Выход: итог_сессии (у КОММИТ и ПУШ — готово: стоп-слова у них нет)
  СЕССИЯ => match тело_события {
    // СЕССИЯ #1: ответ (итог_сессии: ИтогСессии — готово, ревизия, план, требования или вопрос)
    Ответ_сессии { итог_сессии: итог } => {
      @итог_сессии = Some(итог)
      Куда(ПОСЛЕ_СЕССИИ)
    }
    // СЕССИЯ #2: сбой (причина: КодСбоя)
    Сбой { причина } => {
      среда.писать_журнал("сессия ${@сессия} не завершилась: ${слово_кода(причина)}")
      Куда(В13_СЕССИЯ)
    }
    _ => НеЖдёт
  }

  // ===================== В13_СЕССИЯ — обращение =====================
  // Спрашивает человека, что делать, когда сессия не завершилась: повторить её или остановить раннер.
  // При входе: ворота В13: сессия не завершилась, артефакта нет, форма не исправлена со второй попытки, постоянная ошибка или отказ модели; причина —
  //   в журнале. «Повторить» — исполнитель останавливает группу процессов агента, убеждается, что в ней нет процессов, и запускает тот же запрос
  //   заново; «остановить» — раннер выходит из программы.
  // Сторона: человек.
  // Вход: сессия
  // Выход: исход ворот
  В13_СЕССИЯ => match тело_события {
    // В13_СЕССИЯ #1: В13: «повторить»
    В13_повторить => Заново(СЕССИЯ)
    // В13_СЕССИЯ #2: В13: «остановить»
    В13_остановить => {
      @остановка = "В13: остановить"
      Куда(ОСТАНОВЛЕНО)
    }
    _ => НеЖдёт
  }

  // ===================== ПОСЛЕ_СЕССИИ — развилка =====================
  // Решает, куда идти после сессии: у каждого места, откуда сессию запустили, свой путь; место называет «продолжение».
  // Вход: продолжение; итог_сессии; цикл[стадия] (по каждой стадии; читают строки с правкой владельца)
  ПОСЛЕ_СЕССИИ => {
    // ПОСЛЕ_СЕССИИ #1: продолжение = «разбор: очередь», и итог_сессии = «вопрос»
    if @продолжение == "разбор: очередь" && итог_равен(@итог_сессии, ИтогСессии.Вопрос) { return Куда(В4_ВОПРОС) }
    // ПОСЛЕ_СЕССИИ #2: продолжение = «разбор: очередь», и итог_сессии отличается от «вопрос»
    if @продолжение == "разбор: очередь" && !итог_равен(@итог_сессии, ИтогСессии.Вопрос) { return Куда(РАЗБОР_ПРОВЕРКА) }
    // ПОСЛЕ_СЕССИИ #3: продолжение = «разбор: первая сессия»
    if @продолжение == "разбор: первая сессия" { return Куда(РАЗБОР_ПРОВЕРКА) }
    // ПОСЛЕ_СЕССИИ #4: продолжение = «разбор: возврат»
    if @продолжение == "разбор: возврат" { return Куда(СВЕРКА_СПЕЦИФИКАЦИИ) }
    // ПОСЛЕ_СЕССИИ #5: продолжение = «разбор: ответы после вопроса»
    if @продолжение == "разбор: ответы после вопроса" {
      @правка_владельца(Стадия.Разбор)
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_СЕССИИ #6: продолжение = «разбор: ответы»
    if @продолжение == "разбор: ответы" {
      @правка_владельца(Стадия.Разбор)
      @документ_на_утверждении = "спецификация"
      return Куда(УТВЕРЖДЕНИЕ)
    }
    // ПОСЛЕ_СЕССИИ #7: продолжение = «разбор: ответы меняют цель»
    if @продолжение == "разбор: ответы меняют цель" {
      @правка_владельца(Стадия.Разбор)
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_СЕССИИ #8: продолжение = «план: очередь», и итог_сессии = «требования»
    if @продолжение == "план: очередь" && итог_равен(@итог_сессии, ИтогСессии.Требования) {
      @источник_маршрута = "последний абзац плана"
      return Куда(К_ТРЕБОВАНИЯМ)
    }
    // ПОСЛЕ_СЕССИИ #9: продолжение = «план: очередь», и итог_сессии = «вопрос»
    if @продолжение == "план: очередь" && итог_равен(@итог_сессии, ИтогСессии.Вопрос) { return Куда(В7_ПЛАН_ОЧЕРЕДЬ) }
    // ПОСЛЕ_СЕССИИ #10: продолжение = «план: очередь», и итог_сессии отличается от «требования» и от «вопрос»
    if @продолжение == "план: очередь" && !итог_равен(@итог_сессии, ИтогСессии.Требования) && !итог_равен(@итог_сессии, ИтогСессии.Вопрос) { return Куда(ПЛАН_СТОП_СЛОВО) }
    // ПОСЛЕ_СЕССИИ #11: продолжение = «план: первая сессия»
    if @продолжение == "план: первая сессия" { return Куда(ПЛАН_СТОП_СЛОВО) }
    // ПОСЛЕ_СЕССИИ #12: продолжение = «план: решено»
    if @продолжение == "план: решено" {
      @правка_владельца(Стадия.План)
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_СЕССИИ #13: продолжение = «реализация: очередь»
    if @продолжение == "реализация: очередь" { return Куда(ИСХОД_РЕАЛИЗАЦИИ) }
    // ПОСЛЕ_СЕССИИ #14: продолжение = «реализация: первая сессия»
    if @продолжение == "реализация: первая сессия" { return Куда(ИСХОД_РЕАЛИЗАЦИИ) }
    // ПОСЛЕ_СЕССИИ #15: продолжение = «реализация: продолжение»
    if @продолжение == "реализация: продолжение" { return Куда(ИСХОД_РЕАЛИЗАЦИИ) }
    // ПОСЛЕ_СЕССИИ #16: продолжение = «сдача: сдача»
    if @продолжение == "сдача: сдача" { return Куда(СДАЧА_ПРОВЕРКА) }
    // ПОСЛЕ_СЕССИИ #17: продолжение = «сдача: коммит»
    if @продолжение == "сдача: коммит" { return Куда(СДАЧА_СООБЩЕНИЕ) }
    // ПОСЛЕ_СЕССИИ #18: продолжение = «сдача: пуш»
    if @продолжение == "сдача: пуш" { return Куда(В10г) }
    // ПОСЛЕ_СЕССИИ #19: продолжение = «обратная связь: разбор»
    if @продолжение == "обратная связь: разбор" {
      for стадия in стадии_цикла() { @правка_владельца(стадия) }
      return Куда(МАРШРУТ_ОБРАТНОЙ_СВЯЗИ)
    }
    // ПОСЛЕ_СЕССИИ #20: иначе
    среда.ошибка_машины("ошибка машины: развилка ПОСЛЕ_СЕССИИ, ни одно условие не подошло")
  }

  // ===================== К_ТРЕБОВАНИЯМ — операция =====================
  // Возвращает работу на уровень требований: и спецификация, и план становятся черновиками, а фаза РАЗБОР начинает с правки спецификации, фаза ПЛАН —
  //   с правки плана.
  // При входе: `to_requirements`: `invalidate(spec.md)` и `invalidate(plan.md)` — первые строки обоих файлов ← «Статус: черновик», записи об
  //   утверждении удаляются; закрываются диалоги, в слое 3 которых были эти файлы (С3 и С5; диалог автора С1 не закрывается); префикс основного диалога
  //   пересобирается.
  // Вход: спецификация?; план_задачи?; источник_маршрута
  // Выход: спецификация? (статус «черновик»); план_задачи? (статус «черновик»); утверждения[документ]? (снято у обоих документов)
  К_ТРЕБОВАНИЯМ => match тело_события {
    // К_ТРЕБОВАНИЯМ #1: сразу
    Сразу => {
      @установить_отложенную_сессию("РАЗБОР", "С1п")
      @установить_источник_отложенной("РАЗБОР", @источник_маршрута)
      @установить_отложенную_сессию("ПЛАН", "С3п")
      @установить_источник_отложенной("ПЛАН", @источник_с_пометками_спецификации(@источник_маршрута))
      @фаза = "РАЗБОР"
      Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    _ => НеЖдёт
  }

  // ===================== К_ПЛАНУ — операция =====================
  // Возвращает работу на уровень плана: план становится черновиком, а фаза ПЛАН начинает с правки.
  // При входе: `to_plan`: `invalidate(plan.md)` — первая строка плана ← «Статус: черновик», запись об утверждении удаляется; закрывается диалог С5;
  //   префикс пересобирается.
  // Вход: план_задачи?; источник_маршрута
  // Выход: план_задачи? (статус «черновик»); утверждения[план]? (снято)
  К_ПЛАНУ => match тело_события {
    // К_ПЛАНУ #1: сразу
    Сразу => {
      @установить_отложенную_сессию("ПЛАН", "С3п")
      @установить_источник_отложенной("ПЛАН", @источник_маршрута)
      @фаза = "ПЛАН"
      Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    _ => НеЖдёт
  }

  // ===================== УТВЕРЖДЕНИЕ — развилка =====================
  // Вход в ворота утверждения документа (`gate_approve`): если документ уже помечен «утверждено» не по записи программы, сначала спрашивает человека,
  //   его ли это утверждение.
  // Вход: документ_на_утверждении; спецификация?; план_задачи?; утверждения[документ]? (по документу на утверждении)
  УТВЕРЖДЕНИЕ => {
    // УТВЕРЖДЕНИЕ #1: у документа на утверждении чужое утверждение
    if @утверждение_чужое(@документ_на_утверждении) { return Куда(ЧУЖОЕ_УТВЕРЖДЕНИЕ) }
    // УТВЕРЖДЕНИЕ #2: у документа на утверждении утверждение не чужое
    if !@утверждение_чужое(@документ_на_утверждении) { return Куда(В5) }
    // УТВЕРЖДЕНИЕ #3: иначе
    среда.ошибка_машины("ошибка машины: развилка УТВЕРЖДЕНИЕ, ни одно условие не подошло")
  }

  // ===================== ЧУЖОЕ_УТВЕРЖДЕНИЕ — обращение =====================
  // Показывает человеку первую строку документа и спрашивает, его ли это утверждение: чужое «утверждено» нельзя принять как утверждение владельца.
  // При входе: ворота (без номера, часть `gate_approve`): «это ваше утверждение?»; человеку показывается первая строка документа; слова исходов в
  //   источниках не заданы, взяты «ваше» и «не ваше» («Решения при переводе»).
  // Сторона: человек.
  // Вход: документ_на_утверждении; спецификация?; план_задачи?
  // Выход: исход ворот
  ЧУЖОЕ_УТВЕРЖДЕНИЕ => match тело_события {
    // ЧУЖОЕ_УТВЕРЖДЕНИЕ #1: ЧУЖОЕ_УТВЕРЖДЕНИЕ: «ваше»
    ЧУЖОЕ_УТВЕРЖДЕНИЕ_ваше => Куда(В5)
    // ЧУЖОЕ_УТВЕРЖДЕНИЕ #2: ЧУЖОЕ_УТВЕРЖДЕНИЕ: «не ваше»
    ЧУЖОЕ_УТВЕРЖДЕНИЕ_не_ваше => Куда(СНЯТИЕ_ЧУЖОГО)
    _ => НеЖдёт
  }

  // ===================== СНЯТИЕ_ЧУЖОГО — операция =====================
  // Возвращает документ в черновик: утверждение не принадлежит человеку.
  // При входе: первая строка документа на утверждении ← «Статус: черновик» (без закрытия диалогов: `gate_approve` не вызывает `invalidate`).
  // Вход: документ_на_утверждении
  // Выход: спецификация? (если документ на утверждении — спецификация); план_задачи? (если документ на утверждении — план)
  СНЯТИЕ_ЧУЖОГО => match тело_события {
    // СНЯТИЕ_ЧУЖОГО #1: сразу
    Сразу => {
      среда.писать_журнал("чужое утверждение снято: ${@документ_на_утверждении}")
      Куда(В5)
    }
    _ => НеЖдёт
  }

  // ===================== В5 — обращение =====================
  // Ждёт, пока человек поставит в документе «Статус: утверждено, дата, кто» и подтвердит это в программе: утверждает только человек.
  // При входе: ворота В5: человек просматривает документ на утверждении (спецификацию после В4 или план после В6), ставит строку статуса и
  //   подтверждает.
  // Сторона: человек.
  // Вход: документ_на_утверждении
  // Выход: исход ворот
  В5 => match тело_события {
    // В5 #1: В5: «подтвердил»
    В5_подтвердил => Куда(ЗАПИСЬ_УТВЕРЖДЕНИЯ)
    _ => НеЖдёт
  }

  // ===================== ЗАПИСЬ_УТВЕРЖДЕНИЯ — операция =====================
  // Записывает утверждение: когда, кто и хеш текста, чтобы потом заметить правку после утверждения.
  // При входе: `approvals[файл] ← {дата, кто, hash(файл)}`: дата и «кто» берутся из строки статуса, хеш — по тексту документа; префикс основного
  //   диалога пересобирается (слой 3 теперь содержит документ).
  // Вход: документ_на_утверждении; спецификация?; план_задачи?
  // Выход: утверждения[документ] (по документу на утверждении)
  ЗАПИСЬ_УТВЕРЖДЕНИЯ => match тело_события {
    // ЗАПИСЬ_УТВЕРЖДЕНИЯ #1: сразу
    Сразу => Куда(ПОСЛЕ_УТВЕРЖДЕНИЯ)
    _ => НеЖдёт
  }

  // ===================== ПОСЛЕ_УТВЕРЖДЕНИЯ — развилка =====================
  // Переводит задачу в следующую фазу: после спецификации — ПЛАН, после плана — РЕАЛИЗАЦИЯ.
  // Вход: документ_на_утверждении
  ПОСЛЕ_УТВЕРЖДЕНИЯ => {
    // ПОСЛЕ_УТВЕРЖДЕНИЯ #1: документ_на_утверждении = «спецификация»
    if @документ_на_утверждении == "спецификация" {
      @фаза = "ПЛАН"
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_УТВЕРЖДЕНИЯ #2: документ_на_утверждении = «план»
    if @документ_на_утверждении == "план" {
      @фаза = "РЕАЛИЗАЦИЯ"
      return Куда(СВЕРКА_СПЕЦИФИКАЦИИ)
    }
    // ПОСЛЕ_УТВЕРЖДЕНИЯ #3: иначе
    среда.ошибка_машины("ошибка машины: развилка ПОСЛЕ_УТВЕРЖДЕНИЯ, ни одно условие не подошло")
  }

  // ===================== РАЗБОР — развилка =====================
  // Вход в фазу РАЗБОР: есть отложенная сессия — запускает её; нет спецификации — запускает первую сессию разбора; иначе идёт к проверке
  //   спецификации.
  // Вход: отложенная_сессия[РАЗБОР]; источник_отложенной[РАЗБОР]; спецификация?
  РАЗБОР => {
    // РАЗБОР #1: отложенная_сессия[РАЗБОР] не равна `""`
    if @отложенная_сессия("РАЗБОР") != "" {
      @сессия = @отложенная_сессия("РАЗБОР")
      @источник_запуска = @источник_отложенной("РАЗБОР")
      @установить_отложенную_сессию("РАЗБОР", "")
      @установить_источник_отложенной("РАЗБОР", "")
      @продолжение = "разбор: очередь"
      return Куда(В2)
    }
    // РАЗБОР #2: отложенная_сессия[РАЗБОР] = `""`, и спецификации нет
    if @отложенная_сессия("РАЗБОР") == "" && @спецификация() == None {
      @назначить_запуск("С1", "", "разбор: первая сессия")
      return Куда(В2)
    }
    // РАЗБОР #3: отложенная_сессия[РАЗБОР] = `""`, и спецификация есть
    if @отложенная_сессия("РАЗБОР") == "" && @спецификация() != None { return Куда(РАЗБОР_ПРОВЕРКА) }
    // РАЗБОР #4: иначе
    среда.ошибка_машины("ошибка машины: развилка РАЗБОР, ни одно условие не подошло")
  }

  // ===================== РАЗБОР_ПРОВЕРКА — обращение =====================
  // Просит вложенную машину проверки цикла проверить спецификацию (повтор «проверка С2 ↔ правка С1п»); возвращает, чисто ли, и куда вернуть работу,
  //   если нет.

  В8_ПОДТВЕРЖДЕНИЕ => match тело_события {

    В8_подтверждено => {

      среда.записать_слово_человека(событие, слово_человека, автор, источник)
      среда.писать_журнал("продолжение с ${среда.предыдущее()}: ${автор}, ${источник}, запись ${событие.идентификатор}")
      среда.передать_вложенным("продолжить")             // после фиксации шага, журнал «продолжить передано <идентификатор_запроса>»
      Куда(состояние_по_имени(среда.предыдущее()))
    }
    // ПАУЗА #2: ПАУЗА: «остановить»
    ПАУЗА_остановить => {
      @остановка = "ПАУЗА: остановить"
      среда.передать_вложенным("остановить")             // правило 35, пункты 8 и 10
      Куда(ОСТАНОВЛЕНО)
    }
    // ПАУЗА #3: ПАУЗА: «продолжить от родителя» (если `идентификатор_запроса` события = `запрос_вызова`, иначе отброшено) (идентификатор_запроса: Текст)
    ПАУЗА_продолжить_от_родителя { идентификатор_запроса } => {
      if идентификатор_запроса != среда.запрос_вызова() { среда.отбросить(событие); return Остаться }
      среда.писать_журнал("продолжение с ${среда.предыдущее()}: от родителя ${идентификатор_запроса}, запись ${событие.идентификатор}")
      // слова человека не записываются ("")
      среда.передать_вложенным("продолжить")
      Куда(состояние_по_имени(среда.предыдущее()))
    }
    // ПАУЗА #4: ПАУЗА: «остановить от родителя» (если `идентификатор_запроса` события = `запрос_вызова`, иначе отброшено) (идентификатор_запроса: Текст)
    ПАУЗА_остановить_от_родителя { идентификатор_запроса } => {
      if идентификатор_запроса != среда.запрос_вызова() { среда.отбросить(событие); return Остаться }
      @остановка = "ПАУЗА: остановить"
      среда.передать_вложенным("остановить")
      Куда(ОСТАНОВЛЕНО)
    }
    _ => НеЖдёт
  }

  // ===================== КОНЕЦ — конец =====================
  // Записывает, что задача завершена, и возвращает занятую блокировку.
  // При входе: блокировка `runner.lock` снимается; в журнал — «задача завершена, раундов обратной связи: <номер_раунда>»; человеку показывается
  //   «задача завершена».
  // Вход: номер_раунда
  КОНЕЦ => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  // ===================== ОСТАНОВЛЕНО — конец =====================
  // Заканчивает работу раннера без завершения задачи и записывает, почему; решение, что делать дальше, — за человеком вне машины.
  // При входе: группа процессов агента останавливается целиком и проверяется, что в ней не осталось процессов; в журнал — «раннер остановлен:
  //   <остановка>»; задача не завершена, фаза и все данные сохранены; блокировка `runner.lock` остаётся (её держал процесс, который кончил работу,
  //   `prepare` занятой её не считает).
  // Вход: остановка
  ОСТАНОВЛЕНО => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  // ===================== ОШИБКА — конец =====================
  // Заканчивает работу раннера, если сама машина попала в непредусмотренное положение; это дефект машины или реализации, его разбирает человек.
  // При входе: группа процессов агента останавливается; в журнал — запись из перехода и данные машины; задача не завершена; решает человек вне
  //   машины.
  // Вход: все данные машины ((в журнал))
  ОШИБКА => недостижимо("конец: переходов нет; работа при входе — в «Концы и ответ»")

  }
}
```

```nova
/// Результат операции — событие: `Сразу`; у ПОДГОТОВКИ — `Сразу_ПОДГОТОВКА` с итогом и счётчиками цикла каждой стадии.

  ПОДГОТОВКА => {
    // при первом старте исполнителя: итог и счётчики цикла каждой стадии — результатом операции; при возобновлении ту же подготовку делает `при_возобновлении`
    ro итог = @выполнить_подготовку()
    Сразу_ПОДГОТОВКА { итог_подготовки: итог.итог_подготовки, циклы: итог.циклы }
  }
  СНЯТИЕ_СПЕЦИФИКАЦИИ => {

    Сразу
  }
  СНЯТИЕ_ПЛАНА => {
    @снять_утверждение("план", среда)                     // invalidate(plan.md); С5 закрывается, С3 нет; префикс пересобирается
    Сразу
  }
  К_ТРЕБОВАНИЯМ => {
    @снять_утверждение("спецификация", среда)             // to_requirements: оба документа — в черновик, записи об утверждении удаляются
    @снять_утверждение("план", среда)
    Сразу
  }
  К_ПЛАНУ => {
    @снять_утверждение("план", среда)                     // to_plan
    Сразу
  }

    среда.добавить_необратимое(Необратимое.ВернутьВЧерновик(@документ_на_утверждении))   // без закрытия диалогов: gate_approve не вызывает invalidate

    Сразу
  }
  ЗАПИСЬ_ОТВЕТОВ => {
    @записать_ответы_в_спецификацию(@ответы_заказчика)    // write_answers: раздел «Ответы» спецификации
    Сразу
  }
  ЗАПИСЬ_РЕШЕНИЙ => {
    @записать_решения_в_план(@решения_плана)              // write_decisions: раздел «Требует утверждения» плана, пометка «решено:»
    Сразу
  }
  ЗАПИСЬ_РЕШЕНИЙ_ВЛАДЕЛЬЦА => {

    Сразу

    Сразу

  СОХРАНЕНИЕ_ОБРАТНОЙ_СВЯЗИ => {

  _ => недостижимо("у остальных состояний нет работы операции")
```

## Концы и ответ

```nova
/// Работа концов при входе (в последнем, повторяемом без вреда этапе фиксации) и ответ вызвавшей стороне.
/// Вход в любой конец отменяет все открытые запросы (правило 22); машина отвечает ровно один раз (правило 35).
fn Машина mut @при_входе_в_конец(конец Состояние, среда Окружение) Журнал Time -> () => match конец {
  // ОСТАНОВЛЕНО: группа процессов агента останавливается целиком и проверяется, что в ней не осталось процессов; в журнал — «раннер остановлен: <остановка>»;
  //   задача не завершена, фаза и все данные сохранены; блокировка остаётся (её держал процесс, который кончил работу).
  ОСТАНОВЛЕНО => {
    среда.добавить_необратимое(Необратимое.ОстановитьГруппуАгента)
    среда.писать_журнал("раннер остановлен: ${@остановка}")
  }
  // ОШИБКА: группа процессов агента останавливается; в журнал — запись из перехода и данные машины; задача не завершена; решает человек вне машины.
  ОШИБКА => {
    среда.добавить_необратимое(Необратимое.ОстановитьГруппуАгента)
    среда.писать_журнал(среда.запись_перехода())
    @журнал_данных_машины(среда)
  }
  // КОНЕЦ: блокировка снимается; в журнал — «задача завершена, раундов обратной связи: <номер_раунда>»; человеку показывается «задача завершена».
  КОНЕЦ => {
    среда.добавить_необратимое(Необратимое.СнятьБлокировку)
    среда.писать_журнал("задача завершена, раундов обратной связи: ${@номер_раунда}")
    среда.добавить_необратимое(Необратимое.ПоказатьЧеловеку("задача завершена"))
  }
  _ => ()
}
// запись для диагностики: все переменные и хранилища (Вход ОШИБКИ)
fn Машина mut @журнал_данных_машины(среда Окружение) Журнал Time -> ()

/// Таблица «конец → ответ» первоисточника (раздел «Контракт машины»): каждый конец и каждое значение остановка — одна строка.
fn Машина @ответ_по_концу(вызов Запрос[ВходРаннера], конец Состояние, среда Окружение) -> Исход[ИтогРаннера] {
  match конец {
    // КОНЕЦ, условие входа: всегда → СРезультатом: задача завершена, число раундов обратной связи
    КОНЕЦ => СРезультатом(ОтветСРезультатом {
      запрос: вызов.идентификатор_запроса, сторона: вызов.сторона, трасса: вызов.трасса, номер_шага: вызов.номер_шага,
      результат: ИтогРаннера { число_раундов: @номер_раунда } })
    // ОШИБКА, условие входа: всегда (дефект машины) → Отказ, НетРезультата; текст — запись из перехода
    ОШИБКА => отказ_по(вызов, НетРезультата, среда.запись_перехода())
    ОСТАНОВЛЕНО => match @остановка {
      // ОСТАНОВЛЕНО: остановка = «задача занята живым процессом» → Отказ, НетРезультата
      "задача занята живым процессом" => отказ_по(вызов, НетРезультата, @остановка)
      // ОСТАНОВЛЕНО: остановка = «проверка цикла: нет результата» → Отказ, НетРезультата
      "проверка цикла: нет результата" => отказ_по(вызов, НетРезультата, @остановка)
      // ОСТАНОВЛЕНО: остановка = «В13: остановить», «В1: остановить», «ДЕРЕВО_ЗАНЯТО: остановить», «проверка цикла: остановлено человеком» или «ПАУЗА: остановить»
      //   (слово человека; у вызванной машины — сигнал «остановить от родителя» в ПАУЗЕ) → Отказ, ОстановленоЧеловеком
      "В13: остановить" | "В1: остановить" | "ДЕРЕВО_ЗАНЯТО: остановить" | "проверка цикла: остановлено человеком" => отказ_по(вызов, ОстановленоЧеловеком, @остановка)
      "ПАУЗА: остановить" => отказ_по(вызов, код_сбоя_общей_остановки(@остановка), @остановка)
      // ОСТАНОВЛЕНО: остановка = «отмена_запроса» → Отказ, ОтмененоРодителем
      "отмена_запроса" => отказ_по(вызов, код_сбоя_общей_остановки(@остановка), @остановка)
      _ => недостижимо("значение остановка вне таблицы «конец → ответ»: новое значение добавляет строку таблицы")
    }
    _ => недостижимо("ответ отдают только концы")
  }
}

/// Точка подстановки эффектов: обработчики выбирает вызывающий код, один раз (`with`), и вне этого файла — любые (`Time` — стандартный, обработчик по умолчанию).
/// Все функции цепочки от `начать`, `возобновить`, `вызвать` объявляют эффекты в своей сигнатуре; здесь они подставлены. Машину по входу запроса создаёт вызывающий код.
fn запуск_раннера(запрос Запрос[ВходРаннера]) Time -> Исход[ИтогРаннера] =>
  with Хранилище = обработчик_хранилища, Журнал = обработчик_журнала, Связь = обработчик_связи, Объекты = обработчик_объектов {   // псевдокод: обработчики (база, файл поверх Fs/Db, очередь сообщений) — любые, вне файла
    mut исполнитель = Исполнитель.new(Машина.из_входа(запрос.вход))
    исполнитель.вызвать(запрос)
  }
```
