# Слой методики: код общих типов и операций для машин задачи

Слой между движком и машинами методики задачи — раннером, проверкой цикла, запуском сессии и совещанием, — записанный кодом на языке Нова: типы данных, которые разделяют несколько машин методики (цикл проверки, находка, свод итоговой строки, стадия, вход и итог проверки цикла, вход и итог запуска сессии, итог сессии, вердикт), общий вход паузы, ворота человека как данные, сигнатуры операций над объектами задачи (группа процессов агента, объём запуска, показ человеку, блокировка раннера, отпечаток) и арифметика цикла проверки (потолок заходов, сдвиг отсчёта потолка, чистые заходы без проб). Движок — [state-machine-engine-automaton.md](state-machine-engine-automaton.md) — не знает методики: он обобщён по типам машины и этого слоя не подключает; слой подключают сами машины (`use`). Машины, которые его используют: раннер — [task-runner-automaton.md](task-runner-automaton.md), проверка цикла — [task-runner-review-automaton.md](task-runner-review-automaton.md), запуск сессии — [task-runner-session-automaton.md](task-runner-session-automaton.md) (её зовут раннер и проверка цикла), шаг агента — [state-machine-agent-step-automaton.md](state-machine-agent-step-automaton.md) (его зовёт запуск сессии), совещание — [task-runner-meeting-automaton.md](task-runner-meeting-automaton.md).

**Первоисточники.** Методика — [task-runner.md](task-runner.md) (словарь, ворота, форматы файлов, профили запуска) и [task-sessions.md](task-sessions.md), «Правила» (коды сессий, потолок заходов, чистая серия, пробы); типы блока «Типы на Нове» — в первоисточниках машин: [task-runner-states.md](task-runner-states.md), [task-runner-review-states.md](task-runner-review-states.md), [task-runner-session-states.md](task-runner-session-states.md), [state-machine-agent-step-states.md](state-machine-agent-step-states.md), [task-runner-meeting-states.md](task-runner-meeting-states.md). Правила формы машины — [state-machine-spec.md](state-machine-spec.md). Этот файл — производная запись, а не второй источник истины: при любом расхождении верны первоисточники, а этот файл правится вслед за ними. Язык записи — Нова, https://github.com/nv-lang/nova. **Код не компилировался и не проверялся компилятором Нова:** это псевдокод в синтаксисе Нова; помеченные места (`// псевдокод:`), подтверждённое и неподтверждённое спецификацией Нова — в [движке](state-machine-engine-automaton.md), пункт 5 соглашений, здесь только то, что добавляет слой. Имя файла — по `AGENTS.md`, «Вынесенные алгоритмы» (документ `state-machine`, часть `methodology`, форма `automaton`).

**Запись обращения к агенту.** Один вызов агента — линза, запуск сессии цикла, ход чата — описан одним типизированным запросом (`ЗапросАгента`) и одним типизированным ответом (`ОтветАгента`) с единой записью расхода (`Использование`): статистика токенов, моделей и стоимости собирается в одном месте, а транспорт (сегодня — обработчик на файлах и процессах, позже — клиент протокола агента ACP) реализует обращение, не меняя машин. Здесь записаны только типы и коды сбоя; сама машина «Шаг агента» — в [state-machine-agent-step-states.md](state-machine-agent-step-states.md) (первоисточник; типы запроса, ответа и расхода объявлены там один раз) и [state-machine-agent-step-automaton.md](state-machine-agent-step-automaton.md) (код автомата). **Поля `контекст` запроса — свои у каждого вызывающего:** слой хранит их непрозрачным текстом, собирает их вызывающий (раннер, проверка цикла, совещание, чат), слой их не разбирает. Сбой обращения — обычный отказ конверта (`ОтветОтказ`) с кодом `КодСбоя`; к существующим кодам добавлены два — `ПредельТокенов` и `ПредельЗапросовХода` (отдельные коды, не `НетРезультата`): **их порождает только машина «Шаг агента», а таблица «конец → ответ» существующих машин не менялась** (запуск сессии получает их от шага агента как обычный сбой и ведёт к воротам В13, наружу они не вытекают). Каждое поле токенов и стоимости необязательно (`Option`): у источника без этих данных значение — «нет». Соответствие остановки ACP коду сбоя (**описание, реализация — продукт**; других подробностей ACP здесь нет) — таблица «Остановка ACP → код» ниже.

## Соглашения записи

1. **Типы и идентификаторы** — по [движку](state-machine-engine-automaton.md), пункты 1–3: русские имена, поля и функции — змеиный регистр (правило 25 спецификации: имя одной сущности одно). Сокращений в именах нет.
2. **Что в слое.** (а) Типы данных первоисточника, общие у нескольких машин методики: раньше они лежали в файле раннера, и проверка цикла подключала их оттуда; теперь объявлены один раз здесь. Сюда же вынесены `Свод` проверки цикла (его возвращает запуск сессии, читает проверка цикла) и вход и итог запуска сессии — `ВходЗапускаСессии`, `ИтогЗапускаСессии`: раннер и проверка цикла зовут вложенную машину запуска сессии ([task-runner-session-automaton.md](task-runner-session-automaton.md)) и строят её вход и разбирают её итог одними и теми же типами. (б) `ВходПаузы` — вход обращения ПАУЗА: у раннера, проверки цикла и совещания он один и тот же (предыдущее состояние, запрос вызова); каждая машина оборачивает его в свой вариант `ВходРоли` (`ВходПаузыРоли`). (в) `Ворота` — данные ворот человека: их читает обработчик `Связь`; слова ворот остаются событиями машины (по варианту на слово, как в таблицах состояний), в одно событие они не сводятся. (г) Сигнатуры операций над объектами задачи: тело даёт обработчик эффекта `Объекты`; сам эффект движка не расширен. (д) Арифметика цикла: функции над `Цикл` — `потолок_исчерпан`, `сброс_отсчёта`, `шаг_без_проб` — одинаковы у машины совещания и машины проверки цикла (развилки ПОТОЛОК и БЕЗ_ПРОБ, исходы В9 со сдвигом отсчёта); раннер держит `Цикл` по стадиям и берёт `сброс_отсчёта` для правки владельца. Машина оставляет у себя тонкую ветку таблицы с тем же комментарием `// СОСТОЯНИЕ #n`, а счёт — здесь; у машины проверки цикла предел потолка и числа чистых заходов и проб — данные задачи из `ВходПроверки` (`потолок_заходов`, `чистых_подряд`, `проб_в_чистом`; их записывает раннер по маршруту задачи), у машины совещания — её константы (`ПОТОЛОК_ЗАХОДОВ` и др., параметры проекта); значение предела приходит аргументом. (е) Поля маршрута задачи во входах: `ВходПроверки` получил `маршрут`, `чистых_подряд`, `потолок_заходов`, `проб_в_чистом`, `сдача_сжата`, а `ВходЗапускаСессии` — `маршрут`, `перечень_источников`, `сдача_сжата` (слово владельца, 2026-10-18; решения 27–52 [task-runner-states.md](task-runner-states.md)); типы маршрута (`Риск`, `Оценка`, `ПризнакиМаршрута`, `ПорогиМаршрута`, `ПараметрыМаршрута`, `ПараметрыПроекта`) нужны только раннеру и объявлены в его файле.
3. **Одноимённые типы разных машин.** `Находка` и `Критичность` раннера и проверки цикла (`Находка { критичность, уровень }`; `Критичность`: `Существенная`, `Поверхностная`) объявлены здесь. Одноимённые `Находка` и `Критичность` совещания (`Находка { критичность, доказательство, повтор, вопрос }`; `Критичность`: `Критическая`, `Значимая`, `Желательная`) — **другие типы с тем же именем**: они лежат в файле совещания и в слой не входят, как и `Свод` совещания (`критических`, `проб`; `Свод` слоя — `существенных`, `проб` — свод проверки цикла и запуска сессии) и `Утверждение` (у раннера — дата, кто, хеш, у совещания — утверждение свидетеля). Машина называет в `use` только нужные имена; проверка цикла берёт `Находку` слоя и не подключает `Находку` совещания, совещание из слоя берёт только `ВходПаузы` и сигнатуры.
4. **Строки `// псевдокод:`.** Функции без тела (сигнатуры операций над объектами задачи, `отпечаток`) — тело даёт обработчик. Не подтверждено спецификацией Нова: объявление `module` и импорт `use <модуль>.{имя, …}` (как в машинах), конструктор-функция `fn Цикл.new()` — как `fn СостояниеДвижка.new` в движке.
5. **Запись расхода и запрос агента.** `Использование`, `МодельАгента`, `Токены` повторяют запись `usage.log` версии 1 (одна JSON-строка на сессию: код сессии, результат, модель, токены, стоимость, время создания и обновления) с поправкой на необязательность: число, которого источник не даёт, — «нет», а не `0` (ACP не гарантирует токены и сообщает лишь занятость окна контекста и накопленную стоимость). Времена — целые миллисекунды эпохи, как в журнале. Поля конверта (правило 31) `трасса` и `номер_шага` и `семья` модели добавлены к записи версии 1; в строке журнала версии 1 их нет. Новых конструкций Нова, не подтверждённых спецификацией, запись не вводит: `f64` — стандартный вещественный тип, `Option[...]` — как в движке.

## Типы

```nova
module автомат_методики

// псевдокод: тип ошибки операции над объектом — из движка; импорт модулей и разрешение имён — вне записи (соглашения, п. 4)
use движок_автомата.{ОшибкаОбъекта}

/// Цикл
type Цикл { номер_захода int, заход_отсчёта int, серия_чистых int, без_проб_подряд int }

/// Начальные счётчики цикла каждой стадии (раздел «Данные» первоисточника)
fn Цикл.new() -> Цикл => { номер_захода: 1, заход_отсчёта: 1, серия_чистых: 0, без_проб_подряд: 0 }

/// Находка
type Находка { критичность Критичность, уровень Уровень }

/// Критичность
type Критичность enum
  | Существенная
  | Поверхностная

/// Уровень
type Уровень enum
  | Реализация
  | План
  | Требования
  | ВнеЗадачи
  | Сдача

/// Свод: итоговая строка файла проверки захода (существенных находок и проб); у проверки цикла и запуска сессии; одноимённый `Свод` совещания — другой тип
type Свод { существенных int, проб int }

/// ВходЗапускаСессии: вход вложенной машины запуска сессии; один у раннера и проверки цикла; источник правок, фаза, номер захода и перечень источников необязательны (фазы нет у вызова из проверки цикла, номера захода — у вызова из раннера, перечня — у полного маршрута и у вызова из проверки цикла); маршрут и сдача_сжата — данные задачи для подстановок хвоста промптов
type ВходЗапускаСессии { сессия str, источник_запуска Option[str], фаза Option[str], заход_запуска Option[int], папка_задачи str, рабочее_дерево str, режим_сдачи str, маршрут str, перечень_источников Option[str], сдача_сжата bool }

/// ИтогЗапускаСессии: итог вложенной машины запуска сессии; свод и находки захода — только у сессий проверки цикла
type ИтогЗапускаСессии { итог_сессии ИтогСессии, свод Option[Свод], находки_проверки Option[[]Находка] }

/// ИтогСессии
type ИтогСессии enum
  | Готово
  | Ревизия
  | План
  | Требования
  | Вопрос

/// Стадия
type Стадия enum
  | Разбор
  | План
  | Реализация
  | Сдача
  | Совещание

/// ВходПроверки; общий у раннера и машины проверки цикла; маршрут и числа цикла — данные задачи (у стадии «совещание» не читаются); предложение, порядок линз и вопрос автора — только у стадии «совещание»
type ВходПроверки { стадия Стадия, цикл Цикл, вне_задачи []Находка, папка_задачи str, рабочее_дерево str, режим_сдачи str, маршрут str, чистых_подряд int, потолок_заходов int, проб_в_чистом int, сдача_сжата bool, предложение Option[str], порядок_линз []str, вопрос_автора Option[str] }

/// ИтогПроверки
type ИтогПроверки { вердикт Вердикт, источник str, цикл Цикл, вне_задачи []Находка }

/// Вердикт; «остановлено» — только у стадии «совещание»: раннер её не вызывает, значения не получает
type Вердикт enum
  | Чисто
  | Требования
  | План
  | Вопрос
  | Перезапуск
  | Остановлено

/// Вход обращения ПАУЗА: общий у машин методики; предыдущее — имя состояния, прерванного «стоп человека» или «стоп от родителя», запрос_вызова — идентификатор запроса, которым машину запустили
type ВходПаузы { предыдущее str, запрос_вызова str }

/// Вид вызывающего агента: кто просит ответ; поле `контекст` запроса у каждого вида своё
type ВидВызывающего enum
  | Линза
  | СессияЦикла
  | ХодЧата

/// Модель агента: как в записи `usage.log` версии 1 (идентификатор, поставщик, вариант)
type МодельАгента { идентификатор str, поставщик str, вариант Option[str] }

/// Токены вызова; каждое число необязательно — «нет», где источник его не даёт (ACP токены не гарантирует)
type Токены { вход Option[int], выход Option[int], рассуждение Option[int], кэш_чтение Option[int], кэш_запись Option[int] }

/// Использование: единая запись расхода одного вызова агента; поля версии 1 журнала плюс `семья` и конверт трассировки (правило 31); `занято_контекста` — число токенов в занятом окне контекста, которую сообщает ACP; времена — миллисекунды эпохи
type Использование { сессия str, результат str, семья str, модель МодельАгента, токены Токены, стоимость Option[f64], создано int, обновлено int, занято_контекста Option[int], трасса str, номер_шага int }

/// Профиль агента: семья модели, модель и усилие (вариант)
type ПрофильАгента { семья str, модель str, усилие Option[str] }

/// Пределы вызова агента: срок тишины (миллисекунды без вывода до кода `НетОтветаВСрок`) и бюджеты; отсутствие предела — «нет»
type ПределыАгента { срок_тишины Option[int], бюджет_токенов Option[int], бюджет_стоимости Option[f64] }

/// Запрос агента: вызывающий собирает `контекст` сам и непрозрачным текстом; слой его не разбирает
type ЗапросАгента { вид ВидВызывающего, профиль ПрофильАгента, сессия str, контекст str, пределы ПределыАгента, трасса str, номер_шага int }

/// Ответ агента: текст результата или ссылка на артефакт (хотя бы одно из двух) и запись расхода; сбой — отказ конверта с кодом `КодСбоя`, а не этот тип
type ОтветАгента { текст Option[str], артефакт Option[str], использование Использование }

/// Ворота человека — данные ворот: их читает обработчик `Связь` (показывает человеку, принимает слово, при «показывать и продолжать» даёт исход по умолчанию и пишет его в журнал).
/// Слова ворот остаются событиями машины (по варианту на слово): в одно событие они не сводятся, строки таблицы состояния различают слова.
type Ворота { имя str, слова []str, по_умолчанию Option[str], показывать_и_продолжать bool }
```

## Арифметика цикла

```nova
// Арифметика цикла проверки: одинакова у машины совещания и машины проверки цикла (task-sessions.md, «Правила»: потолок заходов, чистая серия, пробы).
// Функции чистые: значения предела (поле входа проверки цикла или константа совещания) приходят аргументом, а цикл — записью `Цикл`; машина читает свои поля в `Цикл` и записывает результат обратно.

/// Потолок заходов исчерпан: засчитанных заходов от отсчёта потолка не меньше предела; идущий заход не считается (номер_захода − 1), отсчёт — `заход_отсчёта`
fn потолок_исчерпан(цикл Цикл, предел int) -> bool => (цикл.номер_захода - 1) - цикл.заход_отсчёта + 1 >= предел

/// «заход_отсчёта = номер_захода»: сдвиг отсчёта потолка по решению человека (исходы ворот В9 у совещания и проверки цикла, правка владельца у раннера); остальные счётчики не меняются
fn сброс_отсчёта(цикл Цикл) -> Цикл => Цикл { номер_захода: цикл.номер_захода, заход_отсчёта: цикл.номер_захода, серия_чистых: цикл.серия_чистых, без_проб_подряд: цикл.без_проб_подряд }

/// Исход развилки БЕЗ_ПРОБ: что делать после чистого захода без проб
type РешениеБезПроб enum
  | ПовторитьПроверку       // без_проб_подряд = 1: просто ещё один заход (БЕЗ_ПРОБ #1)
  | СпроситьЧеловека        // без_проб_подряд больше 1: спросить человека у ворот ПОВТОР (БЕЗ_ПРОБ #2)

/// Развилка БЕЗ_ПРОБ: чистые заходы без проб подряд; None — ни одно условие не подошло (строка «иначе» машины ведёт в ОШИБКУ)
fn шаг_без_проб(цикл Цикл) -> Option[РешениеБезПроб] {
  if цикл.без_проб_подряд == 1 { return Some(ПовторитьПроверку) }
  if цикл.без_проб_подряд > 1 { return Some(СпроситьЧеловека) }
  None
}
```
