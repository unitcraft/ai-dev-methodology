# Слой методики: код общих типов и операций для машин задачи

Слой между движком и машинами методики задачи — раннером, проверкой цикла, запуском сессии и совещанием, — записанный кодом на языке Нова: типы данных, которые разделяют несколько машин методики (цикл проверки, находка, свод итоговой строки, стадия, вход и итог проверки цикла, вход и итог запуска сессии, итог сессии, вердикт), общий вход паузы, ворота человека как данные, сигнатуры операций над объектами задачи (группа процессов агента, объём запуска, показ человеку, блокировка раннера, отпечаток) и арифметика цикла проверки (потолок заходов, сдвиг отсчёта потолка, чистые заходы без проб). Движок — [state-machine-engine-automaton.md](state-machine-engine-automaton.md) — не знает методики: он обобщён по типам машины и этого слоя не подключает; слой подключают сами машины (`use`). Машины, которые его используют: раннер — [task-runner-automaton.md](task-runner-automaton.md), проверка цикла — [task-runner-review-automaton.md](task-runner-review-automaton.md), запуск сессии — [task-runner-session-automaton.md](task-runner-session-automaton.md) (её зовут раннер и проверка цикла), совещание — [task-runner-meeting-automaton.md](task-runner-meeting-automaton.md).

**Первоисточники.** Методика — [task-runner.md](task-runner.md) (словарь, ворота, форматы файлов, профили запуска) и [task-sessions.md](task-sessions.md), «Правила» (коды сессий, потолок заходов, чистая серия, пробы); типы блока «Типы на Нове» — в первоисточниках машин: [task-runner-states.md](task-runner-states.md), [task-runner-review-states.md](task-runner-review-states.md), [task-runner-session-states.md](task-runner-session-states.md), [task-runner-meeting-states.md](task-runner-meeting-states.md). Правила формы машины — [state-machine-spec.md](state-machine-spec.md). Этот файл — производная запись, а не второй источник истины: при любом расхождении верны первоисточники, а этот файл правится вслед за ними. Язык записи — Нова, https://github.com/nv-lang/nova. **Код не компилировался и не проверялся компилятором Нова:** это псевдокод в синтаксисе Нова; помеченные места (`// псевдокод:`), подтверждённое и неподтверждённое спецификацией Нова — в [движке](state-machine-engine-automaton.md), пункт 5 соглашений, здесь только то, что добавляет слой. Имя файла — по `AGENTS.md`, «Вынесенные алгоритмы» (документ `state-machine`, часть `methodology`, форма `automaton`).

## Соглашения записи

1. **Типы и идентификаторы** — по [движку](state-machine-engine-automaton.md), пункты 1–3: русские имена, поля и функции — змеиный регистр (правило 25 спецификации: имя одной сущности одно). Сокращений в именах нет.
2. **Что в слое.** (а) Типы данных первоисточника, общие у нескольких машин методики: раньше они лежали в файле раннера, и проверка цикла подключала их оттуда; теперь объявлены один раз здесь. Сюда же вынесены `Свод` проверки цикла (его возвращает запуск сессии, читает проверка цикла) и вход и итог запуска сессии — `ВходЗапускаСессии`, `ИтогЗапускаСессии`: раннер и проверка цикла зовут вложенную машину запуска сессии ([task-runner-session-automaton.md](task-runner-session-automaton.md)) и строят её вход и разбирают её итог одними и теми же типами. (б) `ВходПаузы` — вход обращения ПАУЗА: у раннера, проверки цикла и совещания он один и тот же (предыдущее состояние, запрос вызова); каждая машина оборачивает его в свой вариант `ВходРоли` (`ВходПаузыРоли`). (в) `Ворота` — данные ворот человека: их читает обработчик `Связь`; слова ворот остаются событиями машины (по варианту на слово, как в таблицах состояний), в одно событие они не сводятся. (г) Сигнатуры операций над объектами задачи: тело даёт обработчик эффекта `Объекты`; сам эффект движка не расширен. (д) Арифметика цикла: функции над `Цикл` — `потолок_исчерпан`, `сброс_отсчёта`, `шаг_без_проб` — одинаковы у машины совещания и машины проверки цикла (развилки ПОТОЛОК и БЕЗ_ПРОБ, исходы В9 со сдвигом отсчёта); раннер держит `Цикл` по стадиям и берёт `сброс_отсчёта` для правки владельца. Машина оставляет у себя тонкую ветку таблицы с тем же комментарием `// СОСТОЯНИЕ #n`, а счёт — здесь; константы (`ПОТОЛОК_ЗАХОДОВ` и др.) остаются у машины: это параметры проекта, значение предела приходит аргументом.
3. **Одноимённые типы разных машин.** `Находка` и `Критичность` раннера и проверки цикла (`Находка { критичность, уровень }`; `Критичность`: `Существенная`, `Поверхностная`) объявлены здесь. Одноимённые `Находка` и `Критичность` совещания (`Находка { критичность, доказательство, повтор, вопрос }`; `Критичность`: `Критическая`, `Значимая`, `Желательная`) — **другие типы с тем же именем**: они лежат в файле совещания и в слой не входят, как и `Свод` совещания (`критических`, `проб`; `Свод` слоя — `существенных`, `проб` — свод проверки цикла и запуска сессии) и `Утверждение` (у раннера — дата, кто, хеш, у совещания — утверждение свидетеля). Машина называет в `use` только нужные имена; проверка цикла берёт `Находку` слоя и не подключает `Находку` совещания, совещание из слоя берёт только `ВходПаузы` и сигнатуры.
4. **Строки `// псевдокод:`.** Функции без тела (сигнатуры операций над объектами задачи, `отпечаток`) — тело даёт обработчик. Не подтверждено спецификацией Нова: объявление `module` и импорт `use <модуль>.{имя, …}` (как в машинах), конструктор-функция `fn Цикл.new()` — как `fn СостояниеДвижка.new` в движке.

Соответствие типов и полей (первоисточник машин — блок «Типы на Нове»):

| Первоисточник | Код (русское имя) | Блок «Типы на Нове» (латиница) |
|---|---|---|
| Цикл: номер_захода, заход_отсчёта, серия_чистых, без_проб_подряд | `Цикл`: `номер_захода`, `заход_отсчёта`, `серия_чистых`, `без_проб_подряд` | `Cycle`: `number`, `origin`, `streak`, `no_probes` |
| Находка: критичность, уровень | `Находка`: `критичность`, `уровень` | `Finding`: `severity`, `level` |
| Критичность: существенная, поверхностная | `Критичность`: `Существенная`, `Поверхностная` | `Severity`: `Essential`, `Superficial` |
| Уровень: реализация, план, требования, вне задачи, сдача | `Уровень`: `Реализация`, `План`, `Требования`, `ВнеЗадачи`, `Сдача` | `Level`: `Implementation`, `Plan`, `Requirements`, `OutOfScope`, `Delivery` |
| Свод: существенных, проб | `Свод`: `существенных`, `проб` | `Summary`: `k`, `p` |
| ВходЗапускаСессии: сессия, источник_запуска, фаза, заход_запуска, папка_задачи, рабочее_дерево, режим_сдачи | `ВходЗапускаСессии`: те же имена | `SessionLaunchInput`: `session`, `source`, `phase`, `launch_pass`, `task_dir`, `repo_dir`, `delivery_mode` |
| ИтогЗапускаСессии: итог_сессии, свод, находки_проверки | `ИтогЗапускаСессии`: те же имена | `SessionLaunchResult`: `result`, `summary`, `findings` |
| ИтогСессии: готово, ревизия, план, требования, вопрос | `ИтогСессии`: `Готово`, `Ревизия`, `План`, `Требования`, `Вопрос` | `SessionResult`: `Done`, `Revision`, `Plan`, `Requirements`, `Question` |
| ВходПроверки: стадия, цикл, вне_задачи, папка_задачи, рабочее_дерево, режим_сдачи, предложение, порядок_линз, вопрос_автора | `ВходПроверки`: те же имена | `ReviewInput`: `stage`, `cycle`, `out_of_scope`, `task_dir`, `repo_dir`, `delivery_mode`, `proposal`, `lens_order`, `author_question` |

## Типы

```nova
module автомат_методики

// псевдокод: тип ошибки операции над объектом — из движка; импорт модулей и разрешение имён — вне записи (соглашения, п. 4)
use движок_автомата.{ОшибкаОбъекта}

/// Цикл
type Цикл { номер_захода int, заход_отсчёта int, серия_чистых int, без_проб_подряд int }

/// Начальные счётчики цикла каждой стадии (раздел «Данные» первоисточника)
fn Цикл.new() -> Цикл => { номер_захода: 1, заход_отсчёта: 1, серия_чистых: 0, без_проб_подряд: 0 }

/// Находка
type Находка { критичность Критичность, уровень Уровень }

/// Критичность
type Критичность enum
  | Существенная
  | Поверхностная

/// Уровень
type Уровень enum
  | Реализация
  | План
  | Требования
  | ВнеЗадачи
  | Сдача

/// Свод: итоговая строка файла проверки захода (существенных находок и проб); у проверки цикла и запуска сессии; одноимённый `Свод` совещания — другой тип
type Свод { существенных int, проб int }

/// ВходЗапускаСессии: вход вложенной машины запуска сессии; один у раннера и проверки цикла; источник правок, фаза и номер захода необязательны (фазы нет у вызова из проверки цикла, номера захода — у вызова из раннера)
type ВходЗапускаСессии { сессия str, источник_запуска Option[str], фаза Option[str], заход_запуска Option[int], папка_задачи str, рабочее_дерево str, режим_сдачи str }

/// ИтогЗапускаСессии: итог вложенной машины запуска сессии; свод и находки захода — только у сессий проверки цикла
type ИтогЗапускаСессии { итог_сессии ИтогСессии, свод Option[Свод], находки_проверки Option[[]Находка] }

/// ИтогСессии
type ИтогСессии enum
  | Готово
  | Ревизия
  | План
  | Требования
  | Вопрос

/// Стадия
type Стадия enum
  | Разбор
  | План
  | Реализация
  | Сдача
  | Совещание

/// ВходПроверки; общий у раннера и машины проверки цикла; предложение, порядок линз и вопрос автора — только у стадии «совещание»
type ВходПроверки { стадия Стадия, цикл Цикл, вне_задачи []Находка, папка_задачи str, рабочее_дерево str, режим_сдачи str, предложение Option[str], порядок_линз []str, вопрос_автора Option[str] }

/// ИтогПроверки
type ИтогПроверки { вердикт Вердикт, источник str, цикл Цикл, вне_задачи []Находка }

/// Вердикт; «остановлено» — только у стадии «совещание»: раннер её не вызывает, значения не получает
type Вердикт enum
  | Чисто
  | Требования
  | План
  | Вопрос
  | Перезапуск
  | Остановлено

/// Вход обращения ПАУЗА: общий у машин методики; предыдущее — имя состояния, прерванного «стоп человека» или «стоп от родителя», запрос_вызова — идентификатор запроса, которым машину запустили
type ВходПаузы { предыдущее str, запрос_вызова str }

/// Ворота человека — данные ворот: их читает обработчик `Связь` (показывает человеку, принимает слово, при «показывать и продолжать» даёт исход по умолчанию и пишет его в журнал).
/// Слова ворот остаются событиями машины (по варианту на слово): в одно событие они не сводятся, строки таблицы состояния различают слова.
type Ворота { имя str, слова []str, по_умолчанию Option[str], показывать_и_продолжать bool }
```

## Операции над объектами задачи

```nova
// Операции над объектами задачи, которых нет в эффекте `Объекты` движка: сигнатуры, тело — обработчик `Объекты`; эффект движка не расширен.
// псевдокод: функции без тела — сигнатуры
// измерено исполнителем перед запуском сессии: «помещается» или «не помещается»
fn объём_запуска() Объекты -> str
// группа процессов агента останавливается целиком и проверяется, что в ней не осталось процессов
fn остановить_группу_агента() Объекты -> Result[(), ОшибкаОбъекта]
// человеку показывается текст (КОНЕЦ раннера: «задача завершена»)
fn показать_человеку(текст str) Объекты -> ()
// блокировка раннера снимается
fn снять_блокировку() Объекты -> Result[(), ОшибкаОбъекта]
// отпечаток предложения: размер, время и хеш (чистая функция)
fn отпечаток(байты []u8) -> str
```

## Арифметика цикла

```nova
// Арифметика цикла проверки: одинакова у машины совещания и машины проверки цикла (task-sessions.md, «Правила»: потолок заходов, чистая серия, пробы).
// Функции чистые: значения констант (предел) приходят аргументом, а цикл — записью `Цикл`; машина читает свои поля в `Цикл` и записывает результат обратно.

/// Потолок заходов исчерпан: засчитанных заходов от отсчёта потолка не меньше предела; идущий заход не считается (номер_захода − 1), отсчёт — `заход_отсчёта`
fn потолок_исчерпан(цикл Цикл, предел int) -> bool => (цикл.номер_захода - 1) - цикл.заход_отсчёта + 1 >= предел

/// «заход_отсчёта = номер_захода»: сдвиг отсчёта потолка по решению человека (исходы ворот В9 у совещания и проверки цикла, правка владельца у раннера); остальные счётчики не меняются
fn сброс_отсчёта(цикл Цикл) -> Цикл => Цикл { номер_захода: цикл.номер_захода, заход_отсчёта: цикл.номер_захода, серия_чистых: цикл.серия_чистых, без_проб_подряд: цикл.без_проб_подряд }

/// Исход развилки БЕЗ_ПРОБ: что делать после чистого захода без проб
type РешениеБезПроб enum
  | ПовторитьПроверку       // без_проб_подряд = 1: просто ещё один заход (БЕЗ_ПРОБ #1)
  | СпроситьЧеловека        // без_проб_подряд больше 1: спросить человека у ворот ПОВТОР (БЕЗ_ПРОБ #2)

/// Развилка БЕЗ_ПРОБ: чистые заходы без проб подряд; None — ни одно условие не подошло (строка «иначе» машины ведёт в ОШИБКУ)
fn шаг_без_проб(цикл Цикл) -> Option[РешениеБезПроб] {
  if цикл.без_проб_подряд == 1 { return Some(ПовторитьПроверку) }
  if цикл.без_проб_подряд > 1 { return Some(СпроситьЧеловека) }
  None
}
```
