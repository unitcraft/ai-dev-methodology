# Совещание агентов: стейт-машина

Та же схема, что в [task-runner.md](task-runner.md), «Совещание агентов», и в псевдокоде ([task-runner-meeting-pseudocode.md](task-runner-meeting-pseudocode.md): `meeting`, `check_meeting`; [task-runner-pseudocode.md](task-runner-pseudocode.md): `loop_review(meeting)`), записанная состояниями и переходами. Нормы — [methodology.md](methodology.md), раздел 18, «Согласование решения несколькими агентами»; первоисточник — псевдокод (он следует правилам `task-runner.md`), при расхождении верен он. Опытный режим: раннером не выполняется.

## Данные

| Имя | Что это | Где хранится |
|---|---|---|
| n | номер текущего захода | `state.pass[meeting]` |
| origin | заход, от которого считается потолок | `state.pass_origin[meeting]` |
| streak | чистых заходов подряд | `state.clean_streak[meeting]` |
| unaccounted | чистых заходов без проб подряд | `state.unaccounted[meeting]` |
| lost[л] | потерянных заходов линзы л подряд | `state.lost[линза]` |
| extra | решение человека у В9 для правки автора | в памяти до ПРАВКИ |
| копия | `proposal.md` с хешем на начало захода | файл рядом с `proposal.md` |
| вопросы | есть ли вопросы автора в `proposal.md` или проверяющих в файлах захода n − 1 | в этих файлах |
| i, L | номер текущей линзы и число линз | i — в памяти захода; L — задание совещания |
| ответившие | число линз, ответивших в этом заходе | в памяти захода |
| K_свод, P_свод | существенных находок и проб по первой строке свода | `proposal-review-n.md` |
| K_В3 | существенных находок после В3, с поправкой человека | решение В3 |

Константы — ПОТОЛОК_ЗАХОДОВ, ЧИСТЫХ_ПОДРЯД, ПРОБ_В_ЧИСТОМ (`task-runner.md`, начало).

## Инварианты

1. **Решает только человек** — на воротах В3, В7, В9, В13 и «принять итог»; секретарь считает, переключает состояния и пишет журнал. Исключение — В3 в режиме «показать и продолжить», если человек так настроил.
2. **Предложение неизменно, пока работают линзы**: в состояниях ЛИНЗА `proposal.md` только для чтения, и любой выход из них возвращает запись; при старте секретаря, если проверка не идёт, запись тоже возвращается; изменение, найденное в СВЕРКЕ, делает заход недействительным.
3. **n не уменьшается**; недействительный заход повторяется под тем же n, его файлы переименованы в `*.void-<k>.md` и в счёт не идут.

## Состояния

Виды состояний и правила формы — [state-machine-spec.md](state-machine-spec.md).

| Состояние | Вид | Что делается при входе |
|---|---|---|
| ЗАХОД | выбор | — |
| ФАКТЫ | действие | держатель фактов отвечает в `facts-n.md` на вопросы автора в `proposal.md` и проверяющих в файлах захода n − 1; секретарь сверяет выдержки: несовпадение — один ход «исправь выдержку», снова несовпадение — строка помечается «не подтверждено». Держатель не ответил — ворота В13 |
| ЗАМОК | действие | копия `proposal.md` с хешем; `proposal.md` — только для чтения |
| ЛИНЗА(i) | действие | линза номер i проверяет `proposal.md` и `facts-n.md`; файлов других линз этого захода она не видит; форму её файла проверяет запуск |
| ОТКАЗ | выбор | — |
| ПОТЕРЯ | действие | ворота В13: линза i не ответила второй раз подряд |
| ДАЛЬШЕ | выбор | — |
| СВЕРКА | выбор | — |
| ИЗМЕНЁН | действие | ворота В13 с копией и изменённым файлом |
| ФИЛЬТР | действие | убираются несостоятельные мнения (четыре признака, `task-runner.md`), каждое идёт в счёт по моделям; у линзы, потерявшей все существенные находки, P = 0 |
| СВОД | действие | `proposal-review-n.md`: первая строка «Заход n: существенных K, поверхностных M, проб P» (K и M — суммы по линзам, P — наименьшее), затем находки с меткой линзы; если первой строки нет — все находки существенные, в журнал «итоговой строки нет» |
| РАЗБОР | выбор | — |
| БЕЗ_ПРОБ | выбор | — |
| ПОВТОР | действие | ворота В13: проверка второй раз подряд без проб |
| В3 | действие | ворота В3: человек читает находки и пробы, может поднять критичность; по его настройке ворота только показывают и идут дальше как «засчитан» |
| ИТОГ | выбор | — |
| ПОТОЛОК | выбор | — |
| В9 | действие | ворота В9: потолок заходов |
| ПРАВКА | действие | автор правит `proposal.md` по находкам захода n − 1 и по extra, дописывает «Изменения захода». Автор не ответил — ворота В13 |
| ВОПРОС | действие | ворота В7: человек отвечает на вопрос автора; затем автор продолжает правку с этим ответом. Автор не ответил — ворота В13 |
| ПРИНЯТИЕ | действие | ворота «принять итог»: человек подтверждает решение и запись источника |
| ОСТАНОВ | конец | в `log.md` — «совещание остановлено: <причина>» и незакрытые находки; итог не принят, программа продолжает остальную работу |
| КОНЕЦ | конец | в `log.md` — решение с источником, числом заходов и незакрытыми находками; тип проверяющего в каждом заходе — по `methodology.md`, раздел 18 |

## Переходы

«Сразу», «иначе» и правила строк — [state-machine-spec.md](state-machine-spec.md). «Запуск заново» повторяет только запуск роли с теми же входами (lost, extra и ответ человека сохраняются, В7 не открывается), действие при входе не повторяется. «Не ответил» — нет артефакта, отказ модели, форма не исправлена или бездействие дольше срока («Срок бездействия роли», `task-runner.md`).
