# Совещание агентов: стейт-машина

Та же схема, что в [task-runner.md](task-runner.md), «Совещание агентов», и в псевдокоде ([task-runner-meeting-pseudocode.md](task-runner-meeting-pseudocode.md): `meeting`, `check_meeting`; [task-runner-pseudocode.md](task-runner-pseudocode.md): `loop_review(meeting)`), записанная состояниями и переходами. Нормы — [methodology.md](methodology.md), раздел 18, «Согласование решения несколькими агентами»; первоисточник — псевдокод (он следует правилам `task-runner.md`), при расхождении верен он. Опытный режим: раннером не выполняется.

## Данные

| Имя | Что это | Где хранится |
|---|---|---|
| n | номер текущего захода | состояние машины |
| origin | заход, от которого считается потолок | состояние машины |
| streak | чистых заходов подряд | состояние машины |
| unaccounted | чистых заходов без проб подряд | состояние машины |
| lost[л] | потерянных заходов линзы л подряд | состояние машины |
| extra | решение человека у В9 для правки автора | в памяти до ПРАВКИ |
| предложение | документ, который обсуждается | хранилище |
| копия | предложение на начало захода с отпечатком | хранилище |
| ответы свидетеля | ответы свидетеля в этом заходе | хранилище |
| находки линзы | находки и пробы линзы i в этом заходе | хранилище |
| свод | свод захода с итоговой строкой | хранилище |
| архив | ответы и находки недействительных заходов, вне контекста ролей | хранилище |
| журнал | запись самой машины | хранилище (запись машины) |
| вопросы | есть ли вопросы автора в предложении или проверяющих в находках захода n − 1 | в памяти захода, из хранилища |
| i, L | номер текущей линзы и число линз | i — в памяти захода; L — задание совещания |
| ответившие | число линз, ответивших в этом заходе | в памяти захода |
| P[i] | проб линзы i в этом заходе | в памяти захода |
| причина | причина последнего отказа роли: ПричинаОтказа | в памяти захода |
| находки_В3 | находки последнего засчитанного захода после поправки человека у В3: [Находка]; пусто, пока засчитанного захода не было; в итог они уходят незакрытыми | состояние машины |
| K_свод, P_свод | существенных находок и проб по итоговой строке свода | в памяти захода, из свода |
| K_В3 | существенных находок после В3, с поправкой человека | решение В3 |

Переменные — строки «в памяти», «состояние машины» и решение В3: меняются только в столбце «Что меняется». Строки «хранилище» — внешние объекты (предложение, копия, ответы свидетеля, находки линз, свод): их меняют только действия при входе, переход их только читает. Как объекты хранятся — «Реализация на файлах» в конце.

Константы — ПОТОЛОК_ЗАХОДОВ, ЧИСТЫХ_ПОДРЯД, ПРОБ_В_ЧИСТОМ (`task-runner.md`, начало).

## Типы

Строка — одно поле. У составного типа имя стоит в первой его строке; у типа с вариантами — «Тип (вариант)». [T] — список значений типа T. Исход ворот — слово ворот из перечня в строке события; тип отдельно не заводится. Примеры выдуманы и показывают форму; у поля с перечнем значений — пример на каждое значение. Подробность типов — по правилу 6 [state-machine-spec.md](state-machine-spec.md): предложение, копия, вопросы, место источника, опора линзы — Текст, потому что машина по ним не ветвится. Что должно быть в месте источника — `methodology.md`, раздел 18, «Свидетель». Столбец «Нова» — те же типы на языке Нова (https://github.com/nv-lang/nova); это одна из возможных записей, машина от неё не зависит (упоминание языка согласовано владельцем методики, 2026-10-17).

## Инварианты

1. **Решает только человек** — на воротах В3, В7, В9, В13 и «принять итог»; секретарь считает, переключает состояния и пишет журнал. Исключение — В3 в режиме «показать и продолжить», если человек так настроил.
2. **Предложение неизменно, пока работают линзы**: от ЗАМКА до РАЗБЛОКА предложение закрыто для записи; запись возвращают РАЗБЛОК, ОСТАНОВ и ОШИБКА; при старте секретаря, если проверка не идёт, запись тоже возвращается; изменение, найденное в СВЕРКЕ, делает заход недействительным.
3. **n не уменьшается**; недействительный заход повторяется под тем же n, его ответы и находки переносятся в архив недействительных заходов и в счёт не идут.

## Термины

«Сразу» и «иначе» — [state-machine-spec.md](state-machine-spec.md), правила 12 и 13. «Запуск заново» повторяет только запуск роли с теми же входами (lost, extra и ответ человека сохраняются, В7 не открывается), действие при входе не повторяется. «Не прочитано» — предложения нет или его нельзя прочесть. «Не ответил» — нет результата роли, отказ модели, форма не исправлена или бездействие дольше срока («Срок бездействия роли», `task-runner.md`).

### СВИДЕТЕЛЬ — действие

При входе: свидетель записывает ответы на вопросы автора в предложении и проверяющих в находках захода n − 1; секретарь сверяет выдержки: несовпадение — один ход «исправь выдержку», снова несовпадение — строка помечается «не подтверждено». Свидетель не ответил — ворота В13.

Вход: вопросы: [Текст]; предложение: Текст.

Выход: ответы свидетеля: [ОтветСвидетеля]; не читал: [Текст].

| Событие | Данные события | Что меняется | Куда |
|---|---|---|---|
| свидетель ответил | ответы свидетеля: [ОтветСвидетеля]; не читал: [Текст] | — | ЗАМОК |
| В13: «повторить» | — | — | СВИДЕТЕЛЬ, запуск заново |
| В13: «остановить совещание» | — | — | ОСТАНОВ |

### ЛИНЗА(i) — действие

При входе: линза номер i проверяет предложение и ответы свидетеля и записывает находки; находок других линз этого захода она не видит; форму её находок проверяет запуск.

Вход: предложение: Текст; ответы свидетеля: [ОтветСвидетеля], может отсутствовать; i: Число.

Выход: находки линзы: [Находка]; пробы: Число; прочитано: [Текст]; опора: Текст — на какие ответы свидетеля опирался вывод и как они сверены, или «ответы свидетеля не использовались».

| Событие | Данные события | Что меняется | Куда |
|---|---|---|---|
| линза ответила | находки линзы: [Находка]; пробы: Число; прочитано: [Текст]; опора: Текст | lost[i] ← 0; ответившие + 1; P[i] ← пробы | ДАЛЬШЕ |
| линза не ответила | причина: ПричинаОтказа | lost[i] + 1; причина ← причина события | ОТКАЗ |

### В9 — действие

При входе: ворота В9: потолок заходов.

Вход: находки_В3: [Находка]; n: Число; origin: Число.

Выход: исход ворот; решение человека: Текст.

| Событие | Данные события | Что меняется | Куда |
|---|---|---|---|
| человек: «ещё заход» | решение человека: Текст | origin ← n; extra ← решение человека (сузить или разбить) | ПРАВКА |
| человек: «остановиться» | — | origin ← n | ПРИНЯТИЕ |
| человек: «остановить совещание» | — | origin ← n | ОСТАНОВ |

### ПРАВКА — действие

При входе: автор правит предложение по находкам захода n − 1 и по extra, дописывает «Изменения захода». Автор не ответил — ворота В13.

Вход: предложение: Текст; свод захода n − 1: Свод; extra: Текст, может отсутствовать.

Выход: предложение: Текст или вопрос автора: Текст.

| Событие | Данные события | Что меняется | Куда |
|---|---|---|---|
| автор закончил | предложение: Текст | extra ← ∅ | ЗАХОД |
| автор остановился (любое его стоп-слово читается как вопрос) | вопрос автора: Текст | — | ВОПРОС |
| В13: «повторить» | — | — | ПРАВКА, запуск заново |
| В13: «остановить совещание» | — | — | ОСТАНОВ |

### ВОПРОС — действие

При входе: ворота В7: человек отвечает на вопрос автора; затем автор продолжает правку с этим ответом. Автор не ответил — ворота В13.

Вход: вопрос автора: Текст; ответ человека: Текст и источник: Текст (ворота В7).

Выход: предложение: Текст или новый вопрос автора: Текст.

| Событие | Данные события | Что меняется | Куда |
|---|---|---|---|
| автор закончил | предложение: Текст | — | ЗАХОД |
| автор снова спросил | вопрос автора: Текст | — | ВОПРОС |
| В13: «повторить» | — | — | ВОПРОС, запуск заново |
| В13: «остановить совещание» | — | — | ОСТАНОВ |

### ПРИНЯТИЕ — действие

При входе: ворота «принять итог»: человек подтверждает решение и запись источника.

Вход: свод захода n − 1: Свод; n: Число; находки_В3: [Находка].

Выход: подтверждение человека: Текст с источником.

| Событие | Данные события | Что меняется | Куда |
|---|---|---|---|
| человек подтвердил | подтверждение: Текст с источником | — | КОНЕЦ |

### ОСТАНОВ — конец

При входе: предложение открывается для записи; в журнал — «совещание остановлено: <причина>» (исход ворот, по которому пришли, или отказ последней линзы) и находки_В3 как незакрытые; итог не принят, программа продолжает остальную работу.

### ОШИБКА — конец

При входе: предложение открывается для записи; в журнал — запись из перехода и данные машины; совещание остановлено, итог не принят; это дефект машины или реализации, решает человек вне машины.

### КОНЕЦ — конец

При входе: в журнал — решение с источником, числом заходов и находками_В3 как незакрытыми; тип проверяющего в каждом заходе — по `methodology.md`, раздел 18.

## Схема

```
ЗАХОД → СВИДЕТЕЛЬ → ЗАМОК → ЛИНЗА(1) → ДАЛЬШЕ → ЛИНЗА(2) → … → ДАЛЬШЕ → РАЗБЛОК → СВЕРКА → ФИЛЬТР → СВОД → СТРОКА → РАЗБОР → В3 → ИТОГ → ПРИНЯТИЕ → КОНЕЦ
ЗАХОД → ЗАМОК                         (вопросов нет)
ЛИНЗА(i) → ОТКАЗ → ДАЛЬШЕ | ПОТЕРЯ    (линза не ответила)
СВЕРКА → ИЗМЕНЁН → [ВОЗВРАТ] → АННУЛ → ЗАХОД   (предложение изменено)
РАЗБОР → БЕЗ_ПРОБ → ЗАХОД | ПОВТОР    (чистый без проб)
В3 → ЗАХОД                            (не засчитан)
ИТОГ → ЗАХОД                          (чистый, серия не набрана)
ИТОГ → ПОТОЛОК → ПРАВКА | В9          (есть существенные)
ПРАВКА → ВОПРОС → ЗАХОД;  ПРАВКА → ЗАХОД
В9 → ПРАВКА | ПРИНЯТИЕ | ОСТАНОВ
ОСТАНОВ — из СВИДЕТЕЛЯ, ПОТЕРИ, ДАЛЬШЕ, ИЗМЕНЁН, ПОВТОРА, В9, ПРАВКИ и ВОПРОСА; ОШИБКА — из «иначе» любого выбора.
```

## Реализация на файлах

Один из вариантов — схема реализации раннера `task-runner.md`; другая реализация может хранить те же объекты иначе (база, очередь, память процесса), машина от этого не меняется.

| Объект или действие | На файлах |
|---|---|
| состояние машины | `state.json`: `pass[meeting]`, `pass_origin[meeting]`, `clean_streak[meeting]`, `unaccounted[meeting]`, `lost[линза]`; находки_В3 — там же |
| предложение | `proposal.md` |
| копия с отпечатком | копия `proposal.md` рядом с ним; изменение распознаётся по размеру, времени и хешу |
| закрыть и открыть для записи | снять и вернуть право записи на `proposal.md` |
| ответы свидетеля | `witness-n.md` |
| находки линзы | `proposal-review-n-<линза>.md` |
| свод захода | `proposal-review-n.md`, итоговая строка — первая строка файла |
| архив недействительных заходов | переименование файлов захода в `*.void-<k>.md`; они лежат вне `task/` и в контекст ролей не входят |
| журнал | `log.md` |
| переменные «в памяти» (i, L, ответившие, P[i], вопросы, K_свод, P_свод, K_В3, extra) | память секретаря, в `state.json` не пишутся; после перезапуска секретаря заход проверяется заново с начала |
| возврат записи при старте секретаря (инвариант 2) | секретарь при старте возвращает право записи на `proposal.md`, если проверка не идёт |
